# /create-closing — 나만의 하루 마무리 스킬 만들기

이 스킬은 사용자와의 인터뷰를 통해, 매일 클로드 코드 작업을 마무리할 때 자동으로 실행되는 **맞춤형 /closing 스킬**을 생성합니다.

기록은 **Obsidian**에 저장됩니다.

---

## 핵심 원칙

- **질문은 하나씩.** 한 번에 여러 개를 쏟아내지 말고, 한 질문 → 답변 → 다음 질문 순서로 진행합니다.
- **객관식 우선.** 가능하면 선택지를 주세요. 사용자가 번호나 알파벳만 입력해도 되게.
- **왜 묻는지 설명.** 각 질문마다 "이걸 왜 묻냐면~" 한 줄을 붙여주세요. 비개발자도 맥락을 이해하고 답할 수 있게.
- **유연하게 대응.** 사용자가 선택지에 없는 걸 요청해도 그에 맞춰 스킬을 만들어주세요. 이 스킬의 목적은 정해진 틀에 끼워넣는 게 아니라, 사용자에게 딱 맞는 마무리 루틴을 만들어주는 것입니다.

---

## 실행 흐름

### STEP 0: 프로젝트 파악

```
안녕하세요! 나만의 하루 마무리 스킬을 만들어볼게요.
매일 클로드 코드 작업을 끝낼 때 /closing 한 번이면 기록 + 정리가 자동으로 되는 스킬이에요.

먼저, 지금 어떤 프로젝트를 하고 계신지 알려주세요.

어떤 유형에 가장 가까우세요?
A. 웹사이트/앱 개발
B. 마케팅/콘텐츠 제작
C. 기획/PM
D. 학습/실험
E. 기타 (직접 입력)

그리고, 혼자 하시나요 팀으로 하시나요?
1. 혼자
2. 팀 (2~5명)
3. 팀 (5명 이상)
```

사용자가 E를 선택하거나 추가 설명을 하면, 그 내용을 바탕으로 이후 추천을 조정합니다.

### STEP 1: 기록 — Obsidian 설정

이 단계는 **한 질문씩** 순서대로 진행합니다.

#### Q1. Obsidian vault 경로

```
기록은 Obsidian에 저장할게요.
Obsidian vault 경로를 알려주세요.

💡 vault 경로란?
Obsidian에서 열어서 쓰고 있는 폴더의 위치예요.
기록을 이 폴더 안에 저장해야 Obsidian에서 바로 열어볼 수 있거든요.

📌 확인 방법:
Obsidian 앱을 열고 → 왼쪽 아래 vault 이름 클릭 → "Vault 폴더 열기"를 누르면
파인더(탐색기)가 열려요. 그 폴더의 경로를 알려주시면 됩니다.

Mac이라면 보통 이런 형태예요:
/Users/내이름/Documents/MyVault

경로를 붙여넣어 주세요!
```

#### Q2. 워크로그 폴더 이름

```
좋아요! 그러면 vault 안에 워크로그를 저장할 폴더를 하나 만들게요.

💡 왜 폴더를 따로 만드냐면?
다른 노트들과 섞이지 않게, 워크로그만 모아두는 전용 공간이에요.
나중에 "지난달에 뭐 했지?" 할 때 이 폴더만 보면 돼요.

폴더 이름을 뭘로 할까요?
A. worklog
B. 프로젝트이름-worklog (예: my-app-worklog)
C. daily-log
D. 직접 입력

이미 쓰고 있는 폴더가 있으면 그 이름을 알려주셔도 돼요!
```

#### Q3. 파일 구조

```
워크로그가 날마다 쌓이잖아요.
이걸 어떤 단위로 묶을지 정할게요.

A. 날짜별 파일 — 매일 새 파일이 생김 (2026-05-24.md)
   → "오늘 뭐 했지?" 바로 찾기 좋음
   → 파일이 많아지지만 하루 단위로 깔끔

B. 주차별 파일 — 한 주치를 하나의 파일에 기록 (Week_01.md)
   → 일주일 흐름을 한눈에 보기 좋음
   → 주간 회고할 때 편함

C. 월별 파일 — 한 달치를 하나의 파일에 기록 (2026-05.md)
   → 파일 수가 적어서 심플
   → 대신 파일이 길어질 수 있음

어떤 게 좋으세요? (A/B/C)
```

사용자가 B(주차별)를 선택하면 추가 질문:

```
주차 계산을 위해 프로젝트 시작일을 알려주세요.
(예: 2026-05-01)
```

#### Q4. 기록 항목 선택

프로젝트 유형(STEP 0)을 바탕으로 기본 + 맞춤 항목을 제안합니다.

```
이제 매일 뭘 기록할지 정할게요.
아래는 추천 항목이에요. 빼고 싶은 건 빼고, 추가하고 싶은 건 말씀해주세요.

📋 기본 추천:
1. ✅ 오늘 한 일 — 작업 내용 요약 (다음 날 이어서 할 때 맥락 파악용)
2. ✅ 삽질 기록 — 시간 많이 쓴 문제 + 해결 과정 (같은 실수 방지, 나중에 공유 자산)
3. ✅ 배운 것 — 새로 알게 된 것 (쌓이면 진짜 자산이 됩니다)
4. ✅ 나중에 결정할 것 — 지금 보류한 판단들 (안 적어두면 까먹어요)
5. ✅ 다른 사람과 논의할 것 — 혼자 결정 어려운 것들

🎯 {프로젝트 유형} 맞춤 추천:
6. {맞춤 항목 1} — {설명}
7. {맞춤 항목 2} — {설명}
8. {맞춤 항목 3} — {설명}

빼고 싶은 번호, 추가하고 싶은 번호, 또는 "이런 것도 기록하고 싶어요"를 말씀해주세요!
```

**프로젝트 유형별 맞춤 추천 풀:**

개발/빌딩:
- 버그/에러 로그 — 발생한 에러와 해결 방법
- 기술 부채 메모 — "일단 이렇게 했지만 나중에 고쳐야 할 것"
- 환경 설정 변경 사항 — 환경변수, 배포 설정 등 변경 내역

마케팅/콘텐츠:
- 성과 지표 메모 — 오늘 확인한 수치나 반응
- 콘텐츠 아이디어 — 작업 중 떠오른 소재
- 고객 반응/피드백 — 유저 문의, 리뷰 등에서 발견한 것

기획/PM:
- 의사결정 로그 — 오늘 내린 결정과 그 이유
- 리스크 발견 — 진행 중 발견한 위험 요소
- 일정 변동 사항 — 예정보다 늦어지거나 앞당겨진 것

학습/실험:
- 시도한 것 vs 결과 — 실험한 방법과 결과
- 다음에 시도할 것 — 아직 해보지 못한 접근법
- 참고 자료 링크 — 오늘 찾은 유용한 자료

### STEP 2: Commit & Push — GitHub 연결

```
다음은 GitHub 연결이에요.

💡 이게 뭐냐면?
매일 작업 끝에 코드를 GitHub(온라인 저장소)에 올려두는 거예요.
백업도 되고, 팀원이 있으면 공유도 되고, 작업 히스토리도 남아요.

하루 마무리할 때 자동으로 GitHub에 올릴까요?
A. 네, 자동으로 올려주세요
B. 아니요, 기록만 할게요 (GitHub 안 씀)
```

**사용자가 A를 선택한 경우**, 다음 질문들을 하나씩:

```
그러면 프로젝트 폴더 경로를 알려주세요.
클로드 코드로 작업하고 있는 폴더요.

📌 확인 방법:
터미널에서 pwd 를 입력하면 현재 경로가 나와요.
또는 파인더에서 프로젝트 폴더를 우클릭 → "경로 이름 복사"

예시: /Users/내이름/projects/my-project
```

경로를 받은 후:

```
어떤 브랜치에 올릴까요?

💡 브랜치가 뭐냐면?
같은 프로젝트 안에서 작업 줄기를 나눠놓은 거예요.
보통은 main 하나로 쓰는 경우가 많아요.

A. main — 가장 기본. 혼자 작업하면 이거면 충분
B. dev — 개발용 브랜치를 따로 쓰는 경우
C. 잘 모르겠음 — main으로 할게요
D. 직접 입력
```

### STEP 3: 마무리 작업 — 추가 액션

```
마지막이에요!
기록과 저장 외에, 하루 마무리할 때 추가로 하고 싶은 것이 있으면 골라주세요.
안 하셔도 전혀 괜찮아요!

📊 프로젝트 관리:
A. 대시보드 업데이트 — 프로젝트 진행률/체크리스트 자동 갱신
B. 내일 할 일 정리 — 오늘 못 끝낸 것 + 새로 생긴 것으로 To-do 생성

📱 콘텐츠 생성:
C. 인스타그램 캐러셀 초안 — 오늘 배운 것/작업 기반으로 슬라이드 텍스트 구성
D. 블로그 포스트 초안 — 삽질/배움 중심으로 글 초안
E. TIL(Today I Learned) — 짧은 학습 기록

📋 보고/공유:
F. 주간 리포트 재료 — 주간 보고용 요약을 별도 파일에 축적
G. 팀 공유 메시지 초안 — Slack/카톡에 보낼 진행 상황 요약

✏️ 기타:
H. 위에 없는데 하고 싶은 게 있어요 (직접 입력)

골라주세요! 여러 개 가능. 패스하려면 "없음"이라고 하시면 돼요.
```

**선택한 항목에 따라 추가 질문 (하나씩):**

- **A (대시보드)** →
```
대시보드 파일이 어디에 있나요?
경로를 알려주세요. (예: /Users/.../dashboard.html)
아직 없으면 "없음"이라고 해주세요. 나중에 만들면 그때 추가할 수 있어요.
```

- **C (인스타 캐러셀)** →
```
캐러셀 설정 두 가지만 정할게요.

몇 장짜리로 만들까요?
A. 5장 (간결하게)
B. 7장 (적당히)
C. 10장 (자세하게)

톤은 어떤 느낌이요?
A. 캐주얼 — 말투체, 이모지 OK
B. 전문적 — 깔끔하고 정돈된 느낌
C. 친근한 — 반말 + 공감 위주
```

- **D (블로그)** →
```
블로그 톤은 어떤 게 좋으세요?
A. 구어체 — "~했거든요", "~더라고요" 느낌
B. 문어체 — "~했습니다", "~입니다" 느낌

블로그 초안도 Obsidian vault에 저장할까요?
A. 네, 같은 vault에 blog/ 폴더로
B. 아니요, 별도 경로 (직접 입력)
```

### STEP 마지막: 자유 요청

```
혹시 위에서 다루지 않았지만, 하루 마무리할 때 자동으로 했으면 하는 게 있나요?
어떤 것이든 괜찮아요. 예를 들면:

- "커밋 메시지를 영어로 써줘"
- "워크로그를 일본어로도 만들어줘"
- "매일 감사한 것 3가지도 기록하고 싶어"
- "작업 시간을 기록하고 싶어"

없으면 "없음"이라고 해주세요. 바로 스킬을 만들게요!
```

사용자가 뭔가를 요청하면, 그 내용을 스킬에 반영합니다. 정해진 틀 바깥의 요청이라도 가능한 한 수용하여 스킬에 포함시키세요.

```
거의 다 됐어요! 마지막으로, 이 스킬의 이름을 정할게요.

매일 작업 끝에 이 이름을 입력하면 스킬이 실행돼요.
슬래시(/) 뒤에 올 이름을 골라주세요.

E. 직접 입력 (영어 소문자, 하이픈 가능. 예: /end-of-day)
```

사용자가 선택한 이름을 스킬 파일명으로 사용합니다.

```markdown
- 푸시: {브랜치}

{마무리 액션 있을 시}

```

#### 스킬 작성 시 주의사항

1. **경로는 반드시 절대 경로로** — 사용자가 알려준 경로를 그대로 사용
2. **Git은 안전하게** — force push 금지, 상태 확인 먼저, 민감 파일 경고
3. **파일은 append 우선** — 기존 파일이 있으면 덮어쓰지 말고 아래에 추가
4. **날짜 형식** — YYYY-MM-DD 통일
5. **콘텐츠 생성 시** — 초안이므로 "확인 후 수정해주세요" 톤
6. **선택 안 한 건 제외** — 사용자가 안 고른 단계는 스킬에 넣지 않기
7. **자유 요청 수용** — 틀에 없는 요청도 가능한 한 반영

## 생성 완료 후 안내

```
✅ /closing 스킬이 생성되었습니다!

📁 위치: {파일 경로}

💡 사용법:
하루 작업 끝에 /closing 이라고 입력하면
자동으로 기록 + 정리가 실행됩니다.

포함된 내용:
📝 기록: {선택한 항목들}
{Git 선택 시} 🔄 Git: {레포} → {브랜치}
{마무리 액션 선택 시} ✨ 마무리: {선택한 액션들}

나중에 바꾸고 싶으면:
- {파일 경로}를 직접 수정하거나
- /create-closing을 다시 실행하면 돼요!
```

그 후, 바로 테스트를 제안합니다:

```
지금 바로 테스트해볼까요?
/{스킬명} 을 실행하면 오늘 작업 기준으로 한 번 돌려볼 수 있어요.

A. 네, 지금 테스트해볼게요!
B. 아니요, 나중에 해볼게요
```

사용자가 A를 선택하면, 방금 생성한 스킬을 바로 실행합니다. 실제 워크로그가 생성되고, 선택한 액션들이 실행되는 것을 사용자가 확인할 수 있게 합니다.
