## 😣 Before → ✨ After
- **Before**: 각 사이트별로 들어가서 어떤 회사가 가장 많이 주는지 파악하고 그 안에서 요금제를 또 찾아야 함
- **After**: 주요 알뜰폰 3사 프로모션 내용 한번에 확인, 내가 사용하는 데이터량, 문자량, 통화량을 입력하면 가장 현금성 환급이 많이 되는 요금제를 추천, 실제로 클릭시 가읻하기까지 가능 

## 🎯 주요 기능 (3~5개)
- 알뜰폰 프로모션 자주하는 회사 별 현재 프로모션 혜택 동시 비교 : 헬로모바일, kt m 모바일, 유모바일
- 어떤 통신사를 쓸지 정하면 자신의 사용량을 적으면 요금제 추천
- 실제로 몇개월 쓰고 갈아타면 될지도 제안해줌

## 🔧 이렇게 만들었어요 (기술 스택)
> - 프론트엔드: HTML · CSS · JavaScript (바닐라, 프레임워크 없음)
- 계산 로직: 순수 JS 함수로 직접 구현 — 요금제별로 "몇 개월 쓰고 갈아타면 순수익이 최대"인지 자동 계산
- 데이터: 통신사 3사 프로모션을 JS 객체로 구조화 (별도 DB·API 없음, 수동 갱신)
- 배포: GitHub Pages
- 서버에 저장·조회할 게 없는 정적 계산기라서. 데이터도 직접 갱신하니까 프레임워크는 오버였고, 빌드 없이 파일 하나로 빠르게 고치는 게 이 단계엔 맞았다.

## 💡 삽질 & 인사이트
### 1. 데이터 수집 삽질 (외부 데이터가 통제 밖이라 생긴 문제)

- **요금제가 너무 많고 이미지로 박혀 있어서 전체 정리가 불가능.** 결국 대표 요금제만 노출하는 걸로 타협. → 단, 이건 "최적 요금제 추천"이라는 핵심 가치를 직접 갉아먹는 타협이라는 점을 의식하고 있어야 함. 누군가에겐 진짜 최적이 대표 요금제 밖에 있을 수 있음.

- **프로모션이 계속 바뀜.** 5월 말 기준으로 작업했는데 6월 초·중순에 연달아 변경됨. 데이터가 2주 단위로 썩는 구조라는 걸 작업 중에 체감.

- **프로모션 내용을 한 번에 이해 못 해서 엑셀로 1차 정리 후 투입.** 복잡한 외부 데이터는 클로드한테 바로 던지지 말고, 사람이 구조화해서 넘기는 단계가 필요.

- **약관·주의사항은 AI한테 위임하면 안 되는 레이어.** 처음엔 "클로드가 주의사항까지 못 챙겼다 / 내가 못 시켰나"로 봤지만, 진짜 교훈은 다름. 프로모션 약관·주의사항은 법적·신뢰 민감 영역이라 구조적으로 사람이 직접 책임져야 하는 부분. 못 시킨 문제가 아니라 위임하면 안 되는 문제.

### 2. 구현·반복 삽질 (만들다가 틀려서 다시 만든 것)

- **네비게이션 갈아엎음.** 페이지 전환 방식으로 만들었다가 피드백 받고 단일 페이지 아코디언으로 다시 짬. 한 번 더 만든 거.

- **결과 카드 정보 구조를 한 번 틀림.** 7개 요금제 다 펼쳐 보여줬다가 1등만 상세 + 2~7등 한 줄 요약으로 접음. "다 보여주는 게 친절"이 틀렸고 "선택을 대신 좁혀주는 게 친절"이 맞았음.

- **혜택 칩 affordance 버그.** 클릭 안 되는데 클릭되는 것처럼 보였음. 보이는 것과 동작이 어긋나면 그 자체가 버그.

- **중첩 클릭 토글 버그 → stopPropagation.** 클릭되는 카드 안에 버튼을 넣으면 카드가 같이 토글됨. 중첩 클릭 요소엔 `event.stopPropagation()` 필수.

- **"고친 게 왜 안 먹지" 함정.** 대화 주제가 바뀐 뒤엔 클로드가 edit을 실제로 적용 안 했을 수 있음. 버그 의심되면 코드 로직보다 "수정이 반영됐나"부터 확인.

- **개발환경 마찰.** 윈도우 + Git Bash, F12 안 먹어서 우클릭 검사로 디버깅. 도구가 불편하면 디버깅 속도가 통째로 느려짐.

### 3. 다시 봐야 할 결론

- **"어드민 대신 수동이 심플하다"는 1개 캐리어 기준 결론.** 
- 통신사가 3사로 늘고 프로모션이 2주마다 바뀌면 "수동"의 부담이 커지지만, 나 혼자 관리하는 한 어드민 UI는 여전히 과잉이다. (어드민이 정당화되는 건 코드를 못 만지는 다른 사람이 데이터를 직접 넣어야 할 때)  실제로 데이터는 이미 코드와 분리돼 별도 파일에 구조화돼 있었고(통신사·금액·기간·조건 등), 남은 건 어드민이 아니라 그 구조를 정리하는 일이었다 — 정직한 파일 이름, 통신사별 기준일 칸, 검증 안 된 값 분리.

- **47만원 숫자 = 의도된 결정이자 시한폭탄.** 임팩트 위해 보수적 25만원 대신 공격적 숫자 + "최대"로 정직성 보강. 하지만 헬로모바일 전용 숫자라 멀티 캐리어 되면 틀린 말이 되고, 프로모션 바뀌면 같이 틀려짐. 화면에 "기준일 5월 말" 같은 날짜가 안 박혀 있으면, 사용자가 틀린 숫자 보고 갈아탔다 손해 보는 순간 신뢰가 통째로 날아감.
