## 미션1: 전지적독자시점 — 배포 후 다듬기

### Summary

기능 세 개 추가하고, 버그 두 번 만나고, 서비스 말투를 처음부터 다시 짰다.

### 최종 구현 결과물

- 패턴 분석 탭 전체 선택 체크박스 (3편 미만 안내, 10편 이상 경고)
- 패턴 분석 리포트 PDF 저장
- 로딩 화면 간소화 — 타이머/팁 슬라이드 제거, "5~15초 정도 걸려요" 한 줄로
- 프롬프트 + UI 말투 전면 교체

배포: slop-detector-beta.vercel.app

### 과정 (타임라인별 + 삽질)

**삽질 1 — PDF 한글 깨짐** jsPDF 기본 내장 폰트가 한글을 지원하지 않는다. 처음엔 텍스트를 직접 렌더링하는 방식으로 짰다가 배포 후에 깨진 걸 발견했다. html2canvas로 화면을 그대로 캡처해서 PDF에 이미지로 넣는 방식으로 바꿨다. 한글 폰트 내장, 레이아웃 재현 같은 문제를 한 번에 건너뛸 수 있다.

**삽질 2 — `Uncaught SyntaxError: Illegal return statement` (862번째 줄)** PDF 저장 함수 추가하면서 `esc()` 함수 앞부분을 덮어써버렸다. 결과는 비밀코드 입력해도 입장이 안 되는 것. Vercel 로그, 환경변수, Redeploy까지 다 뒤졌다가 브라우저 Console에서 잡았다. 코드 수정 후엔 배포 전 `grep`으로 구 표현 잔재 검증하는 루틴을 만들었다.

**말투 전면 교체** 기능을 다 붙이고 나서 실제 진단 결과를 보면서 문제가 보였다. `!` 아이콘, "걸림", "통과/실패" — 전부 틀린 걸 잡아내는 사람의 언어였다. 서비스가 지향하는 건 "날 구원하러 온 편집자"인데, 말투는 "깐깐한 심사위원"이었다.

바꾼 것들:

- 프롬프트 페르소나: "날카로운 편집자" → "글쓴이 편인 편집자. 틀린 걸 잡는 게 아니라 더 닿을 수 있는 길을 보여주는 사람"
- `!` → `→` / "걸림" → "더 닿을 수 있어요" / "모두 통과" → "모두 잘 됐어요 ✓"
- "독자 입장에서 본 진단" → "독자 입장에서 읽어봤어요"
- "문단별 고쳐쓰기" → "여기서 조금 더 가면 닿아요"

### 공유할만한 인사이트

1. **말투는 기능이다.** 기능을 다 붙인 다음에야 보이는 문제라 순서상 어쩔 수 없었지만, 다음엔 프롬프트 페르소나를 먼저 잡고 기능을 붙이는 게 맞겠다. UI 라벨 하나가 서비스 전체의 온도를 결정한다.
    
2. **화면 캡처 PDF가 텍스트 렌더링보다 낫다.** 한글 폰트 문제를 포함해서, 디자인이 이미 잘 돼 있다면 html2canvas 캡처가 제일 빠르고 정확한 길이다.

## 미션2: 직접 써보면서 발견한 것들

### Summary

진단기에 광고 글을 넣어봤다가 서비스의 빈 곳을 발견했다. 그리고 타깃이 막연하다는 걸 알았다.

### 최종 구현 결과물

- 타깃 재정의: "자기계발 SNS 사용자" → "6개월 이상 꾸준히 쓰고 있는데 반응이 없는 사람"
- 문제 정의 교체: "기록은 했는데 읽히고 있나요?" → "열심히 쓰고 있는데 솔직하게 읽어줄 사람이 없다"
- README 전면 개편: 배포 가이드 전용 → 서비스 소개 + 배포 가이드 병합

### 과정 (타임라인별 + 삽질)

**광고 글을 넣어봤더니 기준이 안 맞았다** 인스타 브랜드 협찬 글을 진단기에 넣었다. 진단 내용은 맞았다. 문제는 따로 있었다 — 이 글은 광고주 조건이 붙은 글이라, 지적한 것들을 글쓴이가 고칠 수 없다. 제품명 나열, #제작지원 표기, CTA 문구는 계약 조건일 가능성이 높다. 서비스 타깃이 "자기 경험을 기록하는 사람"인데 광고 글엔 기준 자체가 안 맞는다.

**타깃 딜레마와 해소** "이미 유명한 사람은 이 서비스가 필요 없고, 이제 막 시작한 사람은 글이 없어서 패턴 분석이 안 된다."

정리하다 보니 그 사이 구간이 보였다 — 6개월 이상 꾸준히 써왔는데 팔로워가 늘지 않고, 쓰는 걸 멈추진 않는 사람. 이 사람들이 지금 하는 행동이 뭔지 생각해봤다. 지인한테 "내 글 어때?" 물어보는 거다. 그런데 지인은 솔직한 피드백을 못 준다. 관계가 있으니까. "좋아 보여"만 돌아온다. 이 서비스가 그 자리를 대신할 수 있다.

**문제 정의를 다시 썼다** "기록은 했는데, 읽히고 있나요?"는 유통 문제(알고리즘, 팔로워)와 글 자체 문제를 동시에 연상시킨다. 이 서비스가 실제로 풀 수 있는 건 글 자체의 문제뿐이다. "당신 글, 솔직하게 읽어드릴게요"로 바꿨다.

### 공유할만한 인사이트

1. **문제 정의는 못 하는 것을 먼저 빼는 것이다.** "읽히고 있나요"에서 유통 문제를 빼고 나니 "솔직하게 읽어드릴게요"가 남았다. 무엇을 할 것인가보다 무엇을 안 할 것인가를 먼저 정하는 게 더 빨랐다.
    
2. **타깃은 상황으로 정의해야 한다.** "자기계발 SNS 사용자"는 타깃이 아니라 방향이었다. "6개월 이상 썼고, 반응이 없고, 솔직한 피드백을 받을 곳이 없는 사람"이 들어가야 기능 우선순위도 잡힌다.
