## 미션1: <제목>

### Summary
네이버 블로그 주제 브리핑 봇을 HTML 한 장짜리에서 → Gemini API 붙은 실배포 가능한 앱 구조로 키움. 이번 주는 UI를 집중적으로 디벨롭함 — 디자인 이식, 더보기, 세션캐시, 에러처리, 클릭→소제목 구조까지 다 붙임. 로컬에서 처음부터 끝까지 도는 거 확인 완료. 남은 건 Vercel 배포 한 단계뿐임. (클로드 토큰 떨어져서 배포는 다음 차례로 밀림)

### 최종 구현 결과물
- HTML 골격 위에 디자인 이식 끝 — 봇 화면 자체가 굴러감
- Gemini API 연결 (`api/gemini.js` + `callGemini()` + 프롬프트). 모델은 fallback 배열, `gemini-2.5-flash` 우선 , 다 쓰면 lite모델로 쓰게함.
- UI 인터랙션 4종:
    - **더보기** — 결과 점진 로드
    - **클릭 → 소제목 펼침** (아코디언식 구조)
    - **세션캐시** — 같은 날짜+카테고리+키워드면 재요청 없이 즉시 표시 → 체감 로딩 확 줄음
    - **에러처리 UI** — API 실패해도 화면 안 깨지게
- 카카오 발송은 PlayMCP `KakaotalkChat-MemoChat`로 연결
- 로컬(`node server.js`)에서 end-to-end 동작 확인함
### 과정 (타임라인별 + 삽질)
1단계 — HTML 골격 + 디자인 이식 ✅ 2단계 — Gemini API 연결 ✅ 3단계 — 더보기 + 세션캐시 + 에러처리 + 클릭→소제목 ✅ (이번 주 UI 핵심) 4단계 — 로컬 테스트 ✅ 5단계 — Vercel 배포 ⬜ (다음)

**삽질 모음**

- `vercel dev`가 환경 이슈로 자꾸 말썽 → 그냥 `node server.js`로 로컬 돌림. 테스트엔 충분
- 단일 모델 할당량 금방 터짐 → 모델 fallback 배열로 처리. 하나 막히면 다음 모델로 자동
- API 키 하나로 부족 → `GEMINI_API_KEY` 콤마 구분 다중 키. 소진되면 자동 전환
- 카카오 REST API에서 KOE006 계속 뜸 → 직접 연동 포기하고 PlayMCP로 우회
- `:PRD` 디렉터리 — 콜론 들어가니까 CLAUDE.md에서 참조 자체가 안 됨. `PRD`로 이름 바꿔서 해결
- API 병렬화는 일부러 안 함 → 순차 호출 유지. 속도보다 안정성 택함
