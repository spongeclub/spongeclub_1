## 📅 타임라인 & 삽질 로그

### v3.5 — 최초 커밋 (내부 툴 단계)

- 동일 템플릿 + 텍스트 교체만으로 카드뉴스 완성
- 첫 유저 = 나 자신
- 살짝 공개했더니 주변에서 FOMO 반응 → 다들 자기 OS를 만들기 시작

---

### 삽질 #1 — 누끼

**발단:** 유저가 매번 외부 툴(remove.bg 등)을 거쳐야 했음. 말로 불편하다고 하지 않았고, 행동으로 보였다.

**문제:** 툴을 벗어나는 순간 UX가 끊김

**해결:**

- 스포이드 배경 제거 직접 구현
- 이후 자르기 → 플러드필 → 지우개 → 복구 브러시 → 페더까지 단계적으로 확장

---

### 삽질 #2 — 용량 문제

**발단:** "텍스트만으론 아쉽다"는 피드백 → 이미지 첨부 기능 추가

**문제:** 브라우저 `localStorage` 용량 한계 도달. 저장했는데 데이터가 날아감.

**해결:**

- 이미지를 `IndexedDB`로 분리 저장하는 구조로 전환
- `html2canvas` 렌더링 에러 픽스 (`color-mix` → `rgba`)
- 편집 데이터 보존 관련 버그 3종 동시 수정

---

### 삽질 #3 — 캐릭터 일관성

**발단:** 전혀 예상 못했던 니즈. 유저가 직접 쓰다가 "캐릭터가 매번 달라지면 브랜드가 안 잡혀요"라고 말해줬다.

**문제:** 기획 단계에서는 절대 발견할 수 없었던 종류의 문제

**해결 (단계적):**

1. 캐릭터 라이브러리 구축
2. GIF 애니메이션 지원 추가
3. MP4 출력 → 카드별 개별 파일 방식으로 전환
4. 애니메이션 GIF가 MP4에서 실제로 움직이도록 수정

---

### 예상한 확장 — 멀티 브랜드 + 클라우드

내 페르소나가 여러 개였기 때문에 처음부터 의도한 방향이었음.

- 브랜드별 템플릿 + 이메일 접근 권한 분리
- Google OAuth 로그인 연결
- Supabase 클라우드 저장으로 전환 (브라우저 저장 한계 탈출)
- DB RLS(Row Level Security) 적용

---

### 가장 최근 — AI 자동화

- Gemini API 서버리스 함수로 연결
- 카피라이터 페르소나 부여 + "AI티 제거 규칙" 별도 적용
- JSON 구조화 출력으로 슬라이드 구성 자동 설계 + 장 수 자동 조절

## 💡 공유할 만한 인사이트

### 1. MVP의 첫 유저는 나 자신이어야 한다

직접 쓰지 않으면 진짜 문제를 모른다. 내가 불편하면 남도 불편하고, 내가 편하면 남도 편하다.

### 2. 피드백은 요청해서 나오는 게 아니다

|방법|결과|
|---|---|
|설문조사|원하는 말만 함|
|인터뷰|생각나는 것만 말함|
|**실제로 써보게 하기**|**진짜 문제가 나옴**|

### 3. 기획 단계에서 발견할 수 없는 문제가 있다

캐릭터 일관성 이슈는 유저가 실제로 쓰기 전까지 아무도 몰랐다. 완벽한 기획보다 빠른 공개가 낫다.

### 4. 기능을 추가하면 새로운 문제가 따라온다

이미지 첨부 → 저장 터짐, GIF → MP4 깨짐. 개발은 원래 그런 것. 당황하지 말 것.

### 5. FOMO는 연료가 된다

일주일 뒤 더 좋은 게 나와도 괜찮다. 오히려 더 잘 만들어야겠다는 동력이 된다.

### 6. 커뮤니티가 있으면 공개 전에 반응을 볼 수 있다

스폰지클럽이 없었다면 유저 피드백 없이 혼자 만들다 지쳤을 것.
