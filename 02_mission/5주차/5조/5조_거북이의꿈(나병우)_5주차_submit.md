## 미션1: 콘텐츠 제작 OS 구축 — 1회성 작업을 '자산'으로

### Summary

화장품·식품을 직접 기획하고 콘텐츠까지 만드는 1인 사업자가, **코딩 한 줄 없이 대화만으로** 콘텐츠 제작 OS를 만든 기록.

핵심은 도구 하나가 아니라 **시스템**이다. 그동안은 AI를 바꿀 때마다 제품정보를 매번 다시 입력해 프롬프트·기획서를 쓰던 **1회성 소모 작업**이었다. 이걸 → 내 제품 자료(LLM Wiki)를 중심에 두고, 어떤 AI 도구에서든 그 자료를 꺼내 콘텐츠를 만드는 OS로 바꿨다. **한 번 쌓은 자료·스킬이 재사용·누적되는 자산이 되는 것**이 이 미션의 본질.

- **무엇을**: 제품 자료(DB) + 그 자료를 모든 AI가 공유하는 창구(MCP 서버) + 어디서든 쓰는 접점(Front End) + 콘텐츠를 만드는 자동화 부품(스킬·에이전트) + 리소스·API를 하나로 묶은 OS
- **어떻게**: Claude Code(메인), Claude for Chrome(브라우저 작업 대행), Claude Opus — 전부 대화로
- **결과**: 구성요소 4개 모두 세팅·가동 중. 남은 건 스킬·에이전트를 더 다듬으며 본격 활용하는 단계

---

### 최종 구현 결과물

콘텐츠 제작 OS — 중앙 허브를 중심으로 4개 구성요소가 맞물려 돌아간다.

| 구성요소 | 내용 | 상태 |
|---|---|---|
| **데이터베이스** | LLM Wiki를 MCP 서버로 세팅. raw 원본 → AI가 정리한 wiki 지도 → output. 자사·경쟁사·고객보이스·시장·채널·트렌드 자료를 링크 그래프로 연결하고, MCP 서버를 통해 모든 AI가 직접 꺼내 씀(자체 PIN 인증으로 클로드 웹까지) | 구축·가동 |
| **Front End (접점)** | 클로드 CLI+IDE(PC, 깊은 제작·자동화) · 헤르메스+슬랙(외부·수시·예약) · 클로드 웹(비주얼·디자인) | 3접점 가동 |
| **스킬·에이전트** | 기획자·작가·비주얼·편집자 — 데이터베이스를 읽고 리소스·API를 호출해 콘텐츠를 만드는 자동화 부품 | 기본 구축, 계속 확장 |
| **리소스·라이브러리·API** | 소스·레퍼런스·템플릿 라이브러리 + 생성 AI/API(ElevenLabs·SUNO·higgsfield 등) 호출 | 기본 구축, 계속 확장 |

**업무 프로세스 변화**

- **Before**: AI마다 제품정보를 매번 다시 입력 → 콘텐츠 기획·프롬프트 생성 → 생성 AI에서 소스 생성 → 프리미어·캔바·피그마에서 편집해 완성 (매 작업이 처음부터)
- **After**: OS가 Wiki 자료로 기획·프롬프트 생성 → 생성 AI 호출해 소스 생성 → 소스 편집해 콘텐츠 완성 (자료는 재입력 0)

**실제 산출물**: OS로 뽑은 세로 숏폼(1080×1920). 제품 자료(전성분·기능)는 Wiki가 자동 공급, 기획→소스 생성→편집까지 한 흐름으로 완성.

### 과정 (타임라인별 + 삽질)

**1. "있는 자료를 왜 못 읽지?" — 문제 발견**
릴스를 만들다 AI에게서 *"성분·용량·인증번호·상세페이지 정보가 없어 깊은 설득 카피까지는 못 넣었다"*는 회고를 받았다. 그런데 그 정보는 **위키에 분명히 있었다.** 있는 자료를 못 읽은 것. 위키는 링크로 연결된 '지도' 구조인데, AI가 링크를 끝까지 따라가지 않고 한 페이지만 보고 멈춘 게 원인이었다.

**2. 빠짐없이 읽는 규칙 정립 — wiki-query**
"링크를 타고 들어가며 데이터를 놓치지 않는 것"이 위키의 존재 이유. 이 원리를 BFS link traversal(진입점에서 링크를 따라 그래프 전체를 훑는) 규칙으로 정리해 스킬화했다.

**3. 끊긴 연결 복구 — lint**
위키 전체를 점검(lint)하니 브랜드·제품 페이지 몇 곳에서 **원본(전성분 등)으로 가는 링크가 끊겨 있었다.** 하나씩 복구 → 재점검 → 끊긴 링크 0. 처음 그 "전성분 누락 사고"가 왜 났는지가 여기서 완전히 설명됐다.
> 삽질·교훈: 한 번에 안 되면 단계별로. 점검 → 복구 → 재점검을 반복하며 완성도를 올렸다.

**4. "어디서든 꺼내 쓰게" — MCP 서버화 (가장 인상적)**
자료는 한곳인데 쓰는 곳은 여럿. AI가 **MCP 서버**를 제안 — 내 자료를 여러 AI가 직접 꺼내 가는 창구다. 이게 핵심이다. **1회성으로 매번 입력하던 자료를, 한 번 정리해두면 모든 AI가 재사용하는 자산으로** 바꾼 지점. 테스트로 "○○ 바디워시 전성분 알려줘" 하니 원본 전성분이 그대로 딸려 나왔다.

**5. 클로드 웹 연결 — 낯선 설정과의 씨름 (제일 힘들었던 구간)**
클로드 웹에서도 쓰려면 내 PC 자료를 안전하게 열어줘야 하는데(Cloudflare 터널), 전부 처음 보는 것이라 막막했다.
> 삽질 1: 브라우저에서 직접 클릭해야 하는 설정 → **Claude for Chrome에게 시켜서** 대신 처리. 한 AI가 못 하는 일을 다른 AI가.
> 삽질 2: 클로드 웹 커넥터가 **클로드 쪽 자체 버그로 막힘.** 포기 대신 → **자체 OAuth 2.1 인증(PIN 로그인)을 직접 구현해 우회.** 인증키를 한 번 넣으니 클로드 웹에서 위키 자료가 그대로 나왔다.

**6. 손 안 대도 돌아가게 — 자동 운영**
PC를 켜면 자동 시작, 인증은 한 번만 하면 유지. 같은 창구를 클로드 코드(전역)와 헤르메스에도 등록 → 어떤 도구에서든 사용.

### 공유할만한 인사이트

1. **본질은 '도구'가 아니라 '시스템·자산'이다.** AI 도구를 잘 쓰는 것보다, 내 자료를 한 번 정리해 재사용·누적되는 구조로 만드는 게 훨씬 크다. 같은 일을 두 번 하지 않게 되는 순간 복리가 시작된다.
2. **기술 용어를 몰라도, 목적만 말하면 AI가 방법을 찾는다.** "MCP", "OAuth", "터널"이 뭔지 정확히 몰라도 "내 자료를 다른 AI에서도 꺼내 쓰고 싶어"라고 *목적*만 말하면 구현해준다.
3. **한 번에 안 되면 단계별로.** 점검 → 수리 → 확인을 반복하면 비전문가도 완성도를 올릴 수 있다.
4. **막히면 다른 AI에게 시켜라.** 브라우저 클릭 작업은 Claude for Chrome에게, 메인 구축은 Claude Code에게 — AI끼리 역할을 나눴다.
5. **모른다고 포기하지 않기.** 클로드 자체 버그로 막혔을 때도 "그럼 우리가 직접 우회 방법을 만들자"로 뚫었다. "뭐 하라는 건지 모르겠어"라고 솔직히 말하면 더 쉽게 다시 설명해준다.
6. **자료가 많은 일이라면 무엇이든 적용된다.** 고객 후기·매뉴얼·회의록·거래처 정보 — 흩어진 자료를 모아 AI가 빠짐없이 읽게 정비해두면, 어떤 AI에서든 "그 자료 기반으로 답해줘"가 된다.
