# 5주차 과제 — 이안

## 미션1: 프로덕트 마무리

### Summary

처음 만든 영상 편집 도구 **SSCUT**을 쓰면서 느낀 불편함을 바탕으로 제품 방향을 다시 잡아 마무리했다. ① 자체 렌더링을 포기하고 CapCut **프로젝트 파일까지만** 만들어 NLE에 넘기고, ② 어차피 렌더를 안 하니 picker만 남기고 GUI를 버려 전체를 **CLI로 재구성**해 **AI가 직접 구동**하는 도구로 바꿨다. 이렇게 재설계한 `new_cut`을 **Weft** v0.1.0으로 이름 짓고 공개 GitHub 저장소에 배포한 뒤, 실제 영상 한 편으로 도그푸딩까지 끝냈다.

**왜 이렇게 마무리했나 (SSCUT → Weft)**

- 출발점은 **SSCUT**이었다. 콘티와 소스 이미지가 준비된 상태에서 후보 픽·자막 싱크·모션·렌더를 하는 로컬 브라우저 GUI 앱으로, `SSCUT.command`를 더블클릭하면 로컬 서버가 뜨고 storyboard/picker/sync/motion/narration 등 8개 탭이 열린다. (https://github.com/MinwooPark2026/SSCUT)
- 쓰면서 세 가지가 불편했다. ⓐ 자체 mp4 렌더가 너무 느렸고(20분 영상에 20분 이상), ⓑ `1컷=1이미지=1자막`으로 묶인 per-cut 결합이라 표현이 경직됐으며, ⓒ 로컬 웹 기반 앱인데 최적화가 전혀 안 돼 있어서 프로젝트가 15분 영상급으로 커지면 렉과 로딩이 심해졌다. (조작 자체는 단축키만으로 가능해 마우스는 필요 없었다 — 문제는 웹앱의 스케일 한계였다.)
- 그래서 **렌더링을 포기하고 프로젝트 파일까지만** 만들기로 했다. 긴 영상은 NLE의 GPU 가속과 partial render가 훨씬 빠르니, 도구의 역할을 "컷·자막·모션 의사결정 → CapCut/FCP 프로젝트 파일 핸드오프"까지로 한정했다.
- 어차피 자체 렌더를 안 하니 무거운 웹 GUI가 필요 없어졌다. 사람 눈이 꼭 필요한 **picker만** 로컬 브라우저로 남기고, 나머지(파싱·검증·TTS·이미지·CapCut export)는 전부 `weft` 서브커맨드로 만들어 **AI 에이전트가 그대로 호출**할 수 있게 했다.
- 마지막으로 per-cut 결합을 푸는 **이중 트랙(dual-track)** 모델로 재설계했다. 나레이션 비트와 비주얼 샷을 분리해(many-to-many) 한 비주얼이 여러 비트를 덮거나 한 비트가 여러 비주얼을 쓸 수 있게 했다. 이 재설계 버전이 `new_cut`이고, 최종 제품이 **Weft**다.

### 최종 구현 결과물

- **Weft** v0.1.0 — 긴 호흡 설명형(explainer) 영상용 **이중 트랙(dual-track) 워크플로우 CLI**. 나레이션 비트(대본·자막·TTS 타이밍)와 비주얼 샷(생성 이미지·텍스트 카드·재사용·몽타주)을 분리해 "문장당 이미지 한 장" 노동을 줄이고, CapCut에서 바로 편집 가능한 드래프트를 만든다.
- **GitHub: https://github.com/MinwooPark2026/Weft** (public, MIT 라이선스, 한/영 이중언어 README)
- 설치: 저장소에서 `./install.sh` (editable 설치 + `~/.local/bin` 심링크로 전역 `weft` 명령 생성)
- 실행: 프로젝트 폴더에서 `weft conti → tts → images → pick → capcut`, 또는 한 번에 `weft all`
- 검증: 9개 서브커맨드 동작 확인, 단위 테스트 16개 통과
- 도그푸딩: 배포한 `weft`로 고양이 품종 5분 롱폼을 직접 만들어 봤다. CONTI → TTS(42비트) → 이미지(25컷, gpt-image-1) → CapCut 드래프트(`weft_cat_breeds`, 233.7초) 생성까지 성공했다.

- **2026-06-07**: 도구 이름을 **"Weft"**로 확정. 후보였던 Beatcut/Spool은 동명 영상편집 앱, Conti는 동명 랜섬웨어가 있어 탈락했다. weft(씨실)은 직조 은유와도 맞는다 — 나레이션 트랙(warp, 마스터 클럭) 위에 비주얼 트랙(weft)을 여러 비트에 엮어 타임라인을 짜는 게 이중 트랙 구조 그 자체다.
- **2026-06-07**: `gh repo create MinwooPark2026/Weft --public --push`로 공개 저장소를 만들고 푸시했다. (삽질) `gh api .../trees/main?recursive=1`이 zsh가 `?`를 glob으로 해석해 `no matches found` 에러를 냈는데, URL을 따옴표로 감싸 해결했다. 또 계정 라벨(`dkruru`)과 실소유자(`MinwooPark2026`)가 달라 혼동했는데 `gh api user --jq .login`으로 같은 계정임을 확인했다.
- **2026-06-07**: 저장소에 종속된 `run.sh`를 전역 `weft` 콘솔 명령으로 바꿨다(`[project.scripts] weft = "weft.cli:main"`). `dryrun` 서브커맨드는 `conti`로 개명하고, `weft all`·`uninstall.sh`·`weft whereisskill`을 추가했다.
- **2026-06-07**: 중복되던 스타일 파일을 정리했다(`STYLE_BIBLE.md` 삭제, `STYLE.txt`=설정 / `STYLE_GUIDE.md`=문서로 역할 분리). 첫 image 실행 시 기본 `STYLE.txt`가 자동 생성되게 했다. (삽질) `dryrun/`을 `example/`로 정리하면서 테스트까지 옮겼다가, 샘플과 테스트는 분리하는 게 맞다고 판단을 뒤집어 `tests/`로 되돌렸다(리팩터링 2회).
- **2026-06-07**: 도그푸딩 중 picker 프롬프트 보존 테스트가 `SHOTS/s01` 디렉터리 부재로 실패했다. `_sync_shot_prompt`에 `mkdir`을 추가해 견고화했고 테스트 16개가 전부 통과했다. `TYPECAST_EMOTION`이 실제 API payload에 안 실리던 버그도 함께 고쳤다.

### 공유할만한 인사이트

- **"렌더를 버리니 GUI도 버릴 수 있었다."** SSCUT는 단축키만으로도 조작되는 웹 기반 앱이었지만, 영상이 15분급으로 커지면 최적화가 안 된 웹앱이라 렉·로딩이 심했다. 렌더를 NLE에 넘기기로 하자 그 무거운 웹 GUI의 존재 이유 대부분이 사라졌고, picker만 남긴 채 나머지를 CLI로 내리니 사람이 조작하던 도구가 **AI가 호출하는 도구**가 됐다. 결정 하나(렌더 포기)가 인터페이스 전체(웹 GUI→CLI)를 끌어내린 셈이다.
- "제품 마무리"의 가장 큰 덩어리는 새 기능이 아니라 **배포·설치 경험**이었다. `run.sh` 종속을 전역 `weft` 명령으로 바꾸니 "이 폴더에서만 도는 스크립트"가 "어디서나 `cd`해서 쓰는 도구"가 됐다.
- 공개 repo는 **히스토리부터 깨끗하게** 가져가는 게 좋다. 기존 `.git`을 재사용하고 싶은 유혹을 버리고 fresh `git init`을 한 덕에 옛 커밋이 공개 저장소에 영구히 남는 걸 막았다.
- **도그푸딩이 최종 QA**였다. 배포한 `weft`로 실제 영상을 만들어 보니 테스트가 못 잡은 디렉터리 부재 버그가 드러났다.
- **이름 짓기도 리서치다.** 후보가 기존 앱이나 랜섬웨어와 충돌하는지 확인하고, 제품 구조(이중 트랙)와 맞는 은유(weft=씨실)를 골랐다.
