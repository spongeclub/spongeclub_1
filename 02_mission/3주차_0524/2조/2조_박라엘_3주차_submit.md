## 미션2: 내가 정의하고 적용해보고 싶은 하네스 + 오케스트레이션

사용자(나)의 아이디어
        ↓
① Planner (Claude)    → 컨셉·기능 정의   (아이디어 검증 + 무엇을 만들지 확정)
        ↓
② Generator (Claude/ChatGPT) → 산출물 생성  (점검 도구 코딩 / 캐릭터 이미지 / 데모)
        ↓
③ Evaluator (점검 도구·웹리서치) → 평가  (24종 점검 / 카카오 기준 대조)
        ↓
④ 판정
   ├─ 합격      → 완료
   └─ 미달/수정 → ②로 돌아가 피드백 반영 (반복 루프)
**오케스트레이션의 핵심 원칙 

1. **만드는 단계 ≠ 평가하는 단계** — 캐릭터·24종을 만든 뒤, 같은 머릿속에서 자평하지 않고 _별도의 점검 도구_에 넣어 평가했다. 자기가 만든 걸 자기가 보면 관대해지므로.
2. **평가는 일부러 엄격하게** — "이 정도면 됐나?" 싶을 때 그게 관대해지는 신호로 보고 더 깐깐하게 봤다. 균형 맞췄다고 자신한 24종이 점검에서 57점 나온 게 그 예다.
3. **피드백은 항상 구체적으로** — "별로다"가 아니라 "화남 감정이 4개로 쏠렸다 → 2개로 줄이고 축하·응원 추가" 식으로 무엇을 어떻게 바꿀지까지.
4. **루프 상한을 둔다** — 캐릭터 이미지는 8회까지 반복하되, 무한정 안 가고 "이 정도면 방향이 맞다" 지점에서 멈췄다.
5. **반복해도 안 되면 방향 자체를 바꾼다** — 같은 안을 계속 다듬지 않고, 광고 커뮤니티 → 캐릭터 → 이모티콘 점검 도구로 _컨셉 자체를 피벗_했다.
