## 미션1: 내 고객은 누구고 왜 쓰는가 — 클로드 코드로 프로덕트 구현하기

### Summary
"배우는 걸 좋아하는데 생각이 흩어져서 못 쓰는 사람"을 위한 캡처 인사이트 추출 웹앱 **JY Creator DB**를 만들었다.
캡처 사진을 올리면 Claude가 각 이미지의 핵심을 뽑고, 공통 테마를 연결하고, 글 초안까지 만들어준다.

**프로덕트 URL**: https://jycreatordb.vercel.app

### 내 고객은 누구인가?
- 세미나 슬라이드, 강의 화면, SNS 글을 수시로 캡처하는 사람
- 아이폰 메모, 카톡 나에게 보내기 등 여러 곳에 흩어져 수집하는 사람
- "나중에 써야지" 하고 저장하지만 막상 꺼내 쓰지 못하는 사람
- 글을 쓰거나 기획할 때 재료는 많은데 연결이 안 되는 사람

**핵심 인사이트**: 문제는 수집이 아니라 "꺼내 쓰는 것"이었다. 캡처는 충분히 하고 있었다. 그걸 하나의 언어로 연결해주는 레이어가 없었을 뿐.

### 최종 구현 결과물
- **URL**: https://jycreatordb.vercel.app
- **기능**: 이미지 최대 20장 업로드 → Claude가 각 이미지 핵심 인사이트 추출 → 공통 테마 & 연결고리 발견 → 글 초안 뼈대 생성
- **스택**: HTML/CSS/JS (모바일 최적화) + Vercel Serverless Function (Node.js) + Claude API (claude-haiku-4-5)
- **배포**: Vercel (모바일 브라우저에서 바로 접근 가능)

### 과정 (타임라인별 + 삽질)

**고객 정의 (30분)**
- "배우는 걸 좋아하는데 정리가 안 되는 사람"에서 시작
- 어디에 저장하는지 / 어떤 순간이 불편한지 구체화
- 아이폰 메모, 카톡, 슬라이드 사진, 강의 캡처, SNS 캡처 → 공통 문제: 수집은 되는데 꺼내 못 씀

**환경 세팅 (1시간)**
- Anthropic API 계정 분리 생성 (메인 계정 보호 목적)
- API 크레딧 $20 충전 + Spending Limit $20 설정
- Vercel 계정 연동

**빌드 (1시간)**
- Claude Code로 프로젝트 구조 생성 (public/index.html + api/analyze.js)
- 모바일 최적화 UI (이미지 압축, 미리보기 그리드, 로딩 상태)
- Vercel 배포

**삽질 포인트**
- `echo` 명령어로 .env 만들면 API 키 뒤에 공백 붙음 → 직접 수정
- claude-3-5-sonnet, claude-3-haiku 등 2024년 모델 전부 deprecated → 워크벤치에서 현재 모델 직접 확인 후 `claude-haiku-4-5-20251001` 사용

### 공유할만한 인사이트
- **고객 정의를 먼저 하면 빌드가 빠르다**: "누구를 위한 앱인가"가 명확하니 기능을 추가할지 말지 판단이 쉬웠다
- **모델 deprecated 주의**: API 문서보다 Console Workbench에서 실제 사용 가능 모델 먼저 확인하는 게 빠르다
- **Vercel + Claude API 조합은 최소한의 백엔드로 프로덕트를 빠르게 만드는 데 강력하다**

## 미션2: 내가 정의하고 적용해보고 싶은 하네스 + 오케스트레이션

### Summary
하네스는 "Claude가 내 방식대로 일할 수 있도록 세팅한 환경"이고,
오케스트레이션은 "여러 단계의 AI 처리 흐름을 연결한 구조"라고 정의했다.
미션1 프로덕트에 두 개념을 직접 적용해보았다.

### 내가 정의하는 하네스 + 오케스트레이션

**하네스 (Harness)**
> "Claude가 내 컨텍스트에서 일하도록 세팅한 모든 것"

단순히 "Claude에게 질문하기"가 아니라, Claude가 내 작업 방식에 맞게 동작할 수 있도록 만든 환경 전체.
- API 키 설정, 환경변수 관리
- 시스템 프롬프트 (역할, 출력 형식 정의)
- 입력 전처리 (이미지 압축, base64 변환)
- Spending Limit으로 비용 제어

**오케스트레이션 (Orchestration)**
> "인풋이 들어오면 AI가 처리하고, 아웃풋이 나오는 흐름 설계"

JY Creator DB의 오케스트레이션 흐름:
```
📱 폰에서 캡처 선택
    ↓ (이미지 압축 + base64 변환)
🌐 Vercel Serverless Function
    ↓ (Claude API 호출)
🤖 Claude가 이미지 분석
    ↓ (각 이미지 핵심 추출 → 테마 연결 → 글 초안 생성)
📋 결과 화면에 렌더링
```

### 앞으로 적용해보고 싶은 것

1. **멀티 에이전트 오케스트레이션**: 이미지 분석 → 카테고리 분류 → 관련 아카이브 검색 → 글 초안 생성을 각각 다른 에이전트가 맡는 구조
2. **OpenClaw 연동**: 텔레그램으로 캡처 사진 보내면 자동으로 JY Creator DB 처리 후 결과 반환
3. **CLAUDE.md 기반 하네스**: 프로젝트마다 Claude의 역할과 출력 형식을 문서화해서 일관된 결과물 유지

### 공유할만한 인사이트
- 하네스와 오케스트레이션을 "세팅"과 "흐름"으로 구분하면 설계가 명확해진다
- 오케스트레이션은 복잡해 보이지만 본질은 "인풋 → 처리 → 아웃풋" 단계를 명확히 나누는 것
