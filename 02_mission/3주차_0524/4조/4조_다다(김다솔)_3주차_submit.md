  시트 이름, 색상 코드, 폼 항목, 어떤 파일이 뭘 하는지 — 다시 코드를 읽고 파악하는

  ### 3단계 — 2026.05.11 ~ 05.14: 집중 작업 + Apps Script 첫 연동

### 공유할만한 인사이트
- 하네스와 오케스트레이션을 적용하지 않고 해서, 매번 새롭게 작업을 했었다
- 이 프로젝트를 다음에도 하려면 어떻게 작업하면 좋은지 물어보고, 다음 작업할 때 반영 할 예정
-  ### 1. AI 도구의 진짜 비용은 "첫 세션"이 아니라 "N번째 세션"에서 청구된다
  첫 세션은 누구나 빠르다. AI가 빠른 게 아니라 *백지를 채우는 일이 빠른 것*뿐. 진짜
  차이는 두 번째, 세 번째, 스무 번째 세션에서 난다. 매번 같은 값을 다시 파악해야
  한다면, 시간을 버는 게 아니라 매 세션마다 *콜드 스타트 세금*을 낸다. **두 달간 수십
  번 낸 5분의 합이 이 프로젝트의 진짜 손실이었다.**

  ### 2. "메모 한 줄 없음"이 실제 시스템 버그가 된다
  URL이 두 개로 갈라진 사건은 단순 불편이 아니라 **실제 구조 분기**다. `CLAUDE.md`에
  "Apps Script URL: …" 한 줄만 있었다면 wellness 세션은 새 URL을 만들 이유 자체가
  없었다. 메모가 없으면 AI는 합리적으로 행동한다 — 모르니까 새로 만든다. **그 합리성이
   시스템을 둘로 쪼갠다.** 토대의 부재는 결국 코드의 부채로 나타난다.

  ### 3. "내가 매번 똑같이 하고 있는 일" = 하네스 후보 리스트
  AI에게 새 기능을 시키기 전에, 먼저 던질 질문은 "내가 지금 매 세션 똑같이 반복하는 게
   뭔가". 그게 하네스로 박아야 할 첫 후보다. 배포 명령, 캐시 버스팅, 환경 변수 확인,
  "그 URL 뭐였지" — 전부 한 줄짜리 규칙·메모·훅으로 사라질 수 있는 일들이었다.

  ### 4. 좋은 하네스는 오케스트레이션을 *없앤다*
  "세 파일 동시 수정"을 멋진 병렬 에이전트로 푸는 게 정답처럼 보이지만, 진짜 정답은
  `config.js` 하나 — *애초에 한 파일만 있게 만들면 분배할 일이 없다.* **풀어야 할 문제
   자체를 증발시키는 게 가장 강한 해결책.** AI 시대에 더 자주 마주칠 패턴이라고 본다.

  ### 5. AI 협업의 출발점은 기능이 아니라 "토대"부터다
  "AI한테 뭘 시킬까"보다 먼저 던질 질문은 *"AI가 이 프로젝트에 진입할 때 뭘 알고
  있어야 하는가"*다. `CLAUDE.md` 한 페이지, 훅 두세 줄, config 파일 하나 — **코드 짜기
   전에 토대를 깔고 시작하는 30분**이 두 달짜리 삽질을 막는다. 이건 게으름의 반대가
  아니라, AI와 일하는 사람이 새로 배워야 할 기본기다.Bㅠ

  ## 🔧 하네스 — 이 프로젝트에 박을 5가지 (쉬운 설명)

  ### 1. **"신입한테 주는 회사 위키 한 페이지"** 만들기
  프로젝트의 핵심 정보(주소, 비밀번호, 핵심 값들)를 한 파일에 적어두기. 그러면 다음에
  AI가 새 세션으로 들어와도 그 페이지만 보면 다 알 수 있음. **"그 URL이 뭐였지?"가
  영구히 사라짐.**

  ### 2. **"파일 저장하면 자동으로 인터넷에 올려줘"** 설정
  매번 손으로 "올려!" 안 해도 되게 한 번 설정. 까먹어서 안 올리는 사고 자체가 없어짐.

  ### 3. **"코드 바꾸면 버전 숫자 자동으로 +1"** 설정
  브라우저가 옛날 화면 계속 보여주는 문제 — 손으로 숫자 올리지 말고 자동으로.

  ### 4. **"중요 값은 한 노트에만 적자"** 규칙 (`config.js`)
  같은 주소를 세 군데에 적어두면 바꿀 때 세 번 다 고쳐야 함. 한 곳에 모아두면 한 번만
  고치면 됨. **이번 프로젝트에서 URL 두 개로 갈라진 사고도 이거 하나면 안 일어남.**

  ### 5. **"올린 다음에 진짜 잘 보이나 자동 확인"** 설정
  매번 직접 새로고침해서 확인 안 해도 되게.

  → 이 다섯 개의 공통점: **"한 번 깔아두면 영원히 안 해도 되는 일들."**

  ---

  ## 🎼 오케스트레이션 — 작은 프로젝트엔 많이 안 필요하지만

  쓴다면 이 정도:

  ### 1. **"기획자 AI → 개발자 AI → QA AI" 순서로 일 넘기기**
  한 명한테 다 시키면 빠뜨림. 단계별로 역할 다른 AI한테 넘기면 빠짐없이 끝남.
  *(예: wellness 같은 새 기능 또 만들 때, URL 새로 만드는 사고 같은 거 방지)*

  ### 2. **"쉬운 일엔 가벼운 AI, 어려운 일엔 똑똑한 AI"**
  다 똑똑한 AI한테 시키면 돈 낭비, 다 가벼운 AI한테 시키면 품질 떨어짐. 일에 맞게
  분배하면 **비용 1/3로**.

  ### 3. **"디자이너 AI랑 검토 AI가 짝지어 일하기"**
  화면 바꾸면 자동으로 모바일·태블릿·PC 다 비교해서 깨진 데 알려줌. 사람이 매번 다 안
  열어봐도 됨.
