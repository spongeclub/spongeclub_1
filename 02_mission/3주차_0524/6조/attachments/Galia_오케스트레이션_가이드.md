## 한 줄 요약

ChatGPT에 복사 → Claude에 붙여넣기 → 다른 도구에 또 붙여넣기... 이 복붙 지옥에서 벗어나는 방법. **AI 팀장이 알아서 분배하게 만드는 것 = 오케스트레이션.**

---

## 1. 오케스트레이션이 뭔가

### 세 가지 용어만 알면 된다

|용어|비유|의미|
|---|---|---|
|**AI 에이전트**|전문 담당자|특정 업무만 전문으로 하는 AI. "리서치 담당", "글쓰기 담당", "SEO 담당" 같은 것.|
|**서브에이전트**|팀장 아래 팀원|메인 AI(팀장)가 일을 나눠주는 전문 담당자들.|
|**오케스트레이션**|지휘자가 오케스트라를 조율|여러 에이전트가 협업하도록 전체를 조율하는 시스템.|

### 1인 식당 vs 분업 주방

지금까지의 AI 사용법은 **1인 식당**이다. 하나의 AI(만능 비서)에게 모든 걸 시킨다. 재료 손질, 조리, 서빙, 계산까지 한 명이 다 한다.

오케스트레이션은 **분업화된 주방**이다. 재료 손질하는 사람, 굽는 사람, 플레이팅하는 사람, 서빙하는 사람이 따로 있다. 주방장(메인 AI)이 조율한다. 나는 메뉴(방향)만 정해주면 된다.

---

## 2. 기존 방식 vs 오케스트레이션

### 기존: 내가 조율자 (복붙 지옥)

```
나 → ChatGPT: "자료 조사해줘" → 결과 복사
나 → Claude: "이 자료로 글 써줘" (붙여넣기) → 결과 복사
나 → 다른 도구: "SEO 최적화해줘" (붙여넣기)
```

→ 내가 계속 중간에서 전달해야 한다. AI가 늘수록 내 일도 늘어난다.

### 오케스트레이션: AI가 팀장

```
나 → 메인 AI: "이 주제로 블로그 글 써줘"
메인 AI → 리서치 담당: "자료 조사해"
메인 AI → 글쓰기 담당: "본문 작성해"
메인 AI → SEO 담당: "검색 최적화해"
나 ← 최종 결과물
```

→ 나는 방향만 정해주면 된다. AI가 늘어도 내 일은 안 늘어난다.

### 핵심 차이

|구분|기존 (복붙)|오케스트레이션|
|---|---|---|
|내 역할|조율자 (복붙 담당)|의사결정자 (사장님)|
|맥락 전달|매번 처음부터 설명|에이전트끼리 자동 전달|
|AI 추가 시|내 일이 더 늘어남|시스템이 알아서 처리|

---

## 3. 오케스트레이션 설계 3단계

### 1단계: 뭘 할지 정리하기

나의 반복 업무 중 하나를 고른다. 그리고 AI에게 구체화를 도와달라고 한다.

🧑 **내가 할 일**: 자동화하고 싶은 업무를 하나 고른다. 🤖 **에이전트에게 시킬 일**: 그 업무를 분석해서 작업 정의서를 만들게 한다.

결과물: **작업 정의서** (이 팀이 뭘 하는지)

### 2단계: 누가 뭘 할지 나누기

작업을 담당자별로 쪼갠다. 각 담당자가 언제 시작하고, 뭘 받아서, 뭘 내놓는지 정한다.

🧑 **내가 할 일**: 역할 분담이 맞는지 검토하고, 불필요한 담당자는 빼고, 빠진 역할은 추가한다. 🤖 **에이전트에게 시킬 일**: 역할 분담표 초안을 만들게 한다.

결과물: **역할 분담표** (누가 언제 뭘 하는지)

### 3단계: 실제로 세팅하기

역할 분담을 바탕으로 실제 설정 파일을 생성한다.

🧑 **내가 할 일**: 결과물을 검토하고, 실행해보고, 안 되는 부분을 짚어준다. 🤖 **에이전트에게 시킬 일**: 팀 안내서(claude.md)와 각 담당자 설명서를 만들게 한다.

결과물: **실제 구현 파일들** (바로 사용 가능)

---

## 4. 실패하지 않으려면

> "담당자만 많이 만들고, 협업 규칙을 안 정해서" 실패한다. — Gartner (2027년까지 AI 에이전트 프로젝트의 40%가 중단 예측)

신입 5명을 뽑아놓고 업무 분장표 없이 "알아서 해봐"라고 하면 당연히 실패한다. AI 에이전트도 마찬가지다.

### 체크리스트

- [ ] **역할 겹침**: 두 담당자가 같은 일을 하려 하지 않는가?
- [ ] **시작 조건**: 각 담당자가 언제 일을 시작하는지 정했는가?
- [ ] **순서**: A가 끝나야 B가 시작하는 경우, 순서를 정했는가?
- [ ] **참고자료**: 담당자가 참고할 템플릿/예시를 줬는가?
- [ ] **협업 규칙**: 전체 규칙이 한 곳에 문서화되어 있는가?

핵심: **에이전트를 많이 만드는 게 중요한 게 아니다. 역할을 명확히 정의하고, 협업 규칙을 세우는 게 핵심이다.**

## 5. 하네스와 오케스트레이션의 관계

하네스 가이드에서 배운 것들이 오케스트레이션의 기초가 된다.

|하네스 (에이전트 1마리)|오케스트레이션 (에이전트 여러 마리)|
|---|---|
|CLAUDE.md로 규칙 정의|팀 안내서 + 각 담당자 설명서|
|기능 목록으로 범위 제한|역할 분담표로 각자 범위 제한|
|NOT-DO로 울타리 세우기|각 담당자별 NOT-DO 정의|
|PROGRESS.md로 진행 추적|팀장 에이전트가 전체 진행 추적|
|내가 직접 결과 확인 (기수)|내가 최종 결과만 확인 (사장님)|

**하네스를 잘 하는 사람이 오케스트레이션도 잘 한다.** 에이전트 한 마리도 못 다루면서 다섯 마리를 팀으로 굴릴 수는 없다.

### 적용 순서

```
1. 먼저 에이전트 한 마리를 하네스로 잘 다루는 연습 (지금 하고 있는 것)
2. 반복 업무가 보이면, 그 업무를 담당자별로 쪼개본다
3. 쪼갠 담당자들을 오케스트레이션으로 연결한다
```

급할 것 없다. 하네스가 탄탄해야 오케스트레이션도 탄탄하다.

## 6. 실전 프롬프트 템플릿

### 오케스트레이션 설계 시작용 (3단계 통합)

```
나는 [작업명]을 자동화하는 AI 에이전트 팀을 만들려고 해.

내가 하려는 일:
- 목적: [무엇을 위해]
- 입력: [어떤 재료가 필요한지]
- 결과물: [최종적으로 뭐가 나와야 하는지]
- 주의사항: [특별히 신경 쓸 것]

내가 받고 싶은 것:
1. 작업 정리 문서 (이 팀이 뭘 하는지)
2. 역할 분담표 (누가 뭘 하는지, 순서)
3. 실제 설정 파일들

먼저 나에게 이 작업을 구체화하기 위한 질문을 해줘.
내 답변을 바탕으로 위 결과물들을 순서대로 만들어가자.
```
