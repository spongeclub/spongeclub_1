## 미션1: 내 고객은 누구고 왜 쓰는가 — 클로드 코드로 프로덕트 구현하기

### Summary
매일 상품 리뷰 블로그를 쓰는 블로거(= 나)를 위한 **네이버 블로그 주제 브리핑 봇**을 만들었다. 블로그를 매일 써야 하는데 "오늘 뭐 쓰지?"라는 키워드·주제 선정이 가장 큰 병목이었다. 네이버 카페·인스타그램·유튜브 3개 소스를 병렬로 실시간 검색해 오늘 날짜 기준 핫한 글감 10개를 추천하고, 카카오톡으로 발송까지 자동화했다.

### 최종 구현 결과물
- **HTML 단일 파일** (브라우저에서 바로 실행)
- 네이버 블로그 공식 대주제 5개 + 세부주제 선택 구조
- 세부주제 선택 시 해당 카테고리 최신 추천 키워드 자동 로드 (예: 가전·디지털 → 갤럭시S26, 아이폰17에어)
- 키워드 태그 입력 (Enter로 추가, 추천 칩 클릭으로 추가)
- 네이버 카페·인스타·유튜브 **병렬 수집** 후 글감 10개 추천
- 글감 클릭 시 오른쪽에 **네이버 블로그 상위 3개 미리보기** (출처 제목·날짜·링크 포함)
- **카카오톡 발송** (PlayMCP 연동)

### 과정 (타임라인별 + 삽질)
**카카오 API 삽질 (약 40분)**

- 카카오 개발자 계정 생성 → 앱 만들기 → 플랫폼 등록 → KOE006 오류 반복
- Redirect URI, 동의항목, 플랫폼 키 설정 등 복잡한 단계에서 막힘
- → PlayMCP의 KakaotalkChat-MemoChat으로 전환, 즉시 해결

### 공유할만한 인사이트
**카카오 API보다 MCP가 훨씬 빠름**: 개발자 설정 40분 날리고 MCP로 5분 해결

## 미션2: 내가 정의하고 적용해보고 싶은 하네스 + 오케스트레이션

### Summary
하네스와 오케스트레이션을 개념으로만 이해하는 게 아니라, 직접 만든 **네이버 블로그 주제 브리핑 봇**에 적용하면서 체득했다.

처음엔 AI한테 "트렌드 찾아줘"라고만 했는데, 하네스를 설계한다는 개념을 적용하고 나서 결과물의 질이 완전히 달라졌다. 날짜·카테고리·키워드를 컨텍스트로 주입하고, 3개 소스를 병렬로 돌리고, 캐싱까지 붙이고 나서야 "이게 하네스구나"를 실감했다.
### 최종 구현 결과물
### 내 언어로 정의

**하네스(Harness)** AI가 일을 잘 할 수 있도록 동작 환경 전체를 설계하는 것. 프롬프트를 잘 쓰는 것만이 아니라, 어떤 도구를 연결하고, 어떤 정보를 언제 주입하고, 결과를 어떤 형태로 받을지를 미리 설계하는 것이다. 요리로 비유하면 — 레시피(프롬프트)뿐 아니라 주방 도구·재료 동선·플레이팅 방식까지 설계하는 것.

**오케스트레이션(Orchestration)** 여러 AI 작업을 순서대로 또는 병렬로 자동 실행하는 흐름 설계. 각 에이전트가 독립적으로 작업하고, 결과를 모아서 다음 단계로 넘기는 구조.

### 실제 적용한 하네스 설계

| 레이어      | 적용 내용                                               |
| -------- | --------------------------------------------------- |
| 컨텍스트 주입  | 오늘 날짜(2026.05.24) + 카테고리 + 키워드를 매 호출마다 시스템 프롬프트에 고정 |
| 도구 연결    | Web Search 툴 + PlayMCP 카카오톡 MCP                     |
| 출력 형식 강제 | JSON 스키마 명시 → 파싱 안정성 확보                             |
| 캐싱 전략    | sessionStorage에 날짜+카테고리+키워드 조합 키로 저장                |
**순차 vs 병렬 비교:**

- 순차: 카페(3초) → 인스타(3초) → 유튜브(3초) = **9초**
- 병렬: 셋 동시 실행 = **~3초** (3배 단축)

### 과정 (타임라인별 + 삽질)
**처음 설계 (하네스 개념 적용 전)**

- 프롬프트: "오늘 핫한 주제 찾아줘" 한 줄
- 결과: 올드하고 generic한 주제들만 나옴
- 문제 인식: AI한테 컨텍스트를 안 줬기 때문

**하네스 설계 시작**

- 날짜를 시스템 프롬프트에 명시 → 즉시 최신성 개선
- 카테고리·세부주제·키워드를 동적으로 주입
- JSON 스키마 강제 → 파싱 오류 80% 감소



### 공유할만한 인사이트

**1. 하네스는 프롬프트 엔지니어링의 상위 개념이다** "잘 써달라고 부탁"하는 게 아니라 "잘 할 수밖에 없는 환경"을 만드는 것. 날짜 한 줄 주입했을 뿐인데 결과물 품질이 확 달라졌다.

**2. 병렬 오케스트레이션은 단순히 빠른 게 아니다** 순차로 할 때는 앞 결과가 뒤에 영향을 줄 수 있어서 편향이 생긴다. 병렬로 독립 실행하면 각 소스가 오염 없이 수집된다. 속도뿐 아니라 결과 품질도 개선됐다.

**3. 캐싱도 하네스의 일부다** 같은 컨텍스트로 두 번 호출하지 않는 것 자체가 하네스 설계다. API 비용 절약이 아니라 "불필요한 호출을 제거하는 환경 설계"로 이해하니 개념이 명확해졌다.
