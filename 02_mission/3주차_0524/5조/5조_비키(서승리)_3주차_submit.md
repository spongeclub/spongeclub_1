## 미션1: 내 고객은 누구고 왜 쓰는가 — 클로드 코드로 프로덕트 구현하기

약기법 체크 & 성분명 검색 툴 (데모)**== : [https://xoxosuh.github.io/yakki-os-demo/](https://xoxosuh.github.io/yakki-os-demo/)
🌟**데모ver 이기 때문에 지정된 문장,성분명으로만 검색해서 테스트 가능
### Summary

**한 줄 정의**: 한국 화장품·건기식 브랜드의 **일본 시장 진출을 위한 일본 광고법·薬機法 위반 검사 (단계별 체크) + 한-일 성분명 변환 특화 OS**.

**페르소나**: 나 자신 및 한·일 뷰티/건기식 브랜드 실무 담당자

일본 뷰티·건기식 시장을 타겟으로 Qoo10JP, AmazonJP, 楽天 등의 플랫폼 운영 및 마케팅을 담당하는 실무자.

**약기법 및 광고법 관련 업무**를 **외부 전문 법무법인 없이 내부에서 직접 처리**하고 있으며, **일본어 광고 카피 검수, 상세페이지 표현 수정, 성분명 표기 변환(JCIA) 등의 반복 업무**를 수행하고 있음.

**후생노동성 가이드라인만으로는 실제 마케팅 소구 설계에 한계**를 느끼고 있으며, 신뢰도 높은 대체 표현 및 실무 중심 레퍼런스를 빠르게 찾고 싶어하는 니즈를 가지고 있음.

**핵심 컨셉**: ChatGPT에 같은 질문 매번 묻는 게 아니라, **내 도메인 지식과 작업 패턴이 영구 축적되는 시스템**으로 전환. **"AI를 도구로 쓰기 → OS로 쓰기"**.

- **삽질**
    - 세션 초반엔 **기능 구현 위주**였다가, 중반부터는 **실사용 발견 → 시스템 개선** 사이클로 전환
        - 일괄 검색하면서 "어, 캐시 안 먹네" → 4단계 정규화
        - 검색 결과 보면서 "전각·반각 같은 거 통일됐으면" → NFKC
        - 매일 같은 성분 찾으니 "즐겨찾기 있었으면" → 사이드바 + 메모 + 드래그
        - 시간 지나니 "캐시 정리 필요" → 캐시 관리 UI
    - **🔧 "Claude 하나로 다 시켰더니 답이 어정쩡"**
        - 처음엔 단일 Claude에 "분석하고 검증도 하고 신뢰도도 매겨" 라고 한꺼번에 요청
        - 결과: 분석은 잘하지만 검증이 부실하거나, 검증에 집중하면 분석이 얕거나
        - **해결**: Claude 2개로 분리. 각각 다른 도구만 부여 → 역할 명확화
            - 분석: `Read·Glob` (로컬 자료만)
            - 검증: `WebSearch·WebFetch` (인터넷만)
    - **🔧"신뢰도 4단계 라벨은 어디까지 나눠야?"**
        - 초기엔 단순 "검증됨/안 됨" 2단계로 시작
        - 실사용 해보니 모호한 케이스가 많음 (회원제 사이트라 접근 못 했지만 출처는 존재함, AI가 추정만 한 경우, 자주 발생하는 오타 등)
        - **세션 5에서 4단계로 확장**: ✅공식 / ⚠️비공식·검증 한계 / ❓추정 / 🔴 NG
        - 각 표기마다 라벨 부여 → 사용자가 정보를 그대로 받아쓰지 않고 **판단**할 수 있게 함
        - **4단계 정규화 함수로 종결**:
            `입력 → trim → NFKC → toLowerCase → (한글이면 공백 제거) → 키`
        - 영어는 공백 유지 (`Sodium Hyaluronate` ≠ `SodiumHyaluronate` — INCI 표준 차이)
        - 매번 정규화 룰 변경할 때마다 **기존 캐시 마이그레이션 스크립트** 같이 작성
### 공유할만한 인사이트

- **캐시 키 설계가 OS의 신뢰성을 결정**
    
    - "같은 의미인데 다른 키"가 발생하면 사용자 경험이 박살남. 정규화 룰을 명확히(접두사 제거 + 한글 공백 무시 + NFKC + 소문자 + 퍼지 매치) 정의하는 게 **도메인 OS의 핵심 인프라**
        
        예) ‘병풀추출물’ ‘병풀 추출물’ 한글 공백에 따라 다른 캐시 → 같은 의미이므로 묶어줌 → ‘병풀추출물’ 검색해도 ‘병풀 추출물’ 검색해도 동일 결과
        
        예) 그 외에도 복사 붙여넣기로 인해 발생하는 앞뒤 공백 여부, 전각/반각 등 동일의미로 예상될 법한 것들은 모두 같은 캐시로 묶어줌
        
- **제작 시작 전에 어떻게 배포할지, 어떤 식으로 구축할 지 미리 정하고 진행 (비용문제 등)**
    
- **AI 역할 분리 = 멀티 에이전트 사고**
    
    단일 AI에 모든 걸 시키지 말고, **역할별로 분리 + 도구 권한 차등**. yakki-os의 경우 분석 Claude에겐 인터넷 차단(Read·Glob만), 검증 Claude에겐 로컬 자료 차단(WebSearch·WebFetch만). 각자 자기 역할에만 몰입. **도구 권한 = 역할 정의**.
    
- **신뢰도 라벨은 AI 사용의 안전 장치**
    
    AI가 자신 있게 틀린 답 주는 문제는 본질적이라 못 없앰. 대신 **각 정보마다 "이거 어디서 왔는지" 표시**해서 사용자가 무게 두는 양을 조절할 수 있게 함. 4단계 라벨 (✅⚠️❓🔴)이 비키의 의사결정 도구가 됨. **"AI 답을 받아쓰지 말고, 판단하라"**.
