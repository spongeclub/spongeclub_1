## 미션1: 내 고객은 누구고 왜 쓰는가 — 클로드 코드로 프로덕트 구현하기

### 본인 정의 제목: 알뜰폰, 짧게 쓰고 최대 수익 얻기

### Summary

알뜰폰 갈아탈 때, 주요 사이트 들어가서 이미지 안 작은 글씨로 박힌 프로모션을 일일이 비교하는 게 너무 귀찮았다. 5월 24일 시점, 데이터 7GB 쓰는 사용자(=나) 기준으로 헬로모바일/KT M/유모바일 3사 프로모션을 비교하는 정적 웹 도구를 만들었다.

핵심 발견: 혜택 총액이 큰 곳이 1위가 아니다. 유지 기간이 짧을수록, 즉 "기간당 혜택 밀도"가 높을수록 이익이 크다.

### 최종 구현 결과물

링크: https://sangimpark.github.io/altpon-deal/ 

- 사용자: 데이터 7GB / 통화 100분 / 문자 100건 이내 사용자 (=나)
- 비교 대상: 헬로모바일, KT M모바일, 유모바일
- 비교 지표: 총 통신 비용, 총 혜택, 실질 이익 (= 혜택 − 비용)
- 순위 결과:
  - 1위 헬로모바일: 7개월 / 실질 이익 +221,690원
  - 2위 KT M: 9개월 / 실질 이익 +203,300원
  - 3위 유모바일: 12개월 / 실질 이익 +90,000원
- 추가: 통신사별 혜택 종류(이벤트코드/셀프개통/추천가입/랜덤결합/eSIM/USIM/데이터증정) 비교표

### 과정 (타임라인별 + 삽질)

**5/17 ~ 5/23 (삽질 단계)**
- 처음에는 내 개인 문제(자기관리, 영상 시청 패턴)로 시작
- 한 시간 반 동안 발굴 작업, "모드 전환이 약한 나"라는 발견까지 감
- 회고 봇(텔레그램 ↔ Claude Code) 설계 직전까지 갔으나, 일주일 지나면서 정작 진짜 짜증나는 건 따로 있다는 걸 자각함 (알뜰폰 갈아타기)

**5/23 (방향 전환)**
- "비교 사이트가 이미 시중에 있지 않나" 의심 → 검색 확인 → 단순 가격 비교 사이트는 많지만 "프로모션 텍스트 비교"는 없음 확인
- 단순 가격 비교가 아니라 "실질 이익" 기준 비교로 차별화 결정

**5/23 ~ 5/24 새벽 (구현 단계)**
- 데이터 수동 정리: 3사 사이트 직접 들어가서 이미지에 박힌 프로모션 정보를 표로 옮김 (30분)
- 자동 스크래핑 시도 검토 → 사이트들이 의도적으로 가격을 이미지로 박아두어 거의 불가능 확인
- Claude Code에 프롬프트 전달하여 HTML 한 페이지 생성
- 첫 결과물 받고 → 사소한 수정 3개 반복 (3위 카드 위계 / 부호 처리 / 비교표 해석 안내)

**삽질했던 것들**
- 발견 방향을 4번 바꿈 (개인 문제 → 가입 후 추적 → 가입 전 비교 → 프로모션 중심 비교). 두 마음(바꾸고 싶음 + 오늘은 좀~) 패턴이 코드 작업에서도 똑같이 나옴
- "검색 없이 단정하기" 함정 빠졌다가 사용자 지적으로 검색 확인
- 데이터 정리 중 "복잡하지 않을까" 걱정했지만 "굵직한 것만"으로 좁혀서 통과
- 부호 표시(혜택 −350,000원)가 이상한 걸 사용자가 짚어줘서 수정

### 공유할만한 인사이트

**1. 발견은 책상에서 짜내는 게 아니라 일상에서 마주치는 것이다.**
티로와 과제를 보내면서 스스로 찾기보다 클로드에게 찾아주길 기대했더니 내 개인 패턴(모드 전환 약함)을 한 시간 반 깊게 파봤지만, 시간이 지날수록 좀 아닌거 같다 라는 생각이 들었다. 발굴 작업이 무의미했던 건 아니다. 그 과정 자체가 "내가 진짜 만들고 싶은 게 뭔지" 분별하는 필터였다.

**2. 비교 도구의 진짜 가치는 "어떤 지표로 비교하느냐"다.**
가격 비교 사이트는 많지만 결정에 영향을 주는 건 "프로모션 + 유지 기간"이었다. 혜택 총액이 같아도 7개월짜리가 9개월짜리보다 유리하다. "기간당 밀도"가 진짜 지표다.

**3. 자동화의 벽이 곧 도구의 차별점이다.**
다른 비교 사이트들이 자동으로 정보를 못 긁어가게 알뜰폰 사이트들은 가격을 그림으로만 박아둔다. 그래서 자동 비교 사이트가 안 만들어진다. 다음 단계로는 그 그림에서 글자를 인식해서 가져오는 방법을 시도해보고 싶다. 이게 풀리면 진짜 살아있는 도구가 된다.

## 미션2: 내가 정의하고 적용해보고 싶은 하네스 + 오케스트레이션

### 본인 정의 제목: 하네스 + 오케스트레이션 — 내가 정의한 환경 셋팅

### Summary

하네스는 "클로드 코드가 일할 수 있는 환경 전체(도구·데이터·컨텍스트·규칙)의 셋팅"이다. 처음에는 강아지 목줄처럼 제한하는 도구라 생각했지만, 강의의 "주방 비유"로 정정. 같은 클로드도 환경 셋팅에 따라 일하는 결과가 6배까지 달라진다.

오케스트레이션은 그 위에서 여러 에이전트를 분업시키는 것. 이번에는 단일 흐름으로만 만들었고, 다음 단계로 다섯 개 에이전트 분업을 설계해뒀다.

### 최종 구현 결과물

**이번 프로젝트에 적용한 하네스:**

- 도구: Claude Code
- 데이터: 5/24 시점 3사 프로모션 정보 (수동 정리한 표)
- 컨텍스트:
  - 사용자는 데이터 7GB / 통화 100분 / 문자 100건 이내 쓰는 사람
  - 비교 사이트는 많지만 프로모션 비교는 없음
  - 혜택 총액이 아니라 "기간당 밀도"가 진짜 지표
- 규칙:
  - 자동 스크래핑 시도하지 않음 (사이트들이 이미지로 박아둠)
  - 일회성 도구임을 명시 (작성 시점 박기)
  - 현금성 혜택만 계산, 데이터 증정 등은 비교표에만 표시

**앞으로 적용해보고 싶은 오케스트레이션 (5-에이전트 분업):**

1. 수집 에이전트: 매월 1일 3사 프로모션 페이지 캡처
2. 이미지 해독 에이전트: 이미지에서 가격/혜택 텍스트 추출
3. 검증 에이전트: 추출 결과를 사람이 확인하기 쉽게 정리
4. 갱신 에이전트: 검증된 데이터를 사이트에 반영
5. 알림 에이전트: 새 프로모션 발견 시 사용자에게 알림

### 과정 (타임라인별 + 삽질)

**개념 이해 단계**
- 처음 "하네스"를 강아지 목줄처럼 "AI 제한 도구"로 오해
- 강의 다시 읽고 "주방 전체"라는 비유로 정정. AI가 일하는 환경 전반이라는 것 이해
- 본인 언어로 정의: "클로드 코드가 돌아갈 수 있는 환경을 어떻게 셋팅하느냐에 따라 클로드 코드가 일하는 게 달라진다. 그 셋팅 전체가 하네스다."

**적용 단계**
- 내가 한 일을 정리해보니 도구·데이터·컨텍스트·규칙 네 가지를 셋팅한 거였고, 이게 곧 하네스였다.
- 도구·데이터·컨텍스트·규칙 네 층으로 정리
- 특히 "규칙"에서 "자동 스크래핑 안 함" 같은 제약을 미리 정의해둔 게 시간 절약에 결정적

**오케스트레이션 설계 단계**
- 지금 도구는 단일 흐름이라 "오케스트레이션"이라기엔 부족함 인정
- 강사가 미션 문구를 "앞으로 적용해보고 싶은"으로 바꾼 이유 이해
- 다음 단계 5-에이전트 분업 설계로 글 마무리

### 공유할만한 인사이트

**1. 하네스의 핵심은 "제한"이 아니라 "환경"이다.**
처음 든 직관(목줄)이 부분적으로 맞지만 전체를 놓친다. AI가 일할 도구·데이터·컨텍스트·규칙이 모두 하네스다. 같은 Claude Code라도 이 네 가지가 잘 셋팅되면 결과가 완전히 달라진다.

**2. 미션 1을 만들면서 미션 2가 자연스럽게 정의된다.**
하네스를 추상적으로 정의하려고 하면 안 됐다. 실제 도구를 만들면서 "내가 지금 무엇을 셋팅했는가"를 사후적으로 언어화하는 게 진짜 하네스 정의였다.

**3. 자동화의 벽이 오케스트레이션의 출발점이다.**
"왜 자동 스크래핑이 안 되지?"를 풀려고 하면 자연스럽게 이미지 해독 에이전트가 필요해진다. 그러면 그 결과를 검증할 에이전트가 필요해진다. 그러면 갱신 에이전트가 필요해진다. 분업이 발견된다. 추상적인 분업이 아니라 진짜 문제에서 나온 분업.
