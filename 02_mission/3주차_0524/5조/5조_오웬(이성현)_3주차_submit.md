### 미션1: 내 고객은 누구고 왜 쓰는가 — 클로드 코드로 프로덕트 구현하기

#### Summary

한국 패션 1인 셀러를 위한 신뢰 기반 맞찜 매칭 플랫폼 **찜마켓**(zzim-exchange.vercel.app)을 클로드 코드로 4시간 만에 만들고 카톡 셀러 커뮤니티에 던져 42명 유저 + 협업 제안까지 받았음. 13년간 옆에서 본 셀러 페인이 WHY로 잡히는 순간 도구가 비로소 일하기 시작함.

#### 최종 구현 결과물

- 서비스: **찜마켓** — [https://zzim-exchange.vercel.app](https://zzim-exchange.vercel.app)
- 스택: Next.js + Vercel + Supabase + NextAuth + 카카오 OAuth
- 핵심 기능 3가지
    - 📸 **스크린샷 인증** — "찜했다"를 눈으로 검증
    - 🌡️ **신뢰 온도** — 답방 없거나 먹튀하면 자동 하락
    - 🔄 **크레딧** — 먼저 찜해주면 적립, 매칭에 차감
- 타겟: 에이블리·지그재그·무신사에서 활동하는 1인/소규모 패션 셀러
- 실측: 4시간 1차 빌드 → 카톡 셀러방 1곳 홍보 → 첫날 가입 발생 → 누적 42명 → 카톡 DM으로 협업 제안 수신

#### 내 고객은 누구고 왜 쓰는가

- **WHO**: 에이블리·지그재그·무신사에서 옷 파는 1인 셀러. 카톡 셀러 단톡방 여러 개에 들어가 "찜 좀 부탁드려요"를 매일 올리는 그 사람들.
- **왜 쓰는가**
    - 흩어진 카톡방마다 같은 부탁 복붙하는 게 짜증남
    - 부탁해놓고 답방 안 와서 손해 보는 일이 반복됨
    - 누가 진짜 찜했는지 확인할 방법이 없음
    - 신뢰 안 가는 사람한테 먼저 찜해주는 게 부담
- **페인의 무게**: 매출 직결. 셀러 페이지 초반 노출 알고리즘이 찜 수치에 가장 민감함. 1주 단위로 매출에 즉시 영향.

#### 과정 (타임라인별 + 삽질)

- **1~3주차**: AAA 팀원들이 CRM 자동화·기사 자동발행·알림톡 자동화를 척척 만드는 동안 나는 멈춰있음. 클로드 코드 켜놓고 뭘 만들지 몰라 키보드만 봄. 진짜 빠진 건 도구나 실력이 아니라 **WHY**였음. "AI 시대에 뒤처지면 안 된다"는 불안 하나로 움직이려니 손이 안 나감.
- **WHY 발견의 순간**: 13년 핀테크에서 가장 가까이 본 고객이 한국 패션 1인 셀러. 그들이 카톡에서 끊임없이 부탁하던 게 "맞짐 한 번만 부탁드려요" + 답방 없어서 욕먹는 일. 이거였구나.
- **4시간 1차 빌드**
    1. PRD `.md`로 기능·화면·DB 스키마 먼저 정리 (여기서 결과물 품질의 80%가 결정됨)
    2. 클로드 코드에 Next.js 보일러플레이트 + Supabase 스키마 생성 지시
    3. 카카오 OAuth + 핵심 화면 5개 (랜딩·매칭·인증·신뢰·크레딧)
- **첫 배포 → 홍보**: 400명 셀러 단톡방에 카피 던짐 — _"💥 셀러님들, 맞짐 하다 답방 없어서 속 터진 적 있으시죠?"_. UTM 분기로 채널별 클릭/전환 트래킹.
- **삽질 포인트**
    - 카카오 OAuth 콜백 URL을 localhost / Vercel preview / 커스텀 도메인 별로 따로 등록해야 함을 처음엔 몰랐음
    - 신뢰 온도 감점 곡선이 너무 가팔라서 신규 유저가 다 차가워짐 → 곡선 둔하게 조정
    - 초기 3코인은 셀러 커뮤니티엔 부족 → 채널별 20코인 프로모로 전환 후 전환율 점프

#### 공유할만한 인사이트

- **WHY가 안 잡히면 클로드 코드도 그냥 텍스트 자판기.** 3주 헤맨 진짜 원인은 도구가 아니라 문제 정의였음.
- **PRD `.md` 한 장이 빌드 시간의 80%를 결정함.** 곧장 "만들어줘"가 아니라 "이런 기능, 이런 화면, 이런 DB"를 먼저 마크다운으로 정리하면 클로드가 일관된 시스템을 짬.
- **고객의 실제 언어를 카피에 그대로 박는 게 가장 잘 먹힘.** "맞짐", "답방", "먹튀" — 셀러 커뮤니티 내부 단어가 들어간 카피가 클릭률 차이를 만들었음.

### 미션2: 내가 정의하고 적용해보고 싶은 하네스 + 오케스트레이션

#### Summary

LLM 자체는 텍스트만 뱉는 뇌 하나임. 그 뇌에 팔·눈·귀를 붙이는 게 **하네스**, 여러 개를 자동으로 흐르게 하는 게 **오케스트레이션**. 둘 다 깔고 나서야 ChatGPT/Gemini 쓸 때와 비교해 생산성이 폭발한 진짜 이유를 설명할 수 있게 됨. 모델이 똑똑해진 게 아니라 **모델이 접근할 수 있는 세계가 늘어남**.

#### 내 정의

**하네스 = 모델에게 팔다리를 달아주는 작업장 전체.** 네 가지 층:

- **도구(Tools)** — 뭘 _할_ 수 있는지: 파일 편집, bash, 웹, MCP
- **컨텍스트(Context)** — 뭘 _볼_ 수 있는지: SOUL.md, USER.md, samples, 메모리
- **실행 루프(Loop)** — 어떻게 _반복_하는지: 계획 → 실행 → 검수 사이클
- **실행 환경(Sandbox)** — _어디서_ 돌아가는지: Mac mini, Tailscale, LaunchAgent

같은 클로드라도 챗창에 넣으면 "말 잘하는 조언자", Claude Code에 넣으면 "커밋까지 하는 엔지니어", Mac mini + OpenClaw에 상주시키면 "내가 자도 일하는 직원"이 됨. **모델이 같아도 하네스가 다르면 완전히 다른 존재.**

**오케스트레이션 = 여러 개를 자동으로 지휘하는 것.** 지휘 대상은 셋:

- 여러 **도구**의 순서·병렬 — "웹 검색 → 요약 → 노션 저장 → 슬랙 알림"이 한 흐름
- 여러 **에이전트**에 분배 — 메인이 서브에게 쪼개서 맡김 (OMC의 Sisyphus/Hephaestus/Prometheus)
- 여러 **모델** 라우팅 — 쉬운 건 Haiku, 코드는 Code, 복잡한 건 Opus

OMC가 빛나는 이유는, 사람이 매번 명령하지 않아도 상황에 맞게 흘러가게 만들어주기 때문. `ultrawork` 한 마디에 작업이 쪼개지고 병렬로 굴러감.

#### 최종 구현 결과물 (지금 깔린 내 시스템)

- **정체성 레이어**: SOUL.md (톤·금지어·도메인) + USER.md (배경·도구·선호) + samples/ 폴더 — 새 인스턴스가 백지로 출근해도 5초 안에 내 맥락 인식
- **24시간 상주 환경**: Mac mini + OpenClaw + Tailscale 원격 접속 + LaunchAgent 백그라운드 + Telegram을 메인 컨트롤 채널로 운용
- **하트비트 + 크론잡**: 매일 아침 9시 핀테크 뉴스 + 일정 브리핑, 30분마다 노션 마감 점검, 금요일 5시 12개 챌린지 회고
- **확장 레이어**: Superpowers(스킬 팩 — 레시피북) + OMC(에이전트 팩 — 요리사 팀)
- **MCP 연결**: Notion, Gmail, Google Drive, Slack, Figma, Linear

#### 과정 (타임라인별 + 삽질)

- **1단계 — 손발 노릇**: 챗 인터페이스에서 복붙 노예. AI 답을 내가 직접 노션·슬랙·터미널에 옮기는 I/O 파이프 역할
- **2단계 — Claude Code 진입**: 파일 직접 읽고 쓰는 환경 + `.md` 컨텍스트 엔지니어링. 처음으로 한 번의 지시가 여러 시스템을 관통하는 경험
- **3단계 — Mac mini + OpenClaw 상주**: 텔레그램으로 던지면 내가 자도 굴러감. 24시간 작동하는 원격 지점 주방
- **4단계 — OMC 얹기**: `ultrawork`로 멀티에이전트 오케스트레이션. 작업 쪼개기를 사람이 안 함
- **삽질 포인트**
    - OpenClaw 게이트웨이 시작 실패 — Slack 채널 enabled=true인데 `SLACK_BOT_TOKEN` 환경변수 누락. fail-closed로 60초 타임아웃. `launchctl setenv`로 영구 주입 또는 채널 disable로 해결
    - Superpowers와 OMC 차이가 처음엔 안 잡힘 — Superpowers는 "스킬 팩(레시피북)", OMC는 "에이전트 팩(요리사 팀)". 카테고리가 다름
    - MCP 무턱대고 다 연결 → 컨텍스트가 무거워짐. 작업 유형별로 권한 구획화 필요

#### 공유할만한 인사이트

- ChatGPT/Gemini에서 클로드 코드로 넘어와서 생산성이 폭발한 이유는 모델이 똑똑해져서가 아님. **모델이 접근할 수 있는 세계가 늘어났기 때문.** 하네스가 그 세계를 열어주고, 오케스트레이션이 그 안의 도구들을 자동으로 엮어줌.
- **손발 → 지휘자 → 경영자.** 같은 변화의 연속임. 하네스가 "손발 → 지휘자"까지 데려다 주고, 오케스트레이션이 "지휘자 → 경영자"로 넘김. **"리더십 없이도 굴러가는 훌륭한 팀"이 만들어짐.**
- 다음 방향
    1. **월간 출시 루틴에 오케스트레이션 심기** — "이번달 출시 시작" 한 마디에 PRD → 디자인 → 프로토타입 → 런칭 글 → SNS 카드까지 한 파이프라인
    2. **컨설팅에 이식** — 단발성 산출물이 아니라 클라이언트 회사 안에 AI 주방을 짓고 넘겨주는 방식
    3. **MCP 권한 구획화** — 작업 유형별 도구 세트 분리
