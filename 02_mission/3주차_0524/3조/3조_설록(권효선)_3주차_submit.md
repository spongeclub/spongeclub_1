## 미션1: <자화상>

### Summary

매일 한 줄 던지면 AI가 짧게 비춰주는 개인 도구 **자화상**을 만들고, 그 위에 흐민님 공유회의 "셀프 vs 타인 에이전트 대화" 컨셉을 두 가지 오케스트레이션 패턴으로 풀어봤다.

자화상의 시작은 **"메모로 나를 알아가는 과정"이 되었으면 해서**였다. 매일 흘려보내는 순간들을 모아 일주일·한 달 단위로 다시 만나며 나에 대한 인사이트를 얻고 싶었다. 그런데 실제론 회고 기능을 안 만든 채 일기처럼 흘러갔고, **이번 미션이 그 빠진 자리(회고 시스템)를 우연히 메워줬다**.

구현된 두 오케스트레이션 패턴:

- **병렬 2-에이전트** — 한 줄에 알아봄(내면) + 다른 자리에서(외부) 두 거울이 동시에 응답
- **순차 4-에이전트 파이프라인** — 7일 메모 → 분류자 → 패턴 짚기 → 회고 글쓴이 → 검증·정제

### 과정 (타임라인별 + 삽질)
### 5/20 — 자화상 만들기 (배포까지 약 3시간)

**왜?** **메모로 나를 알아가는 과정이 되었으면 해서.** 기존엔 사고 자산화용으로 텔레그램 봇을 쓰고 있었는데:

- PC가 상시 켜져 있어야 봇이 작동 — 외출 중·자기 전엔 못 던짐
- 한 마디 던지면 응답이 너무 길게 와서 다 읽기 버거움

→ 폰에서 가볍게 한 줄 던지고, AI 응답도 짧게(한두 문장)만 받는 **웹앱**으로 가기로 결정.

**원래 의도** (2단계):

1. 순간순간 스치는 생각들을 데이터베이스에 일단 올려두기
2. 일주일·한 달치 모아 회고록 만들며 인사이트 얻기

**실제 흐름**: 회고 기능은 안 만들고 일상이 거의 일기처럼 흘러감. 한 줄 던지는 행위 자체가 의미 있어서 그 자체로 자리 잡음.

**도구의 결을 결정한 자리 — 시스템 프롬프트**:

```
- 알아봄의 신호. "그게 거기 있구나" 식의 짧은 비춤.- 분석·해석·조언·판단 금지.- "괜찮아요", "잘했어요" 같은 위로/응원 금지.- 한 문장, 길어야 두 문장.
```
### 5/20 ~ 5/22 — 일상 사용, 데이터 누적 (3일간 메모 44개)

음성 입력의 편함 + 짧은 알아봄 응답 → 빠르게 자기 일상에 들어옴. 짧은 메모도, 한 화면 가득 채우는 긴 메모도. **이게 다음 단계의 진짜 입력이 됨. 데이터 없는 도구는 빈 도구.**

### 5/23 오전 — 하네스, 오케스트레이션 적용

스폰지클럽 "하네스·오케스트레이션 적용해보라". 흐민님 공유회의 **"셀프 vs 타인 에이전트 대화"** 컨셉이 떠오름. **이미 만든 자화상 위에 작게 시작하기로 결정** — 새 도구 안 만들고 진화시키기.

### 5/23 1차 — 두 거울 (병렬 오케스트레이션, 1시간)

같은 한 줄에 두 에이전트 병렬 응답. 알아봄(기존, 내면) + 다른 자리에서(새, 외부 관찰자). 코드는 `Promise.all` 한 줄, **진짜 어려움은 두 에이전트의 결을 명확히 가르는 시스템 프롬프트 설계**.
### 공유할만한 인사이트
**1. 하네스는 이미 있는 곳에서 시작하면 빠르다**

자화상은 이미 작동하는 도구였음. 거기 위에 두 에이전트, 4-에이전트 얹는 식으로 진화. **처음부터 새로 만들었다면 3시간 안에 못 했음.** 작은 하네스가 진화의 발판.

**2. 한 모델로 풀기 힘든 문제는 역할 분리로 푼다**

회고 글쓴이의 hallucination은 같은 글쓴이에게 프롬프트 강화로 3번 시도 → 다 실패. 답은 **별도 에이전트(검증자)에게 다른 역할**. 생성과 검증이 다른 자리에 있어야 검증이 작동함. **LLM이 LLM을 감시한다.**

**3. 오케스트레이션 두 패턴: 병렬 + 순차**
![](attachments/Pasted%20image%2020260524051457.png)

**4-에이전트는 1회 약 250원(호출 4번), 1~2분. 일상 두 거울은 호출당 30원. **신뢰가 비용보다 중요해서 4-에이전트 유지**. 주 1회 사용이라 부담 X.
