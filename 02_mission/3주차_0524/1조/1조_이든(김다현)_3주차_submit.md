# 3주차 과제 — 이든

## 미션1: 내 고객은 누구고 왜 쓰는가 — 클로드 코드로 프로덕트 구현하기

### Summary
ADHD 약 복용 기록 앱의 고객은 **성인 ADHD 진단자** — 특히 약물 치료 초기, 약을 바꿔가며 맞는 약을 찾는 과정에 있는 사람. 의사에게 "두리뭉술한 기억"이 아니라 **정확한 기록**을 전달하기 위해 만들었다.

### 최종 구현 결과물
ADHD 약 복용 기록 웹앱 — [adhd-taking-record.vercel.app](https://adhd-taking-record.vercel.app)

**고객 정의:**
- 성인 ADHD 진단을 받고 약물 치료 중인 사람
- 약을 주차마다 바꿔가며 맞는 약을 찾는 과정에 있는 사람
- 진료실에서 "어땠어요?"라는 질문에 기억에만 의존해 대답해온 사람

**왜 이 앱을 쓰는가:**
> ADHD 진단 3년차. 1년간 약을 주마다 바꾸며 고생했다. 의사선생님께 효과와 부작용을 두리뭉술하게 기억에 의존해 말해왔고, 그게 정확한 진단을 어렵게 만들어 치료를 더 오래 걸리게 했다. 빠르게 맞는 약을 찾고, 습관화로 약 의존을 줄이고, 업무에 충실한 삶을 위해 만들었다.

**핵심 기능:**
```
💊 약 기록   : 먹었어 / 늦게 먹었어 / 까먹었어 + 복용 시각
😴 수면 기록 : 잠든 시각 → 기상 시각 (수면 시간 자동 계산)
🏷 효과/부작용 태그: 집중력, 두통, 식욕 감소 등 레벨별 기록
✏️ 지금 느낌 : 즉흥 감정·증상 즉시 메모
📥 가져오기  : 데이터 백업·복원 (진료 공유용)
```

### 과정 (타임라인별 + 삽질)
1. **고객 정의** — "나 자신"에서 시작해 "성인 ADHD 약물 치료 중인 사람"으로 확장. 핵심은 의사에게 전달할 정확한 기록이 없다는 문제
2. **Claude Code로 구현** — React + Vite, Vercel 배포. localStorage 기반으로 데이터 저장
3. **삽질: 알림 없음** — 앱을 만들었는데 정작 약 먹으라는 푸시가 없어서 까먹는 문제가 해결 안 됨. 핵심 문제가 미해결인 채로 배포
4. **삽질: 모바일 접근 불가** — 노트북을 열어야만 기록 가능. 약 먹는 순간 바로 기록하려면 폰에서 돼야 하는데 문턱이 높음

### 공유할만한 인사이트
**1. "내가 고객"일 때 통점이 가장 선명하다**
내 1년치 고통이 고객 정의가 됐다. 리서치 없이도 "왜 쓰는가"가 명확했다. 내 문제를 제대로 언어화하는 것 자체가 프로덕트 기획이었다.

**2. 구현 완료 ≠ 문제 해결**
배포까지 했는데 핵심 문제(알림, 모바일 접근성)는 아직 미해결이다. 빠르게 만들고 배포하는 것과 실제로 쓰이는 것은 다른 문제다.

## 미션2: 내가 정의하고 적용해보고 싶은 하네스 + 오케스트레이션

### Summary
ADHD 앱에 적용하고 싶은 자동화 흐름 — 알림부터 기록, 의사 공유까지 이어지는 파이프라인.

### 최종 구현 결과물
아이디어/설계 단계:

```
저녁 알림 발송 (사라지지 않는 푸시)
       ↓
약 복용 기록 (먹었어 / 까먹었어)
       ↓
효과 · 부작용 태그 입력
       ↓
주간 리포트 자동 생성
       ↓
진료 전날 의사 공유용 요약 출력
```

**핵심 철학**: 알림이 사라지지 않고 나를 푸시해야 한다. 일반 알람은 무시하면 끝이지만, 이 시스템은 기록할 때까지 계속 상기시켜야 한다.

### 과정 (타임라인별 + 삽질)
현재 알림 기능 미구현 상태. 다음 단계로 PWA 전환 또는 Slack/카카오 알림 연동을 검토 중.

### 공유할만한 인사이트
오케스트레이션의 핵심은 "사람이 잊어버려도 시스템이 붙잡아주는 것". ADHD에게 가장 필요한 자동화는 화려한 기능이 아니라 **끈질긴 알림 하나**다.
