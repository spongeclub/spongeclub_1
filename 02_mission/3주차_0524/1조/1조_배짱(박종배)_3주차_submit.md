## 미션1: 내 고객은 누구고 왜 쓰는가 — 클로드 코드로 프로덕트 구현하기

> **morning-mom** — 엄마에게 매일 한 줄을 보내는 손글씨 카드 도구

### Summary

  

매일 아침 엄마에게 보낼 따뜻한 한 줄을, 양식·금기·최근 대화 컨텍스트에 맞춰 만들고 손글씨 카드(PNG)로 출력하는 도구를 빌드. 본인 운용용 Claude Code 스킬(CLI)과 누구나 접속해 쓸 수 있는 공개 웹페이지(GitHub Pages) 두 가지 인터페이스로 출시.

  

- 고객: 엄마(1954년생, 시골 농사, 일요일 교회, 백합을 좋아하시는 분). 일차 사용자는 나(아들). 매일 아침 도구로 카드 받고 카톡으로 직접 전달.

- 왜 쓰는가: 엄마가 아빠와의 대화에서 힘과 기쁨을 잃지 않으셨으면 한다. 사랑받고 있다는 감각을 매일 한 줄로 전해드리고 싶은데, 매번 직접 카톡을 짜내려 하면 결국 못 보낸다. 도구가 첫 생성을 도와주면 본인이 다듬어 보내는 것만 남아 마찰이 0에 가까워진다.

  

### 최종 구현 결과물

  

- 공개 웹 URL: <https://baezzanglion.github.io/morning-mom-web/>

- GitHub: <https://github.com/baezzanglion/morning-mom-web>

- 첫 카드(2026-05-24): "사랑 받는 게 / 당연한 사람이 있어요. / **엄마, 당신이에요.**"

  

**두 인터페이스 분담**

  

| | Claude Code (본인 운용) | 웹페이지 (공유·데모) |

|---|---|---|

| 컨텍스트 자동 흡수 | ✅ `recent/` 통화·카톡 파일 | ❌ 매번 입력 |

| history 자동 누적 | ✅ `history.json` | ⚠ LocalStorage |

| AI 후보 3개 제안 | ✅ Claude Code 내부 | ✅ 본인 API key 등록 시 |

| 와우 포인트 | ✕ (도구) | ✅ 실시간 카드 미리보기, 다운로드, 카톡 직접 복사 |

  

**산출물 구조**

  

```

morning-mom/

├── README.md # 프로덕트 정의 + 미션 1·2 답

├── SKILL.md # /morning-mom 호출 시 6단계 절차 (= 오케스트레이션)

├── context/

│ ├── mom-profile.md # 엄마 프로필 (변하지 않는 부분)

│ ├── harness.md # 톤·금기·길이·좋은예/나쁜예 (= 하네스)

│ └── recent/ # 통화·카톡 컨텍스트 (수동 push)

├── generate.py # 손글씨 카드 PNG 생성 (Gaegu, Gowun Batang)

├── history.json # 보낸 메시지 누적

├── output/ # 카드 모음

├── assets/fonts/ # Google Fonts로 받은 한국어 폰트

└── web/ # GitHub Pages로 호스팅 — 단일 HTML

```

  

**메시지 양식**: 의미단위 줄바꿈은 `|`로, 강조 한 줄은 `**...**`으로 감쌈. LLM 출력 양식이 곧 카드 디자인이 됨.

  

### 과정 (타임라인별 + 삽질)

  

- **14:00** — 정체성 전환 결정. 본부장(회사) 정체성에서 아들 정체성으로. "힘을 주는 표현"이라는 주제 등장.

- **14:10** — 방향 좁히기. 통화 분석(C안)은 4-6시간 안엔 불가, 1인용 변환기(제3 옵션)는 단순 LLM 래퍼. 결국 "엄마"라는 1인 고객으로 좁힘.

- **14:30** — Claude Code 스킬 구조로 폴더+파일 6개 생성. Python PIL로 첫 카드 렌더 성공.

- **15:00** — 첫 디자인 OK. 손글씨 폰트 도전. Google Fonts에서 Gaegu / Gowun Batang / Nanum Pen Script 3종 다운.

- **15:30** — 의미단위 줄바꿈(`|`)과 강조(`**...**`) 문법 도입. 폰트 비교 시안 후 Gaegu(둥근 손글씨) 선택, 사이즈 10% 키움.

- **16:00** — 디테일 추가(강조 굵게). 시간 압박 인지 — 1시간 안에 미션 1·2·3 다 마치도록 재분배.

- **16:30** — 웹페이지 욕심. A(Claude Code+웹 분담) / B(웹에서 LLM 직접 호출) / C(백엔드) 트레이드오프 토론.

- **16:50** — 단일 HTML로 `web/index.html` 작성. Anthropic API 브라우저 직접 호출 (`anthropic-dangerous-direct-browser-access` 헤더).

- **17:10** — Anthropic Console에서 morning-mom-web 전용 API key 생성. CORS 우려는 무사 통과. AI 후보 3개 작동 확인.

- **17:30** — GitHub Pages 호스팅. `baezzanglion/morning-mom-web` public repo 생성, web/ git init+push, Pages 활성화. 백그라운드 폴링으로 빌드 완료 대기 후 공개 URL 발급.

  

**삽질**

  

- Python 3.9에서 `str | None` 타입 힌트 안 됨 → `from __future__ import annotations`로 해결.

- WebFetch가 tiro.ooo 본문을 못 잡음 (SPA라 JS로 동적 로드) → 폴더 구조만 미리 만들고 본문은 수동 채우기로.

- 처음에 LLM 호출 없는 단순 입력 도구(웹 옵션 A/B)를 제안했다가 "그건 기존 LLM에 묻는 것과 큰 차이 없지 않냐"는 지적을 받음. 이 기준을 메모리에 박음.

- "차별점의 정점 손실"이라는 표현이 모호해서 의미를 다시 묻고 설명해야 했음. 사용자 도구(본인용)와 공유 도구(데모용)를 구분하지 않은 게 원인.

  

### 공유할만한 인사이트

  

- **"LLM 한 번 호출과 다를 게 없으면 프로덕트가 아니다"** — 차별점은 (1) 컨텍스트 (2) 루프 (3) 관계/배달 (4) 양식 깊이 중 하나 이상에서 나와야 함. morning-mom은 네 가지가 모두 살아있는 첫 사례.

- **양식이 곧 디자인이다** — `|`로 줄바꿈, `**...**`로 강조라는 출력 양식을 LLM에 강제하니 카드 디자인 결정이 자동으로 따라옴. 자동 wrap에 맡기지 않고 호흡을 의도적으로 끊은 게 따뜻함의 정체.

- **정체성 전환의 가치** — 지금까지 OS 결과물은 본부장(회사) 중심이었음. 이번 주 "아들"이라는 다른 정체성에서 출발했고, 같은 OS 원리가 다른 정체성에서도 작동함을 확인.

## 미션2: 내가 정의하고 적용해보고 싶은 하네스 + 오케스트레이션

> 빌드 안에서 발견한 정의

### Summary

  

- **하네스 = 형용사**. 메시지의 결을 결정하는 *문서화된 규칙 묶음*. 시스템 프롬프트보다 두껍다. 컨텍스트 + 양식 + 금기 + 좋은예/나쁜예가 한 자리에 모인 것.

- **오케스트레이션 = 동사의 연쇄**. 매일 어떻게 메시지가 만들어지고 쌓이는지의 흐름. 단발 LLM 호출 아님. 상태 수집 → 생성 → 검수 → 외부 작용 → 적재.

- **정의는 빌드 안에서 발견됨** — 사전에 정의를 박고 들어간 게 아니라, morning-mom을 빌드하면서 "아 이게 하네스구나, 이게 오케스트레이션이구나" 손에 잡힌 정의.

  

### 최종 구현 결과물

  

**하네스의 실체 — 두 파일**

  

- `context/mom-profile.md` — 변하지 않는 엄마 프로필 (호칭, 일상, 좋아하는 것, 자주 들려드리고 싶은 것, 절대 하지 않을 것)

- `context/harness.md` — 톤·금기·길이·출력 양식·폰트 매핑·좋은예/나쁜예

  

**오케스트레이션의 실체 — SKILL.md의 6단계 절차**

  

1. **컨텍스트 로딩** — mom-profile + harness + recent/ + history.json

2. **오늘 컨텍스트 합치기** — 날짜·요일·계절·농사 사이클

3. **후보 생성** — LLM이 하네스 안에서 결이 다른 3개 생성

4. **사용자 선택** — 휴먼 인 더 루프 (검수)

5. **이미지화** — generate.py 호출, png 파일 생성 (외부 작용)

6. **history 적재** — 다음 호출의 컨텍스트가 됨 (루프 완성)

  

**단순 system prompt와 다른 점 (하네스)**

- **누적성** — 좋은예/나쁜예가 파일로 박혀 호출 간 일관성 유지

- **수정 가능성** — 결이 어긋날 때 `harness.md`만 고치면 다음 호출부터 즉시 반영 (코드 변경 X)

- **출력 양식 강제** — `|`로 의미 단위 줄바꿈, `**...**`로 강조 → 양식이 곧 디자인 결정

  

**단순 챗봇과 다른 점 (오케스트레이션)**

- **상태 누적** — history.json이 어제·그제·작주 메시지를 오늘 생성의 입력으로 만듦

- **외부 작용** — LLM 출력이 텍스트로 끝나지 않고 이미지 파일이 시스템 밖으로 나감

- **단계 명시성** — 각 단계를 따로 고치고 다듬을 수 있음 (디자인은 5단계만, 톤은 1·2·3단계만)

  

### 과정 (타임라인별 + 삽질)

  

- **출발점**: 미션 2를 미션 1과 별개로 "사전 정의 → 적용" 순서로 풀려고 했음.

- **전환**: 미션 1을 빌드하다 보니 SKILL.md의 6단계를 적는 순간 "이게 오케스트레이션이구나" 깨달음. harness.md가 깊어질수록 "이게 하네스의 본질이구나" 잡힘.

- **결정적 발견**: 사용자가 "LLM 호출과 다를 게 없으면 프로덕트가 아니다"라고 짚어줌. 이걸 기준으로 보면 하네스/오케스트레이션은 단순 정의가 아니라 *그 차별점을 만들어내는 도구*임이 명확해짐.

  

**삽질**

- 처음에 미션 2를 추상적 정의로만 풀려고 했다가, 빌드 결과물의 어느 부분이 하네스이고 어느 부분이 오케스트레이션인지 *손가락으로 가리킬 수 있을 때* 진짜 정의가 됨을 확인.

- "차별점의 정점 손실" 같은 모호한 표현을 쓰다가 사용자가 의미를 정확히 물어 다시 설명해야 했음 → 정의는 항상 *어디서 무엇이 어떻게 다른지*까지 가야 함.

  

### 공유할만한 인사이트

  

- **정의는 빌드 안에서 발견된다** — 사전에 정의하고 빌드하는 게 아니라, 빌드하면서 손에 잡힌 정의가 더 정직하고 강력함. 미션 2를 미션 1과 분리해서 푸는 건 함정.

- **하네스 = 형용사 / 오케스트레이션 = 동사의 연쇄** — 둘 다 깊어야 좋은 LLM 프로덕트. 하네스만 깊으면 잘 가둬진 챗봇에 그치고(누적 X), 오케스트레이션만 있으면 매일 다른 톤이 나옴(양식 X).

- **양식 = 디자인** — 출력 양식을 강제하면 시각적 결정이 자동으로 따라온다. `|`와 `**...**`이 그 예.

## 미션3: 스폰지클럽을 하며 남기고 싶은 생각과 고민 SNS 글 작성

> 인스타그램으로 "엄마에게 매일 한 줄" 공유

### Summary

  

morning-mom을 만든 동기·과정·발견을 인스타용으로 정리하고, 공개 웹 URL을 함께 공유해 다른 사람들도 직접 만져볼 수 있게 한 글. "좋은 AI 도구는 프롬프트가 아니라 컨텍스트·루프·관계·양식 네 가지가 살아 있는 것"이라는 발견을 핵심 메시지로.

  

### 최종 구현 결과물

  

- **본문 초안 (긴 버전 ~800자, 짧은 버전 ~300자)**: `morning-mom/sns-instagram-draft.md`

- **첨부 카드**: `morning-mom/output/2026-05-24.png` — "사랑 받는 게 / 당연한 사람이 있어요. / **엄마, 당신이에요.**" (Gaegu 손글씨, 마지막 줄 굵게)

- **공개 URL 첨부**: <https://baezzanglion.github.io/morning-mom-web/> — 다른 사람도 직접 자기 카드 만들 수 있음

- **해시태그**: #스폰지클럽 #AI프로덕트 #ClaudeCode #하네스 #엄마에게

  

**본문 핵심 흐름**

1. 엄마의 프로필 (1954년생, 시골 농사, 일요일 교회, 백합)

2. 매일 카톡 짜내려 했지만 깜박이는 커서 앞에서 멈췄던 페인포인트

3. morning-mom 도구 소개 (이름 + 한 줄 요약)

4. [카드 이미지]

5. 좋은 AI 도구의 4가지 차별점 (컨텍스트·루프·관계·양식)

6. 다음 단계 — 통화 컨텍스트 자동 흡수

7. 직접 만들어보고 싶은 분 — 공개 URL

  

### 과정 (타임라인별 + 삽질)

  

- 미션 1·2 완성 직후 SNS글 초안 작성 (20분).

- 본문 톤 — 너무 기술적으로 가지 않고 "엄마와 나"라는 정서적 동기에서 시작해 자연스럽게 기술적 발견으로 이어지게 구성.

- 두 버전 준비 — 피드용 긴 본문 + 스토리/숏폼용 짧은 버전.

- 호스팅 완료 후 공개 URL을 본문 끝에 추가 — 단순 "보여주기"가 아니라 "초대"가 되도록.

  

**삽질**

- 처음엔 도구 소개 중심으로 썼다가, 동기(엄마)가 너무 뒤로 빠짐을 깨닫고 동기 → 페인포인트 → 도구 → 발견 순서로 재배치.

  

### 공유할만한 인사이트

  

- **결과물 + 만든 과정 + 도구 링크를 함께 공유하면 "보여주기"가 아니라 "초대"가 된다** — 다른 사람도 직접 만져볼 수 있으니까. 단순 자랑보다 잔향이 길다.

- **개인적 동기와 기술적 깊이를 동시에 담을 수 있다** — "엄마와의 관계"라는 매우 사적인 출발점에서 "좋은 LLM 프로덕트의 4가지 차별점"이라는 일반 원리까지 자연스럽게 이어짐.

- **본인의 데이터(엄마 통화·카톡)가 차별점의 정점** — 누구도 못 가져가는 컨텍스트가 진짜 차별점이라는 통찰. SNS 글이 단순 결과물 공유가 아니라 *원리의 공유*가 됨.
