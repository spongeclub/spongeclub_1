## 미션1: <오늘 세션 적용 포인트 반영해서 내 프로덕트 개선하기>

### Summary

패션 셀러용 사입 결정 도구 **남겨요.** 의 **사전 접수 사이트**.  
에이블리·지그재그에서 옷 파는 1인 셀러가, 동대문 사입 현장에서 5초 안에 **권장가·진짜 마진·신호등(🟢🟡🔴)** 을 받게 해주는 도구이고, 본 제품은 아직 개발 전입니다.  
이 사이트의 단 하나의 목표는 **베타 50명 사전 접수** — 폼 한 장 + 인스타 DM 한 줄.  
Owen 월간출시 5번째 서비스, 2026년 5월 말 베타 오픈 예정.

### 최종 구현 결과물

**사전 접수 사이트** → [https://namgyeo.owenai.xyz](https://namgyeo.owenai.xyz/)  
(제품 자체가 아니라, 페르소나 검증·수요 측정용 사전 접수 페이지)

### 과정 (타임라인별 + 삽질)

코드와 카피 모두 Claude Code 단일 세션으로 진행. 사전 접수 페이지 한 장이라 별도 프레임워크 없이 **단일 정적 HTML + Tailwind CDN + Pretendard(jsdelivr)** 만 썼습니다. 8개 섹션(Hero · Pain · How It Works · Difference Table · Pricing · CTA · FAQ · Footer)을 모바일 우선으로 한 파일에 모았습니다.

- **배포**: Vercel 정적 호스팅. 도메인 `namgyeo.owenai.xyz` 는 CNAME으로 `cname.vercel-dns.com` 에 미리 연결해뒀고, GitHub private repo(`owenleekr/namgyeo-landing`)에 푸시 후 dashboard import.
- **접수 폼 백엔드**: Resend·서버리스 없이 **Formspree(50건/월, 카드 X) + vanilla JS fetch**. `@formspree/ajax` 11KB 라이브러리도 추가 안 함 — 같은 동작을 인라인 스크립트로 직접 처리.
- **봇 차단**: Turnstile 대신 우선 Formspree 기본 honeypot으로 시작. 스팸 들어오면 그때 추가.

**삽질 5개:**

1. Google Fonts에 Pretendard가 없어서 첫 빌드가 시스템 폰트로 떨어짐 → jsdelivr `orioncactus/pretendard` CDN으로 교체.
2. 권한 분류기가 public repo 생성을 두 번 막음 → private repo로 전환, Vercel은 private도 빌드해주니 결과 동일.
3. 접수 채널을 세 번 갈아엎음: **인스타+카톡 → 인스타만 → 인스타+접수폼**. 처음엔 "DM만 받자"가 1인 메이커 원칙이었는데, 페르소나가 DM을 어색해할 가능성을 무시할 수 없어서 "DM **또는** 30초 폼" 두 트랙 복원.
4. "현장에서 한 손으로, **7개 탭 안에서 끝**" 카피가 본인도 못 알아들음 → Hero 약속 "5초만 줘봐요"와 톤 맞춰 "**30초면 충분해요**" 로 통일.
5. 페인 인용을 5개 → 4개로 줄임. 같은 출처(`@xxheyxxn`)에서 "단가 듣고 새하얘지면서"랑 "옷 2~3개 사입하면 파산"이 중복 톤 → 더 강한 첫 줄만 남김.

### 공유할만한 인사이트

- **사전 접수 사이트의 본질은 "수요 측정"이지 "제품 광고"가 아님.** 그래서 Hero·Pain은 셀러의 통증을 그대로 보여주고, How It Works·Pricing은 "출시 후 이렇게 작동할 예정"으로 솔직하게 적음. 접수 폼이 곧 수요 검증 데이터.
- **LMF(Language-Market-Fit) 리서치 결과를 그대로 헤드라인·페인에 박는다.** 브런치·clien·디시 스마트스토어 갤러리에서 셀러 본인이 쓴 문장 4개를 따옴표·출처까지 통째로 인용. "셀러가 좋아할 만한 카피"가 아니라 "셀러가 이미 쓴 카피"라는 점이 다르고, 이게 페인 섹션의 신뢰도를 만듭니다.
- **접수 폼을 빼려다 다시 넣은 결정.** 폼은 활동명·플랫폼 라디오(에이블리/지그재그/둘 다/준비중)·사입 빈도·연락처·한 마디·동의 — 6필드로 끊었고, Tailwind `has-[:checked]:bg-kakao` 패턴으로 라디오가 노랗게 차오르는 마이크로 인터랙션만 살림. 폼이 곧 **누가 진짜 페르소나인지 거르는 필터** 역할.
- **Claude Code 워크플로우**: 한 세션 안에서 "빌드 → 권한 거부 → 회피 경로 → 배포 가이드 → 카피 피드백 → 즉시 수정·푸시"까지 끊김 없이 돌아간다는 게 1인 메이커한테 진짜 차이를 만듭니다. 매 커밋이 카피 한 줄 단위로 쪼개져 있어(`copy: drop redundant 파산 quote`) git log만 봐도 어떤 결정이 어떤 이유였는지 추적됨.

### 과정 (타임라인별 + 삽질)

- **페르소나 A · 브런치 @xxheyxxn (1인 셀러)**: "단가를 듣고 머릿속이 새하얘지면서…" → **사입 현장에서 즉시 판단을 도와줄 도구가 없다**. 엑셀은 사무실에서 다시 켜는 거지, 매장 안에서 쓰는 게 아님.
- **페르소나 B · clien 어흥777**: "수수료 15%라구요?? 제 마진율이 15가 안되는데" → **플랫폼 수수료 자체는 다 알고 있음**. 문제는 수수료·반품률·포장·CS·마케팅비를 **다 빼고 남는 진짜 마진**을 한 번에 보여주는 도구가 없다는 것.
- **삽질**: 처음엔 서비스를 "정산 계산기"로 잡았는데, 두 페르소나 모두 "사입 **후** 사무실에서 정산"이 아닌 "사입 **전** 현장에서 결정"이 더 큰 페인이라는 걸 카피에서 발견 → **"사입 결정 도구"** 로 포지셔닝 피봇.

### 공유할만한 인사이트

- **1:1 인터뷰 0건이어도 페르소나 검증은 가능**. 단, 셀러가 **이미 자기 돈·시간 들여 쓴 글**(브런치 연재, 커뮤니티 장문)만 채택. "댓글 한 줄"이나 "설문 응답"은 가치 차이가 큼.
- **카피의 단위가 "문장"이 아니라 "출처가 있는 인용"이 되면 페인 섹션 신뢰도가 비대칭적으로 올라감.** 페이지 보는 셀러가 "이거 내 얘기 같은데?"가 아니라 "이거 진짜 셀러가 쓴 거잖아"로 바뀌는 순간.
- 다음 단계는 사전 접수 50명 중 **2명만 화상 인터뷰**로 들어가는 게 목표. 이미 접수한 사람 = 페르소나 검증된 사람이라 인터뷰 ROI가 훨씬 높음.
