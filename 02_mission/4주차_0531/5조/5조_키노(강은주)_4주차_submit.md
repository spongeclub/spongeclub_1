## 미션1: 하네스 점검 + 브랜드 템플릿 시스템 구축 (easyCard)

### Summary

- 1인 브랜드 카드뉴스 생성 도구 **easyCard**에 세션에서 배운 "하네스(작업 받침대)" 개념을 적용
- 프로젝트에 `CLAUDE.md`(작업 지시서)·`PRD.md`(제품 정의) 추가하여 AI가 매번 같은 기준으로 일하게 하는 받침대를 구축
- **브랜드 템플릿 시스템** 도입 — 코드 수정 없이 `registry.js`에 항목 하나 추가만으로 새 브랜드를 재사용할 수 있는 구조로 전환
- Vercel 배포 트러블슈팅 + 로그아웃 버그 수정까지 완료

### 최종 구현 결과물

**easyCard** → [https://easycard-rho.vercel.app](https://easycard-rho.vercel.app)

- `brands/registry.js`: 브랜드별 정보(배경색·카테고리·타겟·문구·Week·로고자리)를 데이터로 정의
- `index.html`: 로그인 후 브랜드 선택 버튼 → 브랜드를 고르면 입력폼(카테고리·타겟·상단문구·Week)이 자동 전환
- `editor.html`: 브랜드별 슬라이드 배경(일반=흰색 / 스폰지타임즈=노랑), 배경 원형 장식, 하이라이트 라벨 중립화
- "Claude 보강" 프롬프트도 브랜드별로 분리 (기존 운동·웰니스 하드코딩 제거)

### 공유할만한 인사이트

1. **하네스는 배포되는 웹과 별개다.** CLAUDE.md/PRD/메모리는 "내 AI 직원이 매번 같은 기준으로 일하게 하는 받침대"이지, 사용자가 보는 서비스가 아니다. 이 구분을 이번에 처음 명확히 잡았다.
2. **브랜드 = 데이터 묶음(registry).** 새 브랜드를 추가할 때 코드를 건드리지 않고 항목 하나만 추가하면 된다. 세션에서 배운 "오케스트레이션" 개념이 코드 구조에도 그대로 적용된 셈.
3. **자동배포가 끊겨도 CLI로 우회할 수 있다.** Vercel은 GitHub 자동연동과 CLI 두 경로로 배포 가능. 자동배포가 6일째 멈춰 있었지만 `vercel --prod`로 즉시 해결. 배포 경로를 하나만 믿으면 안 된다.
4. **정적 사이트는 모든 파일이 공개된다.** `.vercelignore`로 시크릿(토큰)·내부문서를 빼야 안전하다는 걸 이번에 배웠다. 보안은 나중에가 아니라 배포할 때 바로.

## 미션3: easyCard로 만든 스폰지클럽 자랑 SNS 글

### Summary

이번 주 만든 easyCard 브랜드 템플릿 시스템을 직접 활용해서 스폰지클럽 자랑 인스타 카드뉴스를 제작·게시. 도구를 만드는 사람이 직접 첫 번째 사용자가 되는 dogfooding.

### 최종 구현 결과물

https://www.instagram.com/p/DY2LYfHmLuv/?utm_source=ig_web_copy_link&igsh=MzRlODBiNWFlZA==

### 과정 (타임라인별 + 삽질)

- easyCard 브랜드 템플릿 시스템 완성 후, 직접 카드뉴스를 만들어 인스타에 게시
- 본인이 만든 도구로 본인의 미션을 수행 — 도구의 실사용성 검증까지 한 번에

### 공유할만한 인사이트

- **자기가 만든 도구로 자기 과제를 해결하면 피드백 루프가 가장 빠르다.** easyCard를 만들고 바로 카드뉴스를 찍어보니 "이건 불편하다", "이건 된다"가 즉시 드러난다. 별도 테스터가 필요 없는 셈.
- **"도구 만들기"와 "콘텐츠 만들기"가 하나의 흐름에서 끝나면 1인 브랜드 운영의 마찰이 크게 줄어든다.** 도구 따로, 콘텐츠 따로가 아니라 한 세션에서 둘 다 끝낼 수 있는 구조가 중요.
