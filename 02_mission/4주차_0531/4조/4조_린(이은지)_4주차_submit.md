#### 이번 세션 적용 포인트 — "하네스 엔지니어링" 으로 내 프로젝트 점검

내 프로젝트를 AI가 잘 굴러가게 만드는 5개 부품으로 점검했다:
① CLAUDE.md ② PRD ③ memory ④ SKILL ⑤ agent

- **잘 깔린 곳**: PRD(OS 운영문서·디자인시스템)와 memory는 충실하다.
- **빈 곳 / 끊긴 곳**: CLAUDE.md가 사실상 비어 있고(`@AGENTS.md` 한 줄),
  좋은 PRD·디자인시스템·기능스펙이 다 있는데 **CLAUDE.md가 아무 데도 안
  가리켜서** Claude가 매 세션 그걸 모른 채 시작했다. 프로젝트 전용 SKILL·agent는 0개.
- **가장 먼저 채울 한 가지 = CLAUDE.md.** 매 세션 자동으로 읽히는 유일한 입구라,
  여기 한 곳만 채우면 PRD·디자인시스템·배포규칙·SSOT가 한 번에 연결된다.
  → 예: "임린지 캐러셀 OS = Next.js16+Supabase+Gemini. SSOT=design-system/tokens·theme.
    제품사양=docs/imrinji-carousel-OS-v1.1.md · 배포: master push=Vercel 자동."

#### 이 점검으로 실제 개선한 것 — 디자인 틀 시스템 1차 구현

- **통점**: 디자인(색·폰트·로고)이 내 브랜드 하나로 코드에 박혀 있어 남이 못 쓴다.
- **해결 설계**: 디자인 명세 + 21문항 질문지 → AI가 브랜드별 디자인을 입힌
  재사용 '틀'을 만들고, 내용만 넣어 캐러셀을 뽑는 구조(멀티유저까지 4단계로 분해, A부터).
- **오늘 결과물**: 설계 문서 + 구현 플랜(7단계) 작성 / 1단계(디자인 데이터 토대)
  구현 — 타입검사 0에러 + "기존 캐러셀은 100% 그대로" 안전장치 테스트 통과.
  곁가지에서 작업해 **실서비스 영향 0**.

### 과정 (타임라인별 + 삽질)

1. **요청 시작** — "디자인 md를 넣으면 그대로 캐러셀이 구성되고, 색·폰트·로고를
질문지로 내 맘대로 바꾸는 기능."

2. **코드 뜯어보기** — 발견 3가지: ①'틀(Template)' 기능은 이미 있음 ②근데 색·폰트가
내 브랜드 하나로 코드에 **박혀 있음**(SSOT 고정) ③md 첨부 기능은 있었지만 '글 소스'로만 쓰이고 **디자인엔 전혀 관여 안 함**. → "디자인을 코드에서 떼어내야 한다"가 핵심으로 잡힘.

3. **요구 명확화 문답** — md=전체 디자인 브리프 / 질문지=프리셋 / 결과물=재사용 '틀' /
폰트 종류 교체는 사용자가 폰트 파일 첨부.

4. **[삽질①] 접근법 설명 실패** — A/B/C안을 전문용어로 제안했다가 "무슨 말인지 모르겠다".
→ '쿠키 틀(모양만, 반죽은 나중)' 비유로 다시 설명 → 깔끔하지만 큰 길(B) 선택.

5. **[삽질②] 범위 폭발** — 17문항 질문지 + Gemini 치환 프롬프트 + 역할별 탭 + 무드이미지→md
+ "진짜 멀티유저"까지 추가되며 한 번에 못 담게 됨. → 4덩어리로 **분해(A→M→B→C)**, A부터.

4. **[삽질③] '오너 미리보기' 헛돎** — 내가 토글을 먼저 넣었다가 "뭔지 모르겠다/과하다" →뺐다가 → "오너가 일반유저 기능이 되는지 확인(남의 데이터는 안 봄)"으로 의미 재정의.

5. **[삽질④] 남의 템플릿이 안 맞음** — 17문항이 웹사이트(Coinbase)용이라 캐러셀엔 자리 없는
항목(폼·가격표·푸터)이 섞임. → 카루셀 전용 **21문항으로 손질**, 형광펜은 선택형, 로고는
브라우저 자동 배경제거(누끼)로 정리.

6. **[삽질⑤] git 개념 막힘** — "master가 뭔데?", "본줄기에 하면 못 돌아가?" → 곁가지가
'느린 게 아니라 빠르면서 안전한 길'임을 설명 → 곁가지 생성.

7. **결과물** — 설계 문서(spec) + 구현 플랜(7단계) 작성 → **1단계(디자인 데이터 토대) 구현**: 타입검사 0에러 + "기존 캐러셀은 100% 그대로" 안전장치 테스트 통과. 전부 곁가지(배포 영향 0).

8. **추가** — 하네스 점검 중 **CLAUDE.md가 비어 있는 것** 발견(좋은 PRD가 있는데 연결 안 됨)
→ CLAUDE.md를 채워 문서들을 연결.

### 공유할만한 인사이트
**근본 병목은 '디자인이 코드에 한 브랜드로 박힌 것'.** 이걸 'Theme'로 떼어내는 게
멀티유저·확장 전체를 푸는 매듭이었다. 기능 하나가 아니라 구조의 문제였음.

- **큰 요청은 쪼개야 산다.** 다 한 스펙에 넣으면 엉킨다. A→M→B→C로 나누니 진행이 살았다.
- **"새 기능이 기존 걸 안 깨게"를 처음부터 박아야 한다.** theme가 비면 기존과 똑같이 나오게 하는 안전장치(불변식)를 설계 1순위로 둔 게 핵심.

- **남의 디자인 템플릿을 그대로 쓰면 내 매체에 안 맞는 항목이 생긴다.** 웹용 17문항을 캐러셀용 21문항으로 깎아야 했다.

- **좋은 문서가 있어도 입구가 안 가리키면 무용지물.** 하네스는 '연결'이 핵심 — CLAUDE.md를 채우니 PRD·스펙·규칙이 한 번에 이어졌다.

- **막히는 지점은 늘 용어/개념 갭(틀·git·best-effort).** 비유로 풀면 진행이 빨라진다.

## 미션2: <단 2명, 찐 고객 페르소나에게 피드백 받은 내용 알려주세요>

###  타깃 사용자 피드백

타깃 사용자상(20–30대, 인스타 콘텐츠를 직접 만드는 사람) 두 명에게
프로토타입을 보여줬을 때 반응을 정리.

### 사용자 A — 27세 직장인, 부업으로 인스타 브랜드 운영 (디자인 비전공)

- **좋았던 점**: 주제만 적으면 캐러셀이 통째로 나오는 게 제일 좋다. 카피 톤이
  딱딱하지 않고 친구가 알려주는 느낌이라 내 계정 분위기랑 맞는다.
- **막혔던 점**: 처음 들어갔을 때 뭘 먼저 눌러야 할지 살짝 헤맸다. '틀'이라는
  말이 직관적으로 안 와서, 이게 디자인인지 글 양식인지 헷갈렸다. 용어가 제작자에게 맞춰있는 거 같다.
- **가장 원하는 것**: "지금은 색·폰트가 정해져 있어서 만들면 '이 앱으로 만든 티'가
  난다. 내 브랜드 색이랑 로고로 나왔으면 좋겠다. 그래야 내 계정에 올렸을 때 안 튀니까.
- **결정적 한마디**: 이미지 들어가는 자리에 내 사진만 쏙 끼워 넣게 되면 바로 쓸 것
  같다. 거기서 디자인까지 손대야 하면 귀찮아서 안 쓴다.
- **지불 의향**: 시간 아껴주는 만큼 월 몇 천 원이면 낸다. 대신 결과물이 '내 거'처럼
  보이는 게 조건.

### 사용자 B — 23세 대학생, 취준·사이드프로젝트 기록 콘텐츠 (양산형)

- **좋았던 점**: 장수 조절되고 캡션이랑 해시태그까지 한 번에 나오는 게 컸다.
  나는 일주일에 여러 개 찍어내야 해서 속도가 제일 중요한데 그게 된다.
- **우려**: 템플릿 티 나서 다 비슷해 보일까 봐 걱정됐다. 근데 테마랑 시그니처
  패턴으로 브랜드별로 다르게 갈 수 있다고 구현한다면 그 부분은 안심.
- **막혔던 점**: 모바일에서도 편집되는지 모르겠더라. 그리고 폰트가 내가 쓰던
  거랑 달라서 어색했다.
- **가장 원하는 것**: 레퍼런스(잘된 남의 캐러셀) 넣으면 비슷한 구조로 뽑아주는
  기능. 매번 처음부터 짜는 게 제일 귀찮다.
- **지불 의향**: 무료로 쓰다가 양이 많아지면 그때 결제 고려. 처음부터 유료면
  안 깔아본다.

### 두 피드백에서 공통으로 나온 것 → 내가 바꿀 것
1. **'내 브랜드처럼 보이게'가 핵심 욕구** — 색·폰트·로고 커스터마이징(지금
   설계 중인 디자인 틀 시스템)이 정확히 이 지점을 친다. 우선순위 확정.
2. **첫 화면에서 '틀'이 뭔지 직관적으로** — 라벨/온보딩 한 줄 보강 필요.
3. **이미지 자리 = 클릭 한 번 교체** — 디자인 안 건드려도 완성되게(placeholder).
4. **레퍼런스 기반 생성 수요 확인** — 인스타 import 방향이 맞았음.(그러나 구현안됨) 디자인 md 파일로 틀 생성으로 방향 바꿈
