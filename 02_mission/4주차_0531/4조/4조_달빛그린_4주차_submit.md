# 4주차 과제 — 달빛그린

## 미션1: JY Creator Board — 텔레그램 봇 + GitHub 저장소 기반 캡처 아카이브 설계 및 초기 구축

### Summary
3주차에 만든 JY Creator DB(웹 업로드 방식)의 한계를 발견하고, **텔레그램 봇으로 캡처를 보내면 자동 저장·분석되는 시스템**으로 확장 설계했다. 이번 주차에는 아키텍처 설계부터 첫 배포까지 완성했다.

**프로덕트 URL**: https://jycreatboard.vercel.app
**GitHub**: https://github.com/sylvia049/jycreatboard

### 최종 구현 결과물

- **텔레그램 봇 웹훅 연결**: 이미지를 보내면 Claude API가 핵심 인사이트 추출
- **GitHub `jy-captures` repo를 DB로 활용**: 별도 DB 없이 GitHub API로 이미지·분석 결과 저장
- **Vercel Serverless Functions**: 백엔드 인프라 (Node.js)
- **단일 이미지 자동 저장**: 캡션 없이 사진만 보내도 분석 후 저장

```
초기 아키텍처:
📱 텔레그램에서 캡처 전송
    ↓ (Webhook)
🌐 Vercel Serverless — telegram.js
    ↓
🤖 Claude API — 이미지 분석 + 인사이트 추출
    ↓
💾 GitHub API — jy-captures repo에 저장
    ↓
🌐 웹 UI — 저장된 캡처 열람
```

### 과정 (타임라인별 + 삽질)

**왜 jycreatordb에서 jycreatboard로?**
- 3주차 jycreatordb는 "웹에서 직접 업로드"하는 방식 → 폰에서 캡처 후 웹을 열고, 파일을 선택하는 과정이 불편
- 핵심 문제: 캡처는 텔레그램에서 바로 공유하는 게 가장 자연스러운 흐름
- 결론: **텔레그램 봇을 트리거로 쓰는 구조**로 전면 재설계

**아키텍처 결정**
- DB 선택: Vercel KV(유료), Supabase(복잡) 대신 GitHub API로 무료 저장소 구현
- 이미지 저장: `jy-captures` repo에 날짜별 폴더로 정리
- 분석 결과: 같은 repo에 JSON으로 함께 저장

**Initial commit — JY Creator Board**
- Vercel Serverless + Telegram Webhook 기본 연결 완료
- Claude API로 이미지 분석 → GitHub 저장 기본 흐름 구축
- 첫 배포 후 `/start` 명령어 응답 확인

**초기 삽질**
- 텔레그램 webhook 등록 시 HTTPS 필수 → Vercel 배포 후에야 등록 가능
- GitHub API write 권한: `repo` scope 필요 (처음엔 `public_repo`로 실패)
- 이미지 분석 개선: 초기엔 분석만 하고 저장 안 되는 버그 → `항상 저장` 로직 추가
- `telegram.js` 중괄호 문법 오류로 봇 전체 다운 → 수정

### 공유할만한 인사이트

- **GitHub을 DB로 쓰는 발상**: 무료 스택으로 실제 작동하는 프로덕트를 만드는 핵심 결정이었다. API rate limit이 있지만 개인 용도에선 충분하다.
- **텔레그램은 최고의 모바일 입력 인터페이스다**: 별도 앱 없이 이미 깔린 텔레그램으로 캡처를 보내는 UX가 웹 업로드보다 훨씬 자연스럽다. 사용자 마찰을 줄이는 게 곧 사용률이다.
- **첫 배포가 설계를 검증한다**: 로컬에서 완벽해 보였던 코드가 Vercel + Telegram webhook 조합에서 바로 오류가 터졌다. 빨리 배포하고 실제로 써봐야 진짜 문제가 보인다.

## 미션2: 찐 고객 페르소나 AI 인터뷰 — JY Creator Board 피드백 수집

### Summary
JY Creator Board의 핵심 타깃 고객을 AI 페르소나로 구체화하고, 해당 페르소나에게 직접 피드백을 받아 프로덕트 개선 방향을 도출했다.

### 최종 구현 결과물

#### 페르소나: 김수현 (31세, 콘텐츠 마케터)

| 항목 | 내용 |
|------|------|
| **직업** | 스타트업 콘텐츠 마케터 3년차 |
| **루틴** | 매일 세미나·뉴스레터·SNS를 보며 캡처 5~10장씩 저장 |
| **문제** | 아이폰 앨범에 캡처가 1,200장 넘게 쌓여 있지만 꺼내 쓴 적이 거의 없음 |
| **현재 방식** | 카톡 나에게 보내기, 노션 스크랩, 네이버 메모 — 다 따로 흩어져 있음 |
| **목표** | 캡처한 내용을 SNS 글·기획서·팀 공유 자료로 빠르게 전환하고 싶음 |
| **기술 수준** | 텔레그램 일상적으로 사용, 노션 사용 가능, 개발 지식 없음 |

---

#### AI 페르소나 인터뷰 전문

**Q1. JY Creator Board를 처음 써봤을 때 어떤 느낌이었나요?**

> "솔직히 처음엔 텔레그램 봇에 사진 보내는 게 좀 낯설었어요. 근데 보내고 나서 바로 분석 결과가 오는 게 신기했어요. '아, 이 캡처가 이런 내용이었구나'를 다시 확인하는 느낌? 평소엔 캡처해놓고 뭔 내용인지 까먹는 게 다반사였거든요."

**Q2. 가장 유용했던 기능은 무엇인가요?**

> "웹에서 저장된 캡처들을 한눈에 보는 거요. 흩어져 있던 게 한 곳에 모이니까 '내가 이런 걸 많이 보고 있었구나'가 보여요. 특히 비슷한 주제 캡처가 여러 개 쌓이면 '이거 글 하나 쓸 수 있겠는데?' 하는 생각이 들더라고요."

**Q3. 불편하거나 아쉬웠던 점은요?**

> "사진 여러 장을 한꺼번에 보내면 1장밖에 안 저장돼요. 세미나 슬라이드 5장을 한꺼번에 보내는 일이 많은데, 그럴 때마다 한 장씩 따로 보내야 해서 번거로워요. 그리고 분석 결과가 텔레그램으로만 오고 웹에선 카드로만 보이는데, 나중에 글 쓸 때 복사하기가 좀 불편했어요."

**Q4. 어떤 상황에서 가장 쓸 것 같나요?**

> "세미나 듣고 나서 바로 핸드폰으로 슬라이드 찍어서 보내는 거요. 지금은 카톡 나에게 보내기 하고 나중에 정리하려다가 결국 안 하게 되는데, 텔레그램에서 바로 분석까지 해주면 '오늘 세미나에서 이런 걸 배웠다'가 바로 정리되잖아요. 그게 제일 매력적인 시나리오예요."

**Q5. 다른 사람에게 추천할 것 같나요? 어떻게 소개하겠어요?**

> "'캡처만 하고 안 쓰는 사람들'한테 추천할 것 같아요. 텔레그램에 봇 추가하고 사진 보내면 알아서 정리해준다고 하면 반응 올 것 같아요. 근데 여러 장 한꺼번에 안 되는 건 좀 언급하기 애매하긴 해요."

#### 피드백 정리 및 개선 방향

| 구분 | 내용 |
|------|------|
| **긍정** | 캡처 → 즉각 분석의 흐름이 자연스럽고 유용함 |
| **긍정** | 한 곳에 모아보는 웹 UI가 "패턴 발견"에 도움 |
| **개선 필요** | 미디어 그룹(여러 장 동시 전송) 미지원 — 핵심 사용 시나리오와 충돌 |
| **개선 필요** | 분석 결과 복사/내보내기 기능 부재 |
| **인사이트** | "세미나 직후 즉시 보내기" 시나리오가 핵심 사용 패턴 |

### 과정 (타임라인별 + 삽질)

- Claude에게 페르소나 역할을 부여하고 실제 인터뷰 형식으로 질문
- "콘텐츠 마케터, 캡처를 많이 하지만 꺼내 쓰지 못하는 사람"으로 구체화
- 좋은 점만 말하는 AI 편향을 막기 위해 "솔직하게, 불편한 점도 말해달라"는 지시 추가
- 5개 질문 → 답변 → 구조화 테이블로 정리

### 공유할만한 인사이트

- **AI 페르소나는 "모르던 것"을 발견하게 해준다**: 미디어 그룹 문제가 개발자 입장에선 기술적 도전이었는데, 페르소나 입장에선 "핵심 사용 시나리오를 막는 치명적 결함"이었다. 관점이 달라졌다.
- **"추천할 것 같나요?"는 가장 솔직한 질문이다**: "쓸 것 같나요?"보다 "남한테 소개할 것 같나요?"가 진짜 평가다. 소개할 때 언급하기 애매한 부분이 곧 해결해야 할 것이다.
- **페르소나 인터뷰는 우선순위를 재정렬시킨다**: 미디어 그룹 문제를 "나중에 해결할 것"으로 미루고 있었는데, 페르소나 피드백 후 5주차 최우선 과제로 올라갔다.
