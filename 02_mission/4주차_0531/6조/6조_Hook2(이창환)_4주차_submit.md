# 4주차 과제 — Hook2(이창환)

## 미션1: 오늘 세션 적용 포인트 반영해서, 내 프로덕트 개선하기

### Summary

지난주 강의에서 다룬 **Harness + Orchestration** 개념을 현재 진행 중인 3개 프로덕트에 동시 적용. 각 프로덕트의 빌드 단계가 달라(신규 / 구축 / 스케일업) 같은 개념을 3가지 결로 검증할 수 있는 기회였음. Harness가 *떠오르는 아이디어를 한 흐름 위에 정리*해주는 발판 역할을 한다는 걸 체감.

### 최종 구현 결과물

본인 워크스페이스 3개에 각각 Harness 구조 적용:

| 프로젝트                       | 빌드 단계 | Harness 적용               |
| -------------------------- | ----- | ------------------------ |
| **OnMove** — 운동 센터용 SaaS 앱 | 신규 빌드 | 진행 중인 앱에 하네스 적용          |
| **인생집**                    | 구축    | 하네스 구조 잡고 개발 진행 중        |
| **B2B 리드 마그넷 콘텐츠 생성 서비스**  | 스케일업  | 기존 서비스 위에 하네스 재적용(규모 확장) |

### 과정 (타임라인별 + 삽질)

1. **3주차 미션 2에서 정의한 Harness/Orchestration 개념을 실제 빌드에 대입** — 이전엔 머릿속에서만 굴리던 *명사형 발판 vs 동사형 흐름* 분리를 코드·폴더·문서 구조로 옮기는 작업.
2. **OnMove (신규)** — 기능 4축(회원·강사·비용·일정 + 가계부) 위에 Harness를 잡음. 데이터 구조 + 입력 폼 + 자동 계산 규칙을 한 발판으로.
3. **인생집 (구축)** — 이미 굴러가는 서비스에 Harness를 명시화. 그동안 흩어져 있던 아이디어들이 어느 자리에 들어갈지 명확해짐.
4. **B2B 리드 마그넷 (스케일업)** — 기존 서비스의 카테고리·채널 확장 단계에서 Harness를 다시 적용. 확장하면서 구조가 무너지지 않게 발판을 다시 단단히.

### 공유할만한 인사이트

1. **Harness는 '아이디어 정리 발판'이 된다** — 빌드 중 떠오르는 새 아이디어가 던져질 *자리*가 미리 짜여 있으니, 흩어지지 않고 누적됨. **구조가 아이디어를 받아낸다.**
2. **빌드 단계(신규/구축/스케일업)별로 Harness가 다른 일을 한다** — 신규엔 *첫 골격*, 구축엔 *명시화*, 스케일업엔 *무너짐 방지*. 같은 개념인데 단계에 따라 가치가 달라짐.
3. **3개 동시 적용이 검증의 깊이를 만든다** — 한 프로덕트만 적용했으면 운으로 보였을 패턴이, 세 곳에서 비슷하게 작동하니 *진짜 원리*로 보임.

## 미션2: 단 2명, 찐 고객 페르소나에게 피드백 받은 내용을 알려주세요

### Summary

3개 프로덕트 모두에 대해 실사용자 페르소나로부터 피드백 수집. 각 프로덕트가 마주한 결이 완전히 다름 — **OnMove는 기능 연결성 미비**, **인생집은 유저 유입·리텐션**, **B2B 리드 마그넷은 콘텐츠 품질·확장**. 페르소나 피드백이 다음 우선순위를 자연스레 정해줌.

### 최종 구현 결과물

#### (1) OnMove — 운동 센터용 SaaS 앱

- **현재 단계**: 기존 SaaS 바탕 업그레이드 버전 시도, **필수 기존 기능들이 아직 미비**한 상태
- **피드백 내용**:
  - 회원 칸 ↔ 강사 연동 필요
  - 지출 ↔ 회원 정보 연동 필요
  - → **기능 간 연결성** 부족이 1순위 막힘
- **향후 계획**: 기존에 따로 써야 했던 서비스들을 *하나로 합치는 것*이 OnMove의 핵심이므로, **이 통합 기능을 우선 구현한 뒤 재피드백** 받을 예정

#### (2) 인생집

- **현재 가장 큰 고민**: 유저 유입과 리텐션
- **현황**: 한 번 등록하고 나면 *다시 들어올 이유*가 부족하고, 유저가 적어 추천이나 상호 교류도 어려운 상황
- **깨달은 점**: **프로덕트 제작보다 유저를 모으는 게 더 어렵다**는 것을 확실히 알게 됨. 기존 SaaS는 엑셀 연동이나 가격 경쟁력으로 유저를 데려올 수 있지만, *아예 없던 서비스인 인생집은 커뮤니티 침투 등 공격적인 홍보가 필요해 보임*
- **남은 과제**: 매일은 아니더라도 유저가 *자주 접속할 만한 이유*를 찾는 것

#### (3) B2B 리드 마그넷 콘텐츠 생성 서비스

- **성과**: 코리아 엑스포 해외 진출 관련 콘텐츠는 피드백을 반영하여 **실제 원문 생성이 가능**하고, **바로 게시해도 될 정도의 퀄리티**를 확보
- **확장**: 테크, 교육, 뷰티, F&B 등 회사에서 다루는 다양한 산업 전시로 카테고리 확장
- **추가 피드백 반영**:
  - 생소한 용어에 대한 설명(주석 등)이 필요하다는 의견 → 적용
  - 단락간 연결성이 좀 떨어진다는 의견 → 적용
  - 홈페이지 외에도 LinkedIn, Instagram, 뉴스레터 등 **다양한 채널에 발행할 수 있도록 기능 준비 중**

### 과정 (타임라인별 + 삽질)

1. **세 프로덕트 동시 페르소나 피드백 수집** — 각 프로덕트의 진짜 페르소나가 모두 다름 (운동 센터 사장님 / 인생집 유저 / 회사 동료).
2. **단계별 우선순위 차이** — OnMove는 *기능 부족*이 1순위 / 인생집은 *유저 모으기*가 1순위 / B2B는 *채널 확장*이 1순위. **같은 "다음 액션"이라도 단계에 따라 결이 완전히 다름.**
3. **깨달은 점**
	→ 실제 있던 SaaS는 우선 수요는 있는 것이기에 기능적인 것이나 더 저렴한 가격에 사용할 수 있게 만드는 것이 중요. 그리고 기존 앱에서 사용하던 파일만 다운받아서 마이그레이션 가능하게 하는 것이 중요 → 이후 홍보를 통해 바로 사용할 수 있도록 적용
	
	→ 인생집과 같은 없던 앱은 수요를 정확히 알기 어렵기 때문에 진짜 사업화를 생각하는 것이 아니면 홍보에서 무너짐. 피드백도 비용을 투자하지 않으면 제대로된 피드백을 받기 어려움.
	
	→ 실제로 회사에서 적용가능한 정도로 만들기 위해 팀원의 피드백을 받았고, 몇몇 피드백을 통해 현재 한 주제의 콘텐츠로는 사용할 수 있을 정도로 만들어뒀고, 이후 서비스 규모/차원을 높여 모든 산업을 다룰 수 있도록 진행중.
	
	→ 전체적으로 해보면서 깨달은 것은 이제는 프로덕트를 만드는 것은 누구나 만들텐데, 실제로 유저를 모으고 활성사용자를 만드는 것이 정말 어려운 것 같음. 
	
	→ 만들 때는 어드민 페이지와 백엔드 연결을 해두고 시작하면 좋을 것 같음. 그리고 보통 프론트 화면 캡처해서 개선시켜달라하면 백엔드는 고려를 안하는 경향이 있는데 항상 같이 고려하라고 메모리에 기억시켜두고 진행하면 좋음. 앞으로는 백엔드 연결된 워크 플레이스를 구축해두고 핵심 기능부터 넣고 확장해나가는 형식이 좋을 것 같음.

### 공유할만한 인사이트

1. **'피드백 받는 것'보다 '다음 우선순위 정하는 것'이 핵심** — 페르소나가 던지는 피드백을 그대로 다 반영하려 하면 우선순위 무너짐. *지금 단계에서 가장 큰 막힘 하나*를 골라내는 게 진짜 능력.
2. **프로덕트 만들기 < 유저 모으기** — 인생집에서 가장 강하게 부딪힌 벽. **기능이 아니라 분포가 문제**인 서비스가 있고, 신규 카테고리 서비스일수록 *공격적 홍보가 코어 업무*.
3. **세 프로덕트 동시 진행이 페르소나 다각화의 학습장이 된다** — 한 프로덕트만 보면 페르소나 패턴이 일반화되기 쉬운데, *완전히 다른 세 페르소나*를 동시에 마주하니 "페르소나마다 다른 룰"이 보이고 일반화 함정에서 벗어남.

1. **자랑은 '내 성과'보다 '환경의 힘'을 짚을 때 더 신뢰감 있다** — "이 분위기 없었으면 못 했을 것"이라는 솔직한 인정이 자기 자랑보다 훨씬 잘 전달됨.
2. **'글로 쓰게 하는 시스템'이 진짜 차별점** — 만들기만 해선 머릿속에서 끝나는데, 매주 글을 강제하니 깨달음이 형태를 얻음. 이게 1·2·3주차 모두 본인이 글을 쓸 때마다 새로 발견한 핵심이기도 함.
3. **커뮤니티의 가치는 '시간이 지난 후'에 드러난다** — 1주차 때는 호기심, 2주차 때는 도구, 3주차 때는 기술이 핵심으로 보였는데, 4주차에 와서야 *함께한 사람들*이 가장 큰 자산이라는 게 보임. 자랑할 때는 이 시간 차원이 입체감을 줌.
