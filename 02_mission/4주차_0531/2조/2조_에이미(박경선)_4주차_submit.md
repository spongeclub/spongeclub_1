## 미션1: <제목>

### Summary

인테리어 리모델링을 앞둔 사람을 위한 무료 스타일 진단 웹앱. 5~7개 질문에 답하면 내 집에 맞는 인테리어 스타일·예산대·업체군을 진단해주고, 더 깊은 상담으로 연결한다. 기획(PRD)부터 디자인 시스템, 카피, 개발, 배포까지 클로드코드로 직접 구현했다.

- **핵심 가치**: 투명·분별·상생 — "정직한 쪽이 이기는 시장"
- **핵심 메시지(헤드라인)**: "좋은 인테리어엔 순서가 있습니다"
- **브랜드 태그라인**: "업체를 만나기 전에, 내 집의 방향부터."
- **비즈니스 모델**: 진단은 무료, 심화 리포트·상담은 유료

### 최종 구현 결과물

https://space-fit-opal.vercel.app/
https://space-fit-opal.vercel.app/?admin

### 과정 (타임라인별 + 삽질)

**1. 기획 — 비즈니스 모델 좁히기**

- 기존에 만들던 "견적 검증 서비스"를 백지화하고, 더 가벼운 진입점인 "내 집 스타일 찾기"로 방향 전환.
- 2~4주 MVP가 아니라 "오늘 밤 발표용 결과물"로 목표를 재조정 → 컨시어지 MVP 대신 바로 작동하는 1-기능 웹앱으로 결정.
- 삽질: 처음엔 "완전 백지에서 새 사업"을 찾으려다, 인테리어 25년 경력을 살리는 쪽으로 좁히고 나서야 길이 명확해짐.

**2. 문서화 — PRD + 디자인 시스템**

- PRD.md 작성: 페르소나, 문제 정의, 기능 명세(1차 범위/제외 범위), 사용자 흐름, 진단 로직(규칙 기반 점수표), 콘텐츠, 기술 스택, 수익 모델, 성공 지표.
- 진단 로직은 AI가 아니라 규칙 기반 점수표로 설계 → 안정적이고 시연이 확실.
- 스타일 6종 확정(모던·미니멀호텔식·내추럴·북유럽·클래식·모던클래식), 예산대·업체군은 시장 데이터 기반으로 채움.
- 삽질: 처음엔 주관적 경험으로 채우려다, 웹 데이터를 검색해 객관적 수치로 보강하는 게 신뢰도가 높다는 걸 깨달음.

**3. 디자인 시스템 — 토큰 기반 DESIGN.md**

- 레퍼런스(Figma의 색면 구조 + Streamtime/Warp의 톤)를 인테리어 브랜드에 맞게 합침.
- 색·폰트를 CSS 변수(토큰)로 관리 → 나중에 수정이 쉽도록 설계.
- 삽질: 컬러를 여러 번 갈아엎음. 크림+테라코타 → 어스톤 팔레트(펄·카키·토프·코코아) → 코코아가 답답해서 점토(`#B5876B`)로 밝힘. 폰트도 Pretendard → 나눔스퀘어 → 다시 Pretendard로 회귀(한국 웹 표준).

**4. 카피 — 후킹 헤드라인 잡기**

- 가장 오래 걸린 부분. 추상적·시적 표현은 안 와닿고, 너무 평범해도 안 됨.
- 여러 방향(공감형·약속형·질문형) 중 "장면형 + 약속형"으로 좁힘.
- 최종: 헤드라인 "좋은 인테리어엔 순서가 있습니다" + 서브 "저장해둔 사진은 많은데…" + 버튼 "내 스타일 찾기".
- 삽질: "왜 집다움인가" 섹션을 가치·사람·고객변화 등 여러 각도로 채워봤지만 다 안 맞아서, 결국 섹션 자체를 덜어냄(뺄 게 없을 때 완성).

**5. 개발 — 클로드코드로 단계별 구현**

- CLAUDE.md(항구 규칙) + BUILD_GUIDE.md(단계별 빌드 프롬프트)로 작업을 끊어서 진행.
- 뼈대+토큰 → 화면 → 진단 로직 → 결과 화면 → 연락처 폼 순으로 한 단계씩 확인하며 진행.
- 디자인 설정 패널 추가: ?admin에서만 열리고, 색·폰트·글자크기·자간·행간·정렬을 실시간 조정 가능.

**6. 배포 — Vercel**

- 연락처 폼을 Web3Forms로 연결(정적 사이트의 폼 백엔드).
- Vercel로 배포 → 실제 URL 발급, 깃허브 연동으로 자동 재배포.

### 공유할 만한 인사이트

- **문서를 단일 출처로 두면 일관성이 유지된다.** PRD·DESIGN.md를 먼저 만들고 클로드코드가 그걸 참조하게 하니, 카피·색이 바뀌어도 문서만 고치면 화면이 따라옴.
- **한 번에 다 시키지 말고 단계로 끊어라.** 클로드코드는 큰 작업을 한 번에 하면 헤맨다. 단계마다 브라우저에서 확인하고 어긋난 것만 고치는 사이클이 빠르고 정확.
- **카피는 추상과 평범 사이가 가장 어렵다.** 시적이면 안 와닿고 평범하면 안 걸린다. 고객의 실제 장면을 비추는 게 가장 강력.
- **뺄 게 없을 때 완성된다.** 안 맞는 섹션은 더 다듬기보다 덜어내는 게 답일 때가 있다.
- **디자인 토큰(CSS 변수)으로 관리하면 비개발자도 수정할 수 있다.** 색·폰트를 한 곳에 모아두면 거기만 바꿔도 전체가 바뀐다.
- **객관적 데이터가 신뢰를 만든다.** 주관적 경험 대신 시장 데이터로 예산·업체 정보를 채우니 발표 설득력이 올라감.
