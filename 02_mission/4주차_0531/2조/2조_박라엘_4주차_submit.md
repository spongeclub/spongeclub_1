## Summary

|항목|내용|

|**무엇을**|다수의 웹페이지에서 데이터를 자동 수집해, 변동 이력·이미지·외부 API 결과를 구글 시트에서 한눈에 비교하는 PC 자동화 도구 구축|
|**왜**|수동으로 페이지를 하나씩 확인하는 방식으로는 빠른 변동에 즉각 대응하기 어려움 → 수집·비교·알림까지 자동화 필요|
|**핵심**|수동 페이지 탐색 → Playwright 자동 순회·추출로 전환 + 변동 감지 및 알림까지 자동화|

### 최종 구현 결과물

- **다수 페이지 자동 순회**: 목록 파일에 URL을 작성하면 Playwright(Chrome 자동화)가 순서대로 방문·스크롤·추출
- **데이터 자동 추출**: 텍스트 데이터를 휴리스틱 탐지 방식으로 구조화해 수집
- **이미지 추출**: 썸네일 이미지 URL 수집 → 구글 시트 셀 내 표시, 육안 비교 가능
- **외부 API 연동**: 수집 데이터에 외부 API 결과를 자동으로 결합, 동일 요청은 캐시 처리
- **변동 감지**: 이전 수집 데이터와 자동 비교 → 감소(🔴)·증가(🟡)·신규(🟢)·삭제(⬜) 색상 강조
- **알림 시스템**: 변동이 있을 때만 이메일 요약 1통 발송, 없으면 발송 안 함
- **구글 시트 자동 정리**: 누적 이력·최신 데이터·그룹 분석·환율 환산 탭 자동 생성
- **로컬 백업**: 매 실행마다 타임스탬프 CSV 자동 저장

### 과정 (타임라인별 + 삽질)

## Phase 1. 아이디어 → 브라우저 확장 프로그램

**목표**: 브라우저에서 버튼 하나로 웹페이지 데이터를 뽑아보자

- 특정 페이지를 열고 아이콘 클릭 → 데이터 추출
- 결과를 구글 시트 전송 / 클립보드 복사 / CSV 다운로드로 출력

**한계 발견**

- 한 페이지씩 수동으로 처리해야 함
- 여러 페이지를 다뤄야 할 경우 매번 직접 열어야 해서 비효율적
- → **"여러 페이지를 자동으로 순회하는 별도 도구가 필요하다"** 는 결론

---

## Phase 2. PC 자동화 도구 개발 시작

**목표**: 목록만 입력하면 전부 자동으로 처리되게 만들자

- Node.js + Playwright 조합 선택 (Chrome을 코드로 자동 조종)
- 목록 파일에 URL을 적으면 순서대로 방문 → 스크롤 → 추출

---

## Phase 3. 설치 단계에서 첫 번째 실수

### ❌ 실수: 압축 폴더 구조를 못 보고 바깥 폴더에서 명령어 실행

```
프로젝트폴더/         ← 여기서 npm install 실행 → 오류  프로젝트폴더/       ← 실제 파일이 여기 있음    package.json    ...
```

압축을 풀었더니 폴더가 한 겹 더 생겼는데, 바깥 폴더에서 `npm install`을 실행해서 `package.json 없음(ENOENT)` 오류 발생

**해결**: 안쪽 폴더로 들어가서 다시 실행

---

## Phase 4. 구글 시트 연결 단계에서 두 번째 실수

### ❌ 실수: Apps Script 배포 URL을 잘못 복사

배포할 때 전체 URL이 아닌 **배포 ID만** 설정 파일에 붙여넣어서 데이터 전송이 계속 실패

**해결**: 배포 관리 화면에서 전체 URL(`/exec`로 끝나는 것)을 다시 복사

---

## Phase 5. 구글 보안 경고에서 멈춤

### ⚠️ 혼란: "Google이 이 앱을 확인하지 않았습니다" 경고

직접 만든 스크립트인데 구글이 경고창을 띄워서 진행을 못 하고 멈춤

**해결**: 고급 → "안전하지 않은 프로젝트로 이동" 클릭하면 정상 진행 (본인 스크립트라 안전)

---

## Phase 6. 추출 로직 개선 — 페이지 형식 문제

### ❌ 실수: 페이지 URL 형식이 두 가지인 걸 몰랐음

```
형식 A: /r/-B12345/         ← 처음에 이것만 테스트형식 B: /buyer/12522138/    ← 이 형식에서 추출이 안 됨
```

**해결**: 양쪽 형식 모두 처리하도록 추출 로직 수정

---
## Phase 7. 실행 중 브라우저 창 닫기 실수

### ❌ 실수: 자동화가 실행 중인 브라우저 창을 손으로 닫음

Playwright가 브라우저를 열어서 작업 중인데, 그 창을 실수로 닫아버림 → 이후 작업 전부 오류로 실패

**해결**:

- 브라우저가 닫혀도 재시작하고 이어서 진행하는 로직 추가
- **창이 아예 안 뜨는 백그라운드 모드(`headless: true`) 설정 권장**

---
## Phase 8. 외부 API 연동 추가

- 수집한 데이터에 외부 API 결과를 자동으로 결합
- 동일한 요청은 캐시로 처리해 API 호출 횟수 절약

### ⚠️ 혼란: API 결과 링크가 브라우저에서 막힘

결과 시트의 링크를 클릭했더니 "접속이 일시적으로 제한" 메시지 → 프로그램이 고장난 줄 알았으나
**원인**: 브라우저에서 직접 여는 웹페이지가 막힌 것. 프로그램은 API로 가져오므로 정상 작동 중이었음

## Phase 10. 변동 감지 + 알림 시스템 추가

**피드백**: "매번 직접 확인하지 않고 변동이 생겼을 때만 알고 싶다"

- 이전 수집 데이터와 현재 데이터를 자동 비교
- 시트에서 색상으로 즉시 확인 가능
    - 🔴 빨강: 감소
    - 🟡 노랑: 증가
    - 🟢 초록: 신규 항목
    - ⬜ 회색: 사라진 항목
- 변동 있을 때만 이메일 요약 1통 발송 (없으면 발송 안 함)
- 첫 실행은 비교 기준 데이터가 없으므로 알림 발송 안 함

### 공유할만한 인사이트

### 개념

Windows에 내장된 작업 스케줄러를 활용해 **지정한 시각에 자동 실행**되도록 예약. 별도 서버 없이, 추가 비용 없이 구현 가능.

```
매일 오전 9시    → Windows가 run.bat 자동 실행        → 데이터 수집            → 구글 시트 갱신                → 변동 있으면 이메일 알림
```

### 동작 조건

|상황|결과|
|---|---|
|예약 시각에 PC 켜져 있음|✅ 정상 실행|
|예약 시각에 PC 꺼져 있음|⏭ 해당 회차 건너뜀|
|예약 시각에 절전 중|⏭ 해당 회차 건너뜀|

### 장점

- 추가 코드 수정 없이 적용 가능 (기존 `run.bat` 그대로 사용)
- 실행 주기를 자유롭게 설정 가능 (매일·매주·특정 요일 등)
- 실패해도 다음 예약에 영향 없음
