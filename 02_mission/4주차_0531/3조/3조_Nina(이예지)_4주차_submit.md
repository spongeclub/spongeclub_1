# 4주차 과제 — Nina


## 미션1: 내 프로덕트 개선하기

### Summary

#### 어떤 서비스인가

소규모 쇼핑몰 CS 팀(1~5명)이 쓰는 AI 보조 도구다.

고객이 챗봇과 대화하다 해결이 안 되면 담당자에게 연결된다. 그 순간이 가장 바쁘고 실수가 많은 순간이다. Glance는 그 순간에 담당자 옆에 붙어서 "이 고객 지금 어떤 상태인지, 전에 무슨 문의를 했는지, 뭐라고 먼저 말 걸면 좋은지"를 바로 보여준다.

**화면 구성**
- **왼쪽:** 지금 기다리고 있는 고객 목록. 화가 많이 난 순서, 오래 기다린 순서, 여러 번 다시 연락한 순서로 정렬 가능
- **오른쪽:** 선택한 고객의 감정 상태, 대화 내용 요약, 추천 첫마디 3개, 예전 상담 기록
- **특별 기능:** 고객이 많이 화가 난 상태면, 왜 화가 났는지 원인과 어떻게 대응하면 좋을지 단계별로 자동으로 표시

이번 미션의 목표는 **"그냥 만든 것처럼 보이는 데모"를 "진짜 쓸 것 같은 서비스"처럼 만드는 것**이었다.



### 최종 구현 결과물

- [랜딩 페이지](https://glancehq.netlify.app/landing.html)
- [데모 앱](https://glancehq.netlify.app/)


### 과정 (타임라인별 + 삽질)

#### 1단계 — 소개 페이지 디자인 다듬기
받은 피드백을 바탕으로 서비스 소개 페이지를 보기 좋게 다듬었다.

- 제품 화면 미리보기에 살짝 기울어진 3D 효과 추가 (평면보다 입체감이 있어서 더 완성된 느낌)
- "이런 불편함 있지 않으세요?" 섹션에 어두운 배경과 마우스 올리면 반응하는 카드 효과 추가
- 기능 소개 카드를 복잡하게 배치하던 것을 2×2 깔끔한 정방형으로 정리

#### 2단계 — 소개 페이지 문구 교체
소개 페이지에 쓴 말이 "개발자 말"이었다. CS 담당자 입장에선 낯선 단어들이 많았다. 피드백 7개 항목을 분석한 뒤 전부 바꿨다.

|바꾸기 전|바꾼 후|
|---|---|
|AI 레이어|AI 도우미|
|전환 컨텍스트|대화 요약|
|챗봇 에스컬레이션|챗봇이 못 해결한 순간|
|AI가 처리하지 못한 케이스|챗봇이 처리 못한 순간|
|재방문 고객 (n회차)|세 번째 돌아온 고객|

그리고 섹션 순서도 바꿨다. 원래는 "이런 불편함 있지 않으세요?" 섹션이 먼저였는데, "이런 분들을 위해 만들었어요" 섹션을 앞으로 당겼다. 자기한테 해당되는 이야기인지 먼저 확인해야, 불편함 섹션을 읽을 때 공감이 더 잘 된다.

어떤 메신저·CS 도구랑 연결되는지(채널톡, 카카오채널, Zendesk 등)도 단계 설명 안에 명확하게 넣었다.

#### 3단계 — 데모 속 가상 고객 다시 만들기
데모에 들어 있는 가상 고객 3명이 너무 "만들어낸 티"가 났다. 진짜 상담 신청한 사람처럼 느껴지도록 11명으로 늘리고 더 현실적으로 바꿨다.
- AI가 만든 한국인 페르소나 데이터(NVIDIA에서 공개한 데이터셋)를 참고해서 설계
- 나이대는 20대~50대, 사는 곳은 서울·경기·부산·인천·광주·충남으로 다양하게
- 직업에 맞는 구매 제품도 설정 (회계 사무원 → 노트북 케이스, 항만 노동자 → 작업화 등)
- 감정 상태 분포: 화남 2명 / 불만족 4명 / 보통 5명

**막혔던 것:** 이전에 작업한 고객 데이터 파일에서 한글이 알아볼 수 없는 문자로 깨지는 현상이 생겼다. 파일을 부분 수정하려 했지만 원인이 명확하지 않아 전체를 새로 작성하는 방식으로 해결했다.

#### 4단계 — 프로필 사진 교체
데모 속 고객 프로필 사진이 외부 무료 이미지 사이트에서 자동으로 불러오는 방식이었다. 인터넷 연결이 없으면 깨지고, 무엇보다 너무 딱딱한 증명사진 느낌이었다.

AI 이미지 생성 도구로 만든 사진으로 전부 교체했다.
- 처음엔 증명사진 스타일로 제안했더니 "카카오톡처럼 자연스럽게 해줘"라는 피드백이 왔다
- 셀카, 반려동물, 여행 풍경, 꽃, 기본 프로필 등 실제 사람들이 쓸 법한 사진 믹스로 재설계
- 11명 각각에 맞는 이미지 컨셉을 작성하고, 사용자가 AI 도구로 직접 생성해서 저장

#### 5단계 — 데모 앱 기능 추가
**분노 고객 대응 가이드 신기능:** 화가 많이 난 고객을 클릭하면, 왜 화가 났는지 원인과 어떻게 대응하면 좋을지 자동으로 표시되도록 했다. 3명의 분노 고객 각각에 맞는 원인과 단계별 전략을 직접 작성해 넣었다.

|고객|화난 이유|대응 방향|
|---|---|---|
|황혜란|배송 완료 표시인데 4일째 물건이 없음|감정 인정 → 원인 설명 → 1시간 내 결과 약속|
|김다희|불량품 왔는데 반품 배송비까지 요구받음|잘못 인정 → 불량 확인 → 무료 처리 안내|
|박유하|오배송인데 당일에 3번 연락해도 해결 안 됨|누적 불편 인정 → 담당자가 직접 처리 선언 → 일정 확약|

**첫 화면 개선:** 데모를 열었을 때 "고객을 선택하세요"라는 빈 화면이 떴다. 이제는 가장 급한 고객(가장 화난 고객)이 자동으로 열린다.


#### 7단계 — 소개 페이지와 데모 앱 맞추기 + 배포
앱에서 바꾼 색과 새로 추가한 분노 가이드를 소개 페이지의 미리보기 화면에도 똑같이 반영했다. 소개 페이지에서 본 것과 실제 데모가 다르면 신뢰가 깨지기 때문이다.

### 공유할만한 인사이트

#### 1. 말을 바꾸는 건 단어 교체가 아니라 관점 교체다
"에스컬레이션 → 챗봇이 못 해결한 순간"은 단순히 단어를 쉽게 바꾼 게 아니다. 기능 중심 설명을 사용자가 실제로 겪는 상황 중심 설명으로 바꾼 것이다. 진짜 언어 교체는 관점을 바꾸는 일이다.

#### 2. "나한테 해당되는 이야기인가?"가 먼저다
소개 페이지에서 아무리 공감되는 불편함을 보여줘도, 그 앞에서 "이게 내 얘기인가?"를 판단하지 못하면 사람들은 그냥 나간다. "이런 분을 위한 서비스예요" 섹션이 먼저 와야 뒤에 있는 공감 섹션도 읽힌다.

#### 3. 데모의 첫 3초가 전부다
빈 화면으로 시작하면 사람들이 직접 탐색해야 한다. 가장 극적인 케이스(화난 고객)를 자동으로 열어주는 것만으로 "이 서비스가 뭘 해주는구나"를 즉시 보여줄 수 있다.

#### 4. 가상 고객도 "진짜처럼" 만들어야 한다
데모 속 고객이 작위적으로 느껴지면 서비스 전체가 가짜처럼 느껴진다. 실제 사람들이 카카오톡에서 쓰는 프로필 사진처럼(셀카, 반려동물, 풍경 등 다양하게), 직업과 사는 곳과 구매 제품이 자연스럽게 연결되도록 설계해야 한다.

## 미션2: 피드백 받은 내용

### Summary
크루 4명에게 랜딩 페이지와 데모 앱 피드백을 받았다. "처음 봤을 때 이 서비스가 뭔지 바로 이해되는가"와 "데모 앱이 실제로 쓸만해 보이는가" 두 가지에 피드백이 집중됐다. 당장 반영할 수 있는 5개 항목을 골라 수정 후 배포까지 완료했다.

### 최종 구현 결과물

**랜딩 페이지**

| 항목     | 전                               | 후                                                         |
| ------ | ------------------------------- | --------------------------------------------------------- |
| 히어로 문구 | 불편함 공감("10초 더 기다리게 하지 마세요")만 있음 | 불편함 + 해결책 한 줄 추가 — "Glance가 대화를 읽어드릴 테니, 첫 마디부터 바로 시작하세요" |
| 용어     | "매니저"                           | "상담원" 으로 전체 통일                                            |


**데모 앱**

| 항목        | 전                               | 후                                               |
| --------- | ------------------------------- | ----------------------------------------------- |
| 오른쪽 패널 순서 | 고객 정보 → 대응 가이드 → 대화 요약 → 추천 첫마디 | **추천 첫마디 → 대화 요약** → 고객 정보 → 대응 가이드 → 이력        |
| 대화 요약 형태  | 2~3문장 이어진 글                     | 항목별 짧은 줄로 분리 (• 항목 형식)                          |
| 황혜란 첫마디   | "많이 불편하셨겠습니다" (공감만)             | "4일이나 기다리셨는데 연락도 드리지 못해 **정말 죄송합니다**" (공감 + 사과) |
| 김다희 첫마디   | 반품 처리 여부부터 언급                   | **불량 부위가 어딘지 먼저 확인** → 그 다음 처리 안내               |
| 채팅 표기     | 매니저                             | 상담원                                             |


### 과정 (타임라인별 + 삽질)

**피드백 수집**
- 크루 4명이 링크를 직접 눌러보고 비동기로 의견 남겨줌
- 랜딩: "처음 보는 사람한테 뭔지 바로 안 와닿는다", "왜 써야 하는지보다 이걸 쓰면 뭘 할 수 있는지가 없다"
- 데모: "추천 첫마디까지 스크롤해야 보인다", "황혜란 첫마디가 비꼬는 느낌", "불량품인데 반품 여부부터 물어보는 게 순서가 이상하다"

**우선순위 분류**
- 오늘 바로 할 것 5개 / 나중에 할 것 4개로 나눔
- 나중으로 미룬 것: 히어로를 영상으로 만들기, 챗봇이 혼자 해결하는 케이스 추가, 회사별 CS 가이드 연동

**구현 중 발견한 것**
- 패널 순서를 바꾸는 건 화면에 내용을 그리는 순서만 바꾸면 됐는데, 이때 대화 요약을 불렛 형태로 먼저 준비해두고 순서를 바꿔야 했음. 순서를 잘못 짜면 아직 준비 안 된 내용을 먼저 그리려다 빈칸이 뜨는 문제가 생길 수 있었음
- 대화 요약 불렛 자동 분리는 문장이 끝나는 지점(마침표)을 기준으로 나누는 방식으로 구현했는데, 마침 기존 요약 텍스트들이 마침표로 문장이 잘 구분되어 있어서 별도 수정 없이 바로 동작함
- "매니저"를 "상담원"으로 바꿀 때 "CS 상담 매니저"라는 표현이 있어서 그냥 전체 치환하면 "CS 상담 상담원"이 될 뻔했음. "CS 상담 매니저" 먼저 수동으로 고친 다음 나머지를 일괄 교체하는 순서로 해결함

### 공유할만한 인사이트

**1. "불편하셨겠습니다"는 사과가 아니다**  
공감과 사과는 다르다. "불편하셨겠습니다"는 고객 감정을 이해한다는 말이지, 우리 잘못을 인정하는 말이 아니다. 분노한 고객에게는 둘 다 필요하고, 순서도 중요하다. 피드백 받기 전까지 이 차이를 놓쳤다.

**2. "왜 필요한가"보다 "쓰면 뭘 할 수 있나"가 먼저다**  
랜딩 첫 화면이 불편함 공감으로만 채워져 있으면 "맞아, 나도 그래"는 되지만 "그래서 이걸 써볼게"로 이어지지 않는다. 방문자는 스크롤 내리기 전에 "이걸 쓰면 내 상황이 어떻게 달라지는지"를 먼저 보고 싶어한다. 첫 화면에 해결책 힌트가 한 줄이라도 있어야 스크롤을 내린다.

**3. 실무자는 "지금 당장 쓸 수 있는 것"을 가장 먼저 원한다**  
오른쪽 패널에서 고객 정보와 대응 가이드를 먼저 보여줬더니 "추천 첫마디까지 스크롤해야 한다"는 피드백이 나왔다. 상담원 입장에서 이 패널의 핵심 가치는 "지금 바로 보내도 되는 문장"이다. 정보 배치를 만든 사람 기준(맥락 파악 → 행동)이 아니라 쓰는 사람 기준(행동 → 맥락)으로 뒤집었더니 문제가 바로 해결됐다.

**4. CS 응대에는 순서가 있다**  
김다희 케이스에서 "불량인지 먼저 확인 → 그다음 반품·교환 안내" 순서가 맞는데, 처음엔 반품 처리를 먼저 언급하는 실수를 했다. CS에는 확인 → 판단 → 처리라는 자연스러운 절차가 있고, 이 순서를 어기면 고객이 오히려 더 의심한다. 해당 도메인을 직접 경험해본 사람이 아니면 텍스트만 봐서는 놓치기 쉬운 부분이었다.
