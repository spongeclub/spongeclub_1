## Phase 1 — 우리가 한 일

비유로 시작할게. **새 사무실을 차린 단계**라고 보면 돼.

### 1.1 환경 점검

사무실 차리기 전에 — 가스, 전기, 수도 들어오는지 확인하는 단계. 정옥의 Mac에 우리가 쓸 도구 4개(`claude`, `gh`, `git`, `node`)가 설치돼 있는지 봤어. 다 있었음.

### 1.2 작업 폴더 생성

사무실 건물을 정함. `/Users/jeongohkseo/projects/kolamp-os` 라는 빈 폴더 하나 만들었어.

### 1.3 GitHub 연결

사무실에 **금고**를 설치한 단계. GitHub은 우리가 만드는 모든 작업물의 백업 금고야. Mac이 망가져도 GitHub에 모든 게 안전하게 있어. 이 사무실(`kolamp-os` 폴더)이 그 금고와 연결됨.

### 1.4 폴더 구조 만들기

사무실 안에 **방을 나눔**.

- `knowledge/` 방 — 기획 자료 보관
- `design/` 방 — 디자인 자료 보관
- `templates/` 방 — 빈 양식 보관 (아직 비어 있음)
- `products/` 방 — 실제 작업 결과물 보관 (아직 비어 있음)
- `.claude/commands/` 방 — 자동화 명령서 보관 (아직 비어 있음)

## Phase 2 — 앞으로 할 일

**기획 작업을 자동화하는 단계**야.

### 지금 정옥이 하는 코램프 기획 작업

정옥이 신상품 기획서를 쓸 때 보통 이런 순서로 함:

1. 상품 URL 보고 기존 페이지 분석
2. 코어 지침서 보면서 어떻게 쓸지 정함
3. Knowledge 1·2·3 참고해서 페르소나·니즈·궁금증 확인
4. 섹션별로 카피 쓰고 이미지 지시 작성
5. 엑셀로 이미지 자산 시트 만듦

이걸 **매번 손으로** 함. 클로드한테 매번 같은 자료 첨부하고, 같은 톤 설명하고, 같은 형식 요청함.

### Phase 2가 만드려는 것

이걸 **명령어 한 줄**로 끝내는 거야.

정옥이 Claude Code 안에서 이렇게만 치면:

```
/plan-product 허드슨벽등1
```

그러면 Claude Code가 알아서:

1. knowledge 방의 자료 4개를 읽음
2. 코램프 톤·규칙·고객 궁금증을 머리에 넣음
3. 정옥에게 "URL 주세요" "추가 자료 있어요?" 같은 필요한 질문만 함
4. 섹션별 기획서를 한 번에 출력
5. 이미지 자산 시트(xlsx)도 한 번에 출력
6. `products/허드슨벽등1/` 폴더에 다 저장

**Phase 2 한 줄 요약**: 정옥이 매번 손으로 하던 기획 작업을 명령어 한 줄로 자동 실행되게 만드는 단계.

### Phase 2의 4개 단계

- **2.1** 그 자동 명령(`/plan-product`)이 어떻게 작동할지 정의하는 안내서 작성
- **2.2** 입력 양식(`input.md`) 빈 템플릿 작성 — "이 상품에 대해 이런 정보가 필요해요" 양식
- **2.3** 빈티지디스크라는 실제 상품으로 그 양식을 한 번 채워봄 — 테스트용 입력
- **2.4** 첫 실행 — `/plan-product` 명령 진짜 돌려보고 결과 확인

### 지금 갈림길

Phase 2.1에서 **`/plan-product`가 어떻게 입력을 받을지** 정해야 해. 두 가지 방법이 있다고 했지:

**방법 A — 가볍게 시작** 명령어 한 줄만 치고, Claude Code가 필요한 정보를 그때그때 물어봄. 대화로 풀어가는 방식.

**방법 B — 양식 먼저 채우고 시작** 빈 양식(`input.md`) 파일을 정옥이 먼저 채워. 거기에 상품명·URL·차별점·자료 다 적어두고, Claude Code한테 "이 양식 보고 기획해" 명령. 양식이 입력 역할.

---

쇼핑몰 비유:

- A는 "**전화 주문**" 같은 거. 가게 직원과 통화하면서 "치즈는 빼주세요" "그럼 양상추는요?" 대화로 정함.
- B는 "**주문서 작성**" 같은 거. 종이에 미리 다 적어서 넘기면 직원이 그걸 보고 그대로 만듦.

A는 가볍고 즉흥적. B는 체계적이지만 처음에 양식 짜는 데 시간이 더 듦.
