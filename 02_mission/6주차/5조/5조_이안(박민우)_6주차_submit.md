## 미션2: 갤러리

### Summary

갤러리에 산출물 2개를 올렸다. 
**Automation Level Advisor** — 자동화에 뛰어들기 전에 "이 문제가 AI로 자동화될 일인지, 어디까지 가능한지"를 먼저 진단해 주는 비개발자용 컨설턴트 Skill. 
**Weft** — 대본이나 문서만 주면 나레이션·자막·이미지·CapCut 드래프트 또는 영상까지 만들어 주는 영상 제작 워크플로우 CLI. 
둘 다 "AI에게 어디까지 맡기고 사람은 어디서 개입하나"라는 같은 질문에서 출발했다.

### 최종 구현 결과물

**1. Automation Level Advisor** — https://github.com/MinwooPark2026/automation-level-advisor
- 일상 언어로 작업을 설명하면 짧은 인터뷰로 "AI 혼자 ↔ 사람 주도" 수준을 진단하고, 바로 쓸 실행 계획서와 시작용 리포트 2종을 만들어 준다.
- ROI가 아니라 **감독/개입 수준(oversight)** 을 축으로 판단한다. 거기에 **검증 가능성(verifiability) + 도달 가능성(reachability)** 2축을 더해 "AI가 애초에 낼 수 있는 답인지"까지 본다.
- Claude Code / OpenAI Codex **Skill**(`SKILL.md` + `agents/openai.yaml`). 별도 서버·프레임워크 없이 Markdown 기반으로 동작하고 양쪽 에이전트에서 모두 돌아간다.

**2. Weft** — https://github.com/MinwooPark2026/Weft (데모: https://youtu.be/__sw4e7GVcs)
- 대본 → 콘티(`CONTI.md`) → 검증·컴파일 → 자막(SRT)·트랙 JSON·render plan → TTS·이미지 생성 → CapCut 드래프트, 영상까지 `weft` CLI 하나로 이어진다.
- 나레이션 비트와 비주얼 샷을 분리한 **이중 트랙** 모델(한 이미지가 여러 비트를 커버할 수 있음). 이미지 후보는 로컬 브라우저 picker 단축키로 빠르게 고른다.
- Python CLI(전역 `weft` 명령), Typecast TTS + OpenAI gpt-image-2, 최종 렌더는 NLE(CapCut)에서 하거나 자체 랜더링.

### 과정 (타임라인별 + 삽질)

- **Automation Level Advisor**: 처음엔 "비용 대비 가치(ROI)"로 자동화 여부를 가르려 했는데, 실제로 막히는 지점은 거기가 아니었다. 진짜 축은 **"사람이 어디까지 개입해야 하는가"** 였고, 그래서 판단 기준을 oversight 중심으로 다시 잡았다.
- **Weft**: 자체 렌더링까지 웹에 넣으려다 도구가 무거워졌다. 렌더를 NLE에 넘기고 나니 무거운 웹 GUI 자체가 필요 없어졌고, 사람이 꼭 봐야 하는 picker만 남기고 전부 CLI로 내렸다. 그 순간 "사람이 조작하던 도구"가 "AI가 호출하는 도구"로 바뀌었다. 웹에서 랜더링을 안하고 로컬에서 랜더링을하니 병렬처리가 가능해서 훨씬 빨라 최종적으로 웹 gui를 버리니 캡컷까지 안가도 cli또는 클로드로 랜더링까지 완성했다.

### 공유할만한 인사이트

- 자동화의 판단 기준은 ROI가 아니라 **개입 수준(oversight)** 이다. "얼마나 이득이냐"보다 "사람이 어디까지 손대야 하나"를 먼저 봐야 한다.
- AI가 못 푸는 문제는 따로 있다. 학습 데이터 **밖**의 답은 재조합이 아니라 외삽이 필요해서, 프롬프트를 아무리 다듬어도 닿지 못한다(**reachability**). 그런 건 사람이 먼저 만들어 줘야 한다.
- 도구에서 **GUI도 덜어내고** CLI로 내리면 사람이 쓰던 도구가 AI가 부르는 도구가 된다.
- 자동화가 잘 될수록 **단계마다 AI가 개입할 여지**를 남겨두는 게 오히려 중요하다. 그 틈에서 AI가 생각지도 못한 좋은 결과를 만들어 낸다.
