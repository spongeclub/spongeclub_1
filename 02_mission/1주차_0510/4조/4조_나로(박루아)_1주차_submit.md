## 미션 1: claude code 로 인터뷰스킬 사용해서 인터뷰 까지 진행

### Summary

### Summary
Claude Code를 처음 깔고, GitHub에서 `os-interview-skill`을 받아 설치하고, 그 스킬로 인터뷰까지 마쳤다. 25년 동안  디자이너의 시야에서 AI 환경에 발을 디딘 나는 결과물보다 ****"내가 코드 환경에 들어가 봤다"**** 라는 사실 자체가 가장 큰 수확이었다.

### 최종 구현 결과물
- ****Claude Code 설치 완료****
  환경: macOS Sequoia 15.7.3 / MacBook Pro 16 (Intel i9, 32GB)
- ******`**os-interview**` **스킬 설치 완료****
   -로컬 작업 폴더: `/Users/apple/Documents/project/Interview-skill/`
   -전역 등록: `~/.claude/skills/os-interview` (심볼릭 링크로 로컬과 자동 동기화)
- ****인터뷰 진행 완료****: `/os-interview` 발동 → 작업 패턴·자주 막히는 지점·의사결정 기준이 인터뷰 형식으로 정리됨
### 과정 (타임라인별 + 삽질)
### 1단계 · Claude Code 설치
맥 스펙(Intel i9, 32GB, Sequoia)이 요구사항을 만족하는지 확인하고 `npm install -g @anthropic-ai/claude-code`로 설치. node 버전 18 이상이 필수라는 걸 처음 알았다.
### 2단계 · GitHub에서 스킬 클론 — ****첫 번째 삽질****
강의에서는 "지금 열려있는 폴더에 클론해줘"라고 했는데, 그렇게 시키니까 Claude Code가 안전하게 한 단계 더 들어간 하위 폴더(`Interview-skill/os-interview-skill/`)에 풀어버렸다. 강의 구조와 어긋나서 멈춤.
→ ****해결****: `git clone <URL> .` — 끝에 ****점(.)**** 을 찍어야 "이 폴더에 직접" 풀린다. 점 하나 차이로 폴더 구조가 완전히 달라진다.
### 3단계 · 권한 묻는 창 — 두 번째 멈칫
`gh repo view ...` 같은 명령어가 실행되기 전에 Claude Code가 매번 권한을 물어봤다. 처음엔 무서워서 멈췄는데, 알고 보니 "공개 메타데이터만 조회하는 안전한 읽기 명령"이었다. ****"이 프로젝트에서 항상 허용"**** 누르면 같은 패턴은 반복해서 안 물어본다.
### 4단계 · 워크스페이스 신뢰
새 폴더에서 처음 작업할 때 한 번 물어보는 보안 절차. 본인 폴더니까 그냥 신뢰 누름.
### 5단계 · 세션 새로 켜기 — ****세 번째 삽질****
스킬을 다 설치하고 `/os-interview` 쳐도 발동을 안 했다. 이유는 ****"스킬은 세션 시작할 때 한 번 로드된다"****. 설치 전에 시작된 세션은 새 스킬을 못 알아본다.
→ ****해결****: `/exit` → 같은 폴더에서 `claude` 다시 실행 → 발동.
### 6단계 · 인터뷰 진행
새 세션에서 "내 OS 만들고 싶어" 입력. 인터뷰가 시작되고, 작업 방식·시간이 새는 지점·결정 기준 등이 차례로 질문됐다. 답하면서 머릿속에만 있던 패턴이 글로 정리됐다.

## 미션 2: 따라해보고 싶은 개인/업무/삶 OS 따라서 만들어보기 - SNS(유튜브 등) 에서 찾아 벤치마킹 해오기

### Summary
어제 인터뷰 스킬로 정리한 시호일일 콘셉트("50대 디자이너가 자기를 위해 짓는 식탁")를 토대로 SNS 벤치마킹 1곳 찾기. 두 번 막히고 두 번 방향 전환한 끝에 **그림비(@grim_b · 배성태 작가)** 도착. 손그림 일러스트 + 짧은 글로 51만 팔로워, 책·굿즈·전시·광고까지 IP화한 1인 운영 모델. 이전 이모티콘 작가 경력과 결이 정확히 일치하는 자리였다.
### 최종 구현 결과물

### 과정 (타임라인별 + 삽질)
**1단계 · 1차 후보 도출** 어제 인터뷰 결과를 토대로 시호일일 콘셉트를 다시 잡았다: 50대 1인가구 디자이너 / 자기돌봄 / 차분한 일상 / 디자인 미감. 이 키워드로 검색해서 도출된 1차 후보는 **Taji (@2nd613)** — 53세 1인 가구 일본 디자이너, "나를 우선하는 삶"을 콘셉트로 8.3만 팔로워. 책 출간까지. 콘셉트가 시호일일과 거의 거울처럼 일치했다.

**2단계 · 첫 번째 삽질 — 콘셉트만 보고 운영 부담을 못 봤다** Taji 분석을 마치고 "이거다" 싶었는데, 다시 보니 결정적 문제가 있었다. Taji의 무대는 18평 흰 집의 미니멀 인테리어, 매 컷이 그 공간을 무대로 한 라이프스타일 사진이다. 즉 **매일 공간을 세팅하고 촬영하는 일이 본업화**되어야 굴러가는 구조. 25년 디자인 일을 하면서 시호일일을 동시에 가려는 1인에게 이건 콘텐츠가 아니라 추가 노동이다. 게다가 나에겐 그런 인테리어 공간 자체가 없다. 출발점에서 막힘.

→ 콘셉트가 같다고 운영 모델까지 같은 건 아니다. 벤치마킹은 결과물의 결만 보면 안 되고 _"내 조건에서 지속 가능한가"_ 를 같이 봐야 한다는 걸 여기서 배움.

**3단계 · 방향 재설정 + 두 번째 삽질** "촬영 없음 + 1인 운영 + 자기돌봄/일상의 결"로 키워드 조합을 바꿔 재검색. 일본의 일러스트 에세이스트 마스다 미리(益田ミリ)도 후보로 봤지만 출판사 기반 연재(매월 9일) 시스템이라 인스타 1인 운영 모델은 아니었다. 패스.

**4단계 · 그림비 발견** 한국 일러스트레이터 중 1인 운영으로 일상의 결을 가진 계정을 검색하다 **그림비(@grim_b)** 도착. 51만 팔로워, 게시물 1,500여 개 — 양보다 꾸준함의 누적으로 도달. 출발점이 "전업주부 시절 아내와 함께한 평범한 삶"의 기록이라 **거창한 무대 없이 시작한 케이스**. 책·굿즈·전시·광고까지 IP화 경로 전부 검증됨.

**5단계 · 세 번째 삽질 — 내 카드를 절반만 보고 시스템을 짰다** 그림비를 1순위로 정하고 시각 시스템을 짜는데 또 막혔다. _"그림비는 직접 그림을 그리는 일러스트레이터인데 나는 그림 못 그리니까 AI 일러스트로 우회해야 한다"_ 는 가정 위에서 시스템을 설계하고 있었다. 그런데 다시 들여다보니 이 가정 자체가 틀렸다.

- 나는 이전에 **이모티콘을 만든 작가**다 (카카오/네이버/라인 심사를 통과해 본 적이 있음)
- **아이패드**가 있고, **왼손으로 그림을 그릴 수 있다**
- 내 그림은 실력이 화려하진 않지만 **따뜻한 톤**이 있다 — 그림비의 "담요 같은 그림"과 결이 같다
- 이모티콘은 정사각형 한 칸 안에 캐릭터·감정·메시지를 압축하는 작업. 인스타 피드도 정사각형 한 칸. **포맷이 완전히 같다.**

→ 즉 나는 그림비를 우회해서 따라갈 사람이 아니라 **이미 그 자리에서 출발할 수 있는 사람**이었다. AI 일러스트는 백업으로만 두고, 손그림이 메인으로 올라옴. 시각 시스템을 다시 — A(손그림 시리즈) 주 2회 메인, B(타이포 카드) 주 1회, C(정물 폰카) 격주 호흡으로 재정렬.
