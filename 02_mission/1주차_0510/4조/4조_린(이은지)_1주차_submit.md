## 미션 2: 따라해보고 싶은 개인/업무/삶 OS 따라서 만들어보기 - SNS(유튜브 등) 에서 찾아 벤치마킹 해오기

### Summary

### 최종 구현 결과물

![[20260510-0910-28.1496037.mp4]]
### 과정 (타임라인별 + 삽질)
**시작 — "처음이니까 가볍게"**  
OS 인터뷰 스킬을 켰다. 6단계라는데 일단 가벼운 것부터.

**Step 1 풍경**  
취준생이고, 시간을 가장 많이 쓰는 활동은 단순하게 공부/잠/식사라고 답했다. 

**Step 2 통점이 튀어나옴**  
"공부보다 수면 쪽으로 집중하고 싶다"고 방향을 틀었다. 어제도 새벽 5시까지 클로드 코딩하다 잤다고. 패턴은 명확했다 — 아침엔 설렁설렁, 저녁이 되어야 시동이 걸려서 그 관성이 새벽까지 끌고 간다.

**진단이 뒤집혔다**  
Claude가 가설을 던졌다 — _"몰입을 스스로 켜는 능력 대신, 밤이라는 외부 환경이 켜주길 기다리는 상태."_ Cal Newport의 한 줄이 결정적이었다. **"밀리는 사람은 끄는 의식이 없는 거지, 켜는 의식이 없는 게 아니다."** 잠 문제가 아니라 종료 문제였다.

**Step 3 이상향 — 3블록 구조**  
시간대별 하루를 그렸다. 기상→물/밥→운동→오전 공부→낮 SNS→저녁 코딩→23시 씻기→00시 잠. 
**OS 선언문 픽스**  
_"나는 손만 움직이고, 시동·전환·종료 의식은 시스템이 챙긴다."_

**Step 4 부품 후보 8개**  
시동/전환/종료 묶음으로 정리.

**커뮤니티 사례 웹서치**  
나와 비슷한 생각을 한 사람들이 뭘 만들었는지 보고 싶었다. Cal Newport의 셧다운 의식, Notion Life OS, Claude Morning Briefing 스킬 — 4개 흐름이 일관되게 나왔다. 가장 정통은 종료 의식이었다.

**첫 부품 결정 — 셧다운 의식 스킬**  
밤을 먼저 잡는 처방. 한 파일짜리 SKILL.md, 5분 인터뷰, "오늘 끝. 내일 다시." 종료 멘트.

-**"이게 OS야?" 메타 질문**  
부품 1개로는 OS가 아니라는 사실을 짚었다. 안장만 있는 자전거. 그래도 처음엔 이게 정상이라는 답을 받았다.

-**모닝 시동 시작했다가 스킵**  
다음 부품 1순위로 갔는데 만들기 전에 "필요없을 거 같아"라고 했다. 셧다운 로그 아침에 한 번 보면 그게 시동 역할 한다는 직감.

**전환도 스킵**  
청사진의 8개 부품 중 1개만 만들고 7개를 거절한 셈이 됐다. Claude가 솔직히 짚었다 — 청사진의 후보가 진짜 필요한 게 아닐 수 있다고.

**갑자기 욕망이 튀어나옴**  
"바탕화면에 캐릭터가 움직여서 말풍선으로 셧다운 기록이 나왔으면 좋겠어." 작업이 끝나가는 시점에 이게 만든건가?하고 내버려두려다가 해보고 싶었던 아이디어가 생각났다.

**PRD 1장 → 즉시 구현**  
"실현하자, 18시 테스트 트리거도." Electron + React + TypeScript 프로젝트가 16개 파일로 자동 생성됐다. 곰 SVG 3장 placeholder. npm install 325개 패키지.

**삽질 1 — PNG 1장만 가지고 있다**  
SVG 3장 모드로 만들었다가 코드를 1장 모드로 갈아엎었다. 표정 변화는 CSS 필터/투명도/zzz 텍스트로 흉내.

**삽질 2 — "로그가 없다는데?"**  
첫 클릭에 캐릭터가 "로그 파일이 없어"라고 했다. 셧다운을 한 번도 안 했으니 정상 동작이었다. 시연용 가짜 블록 한 장으로 해결.

**삽질 3 — 30초가 진짜 30초였다**  
시간을 30초로 늘려달라고 하고는 정작 오늘 할일과 내일 할일에 시간간격이 너무 넓었다. 못 기다렸다. 클릭으로 즉시 다음 메시지로 넘어가는 옵션을 추가했다.
### 공유할만한 인사이트
**1. 청사진은 한 번에 짜는 그림이 아니다.** 8개 부품 후보를 그렸지만 1개만 만들고 7개를 거절했다. 그게 잘못된 게 아니라, 부품을 며칠 써보면서 진짜 필요한 게 발견되는 게 정상이다. 머릿속으로 8개 떠올리는 것보다 1개 잘 굴러가게 만드는 게 훨씬 정확하다.
