# 1주차 과제 — 달빛그린

## 미션 1: claude code 로 인터뷰스킬 사용해서 인터뷰 까지 진행

### Summary

Claude Code의 `os-interview` 스킬로 6단계 인터뷰를 진행하고, 나만의 OS 청사진과 첫 프로덕트 PRD를 완성했다. 결과물: **두뇌창고** — 흩어진 메모·사진·음성을 AI가 자동으로 수집·분류·정리해주는 모바일 앱 기획서.

### 최종 구현 결과물

- [`os-blueprint.md`](os-blueprint.md) — OS 청사진 전체 (선언문 + 풍경/통점/이상향/부품 목록)
- [`두뇌창고.prd.md`](두뇌창고.prd.md) — 프로덕트 기획서 (기능 정의 + 로드맵 + 기술 스택)

**OS 선언문**: 나는 캡처·기록(음성 포함)만 하고, 나머지는 시스템이 한다.

### 과정 (타임라인별 + 삽질)

**Phase 1 · 청사진 (Step 1~4)**
- Step 1 풍경: 대기업 UX 디자이너 → AX 이동, AI 공부 + 사람 탐구가 핵심 관심사
- Step 2 통점: 메모가 Apple 메모·UpNote·갤럭시·카카오 4군데에 산재. 사진은 아이폰 갤러리 따로.
- Step 3 이상향: 내용에 맞춰 알아서 분류, 30초 안에 찾기
- Step 4 부품: 캡처 자동 분류 / 음성 제목 자동생성 / 기존 메모 소급 정리 / 주제 검색 — 4개 도출

**Phase 2 · 첫 부품 결정 (Step 5)**
- 부품 3(소급 정리)을 첫 부품으로 선택
- 처음엔 A(Claude 스킬) 고려 → 파일량 너무 많아서 B(플러그인)로 → 다채널 연동 필요해서 C(PRD)로 최종 결정

**Phase 3 · PRD 작성 (Step 6)**
- 5개 질문으로 빠르게 정리: 이름·사용자·기능·플랫폼·성공지표·제약조건

### 공유할만한 인사이트

**"어디다 저장하지?"가 진짜 문제였다.**
분류 결정 비용이 높으면 뇌가 아예 분류를 포기한다. 저장은 되는데 꺼내 쓸 수 없는 구조가 된다. 해결책은 결정을 없애는 것 — AI가 내용을 보고 알아서 분류하면 사용자는 그냥 던지기만 하면 된다.

## 미션 2: 따라해보고 싶은 개인/업무/삶 OS 따라서 만들어보기 - SNS(유튜브 등) 에서 찾아 벤치마킹 해오기

### Summary

유튜브 ["클로드 코드 스킬로 인스타 카드뉴스 자동 생성"](https://www.youtube.com/watch?v=501KRO5QSXM) 영상을 벤치마킹해, 본인 통점(맛집 사진은 쌓이는데 후기는 안 쓰게 됨)에 맞게 변형한 클로드 스킬 `foodspot-cards` v0.1을 작성. 원본은 텍스트·자료 → 카드, 본 스킬은 **이미지 → 가게 자동 식별 → 웹 정보 보충 → 카드 마크다운**으로 차별화.

### 최종 구현 결과물

- [`260509_foodspot-cards.skill.md`](attachments/260509_foodspot-cards.skill.md) — 맛집 사진 폴더만 던지면 인스타 카드 시리즈 마크다운까지 자동 생성하는 스킬 v0.1

**스킬 핵심 동작**: 사진 폴더 → (간판·메뉴판·영수증·EXIF 추출) → 가게명 추정 → WebSearch로 주소·영업시간·대표 메뉴 보충 → 슬라이드 6~8장 + 게시물 본문 + 해시태그 한 파일 출력.

### 과정 (타임라인별 + 삽질)

**Phase 1 · 벤치마크 선정**
- 유튜브 "클로드 코드 스킬로 인스타 카드뉴스 자동 생성" 영상 채택
- 그대로 따라하지 않고 **본인 통점에 맞춰 변형하기**로 결정 — 본인은 자료보다 사진이 쌓이는 쪽

**Phase 2 · 차별점 설계**
- 원본: 텍스트·자료 기반 → 본 스킬: 이미지 우선 (사진만 던지면 끝)
- 빈 칸 질문 X → **사진 안 단서**(간판·메뉴판·영수증·EXIF)로 가게 자동 추정
- WebSearch로 주소·영업시간·대표 메뉴 자동 보충 — 원본에 없는 단계

**Phase 3 · 스킬 v0.1 작성**
- 같은 4조 먼지민의 [`evening-close.skill.md`](attachments/260507_evening-close.skill.md) 형식·원칙(Draft first, confirm second / 회상 fallback) 계승
- 5단계 흐름: 사진 스캔 → 정보 보충 → 카드 시리즈 설계 → 카피 작성 → 출력+라우팅
- Harness rule 4개: 추정 실패 fallback / 사실·추정 분리 / 카드 수 잡아당김 / 본인 톤 빈 칸

**삽질 / 결정 흔적**
- 1차 설계는 "사진 어디서 찍었는지 먼저 묻기"로 시작 → evening-close v0.3 패치에서 깨진 패턴이라 폐기, **추정 우선**으로 재설계
- 카드 매수 자유도 → 6~8장으로 제한(인스타 끝까지 보는 비율 고려해 Harness rule로 못박음)

### 공유할만한 인사이트

**"벤치마크 = 그대로 따라하기"가 아니라 "원본의 패턴을 본인 통점에 이식하기"다.**

원본 영상은 텍스트 자료 기반 카드뉴스 자동화였지만, 그대로 따라했으면 본인이 안 썼을 거다. 본인이 진짜 매번 미루는 건 **맛집 사진 → 인스타 후기 변환**이었고, 그 통점에 영상의 패턴(스킬 + 자동 카드 생성)을 이식하니까 첫 사용 동기가 생긴다. 벤치마크의 가치는 **포맷 복제**가 아니라 **패턴 발견**에 있다.
