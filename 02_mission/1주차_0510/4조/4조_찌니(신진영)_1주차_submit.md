문제: 처음엔 `02_skill&insight/marketing/` (spongeclub 볼트 안) 후보. 발견: 시놀(개인 회사)과 spongeclub(AI 스터디)는 별개 컨텍스트. 섞으면 안 됨. 결정: `~/Documents/sinor-marketing/{YYYY-MM}/` 외부 폴더로 분리. 교훈: 데이터 격리는 처음 설계 시점에 명확히. 나중에 옮기면 frontmatter·경로 다 깨짐.

문제: 주제 2 인스타 영역 Edit 시도 시 매칭 실패. 원인: rev2에서 슬라이드 5에 "신원조회 거친 안전한 또래" 한 줄을 추가했었는데, old_string 작성 시 그걸 반영 안 함 (구버전 기억으로 작성). 해결: `awk` 명령으로 파일 다시 읽고 정확한 내용 확인 후 재시도. 교훈: revision_log에 변경 기록만 남기지 말고, Edit 전 실제 파일 상태 확인 필요. 특히 누적 디벨롭 시.

## 3. 배운 점

### 클로드코드 시스템 구조 — 3중 분리

```
~/.claude/skills/[skill]/      ← 워크플로우 (재사용 로직)
~/.claude/commands/[cmd].md    ← 진입점 (사용자 명령어)
~/Documents/[project]/         ← 데이터 자산 (콘텐츠 결과물)
```

왜 분리? 스킬은 회사 무관 재사용, 데이터는 회사별 격리. 명령어는 사용자 편의 진입점.

### 자가 강화 시스템 설계 (v0.4 핵심)

1. 자가 점검 9기준 (SEO 3 + AEO 3 + GEO 2 + 톤 1) → AI가 자기 출력을 객관 평가
2. 반복 개선 루프 → 부분 Edit으로 점진적 발전 (전체 재생성 X = 토큰·시간 효율)
3. 자동 저장 → 자산 누적 → 톤 가이드 자동 진화 = 3단 자기 강화 시스템

### 검색 노출 강화 = SEO + AEO + GEO 통합

- SEO (Google·Naver): 메인 키워드 10회+, LSI 10개, 제목 숫자/연도, H2/H3 계층
- AEO (Featured Snippets): 도입 답변형, FAQ 7개, 표 구조화
- GEO (ChatGPT·Perplexity): 페르소나 2명, 외부 권위 출처, 인용 가능 사실
- E-E-A-T: 전문가 인용 (김민지 대표 미래에셋 출신), 회원 10만+ 통계, 출처 표기

### 콘텐츠 5종 통합 발행 전략

같은 주제 → 5종 형식별 변형 → 1주일 후속 발행으로 재활용:

- 블로그 (검색 진입, 장기 자산)
- 스레드 (도달 + 인용)
- 인스타 (도달 + 전환)
- 릴스 (영상 도달)
- 유튜브 (장기 영상 자산)
- 인용 카드 별도 분리 → D+1~D+7 스토리/단독 게시 재활용

### 공유할만한 인사이트

**1. "시장 데이터가 가장 좋은 코치다 — AI brainstorm보다 본인 발행글 1개"**  
처음에 메시지 후보 10개를 만들었는데, 정작 사용자가 이미 만든 `Re:Boot 50+`(287 좋아요)가 가장 강한 IP였다. 새 IP를 만들지 말고 **이미 작동하는 신호부터 확인**해야 한다. 좋아요는 노이즈, **저장·진심 댓글이 진짜 신호**.

**2. "책은 시작이 아니라 부산물 — 한 메시지를 18개월 묵힌 후 자산화"**  
Mel의 Let Them Theory(8M부)는 TikTok 1편 시드(2023) → 팟캐스트 1편(2024-09) → 책(2024-12) 순서. 자청·신사임당·김미경도 동일 패턴. **책·강의·코스 같은 자산은 검증된 시드의 결과**이지 시작점이 아니다. 한국에서 1인이 따라할 수 있는 모델은 **시드 → 검증 → 자산화 → 재증폭** 4단 사이클을 6개월~18개월 단위로 돌리는 것.

**3. "위기·실패가 IP의 원료다"**  
Mel(41세 파산), Jinny(12년 경단·부모 상실), 강원국(글쓰기 콤플렉스) — 본인이 망쳤던 것을 회복하는 과정 = 콘텐츠. 약점이 자산이 되는 모델. 이 패턴을 인지하면 50+ 1인 기업의 진입 장벽이 "재능"이 아니라 "이야기 정직성"임이 보인다.

**4. "매일 2편은 콘텐츠 시간이 아니라 시스템 시간"**  
즉흥 제작은 무너진다. **일요일 90분 일괄 제작 → 평일은 발행만**. Mel의 50명 팀이 하는 일을 1인이 흉내 내려면 (a) 시드 분할(시드 1개 = 3~5편) (b) 요일·시간대 톤 분리 (c) 스케줄러 자동 발행 — 이 세 가지가 핵심. 미션 1의 "C레벨 주간보고 자동화 스킬"과 같은 OS 사상이 SNS 운영에도 적용됨.
