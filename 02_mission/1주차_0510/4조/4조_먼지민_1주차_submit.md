> 	✅ AI가 먼저 스캔해 초안을 띄우고, 사람은 빼거나 더할 것만
> 	👉 변경 하나로 마감 로그 시간이 절반 아래로

### 💎 공유할만한 인사이트

1. **🚫 빈 칸·주관식 질문은 가장 비싼 입력**
   *"어디 둘까요?", "다음에 뭐 할래요?"* 라고 묻기 시작하면 사람이 매번 떠올려야 함. 떠올리는 비용이 결국 미루기로 이어짐. → **AI가 초안 먼저, 사람은 한 줄 답.**

2. **👁️ 사람은 검수자 자리에 있어야 빨라짐**
   작성자 자리에 앉으면 모든 빈 칸이 본인 머릿속에서 나와야 함. 검수자 자리에 앉으면 *"맞다 / 아니다 / 빠졌다"* 만. → 시간 절반, 인지 부담 1/3.

3. **♻️ 부품은 쓰면서 디벨롭** — v0.1로 박고 매일 돌리니 3~4일 만에 손에 맞춰짐.

4. **🚧 첫 부품으로 메타 부품 회피** — 매일 마주치는 마찰점 직격 부품이 ROI 빠름.

5. **🧭 OS 선언문 한 줄의 위력** — *"이게 본인 vs 시스템 분담을 그쪽으로 미는가?"* 한 번 비추면 부품 우선순위가 정리됨.

## 🔭 미션 2 · 따라해보고 싶은 OS 벤치마킹

### 📌 Summary

- *받아들일 것 / 받지 않을 것 / 보류* 를 **결정 8건** 으로
- 가장 큰 변경: **시스템 스코프를 "일" → "삶 전체"**

### 🔍 1) 무엇을 봤는가 (대상)

| 갈래 | 자료 |
|---|---|
| 📺 유튜브 | PARA[^3] 기반 Obsidian / Notion 라이프 OS / dotfiles[^4] 동기화 / 디지털 가드닝 |
| 📰 블로그 | 한국어권 *세컨드 브레인*, *Obsidian으로 일상 굴리기* |
| 📦 이전 자료 | 본인이 과거에 따라가다 만 옛 노트 구조 |

### 🧪 2) 무엇이었고 어땠는가 (분석)

**✅ 공통으로 반복된 패턴**
- 📐 폴더 번호 체계 (`100_`, `200_`…)
- 🎨 이모지 prefix로 인덱스/부품/템플릿 시각 구분
- 📝 결정 기록(ADR[^5])을 본문이 아닌 별도 폴더에
- 📱 모바일 동기화 = 지속성의 분기점
- 🌿 *OS는 일만이 아니라 삶 전체*

**❌ 받아들이지 않은 것**
- 과한 자동 분류 / 외부 SaaS 동기화 / 너무 많이 쪼갠 트리 *(유지보수 폭발)*

### 💡 3) 벤치마킹 포인트 — 5가지 원칙

1. 🏠 **하나의 작업 폴더 원칙** — 일·삶을 한 폴더에서. 분리는 도메인으로.
2. 📝 **결정은 따로 기록** — 1주일 뒤 *"왜?"* 를 다시 안 묻게.
3. 🧩 **부품은 작게, 자주, 매일** — 큰 자동화 한 개보다 작은 부품 여러 개.
4. 🎨 **시각 분류는 이모지로** — 색·태그보다 가볍고 모든 OS에서 일관됨.
5. 📱 **모바일은 동급 시민** — 부속이 아니라 *같은 폴더의 또 다른 입구*.

### 🔨 4) 지금 바로 도입한 것 (실행)

#### 📝 결정 기록 8건

| # | 결정 | 한 줄 요약 |
|---|---|---|
| ① | 🌿 시스템 스코프 = 삶 전체 | 일에 국한 X. 사람·재정·건강·재미까지 |
| ② | 📂 삶 영역 도메인 신설 | 다섯 영역(사람/성장/피트니스/재정/재미) |
| ③ | 🔢 영역 내부 prefix | `01_사람` ~ `05_재미` 코드 부여 |
| ④ | 🗃️ 추적 정책 정비 | 워크스페이스 파일 선별 추적, 무거운 파일 외부 |
| ⑤ | 📱 모바일 동기화 = Working Copy[^6] + git | 단축어로 자동 pull/push |
| ⑥ | 🎨 이모지 prefix 도입 | 인덱스·부품·템플릿·임시 시각 구분 |
| ⑦ | 🧭 다음 부품 = 라우팅 도우미 | *"이 자료 어디 둘지"* AI가 던지기 |
| ⑧ | 🚧 부품 위치는 임시 | 5개 누적 시 위치 자체 재검토 |

> *각 결정은 별도 한 장씩 — 고려된 대안 / 선택 이유 / 따라오는 리스크 까지 기록.*

#### 🏗️ 물리 산출물 4가지

- 🌿 **삶 영역 도메인 신설** — *"OS는 삶 전체를 굴린다"* 의 물리적 표현
- 📱 **모바일 자동 연동 완성** — iPhone에서 같은 git → *앱 열 때 자동 pull / 닫을 때 자동 push*
- 📚 **부품 라이브러리 신설** — 만든 부품 + 다음 후보 인덱스
- 🧹 **폴더 트리 정리 + 추적 정책 정비** — 디바이스 간 동기화 충돌 0

### 🛣️ 5) 앞으로 도입할 것 (계획)

- [ ] 🔁 **머신 동기화 전략 정식화** — 부품 누적 시 검토

### 💎 공유할만한 인사이트

1. **📝 벤치마킹 = 따라 만들기 X, "결정"으로 남기기 O**
   가장 많이 한 행위는 *"이건 우리한테 안 맞는다"* 라고 이유와 함께 적는 일. 거른 자료도 *고려된 대안* 자리에 함께 적어 두면 1주일 뒤 같은 자료를 다시 안 봄.

2. **🌍 스코프 결정이 가장 효과 큼**
   *일 vs 삶 전체* 는 폴더 한두 개의 차이가 아님. 부품 우선순위·메모리 구조·동기화 전략까지 줄줄이 바뀜. **가장 먼저** 결정.

3. **🧬 OS는 "구조"가 아니라 "원칙"으로 빌리기**
   특정 폴더 구조를 베끼면 1주 뒤 안 맞음. 원칙(*하나의 폴더*, *결정은 따로*, *작게 시작*)은 시간이 지나도 본인 환경에 다시 적용 가능.

4. **🥣 그릇이 부품보다 먼저**
   부품을 멋있게 만들어도 받을 폴더·라우팅이 없으면 결과물이 떠다니다 사라짐. 1주차에 *부품* 보다 *그릇 정비* 에 더 시간 쓴 게 결과적으로 옳았음.
