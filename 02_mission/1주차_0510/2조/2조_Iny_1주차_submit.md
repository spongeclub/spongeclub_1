# 1주차 과제 — Iny

## 미션 1: claude code 로 인터뷰스킬 사용해서 인터뷰 까지 진행

### Summary

Claude Code의 os-interview 스킬로 개인 업무 OS 인터뷰를 진행해 청사진을 만들고, 거기서 도출한 첫 부품인 "작업 현황판"을 팀이 함께 쓰는 실시간 웹 대시보드로 구현해 배포까지 마쳤습니다. 동시에 진행되는 여러 브랜드 작업의 일정·기획안·피드백을 한 화면에서 확인하고 편집할 수 있고, 모바일에서도 동작합니다.

### 최종 구현 결과물

- **OS 청사진** — 인터뷰 6단계로 만든 개인 업무 OS 문서
- **Work Dashboard** — 팀이 공유하는 웹 대시보드 (Vercel 배포)
  - URL: https://work-dashboard-web.vercel.app/

**핵심 기능**
- 표 보기와 월간 달력 보기 토글
- 라이브 기간과 기획 데드라인을 달력에 가로 바로 표시
- 유형(DA / VID / 기타) 드롭다운
- 브랜드별 색 스트립으로 한눈에 구분
- 담당자별 개별 페이지 (한 작업에 담당자 여러 명이어도 각자 검색 가능)
- 작업자별 고정 색 점
- D-Day 뱃지 (임박도에 따라 색 강도 차등)
- 관리자, 뷰어, 외부 차단 3단계 권한

**기술 스택**: Next.js 16, TypeScript, Tailwind, Supabase, Vercel, Pretendard — 모두 무료 티어.

**권한 모델**: 관리자는 이메일·비밀번호로 로그인 후 작업을 추가·조회·수정·삭제까지 전부 가능, 뷰어는 보기만 가능, 로그인 안 한 사용자는 아예 차단. 데이터베이스(Supabase) 자체에 권한 잠금을 걸어 둬서, 권한 없는 사람은 우회로도 데이터에 닿을 수 없습니다.

**다음 단계**: 회사 슬랙으로 들어온 요청을 자동으로 작업에 반영하는 흐름, 기획전과 담당자 표기 방식 정리.

### 과정 (타임라인별 + 삽질)

**타임라인**
1. **인터뷰** — os-interview 스킬로 6단계 인터뷰를 진행해 청사진 문서를 생성, 첫 부품을 "작업 현황판"으로 결정
2. **MVP 구현** — PRD를 먼저 정리한 뒤 Next.js와 Supabase로 작업 목록, 추가, 편집, 로그인이 끝까지 굴러가는 가장 작은 슬라이스부터 완성
3. **기능 강화** — 유형 드롭다운, 브랜드 필터, 표/달력 토글, 요청일·라이브 종료일 컬럼 추가, 담당자별 개별 화면, 한글 폰트와 인디고 액센트로 디자인 리뉴얼, 한 작업에 담당자 여러 명 입력 처리, 구글 시트 데이터 정규화 후 일괄 임포트, 달력 레인 고정과 색 스트립·점 시각화까지 순서대로 추가

**삽질 포인트**
- 달력 셀 사이 세로 보더가 기간 바를 끊어 "끊긴 칩"처럼 보이던 문제
- 좁은 셀에서 채널만 다른 작업이 같은 작업처럼 보이던 문제
- 인접 셀 사이 바가 위아래로 미끄러지던 레인 정렬 문제
- 두 종 시트의 데이터 구성 차이를 맞춰 매핑 규칙을 정리한 과정

### 공유할만한 인사이트

**처음엔 "할 게 별로 없을 줄" 알았는데, 일을 쪼개 보니까 계속 할 일이 생겼다.**

작업 현황판이라고 하면 단순해 보였는데, 실제로 굴려 보니 단계마다 새로운 일거리가 드러났습니다.
- 인터뷰 단계에선 "내 일이 어떻게 흘러가는지"를 6번이나 쪼개서 답해야 했고
- MVP 단계에선 "가장 작게 굴러가는 한 줄기"가 뭔지 골라내야 했고
- 기능 강화 단계에선 같은 화면을 표/달력으로 나누고, 색 스트립·D-Day 뱃지·레인 정렬까지 시각화 디테일이 줄줄이 따라왔습니다.

처음부터 "완성된 작업 현황판"을 한 번에 만들려고 했으면 어디서부터 손대야 할지 모르고 멈췄을 것 같습니다. 욕심을 줄이고 **가장 작은 슬라이스 → 다음 슬라이스 → 다음 슬라이스** 식으로 잘게 나누니까 한 단계 끝낼 때마다 다음 할 일이 자연스럽게 보였습니다. "작업이 보이지 않는다"는 건 사실 "작업을 충분히 작게 쪼개지 않았다"는 신호에 가깝다고 느꼈습니다.

## 미션 2: 따라해보고 싶은 개인/업무/삶 OS 따라서 만들어보기 - SNS(유튜브 등) 에서 찾아 벤치마킹 해오기

### Summary

한명수 디자이너 인터뷰에서 길어올린 "남의 지식을 자기 언어로 말할 때 비로소 내 세계가 된다(= 레이블링)" 사상을 따라 자기 사전 시스템(Labeling Note)을 만들었습니다. 평일에 본 영감 자료를 AI가 1차 라벨링해 모아두고, 매주 일요일 12시 회고 시간에 내 언어로 다시 명명해서 자기 사전을 한 줄씩 자라게 하는 OS입니다. macOS 자동 알림과 웹 대시보드까지 인터넷 배포를 마쳤습니다.

### 최종 구현 결과물

- **레이블링 노트 시스템** — 한명수 인터뷰 기반 개인 성찰 OS (로컬 폴더 + Claude 스킬 + macOS 알림)
- **Labeling Note 사이트** — 진행 상황과 자기 사전을 시각화하는 웹 대시보드 (Vercel 배포)
  - URL: https://labeling-note-web.vercel.app/

**핵심 기능**
- AI 자동 1차 라벨링 (형태, 한 줄 요약, 키워드 3개)
- 키워드 폭주 방지 (자유 + 동의어 추천, 4주차 또는 자료 100건 도달 시 2계층 전환 검토)
- 매주 일요일 12시 자동 알림 (시스템 배너 + 캘린더 반복 일정 + 30분 후 큰 팝업 안전망)
- 회고 모드 (Claude가 키워드별 묶음과 이름 후보 제안, 본인이 컨펌하고 보태는 방식)
- 자기 사전 색인 (라벨 가나다순, 라벨별 자료 링크)
- 자료 노트 자동 생성 (한 자료당 마크다운 1개)
- 이미지 섬네일 자동 표시 (inbox 폴더 → 사이트 public 자동 동기화)
- 외부에서 받은 원본 자료는 별도 방(material-source)으로 분리
- 단어형 라벨 강제 (문장형 금지)
- 회고 시작 시 마크 파일로 중복 알림 차단

**기술 스택**: Next.js 16, TypeScript, Tailwind 4, macOS launchd, osascript, GitHub, Vercel — 모두 무료 티어.

**시스템 구성**: 로컬 마크다운 폴더와 Claude 스킬을 본인 Mac에서 작동, 매주 일요일 12시 macOS 자동 알림, git push 시 Vercel이 자동으로 사이트 갱신.

**권한 모델**: 사이트는 누구나 읽기 가능, 자료 추가와 라벨링은 본인 Mac에서만 가능 (소스코드 저장소는 비공개).

**다음 단계**: Supabase Storage 기반 클라우드 v2를 이번 주 내 전환해 어디서든 사이트 업로드 폼으로 자료를 던질 수 있게 만들기. 다음 주 외부 원본 자료 방(material-source) 구축. v2 완성 전까지는 핸드폰 사진앱 앨범과 Drive를 임시 보관소로 사용.

**벤치마킹 영상**
- 한명수 — 본질을 찾아가는 방법 (1편): https://youtu.be/OCTi_jO-xOo
- 한명수 — 그룹핑 레퍼런스, 네이밍의 아름다움 (3편): https://youtu.be/R4ee-x2ikx8

### 과정 (타임라인별 + 삽질)

**타임라인**
1. **인터뷰** — 한명수 디자이너 두 영상을 벤치마킹, 1편 대본을 정독해 핵심 인용 추출. 카피라이팅 일과 정확히 같은 동작이라 즉시 1번 부품으로 결정
2. **6단계 의사결정** — 이름과 폴더 → 입력 모양 → AI 1차 라벨 → 회고 방식 → 자기 사전 구조 → 검색 방식 순서로 단계마다 옵션 2~4개 받고 선택
3. **자동 알림 셋업** — launchd로 매주 일요일 12:00 자동 실행, osascript로 시스템 배너와 큰 팝업, 캘린더 ics 파일로 한 주 내내 일정 시각화
4. **Claude 스킬과 운영 매뉴얼 정리** — 카피 업무용 OS와 메모리 파일을 분리해 별도 시스템으로 관리
5. **웹 대시보드 추가** — Next.js로 빈 그릇 사이트 셋업, 마크다운 파서와 동기화 스크립트 작성
6. **GitHub과 Vercel 자동 배포** — git push 한 번으로 Vercel이 자동 빌드해 인터넷 사이트 갱신
7. **이미지 섬네일 기능 추가** — inbox 폴더 이미지를 사이트 public 폴더로 자동 동기화하고 자료 행에 섬네일 표시
8. **첫 자료 라벨링으로 전체 파이프라인 검증** — 카드뉴스 1장을 형태/요약/키워드로 라벨링 → 노트 생성 → push → Vercel 자동 빌드 → 사이트에 섬네일 등장 확인 완료

**삽질 포인트**
- "반대말 트릭"이나 "꽂힌 지점 추측"까지 AI가 자동으로 하도록 설계했다가, "그건 회고 때 내가 직접"으로 잘라낸 뒤에야 한명수 사상의 핵심이 살아남
- 외부에서 받은 원본 자료를 영감 자료와 한 박스에 넣으려다 "본질이 다른 자료"라는 통찰로 폴더부터 분리
- chat에 이미지 던지면 자동 저장될 것이라 가정했지만 chat 첨부는 보기만 가능, 디스크 자동 저장 안 됨. 다음 진화에서 클라우드 기반으로 가야 한다는 통점 발견
- 라벨 예시를 처음엔 "여백이 말한다" 같은 문장형으로 시작했다가, 검색과 재사용이 어렵다는 이유로 "단어형만" 규칙으로 변경
- v1 완성 직후 "회사 컴에서 자료 수집이 안 됨"이 명확해짐. 같은 계정으로 회사 Mac에 Claude Code 설치해도 스킬과 폴더는 각 컴퓨터 로컬이라 자동 동기화 X. "일주일 운영해보고 v2 결정"이라는 원래 가설이 무의미해져서 v2를 이번 주 내 진행으로 우선순위 상향

### 공유할만한 인사이트

**OS 사고는 꼭 "일"에만 적용하지 않아도 된다.**

미션 1에서 카피 업무용 OS(작업 현황판)를 만들고 나니, 같은 사고법이 일과 무관한 영역에도 그대로 옮겨졌습니다. 한명수 디자이너의 "남의 지식을 자기 언어로 말할 때 비로소 내 세계가 된다"는 말은 디자인 강연에서 나온 거지만, 그걸 받아 만든 자기 사전은 결국 **퇴근 후 본 영감 자료를 어떻게 내 안에 쌓을지**에 대한 시스템이었습니다.

이 과정에서 한 번 더 확인한 것도 미션 1과 같았습니다 — 처음부터 "완벽한 자기 사전 OS"를 욕심내려고 하면 막막한데, **이름과 폴더 → 입력 모양 → AI 라벨 → 회고 방식**처럼 6단계로 잘게 쪼개니까 단계마다 결정할 게 명확해졌습니다. 욕심을 작은 단위로 나눠서 일·삶 양쪽에 가벼운 부품으로 흩뿌리는 게, 한 번에 거대한 라이프 OS를 세우는 것보다 훨씬 잘 굴러간다고 느꼈습니다.
