### Summary

`selfishclub/os-interview-skill`을 클론해 Claude Code로 6단계 인터뷰(40분)를 진행. 결과로 **OS 청사진 1장 + Claude 스킬 1개(`brief-bot`)** 가 손에 남음. 인터뷰 도중 이미 만들어둔 데스크탑 캘린더 앱 `think_cd`(Flutter)를 OS의 그릇으로 재배치하면서 첫 부품 형태가 한 번 크게 바뀜.

### 최종 구현 결과물

### 과정 (타임라인별 + 삽질)

**Step 1 · 풍경**
- 답: 그로스링크 마케팅 PM 25% + 클라이언트용 빌드(대시보드·캘린더 앱) 75%
- AI 가설: "마케팅 PM 직함을 단 빌더" — 채택

**Step 2 · 통점**
- 1차 답: "매번 캘린더 들어가는 게 귀찮다"
- AI 가설(R 톤): "이건 표면 통점. 진짜 비용은 (a) 시작 전 결정 / (b) 진행 중 집중력 / (c) 정리·전달 중 어디?" → 한 번 더 파고듦
- 2차 답: 매일 아침 10시 / 구글·노션·네이버 3곳 분산 / 통합 뷰어 + 요약·우선순위 가이드 필요
- 재정의된 진짜 통점: **"일정이 흩어져 있어 '오늘 하루의 형태'가 머릿속에 한 번에 안 그려진다."** (인지 비용 + 하루 시작 의식의 결손)

**Step 3 · 이상향**
- 바탕화면 맨 뒷순위 통합 캘린더 위젯 + "나만의 일정 관리 봇"(우선순위·날씨·작업 가이드·인사이트·슬랙·디스코드 리마인드)
- 오버레이 모드: X (데스크탑 배경 레이어, Rainmeter 결)
- OS 선언문 압축: "일정 체크와 판단만 하고 나머지는 OS" — 본인 표현 그대로 채택

**Step 4 · 부품 매핑 — 게임 체인저 발견**
- AI가 부품 7개 가설 던짐 → 입력원 추가 요청(슬랙·이메일·노션DB·iCal)
- 이 시점에서 **think_cd 폴더 공개** → 이미 입력 어댑터 50% + 위젯 렌더러 90% 완성된 상태 발견
- OS 그림이 "그릇(think_cd) + 두뇌(AI 봇 레이어)"로 재정의됨. 첫 부품 우선순위가 명확해짐.

**Step 5 · 첫 부품 + 형태**
- 첫 부품 = 4번 브리핑 봇 (시간 설정 가능 조건 추가)
- 형태 = A(Claude 스킬) 먼저 → 검증 후 C(think_cd 임베드)로 이식

**Step 6 · 결과물 출력**
- `brief-bot/SKILL.md` + `os-blueprint.md` 두 파일 동시 생성. 스킬은 Claude 재시작 없이 즉시 활성화 확인.

**삽질 / 정정**
- AI가 첫 인사를 이메일 prefix(zoom)으로 부름 → "닉네임은 핑크"로 정정. 이후 사용자 메모리에 박제.
- "캘린더 켜는 게 귀찮다"라는 표면 통점에서 멈췄으면 "통합 위젯 화면" 솔루션으로 갔을 것. R 톤 가설 검증으로 한 번 더 파고들어 "**해석·우선순위 단계가 핵심**"이라는 진짜 통점이 드러남. 이게 brief-bot의 정체성을 결정.

### 공유할만한 인사이트

1. **표면 통점 → 진짜 통점**: "캘린더 켜는 시간 5초"가 비용이 아니라, **"3곳을 머릿속에서 합치는 인지 비용"** 이 진짜 비용. 솔루션의 무게중심을 "통합 화면"에서 **"AI 해석·우선순위"**로 옮긴 결정적 지점. 인터뷰 톤(R, 사고 파트너)이 만든 차이.

2. **이미 만든 것을 OS의 부품으로 재배치하기**: think_cd를 새 프로젝트로 보지 않고 **OS의 그릇**으로 재정의하니 첫 부품 결정이 한 번에 좁혀짐. "새로 뭘 만들지" 보다 "**가진 그릇 위에 무슨 두뇌를 얹을지**"가 빠른 출발점.

3. **OS 선언문이 디자인 원칙을 자동 생성한다**: "체크와 판단만 사람이" → 즉시 두 원칙이 떨어짐. (a) AI가 대신 결정해 통보 X, 정리해두면 사람이 보고 결정. (b) 우선순위는 TOP 3 강제 — 4개 이상은 사람이 다시 정렬해야 하니 OS의 자기 부정. brief-bot의 Harness rules에 그대로 박혀 있음.

4. **A → C 단계적 이식 전략**: 첫 부품을 무거운 형태(데스크탑 앱 코드 수정)로 시작하지 않고, **Claude 스킬로 프롬프트만 검증 → 안정화되면 그 프롬프트를 앱 안 API 콜로 이식.** 매일 1분 사이클로 다듬을 수 있음. think_cd 빌드·실행 비용 0.

5. **Q 톤 발판의 위력**: Step 5의 "X 한 글자 선택지" 식 발판은 결정 피로를 크게 낮춤. 인터뷰 시간 압축의 핵심.

### 다음 부품 후보 (다음 인터뷰)

2. **슬랙/디스코드 리마인드 발사기** — 미팅 놓침 방지 = 빌드 흐름 보호
3. **우선순위 엔진의 think_cd 임베드** — brief-bot 프롬프트를 Flutter 앱 내부 자동 호출로 이식
