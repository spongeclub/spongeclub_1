# 1주차 과제 — 키니

## 미션 1: claude code 로 인터뷰스킬 사용해서 인터뷰 까지 진행

### Summary

 로셀피쉬크루에서 만든 `os-interview` 스킬을 클로드 코드에 설치하고 5 Step 인터뷰를 마쳐, **나만의 OS 청사진 + 첫 부품(스킬) 1개**를 손에 쥐었다. 첫 부품은 라이브 댓글을 시간별·카테고리로 자동 분류하고 다음 액션 후보까지 뽑아주는 `live-comment-os` 스킬.

### 최종 구현 결과물

#### 1. OS 청사진

**OS 선언문**:
> 나는 라이브·컨텐츠가 흘러가는 방향과 고객 경험의 흐름을 설계하는 일만 하고, 나머지는 시스템이 한다.

| 항목 | 내용 |
|------|------|
| **풍경** | 셀피쉬클럽 CX 담당. 라이브 댓글·DM 모니터링 + 댓글 해석 + 1:1 응대에 시간 다 빨려 들어감 |
| **통점** | 라이브 7명 동시 진행 → 댓글 손으로 노션 캡쳐·아카이빙. 모니터링 누락 없으려면 자리 못 뜸. 연결 끊기면 댓글 휘발. 노이즈·중복 많음 |
| **이상향** | 시간별 댓글 분류·반응도 비교·다음 콘텐츠/워크샵 주제 후보가 자동 정리되어 손에 잡힘 |
| **첫 부품** | `live-comment-os` (Claude 스킬, A형) |

#### 2. 첫 부품 — `live-comment-os` 스킬

설치 위치: `~/.claude/skills/live-comment-os/SKILL.md`

5단계 인터뷰형 스킬:

1. **수집** — 댓글 raw 덩어리 받기
2. **맥락** — 라이브 시간/주제 파악, 시간대 끊기
3. **분류** (자동) — 시간대 × 카테고리(불만/긍정/발전/질문) 매트릭스
4. **시그널** — 핫 시그널 Top 3 추출 + 직관 검증
5. **액션** — 다음 콘텐츠/워크샵 후보 3개 제안

트리거 키워드: `라이브 댓글 정리`, `라이브 끝났어`, `댓글 카테고리화`, `라이브 회고`, `댓글 분류해줘`

### 과정 (타임라인별 + 삽질)

#### 0. 스킬 설치

```bash
git clone https://github.com/selfishclub/os-interview-skill.git
cd os-interview-skill
mkdir -p ~/.claude/skills/os-interview
cp SKILL.md ~/.claude/skills/os-interview/
cp -r templates ~/.claude/skills/os-interview/
```

> **삽질 1**: 처음에 명령어를 그냥 채팅창에 붙여넣었는데 실행이 안 됨. 클로드 코드에서는 **`!` 프리픽스**를 붙여야 셸 명령어로 실행된다는 걸 알게 됨.

#### 1. Step 1 · 풍경

CX 업무 + 국악 공연 기획 두 트랙 굴리는 중. 시간 가장 많이 쓰는 활동 3개를 바로 못 짚었지만, 발판으로 **(a) 댓글·DM 모니터링 / (c) 댓글 해석·정리 / (d) 1:1 응대**를 골랐다. → "들어오는 신호를 사람 머리로 받아내는 라인"으로 좁혀짐.

#### 2. Step 2 · 통점

장면: 멤버 7명 라이브 동안 댓글을 노션에 캡쳐해서 아카이빙. 누락 없으려면 자리 못 뜸. 연결 한 번 끊기면 그 사이 댓글 + 이전 것까지 휘발. "이런 것도 질문?" 류 노이즈, 같은 질문 중복 다수.

비용 분류: **(b) 진행 중 집중력 + (c) 끝난 뒤 정리** 양쪽으로 묶임.

```
[수집]                [분류]                [답변]
라이브 7명 동시        "이런 것도 질문?"      같은 질문에
↓ 캡쳐+노션 수동       노이즈 가려내기         같은 답 반복
↓ 한번 끊기면 휘발     같은 내용 중복
```

#### 3. Step 3 · 이상향 ⭐

90% 자동화된 그림: 시간별 댓글이 불만/긍정/발전/질문으로 분류되어 있고, 반응도가 저번 대비 비교되며, 다음 컨텐츠·워크샵 기획에 어떤 주제가 비어있는지 보임.

→ **OS 선언문 도출**: "나는 라이브·컨텐츠가 흘러가는 방향과 고객 경험의 흐름을 설계하는 일만 하고, 나머지는 시스템이 한다."

#### 4. Step 4 · 부품 매핑

부품 6개 후보 + 미래 부품(대시보드) 분류.

> **삽질 2**: "컨텐츠 대시보드도 부품 아닐까?"라고 던졌는데 AI가 **"대시보드는 별도 부품이 아니라 1~6번의 출력이 모이는 화면(=출력 레이어)"**이라고 반박. 첫 부품으로 만들면 빈 화면이 뜬다는 논리에 설득됨. → 대시보드는 미래 부품으로 보류.

> **삽질 3**: "시스템이 0%인 묶음"이라는 표현을 못 알아들음. AI가 "지금 그 일을 순전히 사람 손/머리/눈으로만 하는 묶음"으로 다시 풀어줘서 이해. → 결론: **(a) 입력 처리**가 가장 비어있음.

#### 5. Step 5 · 첫 부품 + 형태

- **부품**: 부품 1 (분류) vs 부품 2 (백업) → **부품 1 선택**. 백업은 라이브 플랫폼 API 필요해서 1주차에 무거움. 분류는 댓글 덩어리만 있으면 즉시 작동.
- **형태**: **A. Claude 스킬**. 글/문서 정리 작업이라 가장 가벼움. 인터뷰 끝과 동시에 사용 시작 가능.

#### 6. Step 6 · 결과물 작성

`~/.claude/skills/live-comment-os/SKILL.md` 작성 — 5단계 인터뷰 흐름 + 4가지 harness rule + 1페이지 출력 템플릿 정의.

### 공유할만한 인사이트

1. **CX는 "응대"가 아니라 "흐름 설계"다.** Step 3에서 OS 선언문을 만들며 본질이 바뀜. "고객 응대를 잘하는 사람"이 아니라 **"고객 신호의 의미를 읽고 다음 액션을 정하는 사람"**으로 직무를 다시 정의했다.

2. **댓글 = 카운트가 아닌 신호.** 좋아요·조회수·댓글 수에 매몰되면 의미가 휘발됨. 댓글은 **다음 콘텐츠를 만들 근거**가 되어야 한다.

3. **첫 부품은 가장 아픈 게 아니라 "데이터만 있으면 도는 가벼운 것"이다.** 통점은 백업(부품 2) 쪽이 더 컸지만, 외부 API 의존이라 1주차에 못 끝냄. 분류(부품 1)는 즉시 사용 가능 → **"이번 주에 손에 쥘 수 있는가"**가 첫 부품의 진짜 기준.

4. **대시보드는 부품이 아니라 출력 레이어다.** 처음엔 "한 화면에 다 보고 싶다"는 직관으로 부품 후보로 던졌지만, AI가 "1~6 결과가 모이는 자리지 일하는 손이 아니다"라고 반박. 데이터를 **만드는 일**과 **보여주는 일**을 구분하는 사고가 늘었다.

5. **`!` 프리픽스 = 클로드 코드 셸 실행.** 작은 거지만 처음 만나는 사람은 다 헷갈리는 포인트. (이걸 모르면 명령어가 그냥 채팅 메시지로 처리됨)
