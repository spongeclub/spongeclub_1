# 나병우의 OS 청사진

**작성일**: 2026-05-10
**OS 선언문**: 나는 **상품 발굴과 기획·영업 판단**만 하고, 나머지는 시스템이 한다.

---

## 1. 풍경 (지금)

- 30년 경력 1인 이커머스 운영자 (소굿마켓 대표)
- 8개 브랜드 운영 (화장품 6: 리얼랩·라라레서피·아르밍·흑삼수·호피걸·트루아일랜드 / 식품 2: 우리원·홀리닭) + 4개 CMO 역할(아르밍·조이코스·현농 + 본인)
- 시간 가장 많이 쓰는 활동 3가지: **컨텐츠 제작 / 기획·영업 / 멀티채널 운영**
- 상품 발굴 → 기획 → 컨텐츠 → 마케팅 → 유통 → 분석까지 A to Z 단독 수행

---

## 2. 통점 (반복 비용)

- **본인이 가장 못하는 영역인 컨텐츠 제작이 매일 필요** — 1인 운영의 한계가 가장 첨예하게 드러나는 지점
- 통점의 핵심 = **(a) 시작 전 결정 비용**: "무엇을 만들지"에서 자주 막힘
- 1차 시도(LLM Wiki 초기 세팅) 교훈:
  - 업무 범위가 너무 광범위 → 컨텐츠 제작 OS로 좁힘
  - OS 부품과 LLM Wiki의 연결 고리 부재 → OS 스킬이 LLM Wiki를 DB로 활용하는 구조로 전환

---

## 3. 이상향 (이게 풀리면)

> "프롬프트 한 줄로 — 내 데이터베이스가 맥락이 되어 — 콘텐츠 기획·제작을 빠르고 다양하게 실행할 수 있는 시스템."

**복리 구조**: 기록 → AI 맥락 DB → 콘텐츠 품질 향상 → 실행력 증가 → 프로젝트 수주 증가

**플랫폼**: 옵시디언 LLM Wiki + Claude Code

## 4. 부품 후보 (도달 경로)

5종 에이전트 (MECE 정렬, 7단계 컨텐츠 제작 프로세스 커버):

- [ ] **기획자 (Planner)** — 위키 + 트렌드 + 분석 → 주제·앵글·캘린더 *(결정 보조)*
- [ ] **큐레이터 (Curator)** — raw → wiki (ingest·lint·query) *(입력 처리, 현재 메인 세션이 부분 수행)*
- [x] **작가 (Writer)** ← **첫 부품 (이번에 만들 것)** — 위키 + 기획 → 카피·대본·비주얼 프롬프트 *(출력 생성·텍스트)*
- [ ] **비주얼 (Visual)** — 작가 프롬프트 → 이미지·영상·합성물 (Gemini·Higgsfield·리모션·FFmpeg) *(출력 생성·비주얼)*
- [ ] **분석가 (Analyst)** — 채널 데이터 + 결과물 → 인사이트 → 기획자에게 피드 *(복리 구조 핵심 고리)*

> 총괄은 별도 부품으로 만들지 않음. Claude Code 메인 세션이 흡수.

## 5. 첫 부품

- **이름**: `sogood-writer`
- **형태**: A · Claude 스킬 (`SKILL.md`)
- **결과물 파일**: [`skills/sogood-writer/SKILL.md`](skills/sogood-writer/SKILL.md)

### 선택 근거
| 기준 | 평가 |
|------|------|
| 자급자족 (의존성 0) | ✅ 위키 ready (아르밍 14개 페이지) |
| "일주일 시간 환원" 임팩트 | 🔥 매일 반복되는 컨텐츠 제작 영역 |
| 형태 적합성 | A 자연스러움 (글 생성 = 인터뷰·정리·생성) |

### 4단계 인터뷰 (요약)
1. **명세** — 브랜드·제품·채널·유형·앵글 한 번에 받기
2. **자료 픽업** — 위키에서 강조점 후보 3~5개 끌어와 사용자가 1~2개 선택
3. **출력** — 채널·유형 사양 맞춰 카피·대본·비주얼 프롬프트 1차안
4. **변형** (선택) — 톤·앵글 축으로 변형 1~2안
