### 과정 (타임라인별 + 삽질)
**Phase 0: 일단 인터뷰. 
- 인터뷰만... 3시간 한것같음. 하고 싶은것도 관심있는것도 많아서 클로드한테 엄청 말했더니 뼈때림.
- 클로드왈, 이 분은 **많은 것을 동시에 흡수하고 탐구하는 사람**인데, 그 탐구들이 아직 서로 연결되지 않고 각자 따로 놀고 있는 상태인 것 같다. 업무의 트렌드 서칭, 인스타툰, 사업, 주식, 재테크, 차 — 다 진심인데, 이게 하나의 그림으로 모이는 순간이 아직 안 온 느낌."...^^....

**Phase 1: 문제 정의 - "루틴에 나를 맞추는 게 아니라, 나에게 루틴을 맞춘다면?"**
- 기존의 운동/식단 앱(다노언니, 삼성건강앱 등)들이 가진 '고정된 루틴'의 한계를 분석.
- 1주치의 몸이 항상 똑같을수가 있을까? 그냥 그날마다 다르게 지정하면 되면 되는거 아닌가?
- 몸이 천근만근인 날에도 똑같은 운동, 똑같은 식단을 하라고 하는 불편함을 해결하고 싶었음.

**Phase 2: 핵심 질문과 필터링 - "무엇을 묻고, 무엇을 뺄 것인가?"**
- **필수 항목**: 컨디션에 큰 영향을 주는 생리 주기, 스트레스 지수, 에너지 레벨, 구체적인 통증부위.
- 아무래도 나의 체력과 몸상태를 체크하는 앱이다 보니, 몸의 구체적인 요소는 물어야한다고 생각.
- 다만 극한의 식사나 운동 지양.

**Phase 3: UX/UI 구체화 - "슬라이더 방식의 간편한 체크인"**
- 챗봇과의 긴 대화보다는 아침에 눈 뜨자마자 슬라이더(1~10)를 슥슥 움직여 30초 만에 입력을 끝내는 직관적인 UX를 설계함.
- 피곤하다고 체크하면 무리한 운동 대신 '릴렉스 방법'을 먼저 제안하는 유연함 확보.

**Phase 4: 확장성 고려**
- 처음엔 Claude 스킬로 시작하려 했으나, 모바일 접근성과 추후 배포 가능성을 고려해 **독립 앱(C안)** 형태로 PRD 작성 완료.

### 과정 (타임라인별 + 삽질)
일단.............. 3D 단상자 구현이 어려울것같아서 (꼬박 하루를 투자했는데 안나와요...하핫)
가장 손이 가는 아웃박스(출고박스) 사이즈 측정 및 적합성 프로그램을 만들어봤습니다..
### **1️⃣ 초기 요구사항 정의 (1차)**
**목표**: 단상자가 아웃박스에 적절히 들어가는지 검증하는 계산기 개발
**주요 기능**:
- 단상자 규격 입력 (W/D/H)
- 배치 정보 입력 (가로×세로 개수)
- 아웃박스 규격 입력 (W/D/H)
- 적합성 판정 (✓/✗)
- 상세 검증 테이블 표시
### **2️⃣ 보강패드 기능 추가 (2차)**
**새로운 요구사항**: 보강패드 크기에 따른 유효 공간 계산
**추가된 기능**:
- 보강패드 유무 체크박스
- 보강패드 사이즈 입력 (길이 1 × 길이 2)
- **양방향 회전 검증** ← 중요!
    - 방향 1: 길이1 × 길이2
    - 방향 2: 길이2 × 길이1 (회전)
    - 둘 중 하나라도 들어가면 ✓ OK

### **3️⃣ 2D 평면도 시각화 추가 (3차)**
**새로운 요구사항**: 단상자가 아웃박스에 어떻게 배치되는지 시각화
**추가된 기능**:
- Canvas 기반 2D 평면도 (상단 시각화)
- 아웃박스 테두리 표시
- 보강패드 영역 표시 (빨간색)
- 단상자 배치 그리드 (초록색)

**중요한 개선**:
- 보강패드와 단상자가 겹치지 않도록 로직 수정
- 보강패드 사이즈를 실제 크기 비율로 표시
- 단상자가 패드 옆에 딱 붙도록 배치
**결과**: 시각적으로 명확한 패킹 상황 파악 가능

### **4️⃣ 3D 시뮬레이터 추가 시도 (4차) ← 🔥 삽질 구간**
**새로운 요구사항**: 3D로 단상자와 아웃박스를 함께 표시
**시도한 방법들**:
1. **CSS 3D Transform** 방식
    - 6개 면을 개별 div로 생성
    - 아웃박스와 단상자 모두 DOM 요소로 표현
    - 문제: 너무 많은 DOM 요소 생성 (4×10×1 = 40개 단상자)
    - 결과: 렌더링 성능 저하, 드래그 반응성 떨어짐
2. **Canvas 3D 렌더링** 방식
    - Point3D 클래스로 3D 좌표 관리
    - 회전 행렬(Rotation Matrix) 적용
    - 깊이 정렬(Depth Sorting) 구현
    - 문제: Canvas 초기화 및 렌더링 타이밍 이슈
    - 결과: 캔버스가 아예 렌더링되지 않음
