### 과정 (타임라인별 + 삽질)

**1. 하네스 95% 세팅** (영상 그대로)
- 폴더 만들고 미션 1 PRD를 `context/` 로 복사
- `CLAUDE.md` 작성 — SOP·차단 회피 6대 룰·의사결정 기준
- `.env`·`.gitignore` (보안)
- 시간: 30분 / 코드: 0줄 (다 마크다운)

**2. API 우선 조사** (PRD §8)
- Qoo10 QAPI 문서 분석 → 키워드 입찰 데이터 API 없음 확인
- 결정: Playwright 스크래핑이 유일한 길

**3. POC 구현 — 13키워드 자동 수집**
- 너가 직접 페이지 5장 캡처 → AI가 셀렉터 추출 → 정식 코드
- 1세션 내에 `美容液` 검색해서 16건 낙찰가까지 정확히 추출 성공

**4. 카테고리별 입찰 확장**
- Deal Plus + Category Plus 대분류/중분류 모두 자동 순회
- bid_type discriminator 패턴으로 4종 통합 저장

**5. 대시보드 (Streamlit)**
- 538키워드 풀에서 그룹별·체크박스 선택 → `last_selection.json` 자동 저장
- 14가지 인사이트 + 트렌드 차트 + 운영 편의 4종

#### 삽질 5개 (진짜 삽질은 코드보다 환경이었음)

1. **Windows SxS 깨짐** — Playwright 번들 Chromium·Firefox 둘 다 실행 안 됨 ("side-by-side configuration is incorrect"). Edge 시도 → reCAPTCHA 차단. 결국 시스템 Chrome 을 subprocess 로 직접 띄우는 우회로.
2. **reCAPTCHA 차단** — Playwright launch 흔적 감지로 Google 이 reCAPTCHA 안 줌. 사람이 직접 통과 후 세션 재사용 방식으로 전환.
3. **세션 쿠키 휘발** — Qoo10 ASP.NET 세션 쿠키가 브라우저 닫는 순간 사라짐 → CDP 로 라이브 추출해서 storage_state 저장하는 방식 발견.
4. **셀러 ID/PW 채팅 노출** — 보안 사고. 즉시 비번 변경 안내 + `.env` 로직.
5. **UI 반복** — 라디오→버튼, 핑크→블루, expander 30개 동시 렌더 느림→lazy 1개씩 등 **내가 실제로 써보면서 발견하고 즉석에서 고친** 게 더 많았음.
