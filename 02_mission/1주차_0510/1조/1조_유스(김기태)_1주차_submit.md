# 1주차 과제 — 유스

## 미션 1: claude code 로 인터뷰스킬 사용해서 인터뷰 까지 진행

### Summary

셀피쉬클럽의 [OS Interview Skill](https://github.com/selfishclub/os-interview-skill)을 설치하고 약 50분 인터뷰를 1회 돌렸다. 끝나면서 **OS 청사진 1장 + 첫 부품 1개(`morning-commute` Claude 스킬)** 가 손에 남았다. "출근길 게임/유튜브"가 의지 문제가 아니라 **디폴트 설계 문제**임을 인터뷰 도중 발견하고, 그 디폴트를 "오늘 영상 1개 추천받는 시간"으로 바꾸는 도구를 만들어 테스트 발동까지 통과.

### 최종 구현 결과물

- **OS 청사진**: `~/Documents/os-blueprint.md` — 선언문 + 풍경/통점/이상향/부품 후보 17개
- **첫 부품**: `~/.claude/skills/morning-commute/SKILL.md` — 출근길에 "출근길 영상 추천해줘" 던지면 4단계 인터뷰(컨디션·시간 → 이번 달 방향 → 오늘 결 → 영상 1개) 후 추천 카드 출력. **시리즈 영상이면 단편/시리즈 선택 + 진행 편 확인** 로직 포함.
- **OS 선언문**: _"나는 ① 행위 목록을 정해두고 ② 이번 달 방향만 정한다. 시간대가 오면 그중 하나가 자동으로 시작되도록 시스템이 굴린다."_

### 과정 (타임라인 + 삽질)

1. **설치 (3분)** — GitHub clone → `~/.claude/skills/os-interview/`
2. **풍경(Step 1) — 첫 정정**: Claude가 "유튜브/잡담/검색"을 일에서의 빈 시간으로 잘못 해석 → 본인이 "그건 삶 영역"이라고 정정해줘서 다시 잡음
3. **통점(Step 2)**: ① 덴탈 지식 부재(구조적, 첫 부품 X) ② **의도-행동 갭(중심)**. Claude가 "디폴트 설계 부재"라는 어려운 용어로 설명 → 본인 "무슨 말인지 모르겠다" → 풀어서 재설명 후 합의
4. **이상향(Step 3)**: 한 문장 압축이 막혀서 후보 3개 받고 (가)+(다) 합쳐서 선언문 완성
5. **부품(Step 4)**: 17개 도출. 본인이 "유혹 차단 안 함(게임 좋아함)" + "월초 자산관리 큐레이션 추가" 결정
6. **첫 부품(Step 5~6)**: 출근길 영상 추천 / A 스킬 형태. 5개 항목 초안 + **본인이 시리즈 처리 로직 추가 요청**
7. **테스트 발동**: 4단계 다 굴러감 확인. **삽질**: YouTube 검색 결과의 영상 길이를 정확히 잡지 못해서 50분 통근에 매칭이 약함 → SKILL.md v0.2 1순위로 메모

### 공유할만한 인사이트

1. **"의지"가 아니라 "디폴트"** — 게임/유튜브가 디폴트로 깔린 환경에서 공부를 의지로 매번 거슬러야 한다면 진다. 게임 좋아하는 사람한테 차단은 자기부정이라 안 통하고, 디폴트 변경 / 인터럽트 + 선택지 제시가 본인 결과 맞으면 그것만으로 OS를 짜야 지속된다.
2. **Claude를 "사고 파트너"로 쓰면 답이 깊어진다** — 단순 Q&A가 아니라 "이거 사실 _의 다른 표현 아닌가요?" 가설 검증 톤. 빈칸 채우기 막힐 땐 후보 3개 받고 합치기가 효율적.
3. **첫 부품 = "매일 발동 + 통점 직격"인 작은 1개** — 17개 후보 중 가장 큰 부품이 아니라 가장 자주 굴러가는 부품이어야 OS 감각이 빠르게 잡힌다. 작게 시작하고 다듬는다.
4. **SKILL.md는 살아있는 v0.1 문서** — 완벽 추구 X, 1주 써본 뒤 어색한 한 줄 수정 = v0.2. 본인 케이스에선 "영상 길이 매칭" 강화가 1순위.
5. **본인 결을 SKILL.md에 박기** — 표준 템플릿엔 없던 "시리즈 vs 단편 선택"을 본인이 인터뷰 도중 추가. 완성된 스킬은 템플릿 결과물이 아니라 본인 결을 담은 한 사람의 도구가 됐다 — 이게 OS의 OS 됨.
6. **셀피쉬클럽 OS Interview Skill의 강점 한 줄** — "인터뷰 끝 = 사용 시작"이라는 약속을 진짜 지킨다. 청사진만 그려주는 도구가 아니다.

## 미션 2: 따라해보고 싶은 개인/업무/삶 OS 따라서 만들어보기 - SNS(유튜브 등) 에서 찾아 벤치마킹 해오기

## Summary
유튜버 Lazy Glow의 "직장인 갓생 모닝/수면 루틴 자동화" 영상을 벤치마킹.
이 사람의 한 줄 선언문은 "자동화 앱으로 루틴을 모두 설정해두고, 
유혹은 시스템으로 차단한다." 본인 OS의 "시간대가 오면 자동으로 
시작된다"는 철학과 닮아있어 흡수할 부분이 많았지만, 본인 결은 
차단형이 아니라 인터럽트형이라 그 부분은 변형해서 가져옴. 영상에서 
영감 받아 OS 청사진에 신규 부품 후보 2개를 추가.

- **핵심 비결**: 시간을 정해두고 그 시간을 지키는 것을 최우선. 
  의지력·기억력에 의존하지 않고 삼성 모드 / 루틴앱 / 구글 홈 자동화에 위임.

  일기 → 핸드폰 흑백·SNS 차단 → 종이책 → 10:30 조명 OFF

| 가져올 것 | 그대로? 변형? | 어떻게 |
|-----------|--------------|---------|

## 과정 (타임라인 + 삽질)

1. **영상 선정** — "갓생 자동화 루틴" 키워드로 탐색. 도구는 다르지만 
   (앱 vs Claude 스킬) 본인 OS와 가장 닮은 영상으로 Lazy Glow 선택.

2. **영상 시청 + 메모** — 한 줄 선언문 / 부품 리스트 / 핵심 비결 / 매칭 포인트 4가지 챙김.

3. **매칭 분석 — ⚠️ 삽질 구간**
   처음엔 "다 따라하면 되겠다"고 생각 → 차단형 부분에서 막힘. 본인은 OS 인터뷰에서 
   "차단 안 함, 인터럽트형"으로 결을 잡았던 게 떠올랐고, SNS 차단·흑백 모드를 그대로 
   가져오면 자기부정이 된다는 걸 인지. 
   교훈: **벤치마킹은 그대로 따라하는 게 아니라 본인 결로 번역하는 작업**.

4. **흡수/변형/신규 분류** — 위 표 작성. 신규 부품 후보 2개 도출.

5. **OS 청사진 업데이트** — 부품 후보 19개로 확장.

## 공유할만한 인사이트

1. **다른 도구, 같은 원리** — Lazy Glow는 안드로이드 자동화 앱, 본인은 Claude 스킬.
도구는 정반대처럼 보이지만 "시간대가 오면 시스템이 다음 행동을 트리거한다"는 
원리는 똑같다. 도구가 멋져 보여서 따라하는 게 아니라, 원리가 같으면 도구는 
본인 손에 가장 잘 맞는 걸로 골라 쓰면 된다.

2. **벤치마킹 = 본인 결로 번역하는 작업** — 좋아 보이는 부품도 본인 결과 안 맞으면 
안 가져와야 한다. Lazy Glow의 SNS 차단·흑백 모드는 강력하지만 본인한테 적용하면 
자기부정이 된다. 좋은 벤치마킹은 "이거 따라했어요"가 아니라 **"이건 가져왔고, 
이건 안 가져왔고, 그 이유는 ___"** 로 채워진다.

3. **수면이 모닝 OS의 전제다** — 그동안 모닝 부품(출근길 영상 추천)에만 집중했는데, 
영상에서 "수면이 무너지면 다음날 시간 확보 자체가 무너진다"는 점이 강조됨. 
모닝 OS만으로는 부족하고 **나이트 OS와 짝**이 되어야 굴러간다. 다음 부품 
우선순위에 나이트 영역을 올릴 근거.

4. **좋은 벤치마킹은 본인 OS의 빈자리를 보여주는 거울** — 단순 따라하기를 넘어, 
영상에서 영감 받아 신규 부품 후보 2개(복장 추천 + 성취 회고)를 청사진에 추가. 
혼자 만들 때는 안 보이던 빈자리가 다른 사람 OS를 거쳐서 보였다.
