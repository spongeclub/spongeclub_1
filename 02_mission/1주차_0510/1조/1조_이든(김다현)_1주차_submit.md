# 1주차 과제 — 이든

## 미션 1: claude code 로 인터뷰스킬 사용해서 인터뷰 까지 진행

### Summary
AI 리서처 과정 + 패션 플랫폼 사업 준비를 동시에 돌리는 30대. 매주 서울/충청/부산을 오가며 혼자 생활하는 상황에서 ADHD 약을 제때 챙기는 게 가장 큰 통점이었다. 약을 빠뜨리면 감정 기복이 2배가 되고, 기쁜 일도 슬픈 일도 전부 극단으로 흘러간다. 인터뷰를 통해 "약 복용 기록 + 의사선생님 공유"라는 첫 부품을 잡았다.

### 최종 구현 결과물
ADHD 약 복용 기록 웹앱 — [adhd-taking-record.vercel.app](https://adhd-taking-record.vercel.app)

```
기능 구성
├── 약 기록 탭  : 먹었어 / 늦게 먹었어 / 까먹었어 + 복용 시각 + 수면 기록 + 효과/부작용 태그 + 메모
├── 지금 느낌 탭: 즉흥 감정·증상 즉시 기록 (Cmd+Enter 저장)
└── 가져오기 탭 : 데이터 백업·복원 (의사선생님 공유용)
```

React + Vite, Vercel 배포 완료. GitHub: [edengroworks/ADHD-Taking-record](https://github.com/edengroworks/ADHD-Taking-record)

### 과정 (타임라인별 + 삽질)
1. **인터뷰 Phase 1** — 하루 루틴 탐색 → 오전 10시~6시 AI 리서처 과정, 퇴근 후 스폰지클럽 + 사업 준비
2. **통점 발견** — "약을 제때 못 먹는다"가 가장 먼저 나옴. ADHD 7가지 특성(건망증, 충동성, 완벽주의, 정리 어려움 등) 중 복용 실패가 하루 전체를 바꾼다는 걸 언어화
3. **이상향 정의** — "시간이 나를 따라오는 삶" + 한 말을 지키는 사람
4. **첫 부품 결정** — 알림 + 복용 기록 + 의사선생님 공유 → 웹앱으로 구현

**삽질:**
- 알림 기능 없음 → 앱을 만들었는데 정작 약 먹으라는 푸시가 없어서 까먹는 문제가 해결이 안 됨
- 모바일 설치 불가 → 노트북을 열어야만 기록 가능, 기록 문턱이 높음
- 기능 과잉 고민 → 주의가 산만한 ADHD 특성상 화면이 복잡하면 오히려 안 쓰게 됨. "구글 메인처럼 검색창 하나" 수준으로 단순해져야 하나 고민 중

### 공유할만한 인사이트

**1. 통점은 "불편하다"가 아니라 "그날이 망가진다"는 수준이어야 한다**
약 복용 문제는 단순한 불편함이 아니라 하루 감정 전체가 흔들리는 문제였다. 부품을 고를 때 임팩트 크기를 기준으로 삼아야 한다는 걸 인터뷰하면서 자연스럽게 알게 됐다.

**2. 만든 것과 해결한 것은 다를 수 있다**
앱을 배포까지 했는데 정작 핵심 문제(알림, 모바일 접근성)는 아직 미해결이다. "구현 완료"와 "문제 해결"은 다른 것. 다음 부품은 PWA 전환 또는 알림 시스템이다.

**3. 사용자 인터뷰는 나 자신에게도 유효하다**
내가 나를 인터뷰했는데, 말로 꺼내기 전까지 몰랐던 것들이 나왔다. "시간이 나를 따라오는 삶"이라는 표현도 질문을 받고서야 나온 말이다.

## 미션 2: 따라해보고 싶은 개인/업무/삶 OS 따라서 만들어보기 - SNS(유튜브 등) 에서 찾아 벤치마킹 해오기

### Summary
3조 흐민의 개인 AI 비서 "오민이"를 벤치마킹. 단순 챗봇이 아니라 일정·태스크·회고까지 이어지는 개인 운영체제를 만든 케이스에서 영감을 받아, 나만의 AI 비서 OS 방향을 처음으로 정의했다.

### 최종 구현 결과물
아이디어 단계 — 이든의 AI 비서 OS 청사진:

```
우선순위
1. 약 복용 알림 + 기록 (매일 저녁, 사라지지 않는 푸시)
2. 일정/태스크 관리
3. 루틴 습관 형성
4. 회고록 의무화
```

### 과정 (타임라인별 + 삽질)
1. 흐민의 "오민이" 케이스를 보면서 — 일정이 바뀔 때마다 재배치해주는 AI, Linear + Obsidian 연결 구조가 인상적이었다
2. "나한테 가장 필요한 게 뭐지?" 생각해보니 일정 관리보다 **약 복용**이 먼저였다. 약을 빠뜨리면 하루 감정이 무너지니까
3. 그 다음이 일정, 루틴, 회고 순서로 자연스럽게 정렬됐다
4. 흐민과 다른 점: 흐민은 생산성 중심, 이든은 **건강/컨디션 관리가 베이스**가 되어야 그 위에 생산성이 올라간다

### 공유할만한 인사이트
- 벤치마킹은 똑같이 따라하는 게 아니라 "저 사람과 나의 차이"를 찾는 과정이다. 흐민은 생산성이 먼저, 나는 컨디션이 먼저.
- OS의 우선순위는 결국 내 통점 순서다. 가장 아픈 곳부터 고쳐야 나머지가 의미 있어진다.
