# 1주차 과제 — 비비안

## 미션 1: claude code 로 인터뷰스킬 사용해서 인터뷰 까지 진행

### Summary
`os-interview-skill` 로 40분 인터뷰 → **OS 청사진 1장 + 첫 부품 PRD 1장**. 모호하던 "운영 프로덕트 고도화 방향"이 _"쉘 위에 얹는 달성형 배지 시스템 (기존 코드 안 건드림)"_ 으로 또렷해짐.
### 최종 구현 결과물
Spongeclub_obsidian/selfish-sponges-os/
├── os-blueprint.md
└── selfish-sponges-achievements.prd.md

- **청사진**: "나는 70명을 일일이 보지 않고, 프로덕트가 한 액션의 로그만 본다. 개선 방향만 말한다."
- **PRD**: 쉘(보상형) 위에 얹는 달성형 동기부여 레이어 — 방향성만, MVP 디테일은 Claude Code 단계로 위임
### 과정 (타임라인별 + 삽질)
1. **설치** — 심볼릭 링크로 전역 설치 (`~/.claude/skills/os-interview`)
2. **Phase 1** — 풍경 → 통점 → 이상향 → 부품 매핑
3. **삽질** — 첫 부품 형태로 X(신기능 단독) 선택했다가 즉시 취소하고 **Z(결합형)** 으로 변경. 이유를 말로 풀어보면서 _"기능 추가 → 효과 모름 → 다음 기능 추가" 루프_ 를 본인이 자각함.
4. **결 좁힘** — Z(조별 협력 + 측정)로 가다가 PRD 작성 직전에 _개인 달성 배지_ 로 한 번 더 좁힘. PRD 범위도 "방향성만"으로 압축.
5. **PRD 출력** — Next.js + Supabase, 기존 코드 안 건드림 제약 박음, 다음 단계는 Claude Code에서 상세 기획.

### 공유할만한 인사이트

### 1. 내 정체성은 _케어러가 아니라 시스템 디자이너_

처음엔 "B(멤버 케어)가 가장 재미있다"고 답했는데, 이상향 문장을 채울 때 자연스럽게 _메타 레벨_로 올라감 — "한 명 한 명 챙기기"가 아니라 "메커니즘이 사람을 어떻게 움직이는지 보기". 두 정체성은 부품 설계가 완전히 다름. 이걸 먼저 정해야 부품이 단단해짐.


### 2. PRD에 _의도적 공백_ 을 둘 수 있다

"여기까지만 PRD" 라는 본인 직감이 옳았음. PRD를 두 종류로 분리:

- **방향성 PRD** (왜·누구·제약) — 사람이 결정
- **구현 PRD** (어떤 배지·언제·어떻게) — Claude Code와 같이 세움

길이가 곧 디테일이 아님. 빈칸이 다음 단계의 입구가 됨.

## 미션 2: 따라해보고 싶은 개인/업무/삶 OS 따라서 만들어보기 - SNS(유튜브 등) 에서 찾아 벤치마킹 해오기

### Summary
  커뮤니티 멤버들이 활동하면서 느끼는 성취감을 눈에 보이게 만들어주고싶었다. 셸(포인트)과는 별개로, "당신이 이걸 해냈다"는 걸 알려주는 배지 시스템을 하루 만에 기획부터 배포까지 완료했다.

### 최종 구현 결과물
  - **바다** **생물** **캐릭터** **배지** **9종** — 불가사리, 고래, 게, 문어, 돌고래, 조개, 거북이, 해마, 왕관 스폰지
  - 공유회 참여/개최, SNS 인증, 스킬 공유, 셸 보내기/받기 등 **활동하면** **자동으로** **배지** **지급**
  - 어떤 배지가 있는지 **미리** **알** **수** **없음** — 획득해야만 보임 (애플 피트니스 스타일)
  - 배지 획득 순간 **Slack** **채널에** **자동** **알림**
  - 홈에 **배지** **랭킹** **Top** **3** + **실시간** **롤링** **피드** (누가 방금 뭘 획득했는지)
  - 마이페이지에 **내가** **모은** **배지** 컬렉션
  - **기존** **코드를** **하나도** **안** **건드림** — 새 파일, 새 테이블만 추가
![[스크린샷 2026-05-09 오후 1.50.26.png]]
### 과정 (타임라인별 + 삽질)
 1. **기획** — PRD에 방향성만 쓰고, 배지 종류/조건/DB 구조는 Claude에게 옵션을 받아서 골랐다. 라인업을 4번 수정했다 (5종 → 9종 → 이름 변경 → 셸 관련 추가).

  2. **배지** **시스템** **구축** — DB 테이블 2개 + 서비스 로직 + API + UI. 기존 서비스에는 checkAchievements() 한 줄만 추가.

  3. **아이콘** **3번** **갈아엎음** — 이모지 → 도형 SVG → 바다 생물 캐릭터. "캐릭터를 모아가는 느낌이면 좋겠다"는 한 마디가 방향을 잡아줬다.

  4. **기존** **활동** **기반** **일괄** **발급** — 배포 전에 기존 데이터로 배지를 소급 발급. Slack 알림이 79명분 한꺼번에 갈 뻔해서 알림만 스킵.

### 공유할만한 인사이트
**1.** **PRD는** **빈칸이** **있어도** **된다**
  배지 이름, 개수, 조건을 다 정해서 주는 게 아니라 "방향만 쓰고 옵션을 받는" 방식이 훨씬 빨랐다. Claude가 기존 DB를 보고 "이 데이터로 이런 배지가 가능하다"고 제안해줬기 때문에, 실현 불가능한 기획을 하는 실수를 피할 수 있었다.

  **2.** **"기존** **코드** **안** **건드림"이라는** **제약이** **오히려** **좋았다**
  제약이 없었으면 기존 코드를 이리저리 고치다가 기존 기능이 깨졌을 것이다. "새 파일만 추가한다"는 룰 덕에 기존 동작은 100% 보존되면서 새 기능이 깔끔하게 붙었다.
  

  **3.** **백필(소급** **적용)할** **때는** **알림을** **반드시** **분리해야** **한다**

  기존 활동을 기준으로 배지를 일괄 발급하면, 알림도 일괄로 나간다. "발급은 하되 알림은 스킵"하는 옵션을 처음부터 만들어둔 게 다행이었다. 이후 실시간 활동에만 알림이 가도록 자연스럽게 전환됐다.
