# 1주차 과제 — 솔라

## 미션 1: claude code 로 인터뷰스킬 사용해서 인터뷰 까지 진행

### Summary 
`/os-interview` 스킬로 6단계 인터뷰를 진행해 **OS 청사진 1장 + 첫 부품 스펙 1건**을 도출. AI 영상 크리에이터로서 이미지·영상 제작 시 시간 도둑이 되는 "의도 → 모델 프롬프트 번역 비용"을 진단했고, OS 선언문(_"나는 의도와 최종 디렉팅만 하고, 나머지는 시스템이 한다"_)과 그에 도달하기 위한 부품 로드맵을 확정. 첫 부품으로 **레퍼런스 자동 수집기(ref-finder)**를 Claude Code 플러그인 형태로 결정.

### 최종 구현 결과물
### 1. OS 청사진 (`~/.claude/plans/os-blueprint.md`)

- **OS 선언문**: 나는 의도와 최종 디렉팅만 하고, 나머지는 시스템이 한다
- **풍경**: 혼자 작업, 광고 영상 메인, 기획→이미지→영상→편집 풀 파이프라인 운영
- **통점**: 한 컷 2~3시간, 디테일한 의도를 모델 언어로 번역하는 패턴 부재
- **핵심 제약**: 비용 비대칭 — 이미지는 무한 시도 가능, 영상(Kling)은 크레딧 차감 = 실질 돈
- **이상향**: 한 컷 30분, 좋은 후보 5개를 자동으로 책상에 올려두고 디렉팅만

### 2. 부품 로드맵 (우선순위)

1. ✅ **레퍼런스 자동 수집기** ← 첫 부품 확정
2. 이미지 프롬프트 생성기
3. **영상 직전 AI 1차 검수기** ⭐ (크레딧 절감 핵심)
4. 영상 프롬프트 생성기
5. 최종 후보 큐레이터
6. (보류) 기획 자동화 — 사용자가 직접 손대고 싶은 영역

### 3. 첫 부품 스펙 (`encapsulated-wibbling-sutton.md`)

- 이름: `ref-finder`
- 형태: Claude Code 플러그인 (B 형태)
- slash 커맨드: `/find-ref`
- 출처 v0.1: Pinterest + filmvibes.io
- 출력: 로컬 HTML 미니 갤러리

### 과정 (타임라인별 + 삽질)
- 타입리스를 활용해서 클로드와 대화를 진행했다. 막히는 구간은 딱히 없었지만 중간 '부품결정' 단계에서 어떤 형태로 만들건지 관해 물어봤을 때 모르는 용어들이 많이 나와서 이해가 잘 가지않았다. 그런부분은 바로 물어보면서 진행했다.
  ![[Pasted image 20260505192959.png]]
- 그 결과 자세히 글로 풀어주고 표 형식으로도 비교해줘서 이해하기가 쉬웠다. 
- 지금 회고를 적으면서 생각해보니 지금 계획한 이 기능들이 실제로 사용이 가능할까? 라는 생각이 든다. 어쨌든 내가 원하는건 레퍼런스 찾는 시간과 이미지 생성 시간을 최대한 줄이는게 목적인데, 과연 사람 손을 타지 않고도 ai가 이걸 해낼 수 있을까 하는 의구심이든다..
- 이런 의구심이 든 이유는, 사실 인터뷰 스킬 끝나고 실제로 첫 부품으로 추천해준 'ref-finder'을 만들어서 구동해봤는데 생각보다 내 맘에 쏙드는 레퍼런스를 찾아내지 못했다. 내가 직접 똑같은 사이트에 접근해서 찾는 것이 더 효율적이라고 느껴졌다.
  -> 애초에 레퍼런스부터 제대로 찾지 못하면 이미지 프롬프트도 잘 쓰지 못할 것 같은데.. 내가 이걸 구현할 수 있을까 의구심이 든다.
### 공유할만한 인사이트
- claude 스킬과 claude 플러그인, 그리고 독립 프로덕트 PRD의 차이점에 대해 간단히 이해한 바로는 우리가 클로드코드에서 쓰는 커멘드(/) 기능처럼 간단하게 만드는 것이 스킬, 거기에 API호출 기능까지 더한 것이 플러그인, 거기에 웹이나 앱으로 더 발전시킨 것이 독립 프로덕트 PRD인듯 하다.
- 무조건 적으로 쉽다고 추천해 주는 것만 고를게 아니라 지금 현재 나에게 필요한 선택지를 고르는 것이 중요하다고 생각되었다. 허용해달라는게 많아서 관성적으로 컨트롤 엔터만 누르게 되는데 정신줄 꼭붙잡고 구성단계에서는 꼼꼼히 읽어보는 습관이 필요한 듯 하다.
- 뭔가 모르겠는 말을 할땐 그냥 '나 아무것도 모르는 바보야. 비개발자고 바이브코딩으로 하고싶어'하면 차근차근 알려준다. 대신 뭔가 중간에 과정과 다른 질문인데 잘 풀리지 않는 질문들은 코드말고 채팅에서 진행했다.(ex.클코가 핀터레스트 토큰을 가져와달라고 요청했는데, 어차피 얘가 직접적으로 진행할 수 없는 부분이라서 받는 방법이나 api허가 실패에 대한 질문은 클로드 채팅으로 진행)

## 미션 2: 따라해보고 싶은 개인/업무/삶 OS 따라서 만들어보기 - SNS(유튜브 등) 에서 찾아 벤치마킹 해오기

### Summary
스폰지타임즈 인스타 운영을 위해 **슬랙 대화 → 구글 시트로 콘텐츠 후보를 자동 적재하는 어드민 페이지**를 만들었다. 슬랙 내에 콘텐츠가 될 수 있는 아이디어를 사람이 일일이 분별하는 것이 아닌, 클로드 대화 내에서 '이번주 후보 콘텐츠 가져와줘'등의 요청을 하면 슬랙에서 데이터를 가져와서 구글 시트-> 어드민페이지 정리로 되는 워크플로우를 제작했다.
또한, 스폰지타임즈 구성원들은 어드민 페이지 내에서 본인 닉네임을 선택하고 로그인하면 기획중 표시를 띄울 수 있고, 또 그 정보를 그대로 클로드가 읽을 수 있게 만들어서 대화로만 기획이 가능하도록 구현했다.
### 최종 구현 결과물
스폰지타임즈 어드민 페이지 https://spongetimes-admin.vercel.app/
### 과정 (타임라인별 + 삽질)
**1단계 — 벤치마킹 찾기** 처음엔 SNS에서 직접 비슷한 사례를 찾으려 했는데 적당한 레퍼런스 찾는 방법을 아예 몰라서 Claude한테 "레딧에서 슬랙 정보를 시트로 가져오는 사례를 찾아달라"고 부탁하고 비슷한 워크플로우 사례를 바탕으로 구현을 시작했다.(특정 게시물을 받지는 않았고 그냥 그 사람들이 한 걸 참고해서 진행해달라고 요청하였음)

**2단계 — 백엔드/API 연동 (← 여기서 삽질)** 가장 오래 걸린 구간. 슬랙에서 메시지를 끌어오고, 후보를 정리해서, 웹훅으로 구글 시트에 꽂히게 하는 파이프라인을 붙이는 과정에서 처음해보는 일이라서 여러 번 막혔다. 클로드 내에서 커넥터 기능을 사용해 슬랙과 구글드라이브(시트사용을 위해)를 연동시켰고, 그 이후에 make에서 클로드가 정보를 쏘면 시트로 정보가 들어가게끔 시나리오 매핑을 했다.
![[Pasted image 20260509164503.png]]
![[Pasted image 20260509164658.png]]

**3단계 — 어드민 페이지 만들기로 결정** 시트로 연동한 뒤에 그대로 사용하려고 했으나, 가독성이 떨어져 어드민 페이지를 만들기로 결정했다. 기존에 셀피쉬클럽 멤버들이 만들었던 어드민 페이지를 참고해서 클로드에게 '나도 이렇게 만들고싶다'고 요청한 뒤 클로드코드로 넘어가서 진행했다.

![[Pasted image 20260509165111.png]]
![[Pasted image 20260509165132.png]]
**4단계 — 클로드코드로 어드민 페이지 작업 시작** 웹으로는 클로드채팅을 켜 놓고, 앱으로는 클로드코드를 켜 놓은채로 양쪽에서 왔다갔다하면서 채팅을 복붙했다. 처음 시작 대화는 클로드가 하라는 대로 시작했고, 이 과정에서는 클로드코드가 잘 진행해줘서 큰 어려움은 없었다. vercel 배포 부분만 직접 할 일이 좀 있었다.

### 공유할만한 인사이트
- **레퍼런스가 없을 때 AI에게 검색을 맡기는 게 진짜 쓸모 있다.** 내가 직접 SNS를 뒤지는 것보다, "이런 워크플로우 사례를 레딧에서 찾아줘"라고 위임하는 편이 훨씬 빨랐다. AI를 답변자가 아니라 리서처로 쓰는 게 OS 따라 만들기에선 가성비가 좋다.
- **클로드코드와 함께라면 뭐든 만들 수 있겠다고 생각했다 하지만,** 클로드 코드가 만들어준 결과물을 바탕으로 이를 어떻게 해야 더 쉽게 사용할 수 있는지는 사람의 몫이라는 생각이 들었다.

불과 몇 주 전 까지만 해도 '클로드라는게 존재한다'는 사실만 알았던 내가 클로드를 다룰 수 있게되고, 나에게 필요한 스킬이나 페이지까지 만들 수 있게 된 것이 신기하다.

몇 주 전 영상프롬프트를 뽑기위해 클로드를 처음 사용했었다. 그 때는 다른 LLM들과 비교했을 때 특출나게 괜찮은 프롬프트를 뽑아주지 않는 모습을 보면서 나는 '클로드가 도대체 왜 좋다고 하는거지?'라는 생각을 했다.

지금에서 그때를 돌이켜보면, 그저 내가 클로드를 잘 사용하지 못했던 사람이라는 생각이 든다. 아무리 똑똑한 도구를 쥐어줘도 사용하는 사람이 사용법을 모른다면 그저 채팅창에 불과해지는 것 같다. 실제로 최근에는 클로드 내의 '프로젝트 지침'을 사용하는 법을 알게 되어서 영상프롬프트 작성시에 사용해봤는데 작업을 할때 평소보다 수월하게 진행되는 것을 느꼈다.

하지만 내가 혼자서 할 수 있는 일의 한계가 흐려지다 보니, 되려 해야 하는 일/하고 싶은 일이 많아져서 감당할 수 없게 되는 부분도 있는 것 같다. 그저 과도기라고 생각하고 조금 더 열심히 해봐야겠다.
