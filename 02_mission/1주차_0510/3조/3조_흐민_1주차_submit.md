# 1주차 과제 — 흐민

## 미션 1: claude code 로 인터뷰스킬 사용해서 인터뷰 까지 진행

### Summary
- GitHub에 공개된 OS Interview Skill(selfishclub/os-interview-skill)을 Claude Code에 로드하여 20분 압축 인터뷰 진행
- 6단계 인터뷰(풍경→통점→이상향→부품매핑→첫부품결정→결과물작성)를 통해 나만의 OS 청사진과 첫 부품 PRD를 도출
- OS 선언문: "나는 방향성을 정하고, 경험·학습에서 인사이트를 선별해 형식지로 바꾸는 작업만 하고, 나머지는 시스템이 한다."

### 최종 구현 결과물
- **OS 청사진 (os-blueprint.md)**: 현재 풍경, 통점, 이상향, 7개 부품 후보와 우선순위를 담은 1페이지 문서
- **첫 부품 PRD (thought-to-knowledge.prd.md)**: 텔레그램 채널 기반 "사고 → 지식 변환기" 설계 문서
  - MVP: 텔레그램으로 사고 입력 → Claude 사고파트너 대화(디깅·확장) → Obsidian 구조화 노트 자동 저장
  - 처리 타이밍: 즉시(캡처), 일간(연결), 주간(콘텐츠화)
  - 컴포넌트: skills(thought-partner, note-writer) + commands + hooks + templates

### 과정 (타임라인별 + 삽질)
1. **스킬 로드**: GitHub 레포(selfishclub/os-interview-skill)에서 SKILL.md + templates 3종을 gh API로 fetch하여 Claude Code에 로드
2. **Phase 1 — 풍경+통점 (5분)**: AI Native 삶을 살며 AX 교육을 하는 풍경 공유. 전통적 통점이 없어서 메타 레벨로 전환 — "전환 아이디어는 넘치지만 정착까지의 간극"이 핵심 통점으로 도출
3. **Phase 1 — 이상향+부품매핑 (7분)**: OS 선언문 도출 후, 사고캡처→지식연결→콘텐츠가공→배포→브랜딩→교육→일정관리의 7개 부품을 파이프라인으로 정리
4. **Phase 2 — 첫 부품 결정 (3분)**: 상류(사고→지식 변환)가 안 돌면 하류 전체가 수동이므로 1번 부품 선택. 형태는 단일 스킬이 아닌 Claude Code 프로젝트(채널+스킬+훅 조합)로 결정
5. **Phase 3 — PRD 작성 (5분)**: Q톤 5개 질문으로 인터페이스, 변환 기준, 저장소, 타이밍, MVP 흐름을 빠르게 채워 PRD 완성

### 공유할만한 인사이트
- **통점이 없으면 메타 레벨로 올라가라**: "반복 작업이 짜증"이 아닌 사람에게는 "전환 과정 자체의 비효율"이 진짜 통점이다. 인터뷰 스킬의 가설 검증(R톤)이 이걸 끌어내는 데 효과적이었다.
- **파이프라인 사고가 우선순위를 명확하게 한다**: 부품을 나열할 때 "상류→하류" 구조로 보면, 어디를 먼저 만들어야 나머지가 자동으로 먹히는지 바로 보인다.
- **형태 선택은 "가장 가벼운 것"이 아니라 "실제 사용 맥락"으로**: 스킬(A)이 가장 가볍지만, 일상 대화 인터페이스가 핵심이면 채널 기반 프로젝트(B)가 맞다.
- **20분 압축도 가능하다**: 원래 40~60분 설계지만, Step 합치기 + 가설 선제 제시로 핵심을 잃지 않고 압축할 수 있었다.

## 미션 2: 따라해보고 싶은 개인/업무/삶 OS 따라서 만들어보기 - SNS(유튜브 등) 에서 찾아 벤치마킹 해오기

### Summary
- 나만의 OS 만들기 케이스로, 개인 AI 비서 **오민이**를 만들고 있다.
- 목표는 단순 챗봇이 아니라, 나의 일정·프로젝트·태스크·회고 흐름을 함께 관리하는 개인 운영체제에 가깝다.
  
핵심은 Linear, Obsidian, OpenClaw, Telegram을 연결해서:
• 할 일을 이슈로 쪼개고
• 하루 시간표로 배치하고
• 변경이 생기면 즉시 재배치하고
• 리마인드와 회고까지 이어지는 시스템을 만드는 것

### 최종 구현 결과물
• Telegram에서 대화하는 개인 AI 비서 오민이
• Linear 기반 프로젝트/태스크 관리
• Obsidian Daily Note 기반 Day Planner 시간표
• 일정 변경 시 오민이가 Daily Note와 Linear 링크 노트를 함께 업데이트
• SwiftBar로 현재 작업을 Mac 메뉴바에 표시
• 오전/저녁 체크인, 긴급 리마인더, 세션 후 회고 알림
• 오민이의 성격/원칙/말투를 SOUL.md, USER.md, MEMORY.md에 저장

즉, “오늘 뭐 하지?”를 매번 새로 고민하는 게 아니라, 대화 → 태스크화 → 시간 배치 → 실행 → 재배치 → 회고까지 이어지는 개인 작업 OS를 만든 셈이다.

### 과정 (타임라인별 + 삽질)
1. 방향 설정
처음에는 감정적으로 자주 체크인하는 비서보다, 실제 생산성을 도와주는 개인 매니저가 필요하다고 판단했다.
그래서 오민이의 역할을 일정·프로젝트·태스크·생산성 관리 중심으로 정했다.

2. 도구 연결
Linear는 프로젝트와 태스크 관리용, Obsidian은 일간 계획과 기록용으로 사용했다.
OpenClaw를 통해 오민이가 로컬 파일과 메모리, 리마인더를 다룰 수 있게 했다.

3. 일정 관리 실험
데드라인과 가용시간을 알려주면 오민이가 작업을 쪼개고, Daily Note의 Day Planner에 시간 블록을 만들어주는 방식으로 실험했다.
예를 들어 공유회 준비, 과제 제출, 지원서 작성 같은 작업을 Linear 이슈로 만들고 날짜별로 배치했다.

4. 삽질: TODO만 있고 시간표가 없음
초반에는 Obsidian Daily Note에 단순 TODO 목록만 생기고, 실제 Day Planner가 인식하는 시간 블록이 빠지는 문제가 있었다.
이후 “반드시 HH:MM - HH:MM 작업 형태의 시간 블록까지 작성한다”는 운영 규칙을 만들었다.

5. 삽질: 계획은 계속 바뀐다
실제로는 가족 일정, 점심, 갑작스러운 일 때문에 계획이 계속 밀렸다.
그래서 오민이와 대화하면서 13시 시작 → 14:30 시작 → 공유회 우선 → 과제 제출 18-19시처럼 계속 재배치했다.
이 과정에서 OS의 핵심은 완벽한 계획표가 아니라, 변경에 빠르게 반응하는 재배치 능력이라는 걸 알게 됐다.

6. 현재 상태
지금은 오민이가 단순히 답변하는 존재가 아니라, 오늘의 우선순위와 시간표를 같이 조정하는 작은 운영체제처럼 작동하고 있다.

### 공유할만한 인사이트
• 나만의 OS는 거창한 앱보다 “반복되는 판단을 덜어주는 흐름”에 가깝다.
• AI 비서는 성격보다 운영 규칙이 중요하다. 언제 말할지, 무엇을 업데이트할지, 어디에 기록할지가 정해져야 쓸모가 생긴다.
• 계획표는 한 번 세우는 것보다 계속 고치는 능력이 더 중요하다.
• Linear는 “무엇을 할지”, Obsidian은 “언제 할지/어떻게 했는지”를 담당하게 하니 역할이 분리되어 좋았다.
• AI가 로컬 파일과 일정 맥락을 다룰 수 있으면, 단순 대화형 챗봇보다 훨씬 개인 OS에 가까워진다.
• 다만 자동화가 많아질수록 “내가 승인할 것”과 “AI가 알아서 해도 되는 것”의 경계가 중요하다.

### 링크
