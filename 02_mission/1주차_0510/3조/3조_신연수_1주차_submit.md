## 미션 1: claude code 로 인터뷰스킬 사용해서 인터뷰 까지 진행

### Summary
육아휴직 중인 PM이 Claude 스킬 3개로 개인 OS를 완성했다. 핵심 문제는 "결정 비용" — 장보기·제품 구매·이유식 식단·발달 파악 모두, 정보를 모아 판단하는 준비 과정이 시간을 잡아먹고 있었다. OS 인터뷰 → 스킬 빌드 → 실사용 테스트 → 반복 개선 → 플랫폼 한계 발견 → 모바일 이전까지 한 세션에 완료.

> **OS 선언문 v1**: 나는 아기와 놀아주고 결제 버튼만 누르고, 나머지는 시스템이 한다.  
> **OS 선언문 v2**: 나는 아기와 함께하며 결정만 하고, 나머지는 시스템이 한다.
> 
> _v1→v2 이유: "결제"는 구매만 가리키지만, 실제로는 식단·발달·제품 전부가 같은 구조였음. "결정만"이 더 정확하다._

### 과정 (타임라인별 + 삽질) by claude code

**[1] OS 인터뷰 6단계**  
풍경→통점→이상향→부품매핑→첫부품결정→스킬빌드. 인터뷰에서 "마감기한 없는 프로젝트"라는 표현이 나왔고, 통점 2개(장보기·공구탐색)가 같은 구조임을 발견.

**[2] 이유식 플래너 첫 출력 → 피드백 폭발**

- _삽질 1_: 부품을 1·2·5번으로 분리 제안 → "이거 다 합쳐야 제대로 되는 거 아닌가요?" → PM이 설계를 통합
- _삽질 2_: 매일 다른 메뉴로 짬 → "무른밥이 3~4일치 한번에 나온다" → 3일 배치 시스템으로 전면 재설계
- _삽질 3_: 재료 궁합 미고려 → 지적받고 추가
- _삽질 4_: 소고기 매일 필수 원칙 누락 → "철분 때문에 매일 먹이는 게 맞지 않나요?" → 전 배치 적용
- _삽질 5_: 곡물 베이스 별도 컬럼 분리 → "아침이 오트밀이라 잡곡 50% 넘으면 안 돼" → 맥락 못 읽은 설계였음

**[3] 공구 판단 도우미 + 월령 발달 브리핑 동시 빌드**  
질문 4개로 두 스킬 완성. 즉시 실사용 테스트 (유모차 선풍기, 돌잡이 전집).

**[4] 공구 판단 도우미 한계 발견**  
링크 줘도 제품 못 읽음 → Chrome 익스텐션 연결 시도 → 다나와 접근 성공, 네이버 스마트스토어·인스타그램 차단 → 스킬에 Chrome 연동 로직 추가했지만 근본 한계는 C(프로덕트)로 올려야 해결됨.

**[5] 모바일 이전**  
claude.ai Projects 기능으로 스킬 3개를 Instructions 텍스트로 변환. 로컬 파일 업데이트와 Projects 수동 동기화가 유일한 불편점으로 남음.


### 공유할만한 인사이트 BY CLAUDE CODE
**1. OS 선언문은 인터뷰 결과물이 아니라 사용 후 이터레이션된다**  
"결제 버튼만"으로 시작했지만, 실제로 스킬을 쓰고 나서야 "결정만"이 더 정확하다는 게 보였다. 선언문은 첫 인터뷰에서 확정하는 게 아니라, 쓰면서 다듬어지는 가설이다.

**2. 실제 생활 맥락 없으면 그럴듯하지만 못 쓰는 결과물이 나온다**  
무른밥이 3~4일 배치라는 걸 모르고 매일 다른 식단을 짰다. "좋은 식단"과 "쓸 수 있는 식단"은 다르다. 스킬 설계에서 사용자의 실제 행동 단위를 파악하는 게 핵심이다.

**3. PM 기질이 가장 강력한 QA다**  
부품 통합, 소고기 원칙, 잡곡 비율, 선언문 업데이트까지 — 사용자가 직접 설계의 구멍을 짚어냈다. "사용자가 수동적으로 답하는 인터뷰"가 아니라 "사용자가 설계에 참여하는 협업"일 때 결과물 품질이 달라진다.

**4. A(스킬)의 진짜 한계는 플랫폼 접근 제한이다**  
Claude 스킬은 텍스트 생성에 강하지만, 외부 플랫폼(인스타그램, 네이버 스마트스토어) 데이터를 가져오는 건 구조적으로 불가능하다. "링크만 주면 끝"이 되려면 C(프로덕트)로 올려야 한다.

### 인사이트 BY 연수
- **한 두 문장 지시로 클로드가 알아서 잘 하기에는 한계점이 있다. 사용자가 어느 정도 잘 알고 있어야 디벨롭이 가능해 보인다.** 이유식 플래너 스킬의 경우, 이유식을 처음 시작할 때 이 OS를 만들고자 했다면 중요한 사항을 많이 놓쳤을 것 같다. (소고기 섭취, 잡곡 비율 관련 등) 이유식에 대해서 아예 모른다고 알아서 좀 잘 짜달라 했으면 나았을까? 모르겠다.

## 미션 2: 따라해보고 싶은 개인/업무/삶 OS 따라서 만들어보기 - SNS(유튜브 등) 에서 찾아 벤치마킹 해오기

### Summary
육아휴직 중 뭐라도 기록하면 좋을 것 같고 수익도 나면 좋을 것 같아 네이버 블로그를 운영하고 있는데, 포스팅 1개 쓰는 데 시간이 너무 많이 걸리는 게 핵심 통점이었다. 목표는 아기 낮잠 40분 안에 포스팅 1개 올리는 시스템 + 장기적으로 워드프레스 애드센스 수익 파이프라인 구축.

### 최종 구현 결과물
**1. 블로그 글 자동 생성 Claude 스킬**

- 위치: `~/.claude/skills/blog-post-generator/SKILL.md`
- 사진 또는 주제만 말하면 육아 블로그 초안 자동 생성
- 워드프레스용 풀버전 + 네이버용 변형본 동시 출력
- SEO 키워드 + 해시태그 포함
- 본인 블로그 어투 분석해서 반영 (솔직한 후기체, ㅋㅋ/ㅠㅠ 자연스럽게, 후회템 명시, "구입 전으로 돌아간다면?" 구조)

**2. OS 청사진**

- 위치: `os-blueprint-blog.md`
- 블로그 수익 파이프라인 OS 선언문, 부품 후보, 다음 스텝 정리

**3. 워드프레스 블로그 세팅 진행**

- 카페24 뉴매니지드 워드프레스 빌드업 플랜 결제 완료
- 도메인 네임서버 연결 완료 (적용까지 최대 24~48시간)
- 내일: 워드프레스 자동 설치 → 테마 → 필수 페이지 3개

### 과정 (타임라인별 + 삽질)
**OS 인터뷰** → 유튜브 영상 접근 권한 없어서 막힘 → 외부 도구로 영상 요약 후 진행

**스킬 제작** → 야물야물 그림책 사진으로 바로 테스트 → 초안 괜찮았는데 내용 부족 → 향기책/팝업책/퍼즐책 구성 추가 → FAQ 추가 (세이펜 필요한지, 단점, 공구 방법) → 네이버 블로그 어투 분석해서 스킬 업데이트

**OS 청사진** → 기존 파일에 추가했다가 원본 건드렸다고 롤백 요청 → 별도 파일로 분리

**호스팅 세팅** → 처음에 애드센스 워드프레스 추천했다가 "그거 나도 할 수 있잖아" 한 마디에 뉴매니지드로 정정 → 카페24 기본 도메인으로 시작하면 애드센스 불가한 거 확인하고 커스텀 도메인 구매 → 네임서버 연결까지 완료

### 공유할만한 인사이트

**"AI가 못 하는 것"이 포스팅의 핵심이다**  
초안은 AI가 잡을 수 있지만, "냄비 바닥이 탔다", "킁킁거리는 게 귀엽다" 같은 실제 경험 디테일은 본인만 쓸 수 있다. AI는 구조와 SEO를 잡고, 사람이 살을 붙이는 분업이 블로그에서 가장 현실적인 조합.

**어투 샘플 1개가 스킬 품질을 바꾼다**  
스킬에 아무리 좋은 원칙을 써도, 실제 본인 글 샘플 하나 분석한 것보다 못하다. OS를 만들 때 "내 스타일 샘플"을 주는 게 가장 빠른 품질 개선.

**중복 콘텐츠 전략은 처음부터 설계해야 한다**  
네이버와 워드프레스에 같은 글 올리면 구글 패널티. 워드프레스 = 원본, 네이버 = 요약 변형본으로 역할 분리하는 걸 처음부터 알고 시작하는 것과 나중에 아는 것은 차이가 크다.

**카페24 AI 기능은 Claude로 대체 가능하다**  
애드센스 워드프레스 플랜의 AI 승인 도우미 = 글 올리기 전에 "이 글 애드센스 정책상 문제 없어?" 한 마디면 끝. 플랜 선택할 때 AI 기능에 돈 더 낼 필요 없다.
