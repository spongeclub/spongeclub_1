# 1주차 과제 — 코니

## 미션 1: claude code 로 인터뷰스킬 사용해서 인터뷰 까지 진행

### Summary
Claude Code에서 OS 인터뷰 스킬을 돌려서 내 업무 방식을 구조화하고, 첫 번째 자동화 스킬(흐름 리더)을 만들었다.
### 최종 구현 결과물
- `os-blueprint.md` — 내 업무 OS 청사진 (선언문 + 현재 풍경 + 통점 + 이상향 + 부품 후보 5개)
- `flow-reader.skill.md` — 첫 부품 "흐름 리더" 스킬 (매일 데이터 받아서 신호 라벨링 → 3축 분해 → 액션 후보 → 결정 칸)
- OS 선언문: "나는 흐름을 읽고 방향만 정하고, 나머지는 시스템이 한다."
### 과정 (타임라인별 + 삽질)
- 클로드 코드에서 OS 인터뷰 스킬 발동 → Phase 1 질문 시작
- Step 1(풍경) — "시간 가장 많이 쓰는 활동 3가지" 질문에 바로 답 못함. claude 웹에서 그동안 같이 한 작업 기반으로 재료 정리받고 답변
- Step 2(통점) — "반복 비용" 질문. 여기서 "해석 레이어가 자동화 안 되는 병목"이라는 핵심 진단 나옴
- Step 3(이상향) — 이게 제일 어려웠음. "90% 풀리면 아침에 뭐가 보이냐" 질문인데, 처음엔 기능 리스트만 나열함. claude가 "장면으로 바꿔야 한다"고 피드백 줘서 다시 씀
- Phase 2~3 — 첫 부품으로 흐름 리더 선택, 스킬 설계 인터뷰 진행
- **삽질 포인트**: 클로드 코드가 "ROAS"를 최우선 지표로 넣음. 현재 회사에서는 ROAS측정을 하지 않아서. "의료 마케팅"이라는 일반 틀로 유추한 거라 실제 운영과 안 맞았음. claude.ai에서 잡아내서 수정 요청함. 
### 공유할만한 인사이트
- **AI가 일반론"으로 채우는 걸 잡아야 한다.**** ROAS 같은 건 흔한 지표지만, 내가 실제로 보는 숫자는 달랐다. 결과물을 그냥 받으면 안 되고, 내 언어로 교정하는 과정이 필요하다.
- **"이상향을 장면으로 그려라"가 제일 어렵고 제일 중요했다.** 기능 리스트 나열하는 건 쉬운데, "아침에 앉았을 때 뭐가 보이고 내가 뭘 안 해도 되는지"를 구체적으로 상상하는 게 핵심이었는데 의외로 어려웠던 부분이였다.

## 미션 2: 따라해보고 싶은 개인/업무/삶 OS 따라서 만들어보기 - SNS(유튜브 등) 에서 찾아 벤치마킹 해오기

### Summary
헬스장 생존 OS를 만들었습니다. PT + 혼자 운동 기록을 한 곳에서 관리하는 1인용 PWA. SNS 벤치마킹 → 인터뷰 → PRD → Claude Code 빌드 → Vercel 배포까지.
### 최종 구현 결과물
- **헬스장 생존 OS (PWA)**: https://fitness-tracker-five-ruddy.vercel.app 
- 3탭 구조: 캘린더 / 오늘 운동 / 기구 가이드 
- 핵심 차별점: 좁은 타겟(PT 초보 + 내 헬스장 한정), 입력 마찰 최소화(한 세트 2탭 이내), 재미를 가미한 카피,  운동 어플에 있는 커뮤니티/프로필/유료 기능 배제
### 과정 (타임라인별 + 삽질)
- **벤치마킹** — 운동 앱 사용자들의 실제 결핍을 SNS와 블로그에서 수집했다. 
- 브런치 글(스트롱 앱 회고): "메타인지 도구" 프레이밍이 인상적이었음 
- 핏터AI: 좁은 타겟팅(크로스핏)과 PR 축하 카드 
- OpenTrainer: "세트 로깅 11단계는 60초 휴식 중 불가능"이라는 입력 마찰 최소화 철학 
- lukhcianen("기존 앱에 없어서 직접 만들었다") — 가장 큰 동기부여 
- 공통 페인 3가지 발견: 내 헬스장-앱 DB 미스매치 / PT 초보 맥락 없음 / 입력 귀찮음 
- **인터뷰** — claude.ai에서 OS 인터뷰 진행. 처음엔 식단 탭까지 넣으려 했는데 인터뷰 중에 폐기. PT/혼자 운동을 한 곳에서 관리한다는 핵심 가치만 남기고 3탭으로 정리. 재미 요소 카피는 이전 클로드코드 워크샵때 만들었던 와인 앱 "냉장고보다 셀러가 비싼 집" 스타일로 가기로 결정. 
- **PRD 작성** — 12장 구조로 정리. 디자인 토큰, 데이터 스키마, 화면 구조, 작업 순서까지 명시. 매니패스트(Manyfast.io) 같은 PRD 자동 생성 도구도 시도해봤는데 이미 클로드로 계획을 다 세워놔서 쓸만한게 많이 없었다. 직접 작성한 인터뷰 결과를 활용한 형태로 갔다. 
- **빌드** — Claude Code로 Step 1~10 진행. 매 단계 계획서 → 검토 → 작업 → 검증 사이클을 반복. - 
- **삽질 포인트 1: Step 6 폐기 → Step 6.5 재작업.** 클로드 코드가 준 계획서를 꼼꼼하게 읽지 않고 넘어가다 보니 처음엔 일반적인 유산소 칩(러닝/사이클/기타)으로 만들었는데, 내가 실제로 하는 건 "마이마운틴(경사/속도/시간)"과 "천국의계단(레벨/시간)" 두 가지뿐이었다. Claude Code가 일반론으로 채운 부분을 직접 사용해보고서야 발견. 
- **삽질 포인트 2: GuideModal 두 모드 분리.** 같은 모달이 가이드 탭 카드 클릭과 운동 행 [?] 버튼 두 곳에서 호출되는데 둘 다 같은 형태라 어색했다. 가이드 탭은 풀스크린, 운동 행은 바텀시트로 분리. 
- **삽질 포인트 3: 캘린더 도트 → 부위 텍스트 칩.** 처음엔 부위별 컬러 도트로 표시했는데, 실제로 캘린더 보면 어느 날 어떤 부위였는지 매번 클릭해야 알 수 있었다. 도트 빼고 "등·코어", "가슴·어깨 +1" 같은 텍스트로 바꾸니 한 주 패턴이 한눈에 들어옴. 
### 공유할만한 인사이트
- **좁은 타겟이 무기다.** "1인용 + 내 헬스장 한정"으로 시작하니까 의사결정이 빨랐다. 일반 사용자를 가정하면 식단/커뮤니티/공유 같은 기능이 자꾸 끼어드는데, "이건 내가 안 쓴다"로 다 잘라낼 수 있었다. 좁히는 게 만드는 것보다 어렵다. 
- **Claude Code가 제안하는 일반론을 잘라내야 한다.** 미션 1에서 ROAS 일반 틀 잡아낸 거랑 똑같은 패턴. 식단 탭은 운동 앱이면 보통 있는 거지만, 내 실제 패턴은 하루 적정한 단백질 누적 g였다. AI가 채워주는 결과물을 그대로 받지 말고 "이게 내가 진짜 하는 건가?"를 매번 체크해야 한다.
