### Summary
**내가 내린 정의 :**  
내 운영체제 = **"나는 '뭘·왜'만 말하고, '어떻게'는 AI한테 맡기는 일하는 방식."**  
캐러셀 만드는 웹앱은 그 방식이 굴러가는 무대일 뿐. 

비개발자가 Claude Code로 **인스타 캐러셀 제작 OS**를 한 세션에 처음부터 끝까지 만든 기록. 기획 인터뷰 → 풀스택 빌드 → 실사용하며 수십 번 갈아엎기. 
**"버튼 하나 누르면 카피·이미지·캡션·다운로드까지"** 자동화가 목표.


### 최종 구현 결과물
- 두 갈래 콘텐츠**: 내 콘텐츠 / 크루 콘텐츠(스폰지클럽 등 기간안에 실행하는 프로젝트 등) 탭 분리
- **3분할 에디터**: 좌(슬라이드 리스트) + 중앙(캔버스, 모든 텍스트 더블클릭 편집) + 우(속성·캡션)
- **AI**: 카피(Gemini 3 Flash) + 이미지(Nano Banana 2), 캐릭터 프롬프트 직접 입력, 4장 비교
- **정밀 타이포**: 형광펜·타이틀·서브카피·체크리스트 × 크기·자간·행간
- **보관함**: Supabase Storage JSON 자동 아카이브, 어디서든 다른 컴퓨터로도 복원할 수 있도록
- **크루  sns 인증 해시태그 고정 공지**: 해시태그·계정태그 기간 고정 → 캡션 자동 삽입
- **보안**: 단일 비번 잠금, 어드민 기능 활용 `.env` git 차단, server-only, .gitignore 추가삽입

### 과정 (타임라인별 + 삽질)
1. 기획 인터뷰(컨트롤타워·모델·테마 결정)
2. **삽질①** Next.js 14인 줄 알았는데 16 깔림 → 컨벤션 다시 학습
3. 모듈 1~6 빌드 → **삽질②** Supabase `permission denied` (테이블 권한 미부여)
4. **삽질③** SQL을 엉뚱한 프로젝트에 실행 (계정에 프로젝트 여러 개)
5. 인증·테마 → **삽질④** 다크↔화이트 요청 왕복, 페이지별 테마 정리
6. **삽질⑤** 모델 ID 헛다리 (`gemini-3.1-flash` 없음 → 실측으로 `gemini-3-flash-preview` 확정)
7. 콘텐츠 유형 → **삽질⑥** 캡처만 보고 만들었다가 문서 §8과 안 맞아 재정의
8. 마이그레이션 v3~v7 (constraint를 매번 막다가 → 아예 제거해 유연하게)
9. 에디터 캡처대로 재설계 + 더블클릭·4장비교·시각자료·타이포·고정공지
10. **삽질⑦** AI 이미지가 프롬프트·배경 무시 → "reference는 생김새만 + 배경 단색 강제"로 개선

### 공유할만한 인사이트
1. **구성하고 싶은 이미지나 앱 UI이미지들을 합성**- 아무리 텍스트로 이렇게 레이아웃을 해달라 구성해달라 해도 맥락을 모르기 때문에 내 구현계획을 따라주지 않는다. 구성하고 싶은 이미지나 앱 UI이미지들을 합성해 "레이아웃 구성만 구현하고 싶어. 디자인이나 다른 부가적인 요소는 md파일을 따라"라고 하면 금방 구현해준다.
2. - **"추측하지 말고 물어봐"가 시간을 아낀다** — 캡처 한 장도 해석 갈림길이 많음. 확인 후 진행이 재작업보다 빠름(이렇게 하니까 ai가 추측해서 맘대로 만들어주는 경우가 확 줄었다)
3. **DB 제약은 처음부터 유연하게** — constraint를 매번 마이그레이션으로 푸느니, 앱(zod)에서 검증하고 DB는 열어두기
4. **AI 이미지는 프롬프트를 100% 안 따른다** — reference가 있으면 포즈를 고집함. "생김새만 참고 / 4장 뽑아 고르기 / 배경 단색"이 현실적
5. **키 보안은 다층으로** — `.gitignore` + `server-only` + NEXT_PUBLIC 규칙. "코드 올렸다"는 말에 사용자가 불안해한 것처럼, 검증을 실측으로 보여주는 게 신뢰
6. .gitignore 보안 마지막까지 추가 — 이파일은 무시하라는 뜻이기에 안전하게 지나간다.
