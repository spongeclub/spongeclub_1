# 나만의 OS: "나는 던지기만 하고, 순서는 시스템이 정한다"

## 미션1: 나만의 [운영체제] OS 설계

### Summary

흐민 사례를 참고해 나만의 OS 청사진을 설계했다.  
내 핵심 통점은 **태스크 재정렬 스트레스** — 하루 중 새 일이 끼어들 때마다 전체 순서를 머릿속으로 다시 계산해야 하는 것.  
이상향은 단순하다: **태스크를 던지기만 하면, 시스템이 순서를 제안해준다.**

> OS 선언문: "나는 오늘 할 일을 던지기만 하고, 우선순위는 시스템이 제안한다."

---

### 현재 풍경 (통점 발굴)

매일 아침 종이에 오늘 할 일을 쭉 적고 하루를 시작한다.  
문제는 **중간에 새 태스크가 끼어들 때**다.

- 슬랙 메시지로 갑자기 급한 요청이 오거나
- 머릿속에 "아, 이것도 해야 하는데"가 떠오르면

종이에 적힌 정렬된 목록이 흐트러지고, 전체 순서를 다시 머릿속으로 계산해야 한다.  
약간의 강박 기질이 있어서 **이 재계산 과정 자체가 스트레스**다. 내용보다 순서 정리에 에너지가 빠진다.

```
[현재 흐름]

아침 종이 정리
      ↓
하루 시작
      ↓
슬랙 메시지 / 갑자기 생각남
      ↓
새 태스크 추가
      ↓
전체 순서 재계산 (← 여기서 스트레스)
      ↓
다시 시작
```

---

### 이상향 + OS 설계

**원하는 것**: 새 태스크가 들어올 때, 내가 순서를 고민하지 않아도 "이 순서로 해봐"를 제안받는 것.

**정렬 기준**:
1. 마감 빠른 순
2. 중요도 순

**인풋 경로**:
- 슬랙에서 날아오는 요청
- 머릿속에서 갑자기 떠오르는 것

**현재 도구**: 노션 + 아이폰 기본 캘린더

```
[이상적인 흐름]

슬랙 메시지 / 갑자기 생각남
      ↓
태스크 던지기 (도구 무관)
      ↓
시스템이 마감+중요도 기준으로 순서 제안
      ↓
"이 순서 맞아?" 확인 한 번
      ↓
실행
```

### 흐민 사례에서 가져온 것 / 나만의 변형

| | 흐민 | 위시 |
|--|--|--|
| 핵심 통점 | 아이디어→지식 전환 간극 | 태스크 재정렬 스트레스 |
| OS 핵심 | 사고 캡처 → 지식화 자동화 | 태스크 입력 → 순서 자동 제안 |
| 주요 도구 | Telegram + Linear + Obsidian | 슬랙 + 노션 + 캘린더 |
| 인풋 경로 | 텔레그램 대화 | 슬랙 메시지 / 머릿속 |
| 핵심 가치 | "나는 방향성만 잡는다" | "나는 던지기만 한다" |

흐민은 **사고를 지식으로 변환**하는 파이프라인을 만들었다면,  
나는 **들어오는 일을 순서대로 배치**하는 파이프라인이 필요하다.

---

### 공유할만한 인사이트 (암묵지 표면화)

**내가 스트레스받는 진짜 이유를 찾았다.**  
종이 할 일 목록의 문제는 "더럽혀지는 것"이 아니라, **한번 정렬하면 고정된다는 환상**을 갖게 만드는 것이다. 새 태스크는 항상 온다. 시스템이 그걸 전제로 설계돼야 한다.

**우선순위 결정에 내가 쓰는 암묵적 기준이 있었다.**  
무의식적으로 "마감 빠른 것 + 중요한 것"을 함께 보고 있었는데, 이걸 말로 꺼내본 건 처음이다. 시스템에 이 기준을 넣으면 내 판단을 위임할 수 있다.

**종이는 캡처엔 좋지만 재정렬엔 나쁘다.**  
아침 정리 도구로는 여전히 쓸 수 있지만, 하루 중 변화에 반응하는 건 디지털 도구가 맞다.

### 실제 구현: `/prioritize` Claude 스킬

설계에서 멈추지 않고 바로 Claude Code 스킬로 구현했다.

**입력 형식 (v1 → v2 개선 과정)**

처음엔 중요도를 직접 입력받는 방식으로 만들었다:
```
태스크: 스폰지클럽 과제 제출
마감: 오늘 19시
중요도: 매우 높음   ← 이걸 직접 입력하는 게 비효율적
```

→ "중요도를 내가 일일이 입력하면 자동화 OS가 아니잖아" 라는 피드백으로 v2로 개선.

**v2: 중요도 자동 추론 (키워드 + 출처)**

| 출처 | 추론 중요도 |
|------|------------|
| 슬랙DM / 카톡 | 높음 (+2) |
| 슬랙채널 | 중간 (+1) |
| 내생각 | 낮음 (0) |

태스크명 키워드(긴급/고객/컨펌 등)도 점수에 반영.

**실제 테스트 결과 → 규칙 버그 발견**

실제 오늘 태스크로 돌려봤더니:

| 순위(v1) | 태스크 | 마감 |
|----------|--------|------|
| 3위 | confeti 인스타 캐러셀 | 오늘 24시 |
| 4위 ❌ | 부스 운영 매뉴얼 | 내일 14시 (카톡) |

→ 카톡으로 온 요청이라 중요도 +2가 붙어, **내일 마감이 오늘 마감을 앞질러버리는 버그** 발생.

**v3: 마감 날짜 절대 우선 원칙 추가**

```
정렬 기준 (이 순서로 적용):
1. 마감 날짜 — 오늘 > 내일 > 이번 주 > 없음 (무조건)
2. 같은 날 안에서 → 중요도 점수
3. 중요도도 같으면 → 마감 시간
```

오늘 마감은 아무리 중요도가 낮아도 내일 마감보다 위로.

**최종 결과 (v3)**

| 순위 | 태스크 | 마감 | 추론 중요도 |
|------|--------|------|------------|
| 1 ⚡ | 스폰지클럽 과제 제출 | 오늘 19시 | 중간(슬랙채널) |
| 2 | 셀피쉬클럽 인스타 캐러셀 | 오늘 24시 | 중간(슬랙채널) |
| 3 | confeti 인스타 캐러셀 | 오늘 24시 | 낮음(내생각) |
| 4 | 부스 운영 매뉴얼 정리 | 내일 14시 | 높음(카톡) |

### 공유할만한 인사이트 (암묵지 표면화)

**내가 스트레스받는 진짜 이유를 찾았다.**  
종이 할 일 목록의 문제는 "더럽혀지는 것"이 아니라, **한번 정렬하면 고정된다는 환상**을 갖게 만드는 것이다. 새 태스크는 항상 온다. 시스템이 그걸 전제로 설계돼야 한다.

**우선순위 결정에 내가 쓰는 암묵적 기준이 있었다.**

**시스템을 만들면서 내 기준의 버그를 발견했다.**  
"중요한 것이 먼저"라고 생각했는데, 실제로는 **날짜가 무조건 우선**이었다. 내일 아무리 급한 것도 오늘 마감보다 뒤에 온다. 이걸 규칙으로 써보기 전까지는 몰랐다.

**종이는 캡처엔 좋지만 재정렬엔 나쁘다.**
