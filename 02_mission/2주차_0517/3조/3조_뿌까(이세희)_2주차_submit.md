# 2주차 과제 — 이세희


# 미션1: 각자만의 정의로 [운영체제]라고 정의내리는 OS 구현

## Summary

내 삶은 결국 다 이어져 있는데, 굳이 따로따로 정리해야 할까? 라는 생각에서 시작했다.
머릿속에 둥둥 떠다니는 운동·식단·감정·생각·일·뉴스를 한 곳에서 적고, 자동으로 분류되고, 한 화면에서 다 볼 수 있는 **나만의 OS 대시보드가 있었으면 좋겠다고 생각했다.**
입력은 텔레그램 한 곳에서, 저장은 데이터 성격에 따라 옵시디언과 노션으로 나누고, 보는 건 직접 디자인한 대시보드에서. 데이터는 외부에 안 올리지만 폰으로 어디서든 볼 수 있게 만들었다.

**추가 기능**
- 메뉴마다 자물쇠 설정 가능 (명품감정 같은 민감한 카테고리 보호용)
- 메뉴 이름·인사말 다 내가 직접 바꿀 수 있음
- 노션에 적은 건 대시보드에 자동으로 보이고, 대시보드에서 적은 건 노션에 자동으로 올라감 (양방향 sync)

## 과정 (타임라인별 + 삽질)

### 🌱 시작점 — 손 다이어리에서 OS까지

손으로 다이어리를 썼던 시절, 캘린더 한 페이지에 운동한 날엔  🏋🏻‍♂️, 책 읽은 날엔 📖로 표시하는 등 하루를 한눈에 보는걸 좋아했다. 1주차 때 만들었던 시간 자투리 스킬도 비슷한 맥락에서 시작했었다. — 머릿속에 둥둥 떠다니는 스케줄을 밀착해서 잡아주는 도구. 그러다 자연스럽게 다음 질문이 떠올랐다. *"적어놓은 기록 자체도 한 곳에 모아서 보면 안 될까?"*

### 🧩 도구를 왜 둘 (옵시디언/노션)로 나눴나 — "원하는 뷰가 달라서"

처음엔 흐민님께 추천 받은 옵시디언 하나로 다 할까 싶었다. 그런데 데이터 성격이 너무 달랐다.

- 운동·식단은 **달력별·표별**로 보고 싶음 → 노션 DB가 적합
- 감정·생각·명품감정 포인트는 **아카이브 형태로 텍스트로 쌓이고, 검색으로 꺼내고 싶었다** → 옵시디언이 적합
- 특히 명품감정 포인트는 예민한 정보가 섞여 있어서 클라우드에 올리기 꺼려졌다 → 로컬 기반인 옵시디언이 더 맞았다

**내 데이터가 어떤 모양으로 쌓일지**를 기준으로 고른 게 핵심이었다.

### 🔒 외부 노출은 안 하지만 폰으로는 보고 싶다

데이터는 외부노출이 아닌 나만 볼 수 있게 내 Mac에만 두는 게 원칙이었는데, 정작 나는 밖에서 활동하는 시간이 더 많기 때문에 폰에서 못 보면 의미가 없었다.

- 처음엔 같은 wifi 안에선 폰과 Mac에서 둘 다 대시보드 보기 가능
- 하지만 밖에 나가서 셀룰러를 쓰면 끊김 → 결국 못 봄
- 배포하자니 외부 노출이 꺼려졌음
- → **Tailscale**을 깔아서 해결-> 무전기의 주파수 같은 거라고 보면 된다. 내 Mac이랑 내 폰만 같은 주파수에 묶여서 비밀 통로로 연결됨. 외부에서는 통로 자체가 안 보임.
- 결과: 5G 셀룰러로도 폰에서 대시보드 정상 접속. 데이터는 여전히 Mac에만 있고 클라우드 안 거침.

### 🛠️ 삽질

**1.만들어 놓고 보니 노션이랑 대시보드가 연동 안되는 상태였음**
- 테레그램에서 입력하고 대시보드에 쌓이는건 되는데 그게 노션하고 연동 시켜놓고자 했던 기록이 자동으로 쌓이지 않고 있었음.
- 코드 안에 "notion-cache"라는 이름이 있어서 당연히 노션이랑 연결돼 있는 줄 알았는데, 실제로는 로컬 JSON 파일만 읽고 있었다.
- 예전에 노션에 직접 적어뒀던 운동/식단/컨디션이 대시보드에 보이지 않았었음
- **해결**: 노션 Integration 토큰 발급 → 4개 DB(운동일지, 운동방법, 식단, 컨디션) 각각에 연결 권한 추가 → 코드에서 진짜로 노션 API 호출하도록 변경 → 양쪽이 같은 데이터를 보게 만들었다
- 결과: 노션에 적어도 대시보드에 뜨고, 대시보드에서 적어도 노션에 들어간다

**2. 노션  (DB ID vs data_source_id)**
- 노션이 API를 v5로 업데이트 하면서 "데이터베이스 ID(건물주소)"랑 "데이터소스 ID(건물호수)"가 분리되어 있었음.
- 내가 알고 있던 데이터베이스 ID로 정보를 주니 4번 다 "DB 못 찾음" 에러
- 클로드에게 문제점 물어보고  API로 실제 필요한 ID를 다시 찾아냄


**4. 터미널 작업->클로드앱 코드로 넘어감
텔레그램 봇으로 이것 저것 얘기하다가 작업 시작한거라 자연스럽게 텔레그램에 연결된 터미널에서 작업 하기 시작 했는데, 나중에 크로드앱 코드로 넘어옴.  다음에도 꼭 그렇게 하기,,

- 채팅창에서는 비번 입력이 안 됨 → 진짜 터미널 앱 열어서 진행

## 공유할만한 인사이트

**1. 도구는 나에게 맞게, 내가 뭘 원하는지 생각해보고 클로드랑 상의하며 고르기
- "노션 좋대" "이거 핫하대" 말고
- 내 데이터가 표로 쌓이는 종류인지, 글로 쌓이는 종류인지를 먼저 봐야 한다
- 데이터 모양에 도구를 맞추면, 도구 두 개 써도 어색하지 않다. (아직까진 그렇다)

**2. 내 OS를 내 입맛대로 수정할 수 있게 어떻게 설계할것인지**
- 메뉴 이름, 인사말, 비번, 잠금 범위 등 — 내가 무엇을 마음대로 수정할 수 있어야 하는지 알아야한다.
- 남이 만든 도구를 빌려 쓰는 것과, 내가 키우는 도구는 완전히 다른 경험이다

**3. Tailscale의 존재 - 바이브코딩을 하다보면 내가 몰랐던 어플 등을 알게된다.
- "외부 노출 안 한다" + "폰으로는 볼 수 있어야한다" — 이게 되나? 싶었지만(사실 왜 안되는지도 클로드가 알려줘서 알았음)
- Tailscale처럼 두 원칙을 다 만족하는 제3의 길이 있을 가능성이 높다.

**4. 기록은 따로 있을 때보다 서로의 거울이 될 때 의미가 커진다**
- 노션과 대시보드가  연동이 안되어 있었던걸 좀 늦게 깨달았다. 여동 시키고자 하는게 잘 되어 있나 확인하기
- 양방향 연동을 만들고 나서야 진짜 "OS"가 됐다는 느낌이 왔다

**5. 내 기록은 결국 미래의 나에게 보내는 자산이다**
- 명품감정 포인트 같은 경우는 쌓아나가다 보면 나중에 들어올 후임들에게 정리된 지식을 전달해줄 수 있음.
- 운동 일지는 내 운동 계획을 세울 때 도움이 된다.
- 컨디션 점수는 내 생각 패턴 발견의 재료가 된다
- 한눈에 보이게 모아두는 순간, 흩어진 기록들이 자산으로 바뀐다
