## 미션1: 각자만의 정의로 [운영체제]라고 정의내리는 OS 구현

### Summary

"꿀팁 정리 스킬 하나"로 시작해서 5일 만에 텔레그램 봇 + 대시보드 홈페이지 + 스킬 6개 생태계로 자라났다.

내가 정의하는 OS: **"나는 골라내는 것만 하고, 나머지는 시스템이 한다."**

스레드/인스타에서 본 AI 도구 정보를 노션에 스크랩하는 습관이 있었는데, 문제는 스크랩한 걸 다시 안 본다는 거였다. "휘발시키지 말자"라는 이름의 노션 페이지가 이름과 반대로 계속 휘발되고 있었다. 이걸 살아있는 시스템으로 만드는 게 이번 OS의 목표였다.

### 최종 구현 결과물

**스킬 6개** (Claude Code SKILL.md)
- `honey-curator` — 매주 월요일 자동 큐레이션. 꿀팁 후보 선별 + 관심사 패턴 분석 + 텔레그램 요약 발송 + "OK" 한 마디로 승인
- `tip-collector` — 텔레그램에 URL 보내면 자동 태깅 + 인사이트 + 노션 저장. 과거 패턴 기반으로 "이 분야는 평소에 안 주던데?" 같은 대화도 건넴
- `tip-oracle` — 텔레그램에 질문하면 꿀팁 카드 DB에서 검색해서 답변
- `memo-collector` — URL 없는 텍스트 메모도 자동 분류·저장
- `wiki-synthesizer` — 같은 주제 카드 5개 이상 모이면 Wiki 문서로 자동 합성
- `kernel-db-register` — 새 노션 DB 추가 시 코드 3곳 동기화

**노션 DB 4개** (Kernel 페이지 하위 통합)
- 휘발시키지 말자 (Raw) — 스크랩 원재료
- AI 꿀팁 카드 (Assets) — 코니가 골라낸 것만. 저장 동기 + 패턴 태그 포함
- Wiki — 같은 주제 카드가 모이면 합성된 문서
- 큐레이션 세션 — 큐레이션 상태 관리 (대기/승인/만료)

### 과정 (타임라인별 + 삽질)

**Day 1 (5/11)** 방향 잡기
1주차에 만든 "헬스장 생존 OS"가 실생활에 필요한 건 맞았는데, 개인용 웹앱이라 재미가 없었다. 업무에서는 이미 AI를 일 자체로 많이 쓰고 있으니까, 스폰지클럽에서까지 업무의 연장이라고 느껴지는 결과물을 만들고 싶지 않았다. 흐민의 Selforge가 "사적인 영역이 시스템화된" 부분이 재미있었다.

**Day 2 (5/12)** 뭘 만들지부터가 막막했다
인터뷰 스킬로 6단계 질문을 받으면서 "내가 뭘 불편해하고 있는지"를 꺼냈다. 노션에 "휘발시키지 말자"라는 페이지가 있었는데, 이름과 반대로 계속 휘발되고 있었다. 스크랩은 하는데 다시 안 봄 → 아카이빙 = 망각.

부품 후보를 6개 뽑았는데, 어디서부터 시작할지 고민했다. 텔레그램 입력(#1)부터 할까 했는데, "중간이 죽으면 양 끝이 살 수 없다"는 판단이 들었다. 입력이 있어도 큐레이션이 안 되면 쌓이기만 하고, 출력은 큐레이션된 자산이 없으면 꺼낼 게 없다. 그래서 #5(주간 큐레이션)를 첫 부품으로 골랐다.

**Day 2~3** 첫 드라이런에서 깨달은 것
SKILL.md를 쓰고 "이번 주 꿀팁 정리" 한 줄로 첫 드라이런. 11개 항목에서 6개 후보가 나왔고, 내가 ✓ 한 건 4개. 근데 돌이켜보니 4개가 전부 "도구 소개"가 아니라 "사고방식" 관련이었다. Claude가 미리 알 수 없는, 그 주의 내 관심사였다. 이때 깨달았다. 큐레이션 전체를 자동화하면 안 된다. **자동화할 수 있는 건 "처리"이지 "판단"이 아니다.**

그래서 v2에서 "선택 패턴 관찰" 기능을 넣었다. 내가 선택을 마치면 Claude가 "이번에 고른 거 보니까 전부 사고방식 관련이네 관점을 찾고 있는 것 같다" 하고 한 줄 던져줌. 묻지 않고 관찰한 걸 던진다. "저장 동기"라는 필드도 추가했는데, 이건 "왜 이게 중요하다고 느꼈는지"를 기록하는 칸이다. 지금은 별 것 아닌 데이터지만, 6개월 쌓이면 내 관심사가 어떻게 이동했는지가 보일 거라는 생각.

**Day 3~4** 텔레그램 봇을 붙이면서 현실을 마주침
"텔레그램으로 링크 던지면 자동 저장되면 좋겠다" → 아키텍처를 설계했는데, 세 가지 현실 확인이 필요했다.

**첫째 (24시간 가동)** 텔레그램 봇이 메시지를 받으려면 Claude Code가 켜져 있어야 한다. 컴퓨터 끄면 봇도 꺼진다. 24시간 돌리려면 별도 서버가 필요한데, 지금은 "이 시스템이 쓸 만한지" 검증하는 단계니까 그건 나중에.

**둘째 (자동 실행 예약)** 매주 월요일에 자동으로 큐레이션이 돌아야 하는데, 예약 방법이 두 가지 있었다. 하나는 3일 지나면 예약이 사라지는 방식(CronCreate) — 월요일이 오기 전에 죽으니까 못 씀. 다른 하나는 예약이 영구 저장되는 방식(scheduled-tasks) — 이걸로 선택.

**셋째 (상태 저장)** "지금 큐레이션 진행 중인지, 끝났는지"를 어딘가에 기록해야 하는데, 내 컴퓨터 파일에 저장하면 나중에 서버로 옮길 때 못 씀. 노션에 저장하면 어디서든 접근 가능하고, 내가 직접 노션에서 상태를 확인할 수도 있다.

**Day 4 (5/14)** 봇이 대답을 안 해
텔레그램 봇을 처음 기동했는데, 권한 승인이 6~7번 연속으로 떴다. 노션 × 도구 종류 × DB 종류 조합별로 각각 물어보는 거였다. 처음엔 뭔가 잘못된 줄 알았는데, 한 바퀴 돌고 나니 안 뜸.

PC를 재부팅했더니 Claude Code 인증이 풀려서 봇이 응답을 안 했다. `/login`으로 다시 로그인해야 하는 것도 이때 배웠다.

그런데 더 큰 문제가 있었다. tip-collector가 URL을 저장하고 "저장했어. 제목: ○○" 만 돌려줬다. 너무 일방향이었다. "응, 알았어" 말고는 할 말이 없었다. 그래서 두 가지를 추가했다 — 인사이트("왜 이게 쓸모 있는지")와 패턴 기반 대화("이 분야는 평소에 안 주던데?"). 봇이 과거 DB를 조회해서 카테고리 분포를 보고 대화를 거는 구조. 이게 들어가니까 시스템이 살아있는 느낌이 됐다. "숙제가 되지 않는 시스템"의 핵심은 이거였던 것 같다 — 쓰는 게 귀찮지 않을 정도의 마찰, 그리고 시스템이 나한테 말을 건넨다는 느낌.

**Day 5 (5/15)** — 하나가 되니까 다음이 보인다
텔레그램 봇을 며칠 쓰다 보니 불편한 점이 자연스럽게 보였다. "URL 말고 그냥 떠오른 생각도 던지고 싶은데?" → memo-collector 추가. "꿀팁이 쌓이니까 같은 주제끼리 묶어서 보고 싶은데?" → wiki-synthesizer 추가. 처음부터 계획한 게 아니라 쓰면서 생긴 필요를 그때그때 만든 거다.

대시보드 홈페이지도 만들었다. 흐민의 Selforge처럼 "내 시스템이 돌아가고 있다"를 웹페이지로 보여주고 싶었다. 
wiki-synthesizer를 처음 돌렸더니 "AI 도구 완전 정리", "피노 누아 취향 정리" 문서 2개가 자동으로 만들어졌다. 와인 시음 기록 12개도 넣었다. 업무 관련 AI 도구뿐 아니라 와인 같은 사적 데이터도 시스템 안으로 들어오기 시작한 순간이었다.

### 공유할만한 인사이트
이번 과정에서 가장 크게 느낀 건 "작게 시작하자". "꿀팁 정리 스킬 하나"에서 시작해서, "여기가 불편하네" 하는 지점을 고치다 보니 여기까지 왔다. 처음부터 전체를 설계했으면 아마 미완성으로 끝났을 거다.그리고 시스템이 살아남으려면 "쓰는 게 귀찮으면 안 된다"는 걸 몸으로 체감했다. 승인을 "OK" 한 마디로 끝나게 만든 것, tip-collector가 대화를 걸어오게 만든 것 — 다 같은 이유다. 마찰이 높으면 시스템은 결국 죽는다. "휘발시키지 말자"가 휘발됐던 이유도 결국 그거였다.
