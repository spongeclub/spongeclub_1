### 과정 (타임라인별 + 삽질)

- 흐민 셀포지 링크 붙여넣고 나도 나만의 설리반 만들고 싶다고 요청 
	- `os-interview` 스킬이 발동되어, 인터뷰 진행.
	- 나의 일상에서 일어나는 여러가지 사건들을 분석해서 생각에 대한 방향성과 심지들을 더 키워나가가게 만드는 os
	
- os 선언문
	- 나는 떠오르는 생각·사례·감정을 텔레그램으로 던지는 것만 하고, 나머지는 시스템이 한다.
	- 12:00 점심 체크인 18:00 저녁 체크인 24:00 자기 전 체크인 01:00 일간 회고 리포트 발송 
	- 매 체크인마다 에너지 / 감정 레벨도 같이 캐치

- 4가지 부품 셋팅 후, 첫 부품 메이킹
	- 흐민의 설리반, 위키, 에디터를 차용하여, 4개의 부품들을 셋팅함.
	- 일단, 설리반 역할의 나만의 "센세" 봇을 만들기로 함. 

- 가장 크리티컬 이슈, 노트북 꺼지면 텔레그램 멈춤 이슈
	- tmux는 사실 "노트북 꺼진 시간"을 못 풀어. tmux의 진짜 역할은 "노트북 **켜져있는 동안** 세션을 안 끊기게 유지하는 것"

|방법|노트북 꺼진 시간 해결?|비용|
|---|---|---|
|launchd만|슬립은 catch up, 완전 꺼짐은 못 함|0|
|**launchd + 백필 커맨드** ⭐|둘 다 풀림 (다음 켤 때 회상 질문)|추가 코드 30분|
|클라우드 서버|100% 풀림 (24h 작동)|월 $1~~5 + 셋업 1~~2h|
|tmux만|노트북 슬립도 안 됨|전기·배터리|

- 텔레그램 연결은 되었고, 먼저 질문도 보내주지만, 내가 답을 보내면 묵묵부답.
	- 수동으로 보냈을때에는 가지만, 답장에서 안온다거나 >> 디버그를 했지만 끝내 원인 못찾음.
	- 디버그 오랫동안하니 자기도 지쳤는지.. 낼 하라고 함 ㅋㅋㅋ
	- 집념으로 계속 파다보니 결국 api 505 에러가 떴음.
	- 아무것도 안되어서 전부 삭제하고 처음부터 다시 만듦


- 새로운 세션을 열고 다시 디버그 시작
	- 문제 1 - 봇 점유 충돌 
		- 여러 claude 세션이 다 같은 열쇠로 사서함 보려 함
			- Obsidian 안에서 켠 claude
			- Claude Desktop 안의 세션들
			- 12시 cron 발동된 claude
			- tmux listener
		- 마지막에 도착한 사람만 사서함 차지, 나머지는 fail -> 답장이 누구에게도 전달 못 됨

	- 문제 2 - cron이 claude를 거쳐서 fail
		- 12시에 cron 발동 → claude를 시작 → 텔레그램 reply 시도 → 점유 충돌 → 발송 fail
		- 사용자는 12시 메시지 못 받음 (cron은 정상 발동했는데 메시지 발송만 fail)
		
		- 12시에 비서 한 명 (= claude) 부르지 말고 curl이 직접 처리
			- 비서는 우편함 열쇠 들고 사서함 확인하러 가서 내가 시킨 일 — "친구한테 편지 보내" 를 진행하려함. (텔레그램 polling 시작, 텔레그램 reply 호출)
			- 근데 이미 다른 비서 (Obsidian의 claude)가 사서함 점검 중이여서 실패
			- 따라서 비서 부르지 말고, curl이 직접 우체국 창구로 가서 편지만 부쳐

	- 문제 3 - listener의 `/mcp` menu 모달에 갇힘
		- 내가 디버그 중 `/mcp` 명령 띄워놓고 닫지 않음
		- listener가 modal에 갇혀 새 메시지 처리 안 함
		- Esc 한 번으로 해결
		
		- listener는 사서함 옆에 앉아 있는 비서로, 멀티 태스킹 가능하게 함.
			- 사서함에 편지 오면 처리하는 일을 함.
			- 근데 비서는 MCP 상태표를 들여다보고 있어서 다른일 처리 못함 (이게 `/mcp` 모달)
			- 사서함에 편지 도착했는데(텔레그램 메시지가 도착했는데), 아무일도 못함.
			- 비서한테 "상태표 치워" 명령

	- 문제 4 - # `--channels` flag 빠짐
		- **옛 방식** — 그냥 비서 한 명 채용했는데, 이사람은 직접 일을 시켜야지만 일 함
			- **사서함은 내 일 아니에요** — 사서함에 편지 와도 무시
		- 새 방식 - 비서에게 업무 지정해줌. 직접 시키는 것뿐 아니라, 사서함 관리도 해라.



### 공유할만한 인사이트

- 충돌이 왜 일어날까?
	- 충돌이 많이 나는 이유는 한마디로 말하면, **Telegram 봇은 “한 명의 접수원”만 허용하는데, Claude Code/MCP/Obsidian/tmux/테스트 스크립트가 전부 자기가 접수원이라고 나서기 쉬운 구조**라서 그래요.
	- **Claude Code한테 전화 받기, 문자 읽기, 일 처리하기, 답장 보내기까지 다 시키는 구조**예요. 안정적으로 만들려면 **전화 받는 직원은 따로 두고, Claude는 업무 처리만 하게 분리**하는 게 좋아요.
- 무한 디버그에 지쳤다면 -> Claude Code에게 디버그 구조를 설계하라고 별도 요청 하는 것도 방법
