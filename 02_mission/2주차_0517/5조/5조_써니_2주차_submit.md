## 미션1: 한글 받침 학습 게임 OS 개척기

### Summary
스폰지클럽 진행 기간 내에 끝낼 수 있는 내 삶과 관련된 이슈를 찾다가 아이 한글 학습 문제를 발견했다. 미국에서 자라는 9살 한인 2세 아이는 말하기 듣기는 자연스럽지만 읽기 쓰기가 부족하다.

이번 미션에서는 단순히 게임을 만드는 것보다, Claude와 반복적으로 대화하며 문제를 좁히고 기획 → 에셋 → 구현 흐름을 나만의 방식으로 구조화하는 과정을 OS처럼 구축해보려고 했다.

처음에는 막연하게 “한글 학습 게임”을 만들려고 했지만, 실제로 아이를 관찰하고 구현을 반복하면서 문제는 단순 콘텐츠 부족보다 “받침 단계에서의 인지적 막힘”이라는 걸 구체적으로 발견하게 되었다.

이후 한글 학습과 미국 수업 수준 사이의 괴리를 게임이라는 도구로 해결하려 했고, Claude와 기획하고 에셋을 직접 제작해서 Claude Code로 구현, Vercel로 배포까지 완료했다.

배포:

### 최종 구현 결과물

## 한글 받침 학습 게임 - 받침 우주 탐험

화면 상단에 "가"가 크게 고정돼 있고, 받침 블록 14개가 마인크래프트 스타일로 둥둥 떠다닌다. 손가락 총쏘기 모션으로 블록을 맞추면 상단 글자로 날아가 붙으면서 합쳐진 소리가 난다.

- "가" + ㄱ → "각"
- "가" + ㄴ → "간"
- "가" + ㄹ → "갈"

### 구현된 기능

- MediaPipe 손 인식 기반 손가락 총쏘기 모션 구현
- 직접 녹음한 받침 결합 음성 파일 14개 + 배경음악 적용
- 마인크래프트 스타일 3D 받침 블록 이미지 14개 제작
- 3분 제한 시간 + 실패/클리어 화면 구현
- 일시정지 / 재시작 / 홈 버튼 추가
- 웹캠 기반 PC 환경에서 우선 구현
- 75인치 TV 및 프로젝터 연결 테스트 진행
- 모바일/태블릿 환경은 아직 최적화 전 단계
- MediaPipe 특성상 현재는 웹캠 환경에서 가장 안정적으로 동작
### 과정 (타임라인별 + 삽질)


## 1. 문제 발견 및 인터뷰

일상생활에서 반복적으로 발생하는 두 가지 이슈를 후보로 놓고 Claude로 나 자신을 인터뷰했다.

처음에는 단순히 “아이 한글 문제” 정도로만 생각하고 있었는데, Claude와 대화를 반복하면서 실제 문제는 “9살 아이가 받침 단계에서 인지적으로 막혀있다”는 부분이라는 걸 구체적으로 발견하게 되었다.

막연했던 고민이 대화를 통해 점점 더 선명한 문제 정의로 좁혀지는 경험을 했다.

---

## 2. 기획

처음엔 자음 모음부터 받침까지 전부 구현하려고 했다. 하지만 범위가 너무 크다는 걸 깨닫고 받침만으로 좁혔다.

게임 방식도 여러 번 바뀌었다.

처음에는 글자가 떨어지는 슈팅 게임 형태였는데, 아이 아이디어를 반영하면서 받침 블록을 손가락 총으로 쏘는 방식으로 수정되었다.

“가 + 받침 = 각/간/갈”처럼 소리 변화 자체를 몸으로 체험하게 만드는 방향으로 기획이 점점 바뀌었다.

---

## 3. 첫 번째 삽질 - Web Speech API

처음에는 Web Speech API만으로 소리를 해결하려 했다.

하지만 발음이 어색하고 불안정했고, 게임 화면은 제대로 안 보이는데 소리만 반복 재생되는 상황도 발생했다.

이 과정에서 “Claude Code가 전부 해결해줄 것”이라고 생각했던 기대가 깨졌고, 인터랙티브 프로젝트에서는 코드보다 에셋·사운드·UX가 훨씬 중요할 수 있다는 걸 몸으로 배우게 되었다.

에셋 없이 코드만 먼저 돌리면 결과물이 쉽게 엉성해진다는 것도 직접 체감했다.

---

## 4. 에셋 준비

Web Speech API 삽질 이후 에셋을 직접 만들기로 방향을 바꿨다.

### 오디오

결합음 14개는 직접 녹음으로 해결했다.

배경음악은 스폰지클럽 특강을 통해 해결했다.

배짱(박종배)님의 AI 음악 생성 특강에 참여해서 Suno라는 AI 음악 툴을 처음 접했고, 바로 게임 배경음악에 적용했다.

특강을 듣고 바로 실전에 써먹은 케이스였다.

### 이미지

처음에는 AI가 한글 형태를 계속 재해석해서 ㄱ/ㅅ 같은 글자 외곽이 무너졌다.

여러 대화창과 이미지 생성 툴을 오가며 작은 큐브 밀도, 카메라 각도, 글자 외곽 형태 규칙을 계속 수정했다.

특히:

- 뒤집지 마
- 곡면화 금지
- 큐브 크기 유지
- 글자 외곽 유지

같은 금지 규칙을 명확하게 정의하는 게 결과 퀄리티를 훨씬 안정시킨다는 걸 배웠다.

시리즈 작업에서는 개별 이미지 하나보다 큐브 크기, 빛 번짐 강도, 보는 각도와 구도를 끝까지 통일해서 모든 글자가 하나의 게임 세계관처럼 보이게 만드는 게 가장 중요했다.

---

## 5. 구현 및 배포

에셋이 준비된 상태에서 Claude Code에 MD 파일로 정리한 기획서를 넣었더니 결과물이 훨씬 깔끔하게 나왔다.

Vercel로 배포까지 완료했다.

### 공유할만한 인사이트 
## MD 파일의 진짜 의미

처음부터 MD 파일을 만들려고 한 게 아니었다.

Claude랑 대화하면서 기획을 정리하다 보니 자연스럽게 MD 파일이 만들어졌다.

새 창 열 때마다 같은 말을 반복해야 하는 불편함의 해결책이 MD 파일이었다.

Claude Code든 미드저니든 어떤 툴에든 붙여넣으면 맥락이 유지된다.

다니가 말한 “규칙 문서화가 자동화의 90%”를 머리가 아니라 몸으로 깨달았다.

---

## 에셋 먼저, 구현은 나중

소리랑 이미지 없이 Claude Code만 돌리면 결과물이 엉성하다.

에셋을 먼저 완성하고 나서 Claude Code에 넣어야 원하는 결과물이 나온다.

---

## 작게 시작해서 확장하기

“가” 스테이지 하나만 먼저 완성하고 테스트한 다음 나머지를 추가하는 방식이 맞다.

처음부터 전부 만들려고 하면 중간에 꼬인다.

---

## 순서가 중요하다

문제 발견 → Claude로 나 자신을 인터뷰해서 진짜 필요한 것 찾기 → 기획 → MD 파일 정리 → 에셋 준비 → Claude Code 구현 → 배포.

이 순서를 지켜야 결과물이 제대로 나온다.

처음에는 AI가 결과물을 대신 만들어줄 거라고 생각했는데, 실제로는 내가 문제를 얼마나 명확하게 구조화하느냐가 결과 퀄리티를 결정한다는 걸 느꼈다.

결국 Claude Code는 “알아서 완성해주는 도구”라기보다, 내가 정리한 맥락과 규칙을 기반으로 구현을 도와주는 협업 도구에 가까웠다.
