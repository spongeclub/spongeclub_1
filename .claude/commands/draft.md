description: 클로드코드 작업 내역을 날짜 범위로 추출해 미션 노트 초안 자동 생성 (미션별로 분류, AI 초안임을 callout으로 표시)
argument-hint: <시작MMDD>[-종료MMDD] [조-닉네임]
---

$ARGUMENTS 기간의 클로드코드 작업 내역을 **미션별로 분류**해서 미션 노트 초안을 만든다.

## 사용법

```
/draft 0510-0516       → 5월 10~16일 작업 요약
/draft 0510            → 5월 10일 하루 작업
/draft 0510-0516 1조-신연수   → 멤버 명시 (운영진 대신 작성할 때)
```

`$ARGUMENTS` 첫 토큰은 **MMDD** 또는 **MMDD-MMDD** 형식의 날짜 범위.
연도는 오늘 기준으로 자동 추론(같은 해 또는 가장 가까운 과거).

## 핵심 원칙 — "사람이 헷갈리지 않게"

- **미션 제목은 운영진이 정한 그대로 유지**. `/draft`는 본문만 채운다.
- 미션 헤더(`## 미션 1`, `## 미션 2`, ...)와 그 안의 서브헤더(`### Summary` 등)는 **건드리지 않는다**. AI 초안은 각 미션 헤더 **바로 위**에 콜아웃으로 붙는다.
- AI가 작성한 모든 본문은 **Obsidian callout** `> [!ai]` 안에 넣는다. 멤버 본인 글과 시각적으로 구분.
- 검토 후 멤버가 콜아웃을 통째로 지우면 = "검토 완료" 표시.
- 사실이 아닌 것은 추측해서 채우지 않는다. 빈 칸이 낫다.
- 입력한 날짜 범위 **밖** 작업은 절대 끌고 오지 않는다.
- **분류 자신감이 약하면 "분류 불명" 콜아웃**으로 빼고, 미션 콜아웃엔 안 박는다.

## 실행 절차

### 0. 인자 파싱
- 첫 토큰: `MMDD` 또는 `MMDD-MMDD`
  - `0510` → 단일 날짜
  - `0510-0516` → 범위 (양쪽 포함)
- 둘째 토큰(선택): `{조}-{닉네임}` (운영진이 멤버 대신 작성할 때만)

연도 추론: 오늘 날짜 기준 같은 해. 같은 해 미래라면 작년으로 해석할지 멤버에게 한 번 확인.

### 1. 멤버 정보 확인
- `99_meta/멤버목록.md`에서 본인의 **조**와 **닉네임** 확인
- 모르면 한 번에 물어본다

### 2. 주차 매핑 (어느 주차 노트에 들어가나)
- `99_meta/주차일정.md`의 주차별 시작·종료 날짜를 읽는다
- 입력 날짜 범위가 어느 주차 범위와 가장 많이 겹치는지 계산
- **단일 주차에 포함**: 그 주차 노트로 진행
- **여러 주차에 걸침**: 멤버에게 묻기
  > "{시작}~{종료} 범위가 N주차와 M주차에 걸쳐 있어요. 어느 주차 노트에 채울까요?"
- **주차 범위 밖**: 멤버에게 묻기
  > "{시작}~{종료}는 정의된 주차 일정 밖입니다. 어느 주차 노트에 넣을지 알려주세요."

### 3. 대상 파일 경로 산출
- 매핑된 주차 → `99_meta/주차일정.md`의 폴더 컬럼
- 파일명: `{조}_{닉네임}_{주차}주차_submit.md`
- 노트를 읽어 미션 헤더(`## 미션 1: ...`, `## 미션 2: ...`, `## 미션 3: ...`)와 그 아래 서브섹션 구조를 파악

### 4. 미션 키워드 자동 추출 (사용자에게 묻지 않음)

대상 노트의 미션 헤더에서 키워드를 **자동 추출**한다. 매번 확인받지 않는다 — 분류 근거는 9단계의 아카이브 노트에 남겨서 멤버가 사후 검증·수정 요청할 수 있게 한다.

키워드 추출 가이드:
- 제목의 **명사**(도구·기능·주제), **고유명사**(claude code, /skill, linkedin), **동작 동사**(인터뷰, 벤치마킹, 작성)를 후보로
- 너무 흔한 단어("작업", "정리", "만들기")는 제외
- 미션당 보통 3~6개 키워드

미션 헤더가 `<제목>` 플레이스홀더면:
> "운영진이 아직 미션 제목을 정하지 않은 것 같아요. `/set-missions` 실행을 권합니다. 그래도 진행하려면 미션별 키워드를 직접 알려주세요."

### 5. 작업 내역 수집

`mcp__plugin_oh-my-claudecode_t__session_search` 로 입력 날짜 범위 안 클로드코드 세션 검색.

수집할 단위(이걸 "활동 항목"이라 부른다):
- 만든/수정한 파일 (파일 경로 단위)
- 실행한 명령어 (특히 슬래시 명령, npm/git, 에러 + 해결)
- 의사결정 (대안 비교가 있었으면 함께)
- git 커밋 메시지

각 활동 항목은 **단일 문장으로 요약 가능한 단위**여야 한다 (분류 단위가 됨).

세션 검색 결과 없음:
- "{기간} 범위 세션이 없네요. 현재 대화창 내용으로 진행할까요?" 라고 물어보고, 동의 시 현재 세션만 사용.

### 6. 미션별 분류

각 활동 항목에 대해, 4단계에서 확정된 미션별 키워드 셋과 매칭:

**매칭 규칙:**
- 활동 항목의 텍스트(파일명, 명령어, 설명)에 미션N의 키워드가 1개 이상 포함되면 → 미션N 후보
- 여러 미션에 동시 매칭되면 → 매칭 키워드 수가 많은 쪽 선택 (동률이면 "분류 불명")
- 어느 미션에도 매칭 안 되면 → "분류 불명"

**자신감 표시:**
- 강함: 키워드 2개 이상 매칭 또는 미션 제목 핵심어 직매치
- 약함: 키워드 1개 + 흔한 단어 — **약하면 "분류 불명"으로 빼는 걸 권장**
- 추측 금지: 키워드 매칭 없이 "이 미션과 관련있어 보인다"는 추측은 금지

**분류 근거 기록:**
각 항목마다 분류 근거 한 줄을 함께 적는다 (멤버 검증용):
> "→ 미션1 (근거: 'claude-code', '인터뷰스킬' 매칭)"

### 7. 초안 생성 — 미션별 콜아웃을 미션 헤더 위에 배치

기존 노트의 `## 미션 N: ...` 헤더 **바로 위**에 해당 미션의 콜아웃을 삽입한다.
처리 규칙:
- **이미 같은 위치에 `> [!ai]+` 콜아웃이 있으면** → 덮어쓸지 추가할지 멤버에게 묻는다.
- **콜아웃이 지워져 있으면** → 멤버가 정리 완료한 미션이므로 그 미션은 건너뛰고 안내.
- **활동이 분류 안 된 미션** → 그 미션 위에는 *"해당 작업 없음"* 콜아웃을 넣되 본문은 비워둔다.

#### 7-1. 미션별 콜아웃 형식 (각 미션 헤더 바로 위에 삽입)

```markdown
> [!ai]+ 🤖 미션N 초안 — {기간} 세션에서 분류
> 아래 항목을 본문(`### Summary` 등)에 옮긴 뒤 본인 말투로 다듬어주세요.
> 정리 끝나면 이 콜아웃은 통째로 삭제 = 검토 완료.
>
> **Summary**
> (한 줄)
>
> **최종 구현 결과물**
> - (만든 파일·결과물·스크린샷 placeholder)
>
> **과정 (타임라인 + 삽질)**
> - YYYY-MM-DD: 무엇 시도 → Y 에러 → Z로 해결
> - YYYY-MM-DD: ...
>
> **공유할만한 인사이트**
> - (배운 점)
>
> 📎 분류 근거: {매칭된 키워드들}

## 미션 N: {확정 제목}
...(기존 본문 그대로)
```

미션3처럼 구조가 다르면(링크만):
```markdown
> [!ai]+ 🤖 미션3 초안 — 링크 후보
> 본인이 작성한 SNS 글 URL을 직접 채워주세요. AI는 URL을 만들지 않습니다.
>
> **링크 후보**
> - (세션에서 발견된 SNS·링크 단서가 있으면 표시, 없으면 *"세션에서 단서 없음"*)
>
> 📎 분류 근거: {매칭된 키워드들}

## 미션 3: {확정 제목}
```

#### 7-2. "분류 불명" 콜아웃 — 노트 맨 아래에 1개

분류 안 된 활동들은 노트 **맨 아래**에 별도 콜아웃으로 모아둔다 (본인이 미션에 옮기거나 버릴 수 있게):

```markdown
> [!ai]- 🗑 분류 불명 — {기간} 세션에서 미션과 매칭되지 않은 작업
> 미션 키워드와 매칭이 약해서 자동 분류에서 뺀 항목입니다.
> 보고 어느 미션으로 옮길지 / 무시할지 본인이 판단해주세요.
>
> - YYYY-MM-DD: {활동 요약} (이유: 키워드 매칭 없음)
> - YYYY-MM-DD: {활동 요약} (이유: 미션1·2 둘 다 약하게 매칭됨 — 동률)
> - ...
```

`[!ai]-` (접힘 상태)로 두어서 노트가 깔끔하게 보이게 한다.

#### 7-3. 빈 미션 안내

특정 미션에 분류된 항목이 0개면, 콜아웃은 짧게:
```markdown
> [!ai]+ 🤖 미션N 초안 — 해당 작업 없음
> {기간} 세션에서 미션N({제목})에 매칭되는 작업을 찾지 못했어요.
> 다른 도구로 작업했거나 아직 미진행일 수 있습니다. 직접 채워주세요.
```

### 8. 작성 원칙

- **사실만**: 세션에 없는 내용은 추측해서 채우지 않는다.
- **숫자/링크는 그대로**: 파일명, 명령어, URL은 변형 없이 인용.
- **삽질은 구체적으로**: "어려웠다" 금지. "X 명령어가 Y 에러를 내서 Z로 해결" 형태.
- **본인 말투로 다시 쓸 수 있게**: AI 초안은 정보 위주, 톤은 멤버 몫.
- **링크는 멤버가 직접**: AI는 URL을 만들어내지 않는다 (placeholder만).
- **분류 근거 투명하게**: 미션에 박은 이유(매칭 키워드)를 항상 표시.

### 9. 분류 아카이브 저장 (자동, 멤버에게 안 묻고 항상 생성)

분류 근거를 멤버가 사후 검증·수정 요청할 수 있도록 별도 노트에 아카이빙한다.

**저장 위치:** `99_meta/draft_archive/{조}_{닉네임}_{N}주차_{YYYY-MM-DD}.md`
- 동일 멤버·주차에 같은 날 여러 번 실행하면 → `_2`, `_3` suffix
- 다른 날 재실행은 별도 파일 (이력 보존)

**아카이브 노트 형식:**

```markdown
---
type: draft_archive
member: {조} {닉네임}
week: {N}
period: {시작MMDD}-{종료MMDD}
generated_at: {ISO 타임스탬프}
target_note: {대상 미션 노트 경로}
---

# /draft 분류 아카이브 — {조} {닉네임} {N}주차

> 이 노트는 `/draft {시작}-{종료}` 실행 시 자동 생성됐습니다.
> 분류가 잘못됐다면 멤버에게 어느 항목을 어디로 옮길지 알려주세요. 다시 실행 시 참고합니다.

## 입력
- **기간**: {시작 ISO ~ 종료 ISO}
- **대상 노트**: [[{대상 노트 파일명}]]
- **세션 검색**: {찾은 세션 수}개

## 사용된 키워드 (자동 추출)

| 미션 | 제목 | 키워드 |
|-----|-----|-------|
| 미션1 | {제목1} | {kw1, kw2, ...} |
| 미션2 | {제목2} | {kw1, kw2, ...} |
| 미션3 | {제목3} | {kw1, kw2, ...} |

## 분류 결과

### 미션1 — {제목1} ({N}건)
- `{YYYY-MM-DD}` {활동 요약} — 매칭: `{매칭 키워드들}`
- ...

### 미션2 — {제목2} ({N}건)
- ...

### 미션3 — {제목3} ({N}건)
- ...

### 🗑 분류 불명 ({N}건)
- `{YYYY-MM-DD}` {활동 요약} — 사유: {키워드 매칭 없음 / 다중 매칭 동률 / ...}
- ...

## 수정 요청 가이드
분류가 잘못됐다면 다음과 같이 알려주세요:
- "X 항목을 미션2로 옮겨줘"
- "Y 키워드를 미션1에 추가해서 다시 분류해줘"
- "Z는 분류 불명에서 빼고 무시해도 돼"

다음 `/draft` 실행 시 이 아카이브를 참고할 수 있습니다.
```

### 10. 저장 후 안내

```
✅ 초안 저장: {대상 노트 경로}
✅ 아카이브 저장: 99_meta/draft_archive/{파일명}

   기간: {시작}~{종료}, 매핑: {N주차} 노트
   분류 결과:
     - 미션1 ({제목}): {N}건
     - 미션2 ({제목}): {N}건
     - 미션3 ({제목}): {N}건
     - 분류 불명: {N}건 (노트 맨 아래 콜아웃)

검토 가이드:
1. 각 미션 헤더 위 파란 callout(> [!ai])이 AI 초안입니다. 사실 확인 부탁드려요.
2. 본문(### Summary 등)에 옮겨 다듬으신 뒤, 콜아웃은 통째로 삭제 = "검토 완료".
3. 노트 맨 아래 "분류 불명" 콜아웃을 보고 적절한 미션으로 옮기거나 무시해주세요.
4. 링크는 본인이 직접 URL로 채워주세요.
5. 분류 근거는 `99_meta/draft_archive/`에 저장됐습니다. 잘못된 분류가 있으면 그 파일 보고 수정 요청해주세요.
```
