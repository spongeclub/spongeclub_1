---
description: 주차별 미션 과제 노트 작성/보강 (초안 있으면 구조화, 없으면 질문으로 수집)
argument-hint: <주차번호> [주제]
---

$ARGUMENTS 에 대한 미션 과제 노트를 작성해줘.

## 사용법
```
/mission 4 웹사이트 구축          → 4주차, "웹사이트 구축" 주제
/mission 4 CRM 알림톡 자동화      → 4주차, "CRM 알림톡 자동화" 주제
/mission 4                       → 4주차, 주제 미정 (질문으로 확인)
```

$ARGUMENTS에서 첫 번째 숫자는 주차, 나머지는 주제다.
주제가 없으면 "이번 주에 뭘 만들었어?"부터 물어본다.

## 실행 절차

### 0. 인자 파싱 + 모드 판별
- $ARGUMENTS에서 주차 번호(숫자)와 주제(나머지 텍스트)를 분리한다
- 해당 멤버의 과제 파일이 이미 존재하는지 확인한다:
  - `00_missions/Week_0{주차}_submit/` 폴더에서 `Week_0{주차}_{멤버이름}_submit.md` 파일을 찾는다
  - **파일이 있고 내용이 있으면** → 초안 다듬기 모드 (Step 2-B)
  - **파일이 없거나 비어있으면** → 처음부터 작성 모드 (Step 2-A)

모드를 알려주고 진행한다:
- "이미 작성하신 초안이 있네요! 구조를 잡고 내용을 보강해드릴게요."
- "{주제}에 대해 과제 노트를 작성할게요! 질문 몇 가지 드릴게요."

### 1. 멤버 정보 확인
- `99_meta/멤버목록.md`에서 현재 사용자의 이름을 확인한다
- 이름을 모르면 물어본다

### 2-A. 처음부터 작성 모드
주제가 있으면 해당 주제에 집중해서 질문한다. 주제가 없으면 먼저 물어본다.
아래 질문을 순서대로 물어본다. 멤버가 자유롭게 답하면 된다:

1. **이번 주에 뭘 만들었어?** (프로젝트명 + 한 줄 설명)
2. **결과물 링크가 있어?** (웹사이트, GitHub 등 — 없으면 건너뛰기)
3. **만드는 과정에서 삽질한 거 있어?** (에러, 시행착오, 돌아간 길)
4. **이번 주 배운 점이나 인사이트는?** (다른 멤버들에게 도움될 만한 것)
5. **다시 한다면 뭘 다르게 하겠어?**
6. **대략 몇 시간 투입했어?**
7. **사용한 기술 스택은?** (도구, 프레임워크, API 등)

### 2-B. 초안 다듬기 모드
멤버가 이미 적어놓은 초안을 읽고 다음을 수행한다:

1. **구조화** — 아래 템플릿(결과물 / 삽질 과정 / 인사이트 / 다시 한다면)에 맞게 내용을 재배치한다. 원본 내용은 절대 삭제하지 않는다.
2. **보강 질문** — 초안에 빠진 항목이 있으면 물어본다:
   - 결과물 링크가 없으면: "혹시 결과물 링크가 있어?"
   - 삽질 과정이 없으면: "만드는 과정에서 막힌 부분이 있었어?"
   - 인사이트가 없으면: "이번 주 배운 점이 있다면?"
   - 투입 시간이 없으면: "대략 몇 시간 정도 투입했어?"
3. **frontmatter 보완** — 없으면 추가, 있으면 빠진 필드만 채운다
4. **문체 유지** — 멤버가 쓴 말투와 표현을 최대한 살린다. AI 톤으로 다시 쓰지 않는다.
5. **도식 추가** — 흐름이나 구조를 설명하는 내용이 있으면 텍스트 다이어그램(```로 감싼 도식)을 제안한다

### 3. 과제 노트 생성
수집한 내용으로 아래 구조의 마크다운 파일을 생성한다:

**파일 경로:** `00_missions/Week_0$ARGUMENTS_submit/Week_0$ARGUMENTS_{멤버이름}_submit.md`

```markdown
---
member: {멤버이름}
week: $ARGUMENTS
date: {오늘날짜}
tags:
  - 과제
  - {관련 태그들}
---

# {프로젝트명 또는 과제 제목}

## 결과물

{만든 것 설명. 링크가 있으면 포함.}

## 삽질 과정

{시행착오, 에러, 해결 과정. 구체적으로.}

## 인사이트

{배운 점, 다른 멤버들에게 공유할 만한 것.}

## 다시 한다면

{회고. 개선할 점.}

---

**투입 시간:** 약 N시간
**기술 스택:** {사용한 도구/프레임워크}
```

### 4. 작성 원칙
- 멤버가 말한 내용을 그대로 살린다. 과도하게 다듬거나 미화하지 않는다.
- 삽질 과정은 구체적으로 쓴다. "어려웠다"가 아니라 "무슨 에러가 나서 어떻게 해결했다"로.
- 도식(```로 감싼 다이어그램)이 필요하면 추가한다.
- 이미지가 있으면 같은 Week 폴더에 저장하고 `![[이미지.png]]`로 삽입한다.

### 5. 저장 후 안내
파일 저장 후 멤버에게 안내:
- "Obsidian에서 `00_missions/Week_0$ARGUMENTS_submit/` 폴더를 열면 과제 노트가 있습니다."
- "내용을 수정하고 싶으면 직접 편집해도 되고, 저한테 말해주셔도 됩니다."
