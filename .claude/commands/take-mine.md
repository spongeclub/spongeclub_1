스터디 종료 후, 공용 레포에 흩어진 **본인 작업물만** 골라 이미지까지 챙겨
**개인 GitHub 레포(Private)로 이관**한다. 이관 후에는 그 레포에서 작업 = 커밋이 내 레포로 간다.

> 추출 로직은 레포 루트 `take-mine.py`가 담당(검증됨). 이미지 두 방식(`![](path)` + `![[파일명]]`)을
> 모두 해석해 본인 게 참조하는 이미지만 가져오고, 주차별 폴더로 평탄화한다.

## 트리거 문구
- `/take-mine`
- "내 작업물 가져갈래", "내 거 내 레포로 옮겨줘", "작업물 이관해줘"

## 실행 절차

### 1. 멤버 확인
- `99_meta/멤버목록.md`에서 본인 **조와 닉네임** 확인 (인자로 주어지면 우선)
- 모르면 물어본다: "본인 조와 닉네임 알려주세요 (예: 3조 흐민)"
- **닉네임은 멤버목록 표기 그대로**(괄호 앞). 파일명 prefix와 일치해야 한다.

### 2. 추출 (평탄화 모드)
레포 루트에서:
```bash
python3 take-mine.py {조} {닉네임} --flat
```
- 결과: `_export/{조}_{닉네임}/` 에 주차별 폴더 + 이미지로 정리됨
- `python3` 없으면 `python`으로 재시도
- 스크립트 출력(노트 N · 이미지 M · 못 찾은 이미지)을 사용자에게 전달.
  못 찾은 이미지는 대개 템플릿 자리표시자/외부링크 → 정상이라고 안내.

### 3. 공용 레포 밖으로 분리
> ⚠️ 핵심: 추출물을 **공용 레포 안에 두면 안 된다**(레포 중첩). 부모 폴더로 옮긴다.
```bash
mv _export/{조}_{닉네임} ../{조}_{닉네임}
```
- 같은 이름 폴더가 이미 있으면 사용자에게 확인 후 다른 이름 사용.

### 4. 개인 GitHub 레포 생성 + push
레포 이름을 사용자에게 확인한다(기본 제안: `{닉네임}-스폰지클럽` 또는 본인 프로젝트명).
```bash
cd ../{조}_{닉네임}

# 간단한 README 생성 (선택)
# "# {닉네임}의 스폰지클럽 작업물 \n\n스폰지클럽 AI 스터디(2026)에서 만든 작업물 아카이브." 정도

git init -b main
git add .
git commit -m "스폰지클럽 작업물 이관 ({조} {닉네임})"
gh repo create {레포이름} --private --source=. --remote=origin --push
```
- `gh` 미인증이면 `gh auth login` 먼저 안내.
- 생성된 레포 URL을 사용자에게 보여준다.

### 5. 완료 보고 + 이후 작업 안내
```
✅ 이관 완료 → https://github.com/{유저}/{레포이름}  (Private)
   로컬 작업 폴더: ../{조}_{닉네임}

이제부터는 이 폴더에서 작업하세요. 공용 레포가 아니라 여기서 커밋하면
자동으로 본인 레포로 올라갑니다:
   cd ../{조}_{닉네임}
   (수정) → git add . → git commit → git push
```

## 주의
- **공용 레포 원본은 절대 수정하지 않는다.** 읽어서 추출만 한다.
- 추출물은 `_export/`(gitignore됨) → 부모 폴더로 **분리**해야 독립 레포가 된다 (레포 중첩 방지).
- 평탄화 시 이미지는 각 `<주차>/attachments/`로 들어가고 md 링크가 그에 맞게 재작성됨 — 그대로 두면 링크 유지.
- "이후 커밋이 내 레포로"는 별도 설정이 아니라 **작업 위치의 문제** — 공용 레포 클론이 아닌
  새 개인 레포 폴더(`../{조}_{닉네임}`)에서 작업하면 자연히 그쪽으로 커밋된다.
- 옵시디언 볼트에 그대로 합치고 싶은 사람은 `--flat` 없이 실행(구조보존 모드)하면 된다.

## 사용 예
```
/take-mine                → 조·닉네임 확인 후 전 과정(추출→분리→레포생성→push)
/take-mine 3조 흐민        → 흐민 작업물 바로 이관
내 거 내 레포로 옮겨줘      → 동일 동작
```
