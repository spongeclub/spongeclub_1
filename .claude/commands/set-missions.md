$ARGUMENTS 의 미션 제목을 해당 주차 모든 멤버 노트에 일괄 적용한다.

## 사용법

```
/set-missions 1 "AI 코딩 어시스턴트 비교 체험"
/set-missions 1 "AI 코딩 어시스턴트 비교" "프롬프트 라이브러리"
/set-missions 1 "X" "Y" "Z"
/set-missions 1                       → 인터랙티브 (미션 개수와 제목을 질문)
```

## 왜 필요한가

멤버마다 같은 미션을 다른 이름으로 쓰면 `/analyze`가 동일 미션을 묶어서 비교/분석할 수 없다.
이 명령어는 **운영진이 주차 시작 시 한 번 실행**해서 모든 멤버 노트의 `## 미션1: <제목>` 줄을 동일한 제목으로 통일한다.

## 실행 절차

### 0. 인자 파싱
- 첫 토큰: 주차번호 (1~6)
- 나머지: 따옴표로 묶인 미션 제목들 (1~3개)
- 제목 없으면 인터랙티브 모드:
  - "이번 주 미션은 몇 개인가요? (1~3)"
  - 개수만큼 제목 물어봄

### 1. 권한 확인
운영진(위시·솔라·에밀리·키니) 또는 조장만 실행하라고 안내. 강제는 아님.

### 2. 대상 폴더 확인
주차 매핑:
- `1` → `02_mission/1주차_0510/`
- `2` → `02_mission/2주차_0517/`
- `3` → `02_mission/3주차_0524/`
- `4` → `02_mission/4주차_0531/`
- `5` → `02_mission/5주차/`
- `6` → `02_mission/6주차/`

해당 폴더 아래 6개 조 폴더(`1조`~`6조`) 안 모든 `*_submit.md` 파일이 대상.

### 3. 일괄 치환

각 파일에 대해:
- `## 미션1: <제목>` 줄을 `## 미션1: {입력제목1}` 로 교체
- `## 미션2: <제목>` → `## 미션2: {입력제목2}` (제목 없으면 `## 미션2: (이번 주 미사용)`)
- `## 미션3: <제목>` → `## 미션3: {입력제목3}` (제목 없으면 `## 미션3: (이번 주 미사용)`)

**중요**:
- `## 미션N:` 줄만 교체. 그 아래 본문은 절대 손대지 않는다 (멤버가 이미 작성한 내용 보존).
- 제목이 이미 `<제목>` 플레이스홀더가 아닌 경우 (= 멤버나 운영진이 이전에 수정함)도 덮어쓴다. 통일이 우선.
- 제목에 특수문자가 있으면 sed 이스케이프 주의.

### 4. 미션 정의 파일 저장 (옵션, 기록용)

`02_mission/{주차폴더}/_missions.md` 에 정의를 저장:

```markdown
---
week: {주차}
set_at: {오늘날짜}
set_by: {운영진닉네임}
---

# {주차}주차 미션

- **미션1**: {제목1}
- **미션2**: {제목2 또는 "미사용"}
- **미션3**: {제목3 또는 "미사용"}

> 이 파일은 `/set-missions {주차}` 실행으로 자동 생성됩니다.
> `/analyze {주차}`가 미션 제목을 키로 사용해 멤버 결과물을 묶어 분석합니다.
```

### 5. 검증 + 리포트

```
✅ {주차}주차 미션 제목 일괄 적용 완료

미션1: {제목1}
미션2: {제목2 또는 미사용}
미션3: {제목3 또는 미사용}

적용된 파일: {N}개 (1조 14, 2조 13, 3조 13, 4조 12, 5조 12, 6조 13)

다음 단계:
- 멤버: `/draft {주차}` 또는 직접 작성으로 본문 채우기
- 운영진(주말): `/analyze {주차}` 로 통합 분석
```

샘플 1개 파일을 읽어서 미션 헤더가 올바르게 갱신됐는지 확인 후 보고.

## 작성 원칙

- 본문 절대 보존. 헤더 줄(`## 미션N:`)만 교체.
- 제목은 분석에 쓰이는 키이므로 한 번 정하면 바꾸지 않는 게 좋다. 변경 시 멤버 노트와 분석 결과가 어긋날 수 있음을 안내.
