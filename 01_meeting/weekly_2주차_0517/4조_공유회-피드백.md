# 4주 - 피드백 공유회

본 문서는 스폰지 클럽 4주 차 피드백 공유회의 내용을 정리한 것으로, 참가자들이 각자 구현한 개인 OS 및 콘텐츠 자동화 도구의 진행 상황과 인사이트를 공유하고, 기술적 문제에 대한 질의응답을 나눈 자리이다.

---

## 발표 1: 캐릭터 기반 SNS 콘텐츠 자동화 도구

첫 번째 발표자는 로컬 파일에 저장된 캐릭터 이미지를 활용해 SNS 콘텐츠(캐러셀)를 자동 생성하는 도구를 구현한 과정을 공유했다. 생성된 콘텐츠는 Supabase JSON 파일로 영구 보관하여 다른 컴퓨터에서도 재사용할 수 있도록 설계했다.

**주요 구현 내용 및 인사이트:**

- **캡션 자동 삽입**: 크루 SNS 인증 시 해시태그와 계정 태그를 매번 수동으로 확인하는 데 시간이 과다 소요되어, Claude에게 캡션 자동 삽입 기능을 요청해 구현했다.
- **보안 기능 추가**: 초기에는 로그인/로그아웃 기능을 생략했으나, 잘못 공유될 경우를 대비해 어드민 기능을 추가했다.
- **프롬프트 제어 전략**: Claude가 지시 없이 임의로 결과물을 생성하는 문제를 해결하기 위해 "추측하지 말고 질문으로 확인해 달라"는 지시를 사전에 부여했으며, 이후 불필요한 수정 작업이 크게 줄었다.
- **이미지 생성 품질 향상**: 텍스트 프롬프트만으로는 원하는 이미지가 나오지 않아, 레퍼런스 이미지를 합성한 뒤 Claude에 업로드하고 "이 레이아웃은 참고하되, 색상은 내 디자인 시스템 파일 기준으로만 적용해 달라"는 방식으로 구현 정확도를 높였다.
- **캐릭터 시트 활용**: 표정, 질감, 포즈 등을 담은 캐릭터 시트를 미리 제작해 로컬 폴더에 저장해 두는 것이 이미지 일관성 유지에 효과적이었다.
- **Claude Code의 한계**: Gemini나 ChatGPT와 달리 Claude Code는 생성된 텍스트를 직접 수정해 재생성하는 기능이 지원되지 않아, 사전 지시 방식이 더욱 중요하다.
- 향후 Claude와의 대화 기록을 공유해 콘텐츠 소재를 자동으로 추출하는 기능도 구현할 예정이다.

## 발표 2: 개인 OS 구축 및 멀티 디바이스 연동

두 번째 발표자(먼지민)는 책상 조립 중인 상황에서도 PC·노트북·모바일 간 연동 및 아침/저녁 브리핑 시스템 구축 과정을 공유했다.

**주요 구현 내용 및 인사이트:**

- **토큰 사용량 최적화**: Claude Max 20 플랜의 주간 한도를 반복적으로 초과하는 문제를 해결하기 위해, 컨텍스트 제공 방식을 체계화했다. 반드시 읽어야 할 룰을 별도로 모아두고, 메모리와 폴더를 분류해 특정 작업 시 관련 폴더만 읽도록 설정한 결과 토큰 사용량이 크게 감소했다.
- **텔레그램 로그 시스템**: 터미널이나 텔레그램 채널을 통한 Claude 대화는 UI 세션으로 남지 않아 추후 참조가 어렵다는 문제를 해결하기 위해, 모든 텔레그램 대화를 저장하는 로그 시스템을 구축하고 폴더별로 정리했다.
- **모바일 연동**: 아이폰에서 Git과의 연동이 원활하지 않은 문제를 **워킹 카피(Working Copy)** 앱으로 해결했다. 이 앱을 통해 Obsidian(로컬 기반 앱)에서도 GitHub 풀/푸시가 가능해져 PC와 모바일 간 작업 연속성이 확보됐다. 워킹 카피는 44,000원 일시불 결제로 영구 사용 가능하며, 7일 무료 체험이 제공된다.
- **OS 구조 설계**: 컴퓨터 구조론의 운영 체제 개념도를 벤치마킹해 개인 OS 폴더 트리를 설계했으며, 이를 개인 프라이빗 GitHub 레포지토리와 연결해 관리 중이다.

## 발표 3: 텔레그램 음성 입력 및 일정 관리 자동화

세 번째 발표자는 텔레그램에 음성 메시지를 보내면 **Whisper**가 이를 텍스트로 변환하고, Claude가 내용을 분석해 할 일·미팅·인사이트로 자동 분류하는 시스템을 구현했다.

**주요 구현 내용 및 인사이트:**

- **음성 입력 지원**: 텍스트 입력 외에 음성 메시지로도 할 일을 입력할 수 있어 편의성이 높다.
- **Google 캘린더 연동**: 미팅 일정을 파악해 Google 캘린더에 자동 등록하는 플러그인 연동을 구현 중이다.
- **연속 작업 흐름**: 단순히 지시를 던지고 끝내는 것이 아니라, Claude와 대화를 이어가며 할 일을 점점 구체화하는 방식이 효과적이었다. 예를 들어 "다음 주 월요일 오전 9시 30분 미팅, 자료 준비 필요"라고 입력하면 Claude가 미팅과 할 일을 분리해 일정을 잡고, 추가 요청 시 MD 파일 형태의 사전 미팅 자료 초안까지 생성했다.
- **우선순위 리마인드**: "급한 일보다 쉬운 일을 먼저 하려는 성향이 있으니, 우선순위를 파악해 리마인드해 달라"는 지시를 봇에 사전 설정해 두었다.
- 맥북이 켜져 있어야만 아침 브리핑이 작동하는 제약이 있으며, 터미널 상시 실행 없이도 동작하도록 직전에 수정한 상태로 검증 중이다.

## 기술 Q&A: Obsidian 터미널 오류 및 GitHub 레포지토리 구조

**Obsidian 터미널 문제**: Windows 환경에서 Obsidian 내장 터미널이 열리지 않는 오류가 다수 보고됐다. 이에 대해 VS Code로 전환하는 것이 가장 빠른 해결책으로 제안됐으며, VS Code에서 마크다운 파일을 Obsidian처럼 체크박스 형태로 렌더링하려면 "마크다운 파일을 GUI 프리뷰 형태로 보여주는 확장 프로그램을 알려달라"고 Claude Code에 문의하면 된다.

**GitHub 레포지토리 분리 권장**: 스폰지 클럽 공용 레포지토리(퍼블릭, 약 70명 참여)와 개인 OS 레포지토리를 분리하는 것이 강력히 권장됐다. 공용 레포는 지속적으로 새로운 콘텐츠가 추가되어 맥락이 과도하게 누적될 수 있으므로, 개인 프라이빗 레포를 별도로 생성해 로컬 폴더와 연결하고 OS를 독립적으로 업데이트하는 구조가 적합하다.

**멀티 디바이스 OS 공유 구조**: 로컬에서 만든 서비스를 다른 기기에서도 동일하게 작동시키려면 GitHub 연동이 핵심이다. 어떤 메모리와 OS 구성 요소를 공유할지는 선택에 따라 달라지며, 맥 미니를 서버처럼 상시 구동하는 방식도 유효한 옵션으로 언급됐다.

## 결론 및 다음 단계

이번 공유회에서는 Claude를 활용한 개인 OS 구축, SNS 콘텐츠 자동화, 일정 관리 자동화 등 다양한 구현 사례와 실질적인 인사이트가 공유됐다. 공통적으로 도출된 핵심 원칙은 **Claude에게 추측 대신 질문을 유도하는 사전 지시**, **컨텍스트 범위를 최소화한 토큰 효율화**, **작업 단위를 좁게 유지하며 연속 대화로 결과물을 구체화하는 방식**이다.

주요 후속 과제는 다음과 같다.

- 개인 OS 레포지토리를 스폰지 클럽 공용 레포와 분리해 프라이빗으로 운영
- 텔레그램 아침 브리핑 시스템 안정화 후 공유 예정
- 워킹 카피 앱을 통한 모바일-PC 연동 7일 무료 체험 권장
- 캐릭터 변천사 및 Claude 대화 기록을 콘텐츠 소재로 활용하는 방안 검토
- 이번 주 MVP로 선정된 발표자의 OS 구축 사례를 추후 별도 공유 세션에서 심층 발표 예정
