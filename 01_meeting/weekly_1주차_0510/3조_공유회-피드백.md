# OS 페르소나·육아플래너 자동화 회의

본 문서는 2026년 5월 10일 진행된 스펀지 클럽 1주차 과제 발표 세션의 내용을 정리한 것이다. 참가자들은 각자 Claude Code 인터뷰 스킬을 활용해 개인 또는 업무용 OS·워크플로우를 제작한 결과물을 공유하였으며, 시행착오와 인사이트를 함께 나누었다.

---

## 개미 님 — 외부 정보 통합 OS

개미 님은 외부에서 생성된 OS를 그대로 따르기보다, 자신의 직업 페르소나를 반영한 맞춤형 OS를 구성하였다. 슬랙 채널 데이터를 자동으로 수집하여 인사이트와 반복적인 실수를 파악하고, 이를 개선 제안으로 출력하는 구조를 설계하였다. 페르소나를 입력하지 않았을 때 시스템이 다른 사용자의 설정을 혼용하는 문제가 발생하여, 세부 규칙 정립의 필요성을 확인하였다.

---

## 연수 님 — 육아 자동화 OS

육아휴직 중인 연수 님은 생후 9개월 아기의 이유식 식단 플래너와 육아 용품 구매 판단 도우미 스킬을 Claude Code로 제작하였다. 냉장고 재고와 아기 생년월일을 입력하면 맞춤 식단을 자동 생성하는 기능이 핵심이며, 모바일 접근성을 위해 Claude 앱 프로젝트 지침에 스킬 내용을 수동으로 등록하는 방식을 채택하였다. 인스타그램 데이터 연동은 API 한계로 구현하지 못하였고, 시스템을 효과적으로 발전시키려면 사용자 본인의 도메인 지식이 선행되어야 한다는 점을 깨달았다. 복직 전 수익화를 목표로 블로그 애드 수익 관련 스킬도 추가 제작하였다.

---

## 솔라 님 — AI 영상 제작 레퍼런스 수집기 & 어드민 페이지

AI 영상 제작 시 레퍼런스 탐색과 이미지 수정에 소요되는 시간을 줄이기 위해 레퍼런스 자동 수집 스킬을 시도하였으나, Pinterest API 승인 반려 등으로 실용화에 어려움을 겪었다. 스킬·플러그인·독립 프로덕트의 차이를 직접 질문하며 개념을 정립한 과정이 인상적이었다. 이후 슬랙 데이터를 구글 시트로 정리하는 어드민 페이지를 Claude Code와 Claude 웹을 병행하여 제작하였으며, "레퍼런스가 없을 때 AI에게 검사를 맡기는 것이 유효하다"는 인사이트와 함께 사용성 설계는 인간의 판단 영역임을 강조하였다.

---

## 그린 님 — 노션 클리너 & 세컨드 브레인

수집 후 방치하는 습관을 해결하기 위해 노션 MCP를 활용한 노션 클리너 스킬을 제작하였다. 페이지를 '보석', '쓰레기', '보류', '보존' 네 가지로 분류한 뒤 처리 방향을 사용자에게 확인하는 구조이다. 이후 기존에 구성만 해두고 활용하지 못했던 세컨드 브레인 페이지(PARA 구조: 프로젝트·에리어·리소스·아카이브)를 연동하여, 매주 자동으로 새 항목을 분류·추천하는 워크플로우를 완성하였다. MCP를 처음 사용하며 Claude가 직접 노션 페이지를 생성하고 내용을 채우는 경험을 하였다.

---

## 리나 님 — 피그마 기반 기획 브리핑 자동화 & 라이프 OS

서비스 기획자로서 최종 피그마 산출물을 기반으로 개발자·디자이너에게 전달하는 브리핑 문서를 자동 생성하는 스킬을 제작하였다. 피그마 API 연동 과정에서 스킬 파일의 폴더 위치 오류로 인한 삽질을 경험하였고, 원인 파악 후 정상 동작을 확인하였다. 개인 OS로는 Obsidian과 OneDrive를 연동한 가벼운 메모 루틴과 주간 점검 기능을 설계하였으나, 모바일 동기화 문제가 미해결 상태로 남아 있으며 이후 PC 환경에서 우선 운영할 예정이다.

---

## 윤리아 님 — 데이터 파이프라인 매핑 시각화

데이터 엔지니어로 이직 후 인수인계가 부족한 상황에서, 회사 데이터 수집 소스(YouTube, X 등 크롤링)와 저장소(GCS, BigQuery, 스프레드시트) 간의 관계를 파악하기 위한 도구를 제작하였다. Claude가 Google Cloud API를 활용해 저장소 목록을 추출하고 소스 코드의 저장 위치와 매핑하였으며, 미션 2에서는 그래프 파이(GraphPy) 스킬을 활용해 노드 간 연결 관계를 시각화하였다. 결과물의 업무 적용 정확도 판단이 어렵다는 점과, 사전 데이터 정리가 유의미한 결과 도출의 전제 조건임을 재확인하였다.

---

## 치코 님 — 커리어 OS "Popple Maker"

커리어 경험을 JD에 맞게 자동 매핑하는 독립 프로덕트 "Popple Maker"를 제작하였다. 인터뷰 스킬로 PRD를 도출하고, 잡스택(JobStack) 등 국내외 레퍼런스 분석을 거쳐 스타트업·프리랜서 타겟으로 차별화 방향을 설정하였다. 주요 기능은 JD 입력 시 핵심 역량 및 어필 포인트 추출, 채팅 형식의 경험 발굴 인터뷰, 경력 기술서 자동 생성, 경험 DB 누적이다. Claude API 비용이 예상 외로 발생하는 문제를 경험하였으며, 기획 단계에서 스펙을 사전에 세밀하게 확인하는 것이 중요하다는 교훈을 얻었다.

---

## 코니 님 — 헬스장 생존 OS

미션 1은 인터뷰 스킬 사용 경험에 의의를 두었고, 미션 2에서 개인 사용 목적의 헬스장 생존 OS를 웹 앱 형태로 제작하였다. 캘린더(운동 태그·출석 트로피), 오늘 운동 루틴 구성, 기구 가이드, 유산소 및 단백질 섭취 기록 기능으로 구성되었다. Claude Code가 제시한 계획서를 충분히 검토하지 않아 본인이 사용하지 않는 유산소 항목이 포함되는 등 완성 후 수정이 필요한 부분이 발생하였다. 매니페스트(Manifest) PRD 서비스를 시도하였으나 개인 용도에는 과도한 규모의 기획서가 생성되어 활용하지 않았다.

---

## 설록 님 — 카카오톡 아카이빙 자동 분류

프리랜서 강사 모임 운영 중 카카오톡 회의 내용의 휘발 문제를 해결하고자 하였다. 최종적으로는 '나에게 보내기' 기능으로 저장한 카카오톡 파일을 Claude Code에 전달하여 카테고리별로 자동 분류하고, TSV 파일을 구글 시트에 붙여넣어 날짜 필터로 조회하는 워크플로우를 완성하였다. 기술적 완성도보다 첫 시도를 성공적으로 마쳤다는 점에서 의미를 찾았으며, 향후 회의 내보내기 기능을 활용한 자동 요약·정리로 발전시킬 계획이다.

---

## 진 님 — 마케팅 에이전시 대체 OS (발표 진행 중)

"Claude가 마케팅 에이전시를 대체한다"는 목표 아래 인터뷰 스킬을 통해 입력·처리·결정 보조·출력 생성·소통·관계 등 9개 부품으로 구성된 청사진을 도출하였으며, 발표는 세션 종료로 인해 일부 내용이 기록되지 않았다.

---

## 공통 기술 이슈 및 권장 사항

-   **Windows 환경 Obsidian 터미널 깨짐**: 커뮤니티 플러그인에서 다운로드 수 기준 두 번째 터미널을 설치하거나, VS Code에서 Obsidian 폴더를 불러와 사용하면 해결된다.
    
-   **뿌까 님**: 일정상 불참하여 3조 채널에 서면으로 과제를 공유할 예정이므로 확인이 필요하다.
    
-   **모바일-PC 연동 문제**: 진행자가 이후 라이브 세션에서 해결 방향을 공유할 예정이다.
    

---

## 종합 및 다음 단계

진행자는 OS 제작 자체보다 **마인드셋과 시행착오 공유**가 세션의 핵심 가치임을 강조하였다. 작은 파이프라인이나 워크플로우부터 시작해 점진적으로 개선하는 접근을 권장하였으며, 아이디어와 불편함만 있으면 스킬·플러그인·독립 프로덕트 어떤 형태로든 구현이 가능하다는 점을 공유하였다. 참가자들은 2주차에도 각자의 OS를 계속 발전시키며 개선 포인트를 가져오기로 하였다.
