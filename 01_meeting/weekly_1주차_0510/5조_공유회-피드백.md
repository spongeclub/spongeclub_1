# 카드뉴스·3D 패키지 자동화 회의

본 문서는 스펀지 클럽 소그룹 워크숍 세션의 과제 공유 회의 내용을 정리한 것이다. 참가자들은 1주차 및 2주차 과제로 진행한 개인 OS 설계, 콘텐츠 자동화, LLM 위키 구축 등의 결과물을 옵시디언 화면 공유를 통해 발표하였으며, 진행자는 각 발표에 피드백을 제공하였다. 세션의 핵심 기조는 "완성도보다 고민의 깊이"로, 부족한 결과물도 당당히 공유하며 서로의 성장을 돕는 것이었다.

---

## 참가자별 과제 발표 요약

### 키노 — 카드뉴스 자동화 OS

키노는 1인 프리랜서로서 복수의 페르소나별 SNS를 운영하는 어려움을 해결하기 위해 카드뉴스 자동 생성 OS를 구축하였다. Claude Code를 활용해 스펀지 타임즈 브랜드 컬러(노란색)를 반영한 디자인을 설계하고, 해당 디자인을 `.md` 파일에 저장하여 주제(예: 텔레그램)만 입력하면 카드뉴스 8장이 자동 생성되는 구조를 완성하였다.

- **삽질 포인트**: 첫 번째 카드 디자인 배치 오류(글씨 겹침, 형광펜 위치 오류); PNG 배경 제거 시 Claude보다 Canva·GPT가 품질·속도 면에서 우수함을 확인
- **피드백**: 그리드 시스템 활용 검토 권장; 프롬프트 및 제작 과정 전체 공유 요청

---

### 덕수 — 개인 컨디션 OS + 아웃박스 사이즈 계산기

덕수는 두 가지 결과물을 발표하였다. 첫째, 하루 컨디션 체크인을 통해 맞춤형 운동·식단·릴렉스 모드를 제안하는 **"오늘의 나" 개인 OS**를 구현하였다. 둘째, 패키지 디자이너 업무에서 단상자 사이즈를 입력하면 아웃박스 사이즈를 자동 계산해 주는 **출고 박스 계산 프로그램**을 제작하였다.

- **삽질 포인트**: 3D 렌더링(드래그 시 면 표시) 구현 시도 중 캔버스 렌더링 오류 반복 → 최종적으로 3D 제거, 적합/부적합 판정 기능만 유지
- **시장성 논의**: 기존에는 엑셀 공식 계산기를 업체로부터 받아 일러스트로 수작업 크로스체크하는 방식이었으며, 해당 자동화 툴은 시장에 부재한 것으로 파악됨. 진행자는 "돈 냄새 나는 제품"으로 평가하며 사이드 프로젝트로 발전시킬 것을 권장

---

### 상임 — 블로그 수익화 자동화 + 커리어 정체성 재설계

상임은 블로그 CPA 마케팅(트립닷컴, 마이리얼트립 등 제휴 링크 수익화) 자동화를 시도하였다. 각 플랫폼의 프로모션을 자동 스크래핑하여 매일 1개씩 추천해 주는 스킬을 구축하려 했으나, 트래픽 차단 및 로그인 필요 페이지 접근 한계로 완전 구현에는 미치지 못하였다. 블로그 글쓰기 스텝 없이 진행하여 14번의 수정이 발생하였다.

두 번째 미션에서는 2019년부터 운영한 블로그(누적 방문자 100만 달성 후 저품질 처리)의 방향성을 Claude와 함께 재설계하였으며, 2년 타임라인 기반의 커리어 계획을 수립하였다.

- **진행자 피드백**: 발표 전체에 생동감이 있었으며, 커리어 전반의 고민이 깊이 담겨 있어 조 대표 발표자로 선정. 로그인 필요 사이트 접근을 위해 Chrome 확장 프로그램으로 Claude를 설치하고 로그인 상태 유지 후 스크래핑 시도 권장; 자동 실행을 위한 **Scheduled** 기능 활용 제안

---

### 거북이의 꿈 — LLM 위키 기반 콘텐츠 생성 OS

이커머스(화장품·식품) 솔로 프리너로 15년 경력의 발표자는 콘텐츠 제작이 업무 에너지를 과도하게 소모한다는 문제의식 하에 **LLM 위키**를 옵시디언에 구축하였다. 폴더 구조는 `1_raw(원본 문서) → 2_wiki(Claude가 자동 생성한 연결 문서) → 3_output(결과물)`으로 설계되었으며, 자사 브랜드 **아르밍**(헤어케어·바디케어)의 제품 정보, 경쟁사 정보, 고객 후기, 검색량 분석 데이터를 위키에 축적하고 있다.

- **목표**: 제품명과 콘텐츠 유형만 입력하면 자사 데이터 기반의 콘텐츠 기획안이 자동 생성되는 구조 완성
- **진행자 해설**: LLM 위키 = 다차원 지식 체계 → 해당 지식 베이스를 통해 일반 생성 콘텐츠 대비 고품질 결과물 도출 가능; 옵시디언과 궁합이 우수하므로 전체 공유 요청

---

### 봄이 — 여성 호르몬 주기 기반 컨디션 대시보드

봄이는 업무용 OS 구현이 개인 맥북과 회사 노트북 간 자료 접근 문제로 불가능함을 확인한 후, 여성의 4주기(생리기·황체기·난포기 등)에 따른 맞춤형 운동·음식·수면·스트레스 관리 대시보드를 제작하였다. 애플 워치 데이터와 텔레그램 입력값을 연동하는 구조를 설계하였으며, 이종재 대표의 유튜브 영상(다이어트 OS 구축 사례)을 벤치마킹하였다.

- **인사이트**: 마케터 직무 특성상 Claude가 "내부용 데이터와 외부 공유용 데이터를 오디언스별로 분리해야 한다"는 관점을 제시하여 유의미한 인사이트를 얻음
- **진행자 피드백**: 과제를 주 초에 시작하여 충분한 시행착오를 거치는 것이 중요함을 강조; 다음 주 초부터 공유 시간 권장

---

### 이안 — 유튜브 영상 반자동화 파이프라인

이안은 유튜브용 영상 제작을 반자동화하는 파이프라인 구축을 목표로 하였다. 대본 → 콘티/스토리보드 → 클립 단위 영상 생성의 흐름을 설계하였으나, 최적 파이프라인으로 검토한 **Hedra** 사용 시 15~30분 영상 기준 비용이 300~500달러에 달해 적용을 보류하였다. 로컬 실행 가능한 경량 파이프라인으로 전환하였으나 메모리 오류로 영상 생성 단계에는 미치지 못하였으며, 대본을 스토리보드 형식으로 분할하는 단계까지 구현하였다.

- **진행자 피드백**: 스코프(15~30분 영상)가 과도하게 넓으므로 3~5분 영상으로 범위를 축소하여 의미 있는 결과물을 먼저 도출할 것을 권장

---

### 아트리 — 초기 설정 단계

아트리는 윈도우 환경에서 터미널 연결 및 기본 구조 파악에 어려움을 겪었으며, Claude 인터뷰 스킬 설치 후 첫 질문을 받은 단계까지 진행하였다. 진행자는 어려움을 느끼는 참가자를 위한 밀착 케어 채널(DM) 운영 의사를 밝혔다.

---

### 헤이즈 — 맛집·카페 지도 + 스타트업 뉴스 스크래퍼

헤이즈는 마케터로서 프로모션 페이지 모음 자동화를 시도하였으나 크롤링 차단으로 중단하였다. 이후 회사 이전을 계기로 사옥 반경 100m·200m 기준 맛집·카페 지도를 Claude로 구현하였으며, 거리·메뉴·가격대 필터링 기능을 추가하려 했으나 API 스펙 불일치로 시간을 소모하였다. 추가로 스타트업 업계 뉴스 스크래퍼를 제작하였으나 프롬프트 품질 부족으로 광범위한 결과가 출력되는 한계를 확인하였다.

- **인사이트**: "업무 자동화의 첫 번째 발전기는 평소 업무를 한 발짝 뒤에서 관찰하는 습관"

---

### 써니 — 환경 설정 단계

써니는 몸 상태 악화로 과제 진행이 어려웠으며, 윈도우 환경 터미널 연결 자체가 큰 도전이었다고 공유하였다. 슬랙 기반 공지 체계에 대한 적응 어려움도 언급하였다. 진행자는 "Y(왜 이것이 필요한가)를 먼저 명확히 하는 것이 선행 과제"임을 강조하며, Claude와의 대화를 통해 방향성을 탐색할 것을 권장하였다.

---

### 진행자 — 개인 비서 OS (모아라)

진행자는 OpenAI를 활용한 개인 비서 **"모아라"** 를 제작 중임을 공유하였다. Linear와 Google Calendar를 연동하여 태스크·일정을 통합 관리하고, 매일 오후 5시 30분에 하루 회고를 진행하는 기능을 구현하고 있다.

---

## 전체 세션 공유 — 조별 MVP 발표

전체 세션에서 각 조의 조장 또는 MVP가 대표 결과물을 공유하였다.

- **1조 MVP**: 에이미 — SRS·기능정의서·화면정의서를 스킬 하나로 자동 생성하는 업무 OS와 개인 컨디션 기록 OS를 모두 구현; 반복 개선 방식과 삽질 과정의 상세 공유가 높이 평가됨. 진행자는 모바일 최적화 후 앱처럼 배포할 것을 권장
- **2조 MVP**: 라엘 — 내 집 마련 OS 구축; 대출·투자 자산 입력 시 예산 자동 산출, 호갱노노 연동 실매물 탐색, 플랫폼별 필터링, 정부 지원 추천, 뉴스 기반 매수 타이밍 분석까지 구현하여 조원 전원의 극찬을 받음

---

## 결론 및 다음 단계

진행자는 세션 전반에 걸쳐 다음의 핵심 메시지를 반복 강조하였다.

- **Y(목적) 탐색이 최우선**: 결과물의 완성도보다 "왜 이것이 필요한가"에 대한 깊은 고민이 선행되어야 하며, 이 과정을 Claude와의 대화로 진행할 것을 권장
- **스코프 관리**: 초기 범위를 좁게 설정하여 완성 가능한 MVP를 먼저 만들고 점진적으로 확장하는 방식 권장
- **Scheduled 기능 활용**: 스킬·에이전트가 별도 트리거 없이 특정 시간에 자동 실행되도록 설정하는 방법 소개
- **슬랙 운영 개선**: 채널 과다로 인한 정보 누락 문제를 해결하기 위해 조방 내 섹션 분류 기능 활용 및 조장 중심의 밀착 케어 운영 방향 논의
- **다음 주 과제**: 각자 Y를 더욱 명확히 정의하고, 이번 주 삽질 경험을 바탕으로 스코프를 조정하여 실사용 가능한 결과물을 발전시킬 것
