# 4조 3주차

본 문서는 2026년 5월 24일 진행된 4조 3주차 스터디 세션의 과제 발표 및 피드백 내용을 정리한 것이다. 각 참여자가 Claude를 활용해 제작한 프로젝트를 화면 공유를 통해 발표하고, 상호 피드백을 나누는 방식으로 진행되었다.

---

## 과제 발표 및 피드백

### 1\. 핸드메이드 가죽 브랜드 OS 기획 (정선)

창업을 준비 중인 발표자는 핸드메이드 가죽 가방 제작 공방을 운영하며, ERP·CRM 기능을 포함한 자체 운영 시스템(OS) 구축을 목표로 과제를 진행했다. 현재 약 30장의 영수증을 Claude에 입력해 재고 현황을 정리하는 작업을 시작했으며, 런칭 예정 브랜드명 **'스튜디오 등'** 을 설정하고 고객 페르소나 작업까지 진행했다. 백드롭 디자인 툴을 활용해 웹사이트 콘셉트 시안도 초안 수준으로 제작했다.

피드백으로는 실제 사업에 적용 가능한 사례라는 점이 긍정적으로 평가되었으며, 어드민 페이지와 웹사이트를 동시에 구축하려는 접근이 지나치게 방대하다는 의견이 제시되었다. **브랜드 스토리텔링 기반의 랜딩 페이지 하나를 먼저 완성한 뒤 탭을 하나씩 추가하는 방식**으로 진행하는 것이 권장되었다.

### 2\. 월간 사진 기록 웹앱 'ScrapUpDay' (보경)

다이어리 꾸미기 문화에서 착안하여 월 캘린더 형식으로 하루하루의 사진·감정·메모를 기록하는 한 달 기록용 웹앱을 제작했다. 주요 기능으로는 사진 업로드 후 확대·축소 편집, 폴라로이드·클래식·미니멀 디자인 타입 선택, 감정 색상 표현(기쁨·설렘·우울), 간단 메모 입력, 기록 수정(이미지 삭제 후 재업로드 방식으로 제한), 월별 전체 이미지 저장·공유 기능이 포함된다.

개발 과정에서 **Harness Orchestration 스킬**을 활용해 PRD(470줄)를 분할 점검했으며, Claude와의 대화를 통해 iOS 환경에서 1주일 미사용 시 DB가 자동 삭제되는 문제를 파악하고 백업 기능 및 모바일 최적화를 PRD에 보강했다. 피드백으로는 완성도가 높다는 평가와 함께, 특정 인물과의 기록을 별도로 모아볼 수 있는 **카테고리 기능**(예: 연인, 가족별 앨범)과 일괄 삭제 기능 추가가 제안되었다. 또한 개인 기록 전용으로 유지할지, 친구 간 공유 기능을 추가할지에 대한 방향성 결정이 과제로 남았다.

### 3\. 웰니스 네트워킹 파티 이벤트 랜딩 페이지 (다다)

구글 설문 폼 대신 행사의 품격을 높이기 위해 Claude로 랜딩 페이지 3장을 제작했다. 페이지 구성은 행사 소개·타임라인·모더레이터·스폰서 섹션·FAQ·신청 폼으로 이루어졌으며, 데이터베이스 연동 없이 **Google Sheets에 신청 데이터가 직접 적재**되도록 구현했다. 초대받은 참여자를 위한 별도의 시크릿 초대장 페이지도 추가 제작했다.

디자인 작업에는 **슈퍼디자인(SuperDesign)** 사이트에서 레퍼런스 디자인의 프롬프트를 복사해 Claude에 적용하는 방식을 사용했으며, 브랜드 키컬러(헥스 코드 지정)와 한글·영문 폰트(구글 무료 폰트)를 별도로 지정했다. 사진은 AI 생성 대신 실제 현장 사진을 사용해 현장감을 살렸다.

피드백으로는 전체 디자인 완성도가 높다는 평가와 함께, 페이지를 끝까지 읽지 않아도 핵심 정보를 한눈에 볼 수 있는 **Summary 페이지 또는 상단 고정 메뉴의 바로 신청하기 버튼** 추가가 제안되었다. 실제 운영 시 참여자들이 수영복 지참, 선착순 마감 등 중요 정보를 놓치는 사례가 있었음이 공유되었다. 또한 Harness Orchestration을 처음부터 적용했다면 URL 꼬임 등의 시행착오를 줄일 수 있었을 것이라는 인사이트가 도출되었다.

### 4\. 디지털 부고·추모 서비스 'WeIbu' (찌니)

발표자는 부모님의 별세 경험을 바탕으로 2026년 3월 1일부터 서비스를 기획했다. 어머니 별세 시 계좌번호 없는 부고장을, 아버지 별세 전날에는 아버지와 함께 조문문을 완성해 전달한 경험에서 출발했다. 브랜드명 **WeIbu**는 어머니의 퀼트 작업에서 착안한 '엮다(Weave)'와 '우리가 떠나기 전에 남기는 메시지(We, Ibu)'의 의미를 담았으며, 도메인은 `we-memory.day`로 설정했다.

주요 기능은 두 가지로, 첫째는 영정사진 AI 보정(GPT API → 타사 툴 → **Gemini API** 순으로 테스트 후 Gemini 채택, 헤어·피부톤·의상 정돈), 둘째는 Claude API를 활용한 조문 텍스트 자동 생성이다. 세 가지 API를 유료 연결해 비용 최적화를 지속적으로 진행 중이며, 영정사진 보정 1건당 약 50원의 비용이 발생한다. 피드백으로는 장례 문화에 대한 깊은 공감과 함께 **어른 세대에게 특히 유효한 서비스**라는 평가가 있었으며, 향후 사업화 시 BM 설계가 추가 과제로 제시되었다.

---

### 5\. 이미지 기반 학습 인사이트 수집 웹앱 (달빛그린)

강의 슬라이드·SNS 캡처·유튜브 스크린샷 등 흩어진 학습 자료를 한곳에 모아 핵심 인사이트를 추출하는 웹앱을 제작했다. 이미지를 업로드하면 각 이미지의 핵심 내용과 공통 테마·연결고리를 분석해주며, 블로그 작성 가이드도 제공한다. **Vercel** 배포를 통해 모바일 최적화를 구현했으며, Claude Code로 프로젝트 구조를 생성했다. 현재 데이터베이스(클라우드 DB) 미연결로 일시 저장만 가능하며, 향후 **OpenCloner(오픈플로우)와 텔레그램 연동**을 통해 모바일에서 이미지를 전송하면 자동 저장·분류되는 구조를 구상 중이다.

피드백으로는 사진이라는 직관적인 시작점이 진입 장벽을 낮춘다는 점이 긍정적으로 평가되었다. 태그 기반 분류(토픽화)를 도입해 하나의 이미지에 다중 태그를 부여하고 태그별로 자료를 모아볼 수 있는 구조가 제안되었으며, OpenCloner를 기준 허브로 삼아 워크플로를 통일하는 것이 권장되었다.

## 자유 토론 및 기술 Q&A

**슈퍼디자인 활용법**: 유료 구독 없이 갤러리에서 마음에 드는 디자인의 프롬프트를 복사(Copy Full Prompt)해 Claude에 붙여넣은 뒤 브랜드 컬러·폰트를 지정하면 디자인 시스템을 적용할 수 있다. 단, 수정이 잦은 경우 코드 재작업이 필요하므로 일회성 랜딩 페이지에 적합하다.

**Claude 채팅 vs. Claude Code 구분**: 스킬(Skill)은 Claude Code 전용이며, 채팅은 기획·인터뷰 단계에, Code는 실제 개발 단계에 활용하는 것이 효율적이다. 채팅 결과물을 Code로 이관할 때는 "entity 파일로 정리해줘"와 같이 요청하면 된다.

**모델 선택(Sonnet vs. Opus)**: Opus가 성능이 높은 대신 토큰 소모가 많으며, 가벼운 작업에는 Sonnet 사용이 권장된다. Harness·Orchestration을 잘 설정하면 반복 작업 시 토큰 절감 효과가 있다.

**Obsidian + iPad 연동**: iCloud를 통해 볼트를 연결하는 방식이 권장되나, 스폰지클럽 관련 로컬 폴더와 개인 사업 폴더는 별도 보관함으로 분리 운영하는 것이 충돌 방지에 유리하다. GitHub 연동은 스폰지클럽 레포와 분리해 개인 레포에 연결하는 것이 권장된다.

**API 비용 관리**: API 연동 시 비용이 건당 발생하므로, 배포 후 비밀번호를 설정해 무단 사용을 차단하고, Claude에게 비용 최적화 방안을 지속적으로 요청해 모델 단가를 낮추는 것이 중요하다.

## 결론 및 다음 단계

각 참여자는 실제 사업 또는 개인 필요에 기반한 프로젝트를 진행 중이며, 다음 주 과제는 신규 제작이 아닌 **기존 프로젝트 발전(Develop)** 으로 설정되었다. 오프라인 모임에 대한 수요가 확인되어 강남 위워크 공간 활용을 검토하기로 했다. 주요 후속 과제는 다음과 같다.

-   **정선**: 브랜드 스토리 랜딩 페이지 1개 우선 완성 후 기능 확장
    
-   **보경**: 인물별 카테고리 기능 및 공유/나만보기 옵션 추가 검토
    
-   **다다**: 슈퍼디자인 활용 공유회 기획, 상단 Summary 메뉴 추가
    
-   **찌니**: 카카오톡 로그인 재시도, 어드민 구축, B2B(요양원·상조사) 연계 검토, Toss 인앱 서비스 테스트 검토
    
-   **달빛그린**: 클라우드 DB 연결, OpenCloner·텔레그램 연동 구조 완성, 태그 기반 분류 기능 구현
