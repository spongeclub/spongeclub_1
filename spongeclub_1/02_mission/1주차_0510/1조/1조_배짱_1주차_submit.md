- **JSON 출력 스키마:** `id, hypothesis, media, period, metrics, verdict, next_hypotheses, tags`

### 공유할만한 인사이트
1. **OS 선언문은 "내가 안 할 일"을 명확히 정의해야 작동한다.** "통찰과 사람만 한다" 같은 추상적 문장보다, "검증·추적·다음 후보 제안은 시스템이 한다"처럼 시스템에 위임할 일이 또렷해야 다음 설계가 자연스럽게 따라온다.
    
2. **첫 부품의 출력 양식 = 다음 부품의 입력 양식.** 처음부터 JSON-like 스키마로 설계해두면, 나중에 부품을 늘릴 때 재작업이 거의 없다. 이 원칙은 미션2에서도 그대로 적용됐다.
    
3. **자동화는 검증 다음에.** 1차 빌드는 가장 가벼운 형태(Skill)로 만들고, 로직이 검증되면 그때 Plugin/Product로 진화. 검증 안 된 로직을 자동화하는 게 가장 비싼 실수.
    
4. **인터뷰 형식의 강력함.** os-interview는 단순한 질문지가 아니라, 답변마다 다음 질문이 정교하게 좁혀진다. 6단계를 마쳤을 때 청사진과 부품이 동시에 나오는 경험이 인상적이었다.
    
5. "같이 고민하자"가 만든 사고 파트너십.** 의사결정 갈림길마다 (B 통점 선택, 첫 부품 ① vs ②, 형태 A vs B/C 등) 혼자 결정하지 않고 Claude에게 "같이 고민하자"고 물어본 게 결정적이었다. 한쪽 화면엔 작업 중인 터미널, 다른 쪽엔 Claude 대화창을 띄워두고 **"단순 도구 사용 → 사고 협업"** 으로 전환했더니, 욕심으로 키울 뻔한 결정들을 검증하는 두 번째 시선이 생겼다. AI는 "내 일을 대신하는 도구"가 아니라 **"의사결정의 사고 동반자"** 가 될 때 가장 강력하다는 걸 체감했다.

### Summary
YouTube에서 발견한 **Karpathy의 "LLM Wiki" 패턴**(칼퇴연구소 영상)을 벤치마크해, 옵시디언 + Claude Code 조합으로 4-layer 지식 시스템을 직접 만들었다.

핵심 구조: **`sources/` (원본) → `wiki/` (AI 정리) → `outputs/` (외부 발신) → `reviews/` (내부 회고)** + `AGENTS.md` (AI 작업 규칙).

미션1에서 만든 `campaign-result-engine` 스킬의 **JSON 출력 = LLM Wiki의 wiki 항목**이라는 자연스러운 연결을 발견하면서, **두 미션이 하나의 시스템으로 통합되는 경험**이 가장 큰 수확이었다.

#### 의사결정 갈림길

**LLM Wiki를 고른 결정적 이유:** 미션1의 첫 부품 `campaign-result-engine`이 출력하는 JSON 구조가, LLM Wiki의 `wiki/` 항목 형태와 거의 동일. 즉 **미션2가 미션1의 다음 부품(②가설 아카이브) 설계를 사전 학습하는 역할**이 됨. 두 미션이 하나의 시스템으로 통합.

**공용 vault에 데이터 안 넣은 이유:** GitHub 동기화로 다른 조원들이 모두 보게 됨. 실제 캠페인 데이터(광고비, ROAS, 클라이언트명 등)는 보안 이슈. 익명화 샘플로 구현 데모 + 실제 운영은 개인 vault에서.
### 공유할만한 인사이트
1. **두 미션이 하나의 시스템이 됐다.** 별개로 보이던 미션1(스킬 만들기)과 미션2(OS 벤치마크)가 "campaign-result-engine 스킬의 JSON 출력 = LLM Wiki의 wiki 항목" 구조로 자연스럽게 연결됨. 사실상 1주차 과제 = 본인 OS의 v0.1.
    
2. **raw 데이터와 가공 데이터의 분리는 강력하다.** 그래프 뷰에서 sources가 외톨이로 떠있는 모습이 시각적으로 이를 증명. 원본은 절대 수정 안 하고, AI가 만든 wiki는 마음껏 재구성. "AI가 망가뜨려도 원본은 안전" 이라는 심리적 안전망이 큼.
    
3. **AGENTS.md는 작은 헌법이다.** 짧은 5~6개 규칙만으로 AI가 매번 같은 품질의 wiki/outputs를 만들어준다. 한 번 잘 써두면 매번 프롬프트 길게 쓸 필요 없음.
    
4. **외부 도구 활용으로 시간 압축.** Gemini의 YouTube 요약 + GPT 교차검증 = 영상 시청 + 자료 조사 시간을 절반 이하로 단축. AI 도구를 학습 자체에도 적용하는 사고 전환.
    
5. **첫 빌드는 작게.** 욕심내서 자동 연동(B 플러그인)이나 팀 도구(C 프로덕트)까지 가려다 멈춤. 검증 안 된 시스템을 키우는 건 부채. **"가설 → 검증 → 진화"** 의 사이클을 시스템 만들기 자체에도 적용.
