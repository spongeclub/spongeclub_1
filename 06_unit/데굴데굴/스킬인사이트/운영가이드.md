# 스킬 후기 페이지 운영 가이드

> 슬랙에 올라온 "써본 스킬 후기"가 어떻게 홈페이지 `/skills/` 카드가 되는지 정리한 문서.
> 유닛원 누구나 한눈에 흐름을 보고, 운영자(코니)는 실제 작업 순서를 따라할 수 있게 만들었다.

---

## 한 줄 요약

**슬랙에 `/써본스킬`로 후기를 쓰면 → 자동으로 모아서 → 카드로 빌드 → 홈페이지에 뜬다.**
중간에 사람이 판단할 부분(명대사 고르기·분야 분류·노출 여부)만 손이 가고, 나머지는 자동이다.

---

## 전체 흐름도

```
┌──────────────────────────────────────────────────────────────┐
│  ① 슬랙 채널  (a유닛-이기적인스킬러들-에밀리)                       │
│     유닛원이 /써본스킬 양식으로 후기 작성                          │
└───────────────────────────┬──────────────────────────────────┘
                            │  자동 수집  (스크립트)
                            │  node fetch-skill-reviews.mjs
                            ▼
┌──────────────────────────────────────────────────────────────┐
│  ② 원본 데이터 3종  (스킬인사이트/ 폴더)                          │
│     • raw_data.md          : 슬랙 메시지 원본 그대로              │
│     • messages_extracted.md: 작성자·스킬이름 등 메타 표           │
│     • quote_picks.md       : 카드에 실을 "명대사" 선별            │
└───────────────────────────┬──────────────────────────────────┘
                            │  카드 빌드  (운영자가 실행)
                            │  node build-skills.mjs
                            ▼
┌──────────────────────────────────────────────────────────────┐
│  ③ 카드별 문서  skills_md/{스킬이름}.md                          │
│     ※ 분야·난이도는 여기서 사람이 채운다 (backfill)               │
└───────────────────────────┬──────────────────────────────────┘
                            │  JSON 변환  (빌드 때 자동)
                            │  node build-skill-bodies.mjs
                            │  ※ VISIBLE_SLUGS 가 "화면에 보일 카드" 결정
                            ▼
┌──────────────────────────────────────────────────────────────┐
│  ④ 데이터 JSON  skills.generated.json / skill-bodies.generated │
└──────────────┬──────────────────────────────┬────────────────┘
               │  홈페이지가 읽어서 표시        │  인사이트 신호 추출
               │  (빌드 때 자동)               │  node build-insights.mjs
               │                              ▼
               │              ┌────────────────────────────────┐
               │              │  ④' 이번 주 인사이트 블록         │
               │              │  신호(숫자·분포·후기) → AI가      │
               │              │  2~3문장 작성 → insights.        │
               │              │  generated.json (/skills 상단)  │
               │              └───────────────┬────────────────┘
               ▼                              ▼
┌──────────────────────────────────────────────────────────────┐
│  ⑤ 홈페이지 /skills/  →  Vercel 자동 배포 (main 머지 시)          │
└──────────────────────────────────────────────────────────────┘
```

## 단계별 설명

| 단계 | 무슨 일이 일어나나 | 결과물 |
|------|-------------------|--------|
| ① 후기 작성 | 유닛원이 슬랙에 `/써본스킬` 양식으로 후기를 올린다 | 슬랙 메시지 |
| ② 수집 | 스크립트가 슬랙 채널을 통째로 긁어 `raw_data.md`에 채운다 | 원본 데이터 |
| ②' 메타·명대사 | 후기에서 카드에 쓸 정보(작성자·스킬명)와 명대사를 정리한다 | messages_extracted / quote_picks |
| ③ 카드 빌드 | 원본 3종을 합쳐 카드별 문서(`skills_md/`)를 만든다 | 카드 문서 |
| ③' 분야·난이도 | 새 카드의 분야·난이도 칸을 채운다 (안 채우면 필터에서 빠짐) | 보강된 카드 문서 |
| ④ JSON 변환 | 카드 문서를 홈페이지가 읽을 JSON으로 바꾼다. 이때 "보일 카드"만 표시 | generated.json 2개 |
| ④' 인사이트 블록 | 카드들을 가로질러 신호(최다 사용·분야 분포·솔직 후기)를 뽑고 → AI가 2~3문장으로 다듬는다 | insights.generated.json |
| ⑤ 배포 | main에 합치면 Vercel이 홈페이지를 다시 빌드해 올린다 | /skills/ 페이지 |

## 무엇이 자동이고 무엇이 수동인가

| 작업 | 누가 한다 | 자동? |
|------|----------|:----:|
| 슬랙에서 후기 긁어 raw_data에 넣기 | 스크립트 `fetch-skill-reviews.mjs` | ✅ 자동 |
| 명대사 고르기 (quote_picks) | AI가 후보 뽑고 → 코니가 확인 | 반자동 |
| 작성자·스킬명 메타 정리 | AI/사람 | 반자동 |
| 카드 문서 만들기 (build-skills) | 운영자가 명령 한 번 | 트리거만 수동 |
| 분야·난이도 채우기 | AI가 후보 → 코니가 확인 | 반자동 |
| **화면에 보일지 결정 (VISIBLE_SLUGS)** | **코니가 직접** | 🖐 수동 |
| JSON 변환 (build-skill-bodies) | 빌드가 알아서 | ✅ 자동 |
| 인사이트 신호 뽑기 (build-insights) | 스크립트가 숫자·분포만 출력 | ✅ 자동 |
| 인사이트 문장 쓰기 | AI가 신호로 2~3문장 → 코니가 확인 | 반자동 |
| 홈페이지 빌드·배포 | Vercel | ✅ 자동 |

> 핵심: **사람이 "꼭" 판단해야 하는 건 "이 카드를 화면에 보일까 말까" 정도.**
> 명대사·분야·난이도는 AI가 후보를 만들고 코니가 "맞아/고쳐" 한 번 봐주면 된다.

## 실제 사용법

### 유닛원 (후기 쓰는 사람)
슬랙 채널에 **`/써본스킬`** 양식대로 후기만 올리면 끝. 나머지는 운영이 처리한다.
- `:pushpin:` 한줄 요약
- `:mag:` 주요 내용
- `:briefcase:` 내가 써본 상황 + 결과
- `:link:` 링크 / 스크린샷

> 양식(마커)을 지켜야 카드 본문이 제대로 만들어진다. 상단 고정 템플릿 참고.

### 운영자 (코니)
1. **수집**: `cd 06_unit/데굴데굴/web` → `node scripts/fetch-skill-reviews.mjs`
   (먼저 `--dry-run` 붙이면 몇 건 잡히는지 미리보기)
2. **명대사·메타 정리**: 새 후기의 명대사를 `quote_picks.md`에 추가
   (quote_picks에 없는 스킬은 카드가 안 생긴다)
3. **빌드~검증~노출~인사이트**: `/build-skills` 한 번이면 ① 검증 → ② 미리보기 승인 → ③ 빌드 →
   ④ 분야·난이도 backfill → ⑤ 노출 토글 → ⑥ 검증 → ⑦ 인사이트 블록 생성까지 안내된다
4. **제출**: `/submit` 또는 브랜치 → PR → 스쿼시 머지 (main 직접 push 금지)

## 알아두면 좋은 규칙

- **카드는 `quote_picks.md`에 명대사가 있어야 생긴다.** 후기만 있고 명대사 없으면 카드 없음.
- **노출/숨김은 완전 가역.** `VISIBLE_SLUGS`에서 빼면 데이터는 남고 화면에서만 사라진다.
- **분야는 4개, 난이도는 3개로 고정** (필터·칩이 이 값만 인식)
  - 분야: 클로드코드 / 콘텐츠·마케팅 / 개발도구 / 생산성
  - 난이도: 설치만하면됨 / 설정좀필요 / 코드만져야함
- **데이터 출처는 web 한 곳.** 홈페이지(`_site`)는 web이 만든 JSON을 읽어 쓴다.
  그래서 화면을 바꾸려면 web에서 빌드해 JSON을 갱신하고 커밋해야 한다.

## 문서 세 개의 역할 구분

이 파이프라인에는 비슷해 보이는 문서가 셋 있는데, 역할이 다르다. 헷갈리면 아래로 돌아온다.

| 문서 | 한마디로 | 답하는 질문 |
|------|---------|------------|
| **운영가이드.md** (이 문서) | 흐름 지도 | "후기가 어떻게 카드가 되나? 뭐가 자동이고 뭘 내가 하나?" |
| **카드화규칙.md** | 판정 기준 | "이 후기를 어느 분야·난이도로? 인용은 뭘 고르나? 인사이트 톤은?" |
| **build-skills.md** (`.claude/commands/`) | 실행 절차 | "`/build-skills` 치면 무슨 단계가 순서대로 돌아가나?" |

> 흐름이 궁금하면 여기, **무엇을 어떻게 판단할지**는 카드화규칙.md, **명령 한 번에 뭐가 도는지**는 build-skills.md.
