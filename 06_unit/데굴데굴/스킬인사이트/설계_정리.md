# 스킬 & 인사이트 설계 정리

> 작성자: 코니 | 최초 작성: 2026-05-13 | 최종 수정: 2026-05-19
> 실데이터 분석 기반 확정 버전.

---

## 1. 이게 뭔지

이기적스킬러들 채널의 스킬 공유 글을 옵시디언 md 파일로 구조화해서, 데굴데굴 사이트(spongeclub-community.vercel.app)의 스킬&인사이트 탭에서 필터링·탐색할 수 있게 만드는 것.

핵심 가치: 스킬이 사람을 타고 번지는 순환 흐름을 보여주고, 다음 행동을 유도한다.

---

## 2. 데이터 흐름

```
슬랙 (이기적스킬러 채널)
    │  Bot Token fetch (코니 데이터수집봇)
    ▼
raw 데이터 (메시지 + 스레드 + 이모지)
    │  변환 규칙 적용 (봇·참여 메시지 필터링, 템플릿 파싱)
    ▼
옵시디언 md 파일 (frontmatter + 본문)
    │  Next.js 앱이 md 파일 읽음
    ▼
사이트 스킬&인사이트 탭
```

---

## 3. frontmatter 스키마 (확정)

```yaml
---
# 식별
title: "skillers-finder 써본 후기"
skill_name: skillers-finder
summary: "내 상황에 맞는 스킬 자동 추천+설치"

# 작성자
author: 슬로우퀵
team: 2조

# 분류
type: 스킬
post_type: 써본후기
category: 클로드코드
audience: [코딩초보]
difficulty: 설치만하면됨

# 순환 연결
inspired_by: "에밀리_skillers-finder_공유회"

# 참조
keywords: [스킬추천, GitHub, 자동설치]
links:
  - https://github.com/emily-mkt/skillers-finder

# 운영
created: 2026-05-13
updated: 2026-05-13
published: true
featured: false
---
```

## 4. 필드 상세

### 식별

| 필드 | 뭔지 | 비고 |
|------|------|------|
| title | 게시글 제목 | "skillers-finder 써본 후기" |
| skill_name | 스킬 이름 (묶기용) | 같은 스킬의 후기를 묶어서 "N명이 써봤어요" 표시 |
| summary | 한 줄 설명 | 카드에 표시. 슬랙 한줄 요약에서 매핑 |

### 작성자

| 필드 | 뭔지 |
|------|------|
| author | 닉네임 |
| team | 조 |

### 분류

| 필드 | 선택지 | 비고 |
|------|--------|------|
| type | 스킬 / 가이드 | 스킬 = 설치 가능한 도구. 가이드 = 지식·팁·튜토리얼 |
| post_type | 써본후기 / 공유 | 써본후기 = 직접 써본 상세 후기 (+3쉘). 공유 = 발견·소개 (+1쉘) |
| category | 아래 taxonomy 참고 | 단일 선택 |
| audience | 아래 taxonomy 참고 | 다중 선택 |
| difficulty | 아래 taxonomy 참고 | 단일 선택 |

### 순환 연결

| 필드 | 뭔지 | 비고 |
|------|------|------|
| inspired_by | 이 후기의 출발점 | "먼지민_claude-mem_공유" 형태. 없으면 비워둠 |

### 참조

| 필드 | 뭔지 |
|------|------|
| keywords | 검색용 태그 3~5개 |
| links | GitHub, Google Drive 등 URL |

### 운영

| 필드 | 뭔지 |
|------|------|
| created / updated | 작성일 / 수정일 |
| published | true면 사이트 노출 |
| featured | true면 상단 고정 |

## 5. taxonomy (실데이터 기반 확정)

### 카테고리 (category) — 4개

| 값 | 포함 범위 | 실데이터 건수 |
|---|----------|------------|
| 클로드코드 | Claude Code 스킬, 플러그인, CLAUDE.md 관련 | 7 |
| 콘텐츠마케팅 | 캐러셀, 카드뉴스, SEO, 영상, 디자인, SNS, 블로그 | 12 |
| 개발도구 | MCP, 코드 분석, Supabase, 브라우저 연동 | 6 |
| 생산성 | PPT, 노션 미팅, 범용 플러그인, 리서치 | 4 |

### 난이도 (difficulty) — 3단계

| 값 | 설명 | 실데이터 근거 |
|---|------|------------|
| 설치만하면됨 | 설치 한 줄이면 바로 사용 | "깃허브 못 다뤄도 됨", "5분 컷" |
| 설정좀필요 | API 키, 설정 파일 등 필요 | "API 키 필요해서 멈춤" |
| 코드만져야함 | 코드 수정, 파이프라인 구성 | "Puppeteer+FFmpeg 직접 구현" |

### 추천대상 (audience) — 5개 (1차)

| 값 | 실데이터 근거 |
|---|------------|
| 코딩초보 | "깃허브 못 다뤄도 됨", "진입장벽 0" |
| 마케터 | "블로그 CPA", "인스타 콘텐츠", "SEO" |
| 디자이너 | "디자인 시스템", "캔바 풍" |
| 개발자 | "코드베이스 분석", "Supabase" |
| 일반 | 특정 직무 한정 아닌 범용 |

### 타입 (type) — 2개

| 값 | 설명 |
|---|------|
| 스킬 | 설치·사용 가능한 도구/플러그인 |
| 가이드 | 지식, 팁, 튜토리얼 |

### 게시유형 (post_type) — 2개

| 값 | 슬랙 명령어 | 셸 | 설명 |
|---|-----------|-----|------|
| 써본후기 | /써본스킬 | +3 | 직접 써본 상세 후기 |
| 공유 | /써보고싶은스킬, /공유 | +1 | 발견·소개 |

## 6. 변환 규칙

### 슬랙 → frontmatter 매핑

| 슬랙 | frontmatter |
|------|-------------|
| /써본스킬 | post_type: 써본후기 |
| /써보고싶은스킬, /공유 | post_type: 공유 |
| 한줄 요약 | summary |
| 링크 | links |
| 작성자 UserID | author (닉네임 변환) |
| 이모지 반응 | frontmatter 밖, 인기순 정렬용 |

### 제외 대상

| 유형 | 판별 기준 |
|------|---------|
| 봇 자동응답 | 작성자 ID가 B로 시작 |
| 채널 참여 | "님이 채널에 참여함" |
| 셸 선물 | "오늘의 셸을 보냈어요" |
| 운영 공지 | 채널 규칙, 템플릿 변경 안내 |
| 테스트 | 비비안 테스트 등 |

### 이미지 처리

1차: 텍스트만 변환. 이미지는 "원본 슬랙 스레드 참고" 안내로 대체.

## 7. 사이트 구현 방향

- 스킬별 묶기: 같은 skill_name 후기를 카드 1개로, "N명이 써봤어요"
- 순환 흐름: inspired_by로 연결된 여정 시각화
- 필터: 카테고리(4) + 난이도(3) + 추천대상(5) + 타입(2) + 게시유형(2)
- 정렬: 최신순(기본), 인기순(이모지), 후기 많은 순

## 9. 설계 과정 기록

### 5/13 — 최초 설계
율리아 "4축 분류" 참고. 카테고리 8개로 설계. 문제: 실데이터 없이 카테고리 선정, 해당 0건인 카테고리 포함.

### 5/19 — 실데이터 수집
코니 데이터수집봇 직접 생성. 채널 전체 133개 메시지 fetch 성공.

### 5/19 — 분석 결과 기반 재설계
- 카테고리 8개 → 4개 축소 (0건 카테고리 제거, 유사 항목 병합)
- type 필드 신설 (스킬 vs 가이드 분리)
- post_type 필드 신설 (써본후기 vs 공유, 셸 지급 기준 연동)
- skill_name 필드 신설 (같은 스킬 후기 묶기)
- inspired_by 필드 신설 (순환 흐름 시각화)
- 변환 규칙 수립 (필터링 기준, 매핑 규칙)
