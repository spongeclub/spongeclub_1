## 한 줄 요약
• LLM 코딩 실패 패턴을 막는 행동 지침을 참고하여 Claude Code가 가정을 드러내고, 요청한 것만 최소로 고치고, 검증 가능한 성공 기준을 세우게 만드는 단일 CLAUDE.md 스킬.

## 주요 내용
• ① 멋대로 가정하고 확인 안 함, 명료화·반대·트레이드오프 제시 안 함 
• ② 코드·추상화 과잉(100줄이면 될 걸 1000줄) 
• ③ 죽은 코드 방치. - 4대 원칙: 가정 명시 / 단순함 우선(투기적 복잡성 배제) / 수술적 편집(요청 범위만, 주변 코드 임의 정리 금지) / 검증 가능한 성공 기준(모호한 요청을 체크 가능한 결과로, 단계마다 verify 훅). 
• 핵심 발상: "무엇을 하라 지시하지 말고, 성공 기준을 주고 모델이 루프 돌게 하라"(Karpathy 인용)

## 써본 상황 + 결과
• 개발 작업에서 에이전트가 시키지 않은 리팩터링·추상화를 덧붙이거나, 모호한 가정을 확인 없이 밀고 나가는 일이 반복돼 도입했습니다. 
• 결과: diff에 요청한 변경만 남고, 구현 전에 가정·트레이드오프를 먼저 묻는 빈도가 늘었습니다. 평소 제 작업 방식(가정과 사실 분리·최소 변경·검증 기준 명시)과 그대로 포개져 마찰이 적었습니다. 
• 한계: 신중함에 치우친 설계라 오타·한 줄 변경 같은 사소한 작업엔 절차가 과합니다. 그런 건 지침을 건너뛰거나 가볍게 적용합니다.
