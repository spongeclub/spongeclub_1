## 한 줄 요약
• 40~60분 6단계 인터뷰로 본인 일·삶을 운용하는 OS 청사진을 그리고, 그 OS의 첫 부품 1개의 실행 가능한 결과물(Claude 스킬 / 플러그인 / 프로덕트 PRD 중 하나)까지 한 파일로 산출하는 스킬.

## 주요 내용
• Phase 1 (사고 파트너 톤): 풍경 → 통점 → 이상향 → 부품 후보 매핑. Claude가 가설을 던지고 검증받으며 본인도 몰랐던 통점·이상향을 끌어냄.
• Phase 2 (전환 톤): 부품 후보 3~7개 중_효과 큰 1개_만 결정 + 형태 결정 (스킬 / 플러그인 / 독립 프로덕트).
• Phase 3 (효율 톤): 결정된 형태별 템플릿에 따라 결과물 1파일 작성.
• 산출물 2개:`os-blueprint.md`(풍경·통점·이상향·부품 후보·"나는 ___만 하고 나머지는 시스템이 한다" OS 선언문 1줄) + 첫 부품 결과물 1파일.
• "다 만들고 싶다" 함정 차단 — 부품 후보를 1개로 좁히게 강제함.

## 써본 상황 + 결과
• 어떤 상황에서: 혼자 일하기 시작하며 _일하는 방식 자체_가 흐트러진 상태._내 일을 시스템처럼 굴리고 싶다_는 결만 있고 어디서부터 손대야 할지 막막함
• 어떻게 썼는지:_"내 OS를 만들고 싶다"_트리거로 1세션(약 1시간) 인터뷰 진행 → 청사진 파일 출생 → 인터뷰 끝에 통점을 직접 응답하는_첫 부품 (자기 점검용 매일 루틴 스킬)_까지 그 자리에서 만듬
• 결과 / 인사이트: 통점이_끝낼 줄 모르는 깊이_라는 한 줄로 명료화됨. OS 선언문도_시간·결정·진화_3줄로 구조화됨. 큰 시스템 한 번에 만들기 부담 X —_청사진 + 첫 부품 1개부터 시작_결이 자연

## 결과·인사이트
> "통점이 '끝낼 줄 모르는 깊이'라는 한 줄로 명료화됨. OS 선언문도 시간·결정·진화 3줄로 구조화" — 아가타
