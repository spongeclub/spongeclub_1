# 스킬 카드화 규칙 (무인 자동화 기준)

> `/써본스킬` 슬랙 후기 → 스킬 카드를 **AI가 사람 개입 없이** 만들 때 따르는 판정 기준.
> `/build-skills` 절차(생성·빌드·검증)는 `.claude/commands/build-skills.md`, **무엇을 어떻게 판정하는지(이 문서)** 는 여기.

## 전제 — 사후수정 방식

완벽을 목표로 하지 않는다. AI가 규칙대로 일단 카드를 만들어 게시하고, 이상한 카드가 보이면 그때 고친다.

- 모든 산출물은 git에 박제 → 잘못돼도 복구 쉬움
- 노출은 `VISIBLE_SLUGS` 토글로 즉시 끔 (데이터는 보존, 완전 가역)
- 사람이 손으로 고친 분류·인용은 다음 자동 빌드가 **덮어쓰지 않음**(frontmatter 사람 입력칸 보존)

그래서 "자동 게시 → 사후 검수"가 안전하다.

## 파트 1. 스킬 카드 7축

### ① 카드 생성 기준
`/써본스킬`로 시작 + 본문(한줄요약 또는 주요내용)이 있는 글만 카드화한다. 잡담·질문·링크만 있는 글은 제외한다. (`/써본스킬` 프리픽스가 부적절 내용 1차 거름망 역할도 한다.)

### ② 같은 스킬 묶기
같은 스킬을 가리키면 **1개 카드로 합친다.**
- `usedBy` = 후기 쓴 사람 수
- 각 후기에서 인용 1개씩 (⑥ 참조)
- 표기가 흔들리면(대소문자·띄어쓰기) AI가 같은 스킬로 정규화

### ③ 분야 — 위에서부터 먼저 걸리는 것
| 순위 | 분야 | 판정 기준 |
|------|------|----------|
| 1 | `클로드코드` | 클로드코드 자체를 설치·관리·확장·연동하는 메타 스킬 |
| 2 | `콘텐츠·마케팅` | 산출물이 글·SNS·광고·보도자료 등 마케팅/콘텐츠 |
| 3 | `개발도구` | 산출물이 코드·웹앱·영상·디자인시스템 등 개발 결과물 |
| 4 | `생산성` | 그 외 업무 효율·리서치·의사결정·자동화 판단 |

> 분야는 100% 일관된 규칙으로 안 떨어진다. 4개 중 하나는 반드시 찍고, 애매하면 사후수정.
> frontmatter에는 `콘텐츠마케팅`(가운뎃점 없이)으로 쓰면 빌드가 `콘텐츠·마케팅`으로 정규화한다.

### ④ 난이도
| 난이도 | 판정 기준 |
|--------|----------|
| `설치만하면됨` | 설치 후 **자연어로 호출만** 하면 끝. 추가 설정·연동·코드 없음 |
| `설정좀필요` | 인터뷰·다단계 설정을 거치거나, 외부 도구·API 연동(봇 토큰·MCP 등) 필요. 단 코드는 직접 안 씀 |
| `코드만져야함` | 코드를 직접 다루거나(React/JS), 여러 스킬·서브에이전트·파이프라인을 직접 구성해야 결과가 나옴 |

> 한 줄 핵심: **호출만 = 설치만 / 연동·설정 = 설정좀 / 코드·조립 = 코드만져야**

### ⑤ 제목·본문
- `name` (작은 식별자) = 슬러그(영문 소문자-하이픈). 예: `skillers-finder`
- `summary` (카드 큰 제목) = **"이 스킬이 나한테 뭘 해주는가"를 사용자 언어 한 줄로.** 기능 나열❌, 효익 중심⭕. `:pushpin:` 한줄요약이 있으면 그걸 다듬고, 없으면 본문에서 생성. 40자 내외
- 본문(주요 내용) = `:mag:` 마커에서 추출

### ⑥ 인용
- **개수:** 1명당 1개, **최대 3개** (여러 명이 같은 스킬 쓰면 각자 한 마디씩)
- **선정 우선순위** (위에서부터):
  1. 구체적 효과·수치 변화 ("수동 4번→0번", "1~2시간→수 분")
  2. 그 스킬만의 차별점·본질 ("ROI 대신 oversight를 따짐", "문법 학습 0")
  3. 솔직한 체감 — 긍정/아쉬움 무관 ("예전보다 덜 빡치게 됨", "제대로 된 건지 모르겠음")
- **원칙:** 작성자 본인 말 그대로 살리되(말투 보존), 길면 핵심만 다듬어 90자 내. 출처는 작성자 닉네임.

### ⑦ 본문↔인용 비중 (usedBy 2단계)
| usedBy | 본문 | 인용 |
|--------|------|------|
| `1명` | 충실히 (핵심 3~5포인트) | 1개 |
| `2명+` | 핵심만 (1~2포인트) | 사람 수만큼 (최대 3) |

> 여러 명이 썼다는 것 자체가 신뢰 신호 → 인용(사회적 증거)을 부각, 본문 설명은 줄인다.
> 1명일 땐 아직 입증이 약하니 스킬 자체 설명(본문)으로 채운다.

## 파트 2. 인사이트 블록

페이지 이름이 "스킬&인사이트"인데 스킬만 있어서, **인사이트 블록**으로 이름값을 채운다.

- **데이터:** 이미 만든 스킬 카드들을 가로질러 패턴 2~3개를 추출 (새 데이터 파이프라인 없음)
- **후보 패턴:** 최다 사용 스킬, 분야 쏠림(예: 시각화 3종 등장), 새 트렌드(예: '나만의 시스템' 붐), 솔직 후기
- **위치:** 페이지에 "이번 주 인사이트" 블록 1개

### 톤 규칙
| 항목 | 규칙 |
|------|------|
| 문체 | "~어요/~예요" 다정한 관찰체 (현재 페이지와 일관) |
| 필수 | 문장마다 **구체 사실 1개 이상** — 스킬명·숫자·멤버 흐름 중 하나. 없으면 폐기 |
| 길이 | 1~2문장. 짧게 |
| 이모지 | 문장당 0~1개, 의미 있을 때만 (🔥 인기, 👀 주목 등). 장식 남발 금지 |
| 멤버명 | 긍정·인기 = 박아도 OK / **부정·아쉬움 = 스킬명만, 멤버명 빼기** (박제 안 되게) |
| 금지어 | "다양한", "활발히", "~에 기여", "생산성 향상" 등 무색 단어 |

> 안티패턴(피할 것): 뻔한 일반화, 숫자만 나열, 안전한 무난함, 호들갑.
> 공통 증상 = **읽어도 멤버가 새로 알게 되는 게 없음.**

**좋은 예**
> 🔥 skillers-finder가 8명으로 압도적 1위예요. 에밀리 공유회에서 시작된 게 유닛 전체로 번졌어요.

> 솔직 후기도 있어요 👀 anydesign은 "원하던 느낌이 안 나온다"는 후기가 달렸어요 — 모든 스킬이 다 통하는 건 아니죠. *(부정 후기라 멤버명 없음)*

## 적용 흐름

```
슬랙 →(fetch 자동)→ raw_data → (이 규칙으로 AI 카드화) → generated.json → 사이트
                                                            ↑
                                              인사이트 블록도 같이 생성
```

- **fetch는 주기적으로** (90일 안에) 떠서 raw_data를 커밋 → 슬랙 무료 플랜이 옛 메시지를 숨겨도 후기가 영구 보존된다.
- 카드가 잘못 나가면 사후수정(숨김 토글 / 직접 교정). 다음 빌드가 안 덮어쓴다.
