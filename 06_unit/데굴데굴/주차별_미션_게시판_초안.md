# 스폰지클럽 1기 — 데굴데굴 과제 게시판(주차별 미션) v1 제안

## 1. 풀고 싶은 문제

- 과제 공지·질문·꿀팁이 Slack 쓰레드에 흩어져 멤버들이 정보를 놓침.
- 같은 질문이 반복되고 운영진이 반복 응답하는 부담.
- "막혔는데 어디 물어보지" 상태 → 제출률 저하·이탈 위험.

회의에서 합의한 방향: **기능 추가 ❌ / 정보가 모이는 한 곳 ⭕**.

## 2. v1 한 줄

**Slack에 흩어진 미션 관련 정보를 "주차별 미션" 한 페이지로 모은다.**

- 로그인 없음
- 기존 운영 도구(`spongeclub-homepage`·`spongeclub-community`)와 자연스럽게 연결.
- **여러 레포에 흩어져 배포된 Vercel 프로젝트들을 하나의 진입점·통합 도메인으로 묶어** 한 곳에서 사용 가능 (`spongeclub-homepage` + `spongeclub-community` + 신규 미션 페이지).

## 3. 사이트 구조 (v1)

3-탭 / 로그인 없음 / 헤더 워드마크 🧽 스폰지클럽으로 기존 사이트와 연결성.

| 탭 | 역할 | v1 범위 |
|---|---|---|
| **주차별 미션** (메인/홈) | 본 제안의 핵심 | §4 상세 |
| **스킬 & 인사이트** | 멤버 도구·꿀팁 카탈로그 | **지정된 Slack 채널만 자동 수집해 카드 노출.** 분류 4축(난이도·대상·토픽·반응 이모지) |
| **이기적인 스폰지들 ↗** | 활동 랭킹·공유회 등 커뮤니티 활동 | **외부 링크로 연결** (기존 `spongeclub-community.vercel.app` 그대로 사용) |

v1 제외: 멤버 페이지 · 사이트 내 글쓰기 · 인증·로그인 (모두 v2 검토).

## 4. 주차별 미션 페이지 — 상세 설계

랜딩 페이지 1장이 곧 v1의 본체입니다. 4꼭지(**미션 내용 · 일정 · 개인/조별 진척도 · 질문/공유**)를 한 화면 안에 위에서 아래로 배치.

### 4.1 페이지 섹션 구성 (위에서 아래)

| # | 섹션 | 역할 | 데이터 출처 |
|---|---|---|---|
| 1 | **7주 타임라인** | 0–6주차 핀(현재 주차 강조) | 운영진 입력 (커리큘럼) |
| 2 | **📢 공지사항 배너** | 긴급·일정·자료 라벨로 라벨링된 최근 공지 3–5개 (전체 보기 링크) | Slack `#0-공지사항` 자동 수집 |
| 3 | **Hero — 이번주 미션** | 미션 제목·D-day + 3-col(🎯 학습 목표 / 📦 결과물 / 📚 학습 자료 배너) | 운영진 입력, spreadsheet 연동 |
| 4 | **이번주 일정** | 3카드: 목요일 Q&A / 일요일 19시 제출 마감(핵심) / 일요일 20시 이기적공유 3단 | 운영진 입력 |
| 5 | **6개 조 진척 매트릭스** | 6개 조 × 멤버별 칩(✓제출 · ✏️작성 중 · ○미작성), 평균·총계 노출 | `spongeclub-homepage.vercel.app` (이미 트래킹 중) |
| 6 | **미션 관련 질문 & 공유** | Slack 자동 수집 → 필터(전체/`#질문`/`#노하우`/`#사이트`) · 미해결/해결/공유 뱃지 · **카드별 해시태그**(`#질문`·`#노하우`·`#사이트` + 토픽 태그) · **🎯 미션 관련도 점수** · 반응 카운트 | Slack Events API → Supabase, Graphify로 주차 매칭 + 미션 관련도 스코어링 |
| 7 | **🧽 이기적인 스폰지들 CTA** | 외부 사이트 진입점 | 링크만 |

**상단 4꼭지**가 페이지 절반 안에 모두 들어가 "한 눈에 보이는 현황판" 형태를 유지합니다.

### 4.2 데이터 흐름 (요약)

```
[운영진 입력]                    [Slack]
   │ 미션 내용/일정/주차          │
   │ (Notion or 간단 CMS)        │ Events API
   ▼                             ▼
[Next.js Vercel]            [Vercel API Route]
   │                             │
   │                             ▼
   │                       [Supabase Postgres]
   │                             │
   │           일 2회 GH Actions │
   │                  ┌──────────┘
   │                  ▼
   │            [Graphify]
   │            주차·카테고리 분류
   │                  │
   ▼ ◄────────────────┘
[주차별 미션 페이지]
   │
   └─ 6개 조 진척 ← [spongeclub-homepage] (HTML fetch or shared DB)
```

- **Slack은 source of truth** (v1 단방향): 사이트엔 글쓰기 폼 없음. 푸터에 "✏️ Slack에 바로 쓰기 ↗" 딥링크.
- **6개 조 진척**은 이미 `spongeclub-homepage`가 관리하므로 그쪽을 단일 출처로. 데이터 가져오는 방식(공유 DB / API / iframe / fetch HTML)은 §6에서 합의 필요.

### 4.3 분류·큐레이션 정책(추가 고민 필요)

- **카테고리**: 1차 Slack 채널 매핑(공지·질문·공유), 2차 Graphify 클러스터링·주차 매칭.
- **콘텐츠 타입 해시태그**: 카드별로 `#질문` / `#노하우` / `#사이트` 자동 태깅 — Slack 채널·키워드 패턴(URL 포함 여부, "추천"·"꿀팁" 등) + Graphify 분류 기반. 도움 사이트는 별도 페이지/섹션을 만들지 않고 `#사이트` 해시태그로 식별.
- **🎯 미션 관련도 게이팅**: Graphify가 각 메시지의 "이번 주차 미션과의 관련도"를 0–100점으로 매김. **임계값 ≥ 70점** 이상만 §6 페이지에 노출 (관련도 낮은 글은 Slack에 그대로 두고 페이지엔 안 띄움). 임계값은 1주 운영 후 조정.
- **운영 모드**: v1 초반 **운영진 승인 후 게시** → 안정화되면 Graphify 점수 기준 **자동 게시**.
- **승인 UI**: Slack 봇 메시지의 ✅/❌ 버튼(1차) + admin 페이지에서 수정·삭제(2차).
- **PII**: 작성자는 **닉네임만** (본명·이메일·아바타 URL 저장 안 함).

## 5. 스킬 & 인사이트 탭

- **수집 대상**: #a유닛-이기적인스킬러들-에밀리 채널만.
- **노출 형태**: 단일 컬럼 카드 리스트. 4축 분류 — 난이도/접근성, 추천 대상, 토픽 태그, 다종 반응 이모지.

## 6. 운영진 합의 필요 항목

기술 작업과 병렬로 진행해야 일정이 직렬화되지 않습니다.

1. **Slack workspace admin 권한** — App 설치·Events API 구독을 위해 필요. 누구 admin인지·설치 가능 시점.
2. **community / homepage GitHub repo 접근** — 기존 코드 작성자와 연결, repo URL·권한.
3. **Vercel 프로젝트 통합 방식** — 단일 Next.js로 합칠지(추천), Turborepo 유지, 계정만 통합 중 선택. 기존 repo 구조 보고 결정.
4. **수집 대상 Slack 채널 명단 + 카테고리 매핑** — 두 탭에 들어갈 채널을 분리해 정리:
   - 공지사항 → #0-공지사항
   - 주차별 미션 → 각 조별 채널, #0-무지성질문아무나답변, #0-아무말대잔치
   - 스킬 & 인사이트 → #a유닛-이기적인스킬러들-에밀리
5. **6개 조 진척 데이터 연동 방식** — `spongeclub-homepage`의 진척 데이터를 어떻게 가져올지 (공유 Supabase / API / HTML fetch). 가장 깔끔한 길은 같은 DB.

## 7. 성공 지표 (MVP)

1. 주 1회 이상 미션 페이지 방문한 스폰지클럽 멤버 비율 **≥ 50%**
2. Slack → 페이지 노출까지 **≤ 10분**
3. 미션 페이지 반응(👍·👏·❤️ 등) **주당 N건** — 1주 베이스라인 측정 후 확정
